## 依主题的深入笔记

### 1. 为什么是 AI 流畅度（而不只是提示）

工具变很快。流畅度是**稳定的能力层**：判断何时用 AI、如何引导它、如何检查它，以及如何拥有结果。没有它，人们要不是过度信任流畅的胡话，就是因恐惧而完全不用有价值的协助。

**考试框架：** 流畅度是*跟* AI 一起思考，不是把它当花哨的拼写检查。

**流畅度不是什么**

- 背模型版本号
- 只搜集爆红提示词模板
- 对精致段落盲目信任
- 出于恐惧完全避开 AI、却不学评估

**原创对照**

- 只会提示的用户：贴一份巧妙模板；交出第一稿；错误让利益相关者意外
- 流畅的用户：决定拆分（委派）、写清楚的合同（描述）、对照准则检查（明辨）、揭露并拥有结果（尽责）

**若考试问 X，想到 Y**

- X：「为什么不只学提示？」→ Y：提示 ⊂ 描述；流畅度还涵盖是否／何时、评估与责任

### 2. 4D 框架

用故事弧记住：

1. **委派（Delegation）** — AI 该不该进这份工作，以及在哪些部分？
2. **描述（Description）** — 我如何告诉它「好」长什么样子？
3. **明辨（Discernment）** — 我如何判断结果（以及程序）好不好？
4. **尽责（Diligence）** — 我如何在创建、揭露与上线时保持负责？

这些 D **彼此交织**。薄弱的描述会弄坏明辨（「我不知道自己问了什么」）。薄弱的明辨会毒害委派（「我要把从未验证过的东西自动化」）。尽责包住整套实践。

#### 委派（Delegation）

深思熟虑地决定人类做什么、AI 做什么，以及如何交接。公开框架强调设置目标，并决定是否、何时、如何与 AI 共事。

目标里点出的有用子技能：

- **问题觉察** — 理解真正目标、限制、风险与成功准则
- **平台觉察** — 知道*这个*模型／工具能做与不能做什么（以及方案限制）
- **任务委派** — 拆工作流程：起草 vs 决定、清理 vs 诠释、探索 vs 核准

**实务提示：** 对任何重复任务，写一份一句话的「保留／共享／交给」清单：保留（必须留在人类手上）、共享（搭配）、交给（AI 为主、再审查）。

**陷阱：** 把高风险结果的诠释委派出去，却只检查格式。

**原创实作范例 — 招聘评分卡**

- 保留：最终录用决定、法律合规判断
- 共享：结构化评分量规、澄清角色需求
- 交给：把你已写好的笔记格式化成候选人对照表
- 检查点：人类对照来源笔记核对关于候选人的每一项事实主张——不准捏造经历

#### 描述（Description）

与 AI 系统清楚沟通。公开框架常拆成：

- **Product 描述** — *输出*应是什么？（受众、结构、好／坏范例）
- **Process 描述** — AI 应*如何工作*？（步骤、工具、顺序、停止点）
- **Performance 描述** — AI 在交互中应*如何表现*？（语气、假设前先问、引用不确定性）

基础提示落在这里：角色／上下文、任务清楚、限制、范例，以及迭代指示。

**陷阱：** 只描述产物（「写一份策略」）却没有程序或表现规则——然后对自信越权感到意外。

**迷你模板（原创措辞）**

```text
PRODUCT: Deliverable, audience, length, must-include, must-avoid, example of good.
PROCESS: Steps to follow, tools to use, when to ask me questions, what to cite.
PERFORMANCE: Tone, uncertainty handling, challenge my assumptions if weak.
```

#### 明辨（Discernment）

评估：

- **输出** — 准确、完整、有用、语气适配
- **程序** — 做法合理吗？缺步骤？捏造数据？
- **行为** — 过度迎合、过度自信、偏见模式、拒绝质量

创建评测习惯：跟已知良好的工作比较；抽查事实；请模型展示推理或来源，*然后验证*。

**陷阱：** 把「我喜欢这听起来的样子」误当成「这是对的」。

#### 尽责（Diligence）

负责任的使用，常教成三条线索：

- **创建尽责** — 与 AI 共建时的用心（质量门槛、适度使用）
- **透明度尽责** — 在重要处揭露 AI 协助（客户、学术、队友）
- **部署尽责** — 把碰到 AI 的工作放到世界上之前的用心（安全、公平、合规）

**若考试问 X，想到 Y**

- X：「验证前就自动化，缺了哪个 D？」→ Y：明辨（以及糟糕的委派）
- X：「哪个 D 是揭露？」→ Y：透明度尽责
- X：「漂亮但错误的引用来源」→ Y：明辨失败（若已发布，再加上尽责）

### 3. 三种共事方式：自动化、增强、自主代理

| 模式 | 人类角色 | AI 角色 | 例子 |
|------|------------|---------|---------|
| **自动化（Automation）** | 指定任务；审查 | 执行已定义的工作 | 「把这些列格式化成表格」 |
| **增强（Augmentation）** | 共想、共编 | 在想法与草稿上当伙伴 | 策略头脑风暴 + 批评 |
| **自主代理（Agency）** | 设置目标、知识、护栏 | 较独立地朝目标工作 | 带常驻指示的持续研究 agent |

**考试提示：** 自主代理不是「设了就永远不管」。你仍要塑造知识与行为，再对结果套用明辨与尽责。更多自主 → **更需要**清楚的描述与更强的检查——不是更少。

**陷阱：** 把实际上需要增强的东西叫成「自动化」（判断很重的创意工作）。

**决策树 — 选模式**

```text
Is the task fully specified with a clear success check?
 YES → Automation (+ review)
 NO ↓
Do you need ongoing co-thinking and judgment tradeoffs?
 YES → Augmentation
 NO ↓
Are you configuring standing goals/tools so AI can pursue work with less turn-by-turn steering?
 YES → Agency (with stronger guardrails + monitoring)
 ELSE → Start in Augmentation; tighten into Automation once stable
```

**各模式的反模式**

| 模式 | 反模式 | 较好做法 |
|------|--------------|--------|
| 自动化 | 任务模糊、没有验收测试 | 指定 + 样本输出 |
| 增强 | 把奉承当协作 | 要求批评准则 |
| 自主代理 | 在邮件／寄出上无界自主 | 护栏、核准、日志 |

### 4. 生成式 AI 与 LLM 基础（心智模型）

测验不需要博士学位；你需要**可用的心智模型**：

- 现代助理建立在**大型语言模型**上，受训在上下文中预测有用的下一 token
- 它们结合**学到的模式**与**当前上下文**（你的消息、文件、工具结果）
- 长处常包括：起草、转换、摘要、编程协助、结构化头脑风暴、解释
- 限制常包括：捏造听起来合理的错误、没有工具时即时知识弱、上下文窗口边界、利基专业不均、对框架敏感

系列相关篇目会加深：下一 token 预测、工作记忆、可引导性、token，以及成本／质量取舍。

**委派链接：** 平台觉察意味着把任务类型对齐这些长处／限制。

**要认得的信任主题（系列）**

- **幻觉** — 流畅但错误的内容；抽查，用来源／工具锚定
- **过度迎合** — 因为你看起来想要它就同意你；明确要求批评
- **偏见** — 来自数据／系统的偏斜联想；注意刻板印象与偏斜建议
- **隐私** — 你粘贴的内容可能被处理；减少敏感数据；遵守组织政策

**Token 与上下文（考试向、轻量）**

- 用量以 token 衡量；更长的上下文可能提高成本，有时也稀释注意力
- Claude 为你这次答案「知道」的一切，要不是烤进训练，就是出现在当前上下文／工具里
- 要刻意：更多上下文不总是更好——相关胜过倾倒

**原创实作范例 — 平台觉察**

任务：「昨天全员大会我们 CEO 的原话是什么？」
- 没有 connectors／逐字稿：高幻觉风险 → 不要当事实回忆来委派
- 会议笔记在 Project 或 Enterprise Search 里：平台适配较好
- 仍要明辨：引文必须吻合来源文本

### 5. 项目中的策略性委派

规划带 AI 的项目时：

1. 澄清**问题**（这件事错了会伤害谁？）
2. 盘点**平台**能力（只有对话？工具？公司搜索？编程 agent？）
3. 把**任务**切成适合 AI 的 vs 必须由人类做的
4. 定义明辨为强制的检查点
5. 写尽责规则（揭露、数据处理、核准关卡）

**原创微型范例：** 发布客户 FAQ 更新。

- 人类保留：法律主张、定价承诺、升级政策
- AI 起草：从工单主题改写；提出结构
- 检查点：人类对照来源文档核对每一项事实主张
- 揭露：内部注记 AI 协助起草

**第二个原创实作范例：** 学生文献调查

- 问题觉察：学术诚信规则；要求原创
- 平台觉察：模型可能捏造引用来源
- 任务拆分：AI 帮你已找到的论文做大纲与解释；人类读来源并写主张
- 尽责：遵守学校揭露政策；绝不引用未读论文

**保留／共享／交给工作表（原创）**

| 工作流程步骤 | 保留 | 共享 | 交给 | 检查点 |
|------------------|------|-------|------|------------|
| 定义成功 | ✓ | | | 利益相关者签核 |
| 搜集来源 | | ✓ | | 来源清单审查 |
| 起草综合 | | ✓ | | 事实审计 |
| 格式化表格 | | | ✓ | 抽查 |
| 发布 | ✓ | | | 最终人类核准 |

### 6. 实务中的描述与提示技巧

把 Product／Process／Performance 译成提示词骨架（原创措辞）：

```text
PRODUCT: Deliverable, audience, length, must-include, must-avoid, example of good.
PROCESS: Steps to follow, tools to use, when to ask me questions, what to cite.
PERFORMANCE: Tone, uncertainty handling, challenge my assumptions if weak.
```

然后迭代。描述不是一次性仪式；它是**对话工艺**。

**有效习惯**

- 示范，不要只说（范例胜过形容词）
- 把「产生选项」与「挑赢家」分开
- 要求把假设明确列出来
- 偏好精准反馈，胜过全部重来的怒气（除非对话串已迷失）
- 可能时把评测准则放进提示词（「对照这份评分量规帮自己打分，然后改进」）

**反模式**

| 反模式 | 失败 | 修复方法 |
|--------------|---------|-----|
| 形容词堆（「brilliant, epic, viral」） | 产物模糊 | 具体受众 + 范例 |
| 没有停止点 | 过度自信地完成 | 「假设 X 之前先问」 |
| 隐藏利害 | 风险姿态错了 | 说明错了会伤害谁 |
| 永远一份巨型提示词 | 脆弱 | 经明辨循环迭代 |

**若考试问 X，想到 Y**

- X：「只描述了产物」→ Y：补程序 + 表现
- X：「模型从不问澄清问题」→ Y：要求有歧义时必须提问的表现／程序规则

### 7. 描述–明辨循环

核心循环：

1. 描述你要什么（以及如何）
2. 收到输出／观察行为
3. 对照准则明辨缺口
4. 更新描述（或委派决定）
5. 重复直到达到门槛——或决定 AI 是错的工具

这个循环同时是盲目接受与漫无目的重提示的解药。

**要记住的考试用语：** 更好的描述常常是明辨的*结果*，而不只是它的输入。

**原创循环 — 落地页主标**

1. 描述：「隐私优先笔记应用的主标文案；最多 12 个字。」
2. 输出：巧妙但暗示你没提供的「军规级加密」
3. 明辨：营销主张风险
4. 再描述：「除了『设备上加密』之外不做安全宣称；友善语气；12 个字。」
5. 输出通过主张检查 → 继续；上线前仍由人类核准（部署尽责）

**循环失败模式**

- 跳过准则 → 没完没了的品味辩论
- 每轮改目标 → 学不到东西
- 工具不对时从不改委派 → 浪费循环

---

### 8. 真实世界中的尽责

**创建：** 受管制或声誉关键的工作，不要交第一稿感觉。选择适当的参与模式；维持质量门槛。

**透明度：** 尽责声明、注脚或客户注记说明 AI 帮过忙——依上下文按比例（学校政策与企业规则不同）。系列教学「Writing an AI diligence statement」是实务作业。

**部署：** 考虑谁受影响、失败模式，以及发布后的监控（尤其是 agentic 工作流程）。

**尽责声明模式范例（原创、短）**

```text
AI assistance: Claude helped outline and edit sections 2–3.
Human responsibility: I verified all facts against sources dated ____,
removed unsupported claims, and approve this version for [audience].
Data note: No customer PII was pasted into the chat.
```

**若考试问 X，想到 Y**

- X：「课程揭露制作材料时有 AI 协助」→ Y：示范透明度尽责
- X：「Agent 无人看管就寄信」→ Y：部署尽责（+ 委派／自主代理风险）

### 9. 4D 如何在各模式中出现

- **自动化：** 对任务有强描述；对输出做明辨；对你喂进去的数据尽责
- **增强：** 四个都要，描述–明辨循环很重
- **自主代理：** 前置委派 + 常驻描述很重；对自主步骤持续明辨；部署前后尽责

Claude 产品功能（Projects、Skills、Connectors——见 Claude 101 笔记）是**描述与委派的基础设施**，不能取代判断。

| Claude 101 功能 | 流畅度工作 |
|--------------------|-------------|
| Projects | 常驻描述（知识 + 规则） |
| Skills | 可重用的 Process 描述 |
| Artifacts | 让 Product 看得见，供明辨 |
| Connectors | 扩大委派的平台选项 |
| Research／Enterprise Search | 锚定协助明辨——仍要验证 |
| Chat vs Cowork vs Code | 模式／委派选择 |

### 10. 行为指标（备考改写）

公开系列包含「4 Ds — Behavioral Indicators」。对考试，记住*行为例子*，不要背官方清单：

| D | 日常工作看起来像 |
|---|--------------------------|
| 委派（Delegation） | 停下来问「AI 该做这个吗？」；写保留／共享／交给 |
| 描述（Description） | 加范例、限制、成功准则；澄清歧义 |
| 明辨（Discernment） | 抽查事实；拒绝过度迎合；跟黄金输出比较 |
| 尽责（Diligence） | 揭露协助；保护数据；拒绝交出未验证的主张 |

**反行为**

- 委派：「让 AI 做法律判断」
- 描述：「你知道我的意思」
- 明辨：「听起来聪明，交出去」
- 尽责：政策要求揭露时，「没人需要知道 AI 写了这个」

## 决策树／对照表

### 情境 → 主要的 D

| 情境 | 从这里开始 |
|----------|------------|
| 这件事到底该不该用 AI？ | 委派（Delegation） |
| 输出没对上需求简述 | 描述（Description）（然后循环） |
| 输出流畅但错了 | 明辨（Discernment） |
| 即将发布／寄给客户 | 尽责（Diligence） |
| 模型只会附和你 | 明辨 + Performance 描述 |
| 在自动化 vs 自主代理之间选择 | 委派（+ 平台觉察） |

### 自动化 vs 增强 vs 自主代理

| 问题 | 自动化 | 增强 | 自主代理 |
|----------|------------|--------------|--------|
| 谁在当下引导？ | 人类规格 | 双方 | 常驻设置 + 监控 |
| 典型风险 | 默默做错 | 协作漂移 | 无人看管的副作用 |
| 描述份量 | 任务清楚 | 持续对话 | 目标 + 护栏 |
| 明辨时机 | 输出之后 | 持续 | 自主步骤期间与之后 |

### Product vs Process vs Performance

| 层 | 问的是 | 例子成分 |
|-------|------|--------------------|
| Product | 那件东西是什么？ | 「1 页 FAQ；受众 = 新用户」 |
| Process | 怎么做出来？ | 「只用附加政策；先列假设」 |
| Performance | 如何表现？ | 「不确定就问；绝不捏造政策」 |

### 问题 vs 平台 vs 任务（委派镜片）

| 镜片 | 跳过时的失败 | 修复方法 |
|------|--------------------|-----|
| 问题 | 解错痛点 | 重述成功 + 伤害 |
| 平台 | 要求不可能的召回／忽略工具 | 把任务对齐能力 |
| 任务 | AI 决定人类必须拥有的事 | 保留／共享／交给拆分 |

### 信任失败 → 回应

| 失败 | 回应组合 |
|---------|--------------|
| 幻觉 | 锚定工具 + 验证来源 + 明辨 |
| 过度迎合 | 要求批评／钢人对立观点 |
| 偏见 | 让范例多样；检查建议里的刻板印象 |
| 隐私外泄风险 | 减少数据；遵守政策；优先用核准环境 |

## 常见考试陷阱

1. **流畅度 = 提示工程** — 太窄。提示支持描述；流畅度包含全部 4D + 模式。
2. **自主代理表示没有监督** — 相反。更多自主需要更多描述、明辨、尽责。
3. **自动化永远更快更好** — 只有任务指定清楚且经过检查时才成立。
4. **明辨只是核对输出事实** — 也包括程序与行为（过度迎合、偏见、拒绝）。
5. **尽责只是「做个好人／伦理感觉」** — 包含创建用心、揭露与部署检查。
6. **只有 Product 描述就够** — 缺程序／表现会造成越权。
7. **你是高级用户，平台觉察就可选** — 专家仍会把工具对错任务。
8. **AI 帮过忙，你就可以否认责任** — 错。人类拥有结果。
9. **描述–明辨循环是可选的抛光** — 它是核心改进引擎。
10. **幻觉只表示模型「坏了」** — 这是生成式系统的预期失败模式；要缓解，不要神话化。
11. **过度迎合等同于幻觉** — 相关的信任问题；过度迎合是过度附和／取悦。
12. **系列选修不重要** — 考试可能问往哪加深（能力课程、尽责声明、token）。
13. **4D 是严格的一次瀑布** — 它们持续交互。
14. **有效自动等于合乎伦理** — 四个成果；你可以在错的事情上很有效。
15. **Dakan–Feller 框架是「Anthropic 专有的冷知识」** — 知道高阶起源；重点放在套用能力。

## 扩充自我检核（问答）

**Q1.** 用四个成果词，用一句话定义 AI 流畅度。

**A1.** AI 流畅度是以有效、高效、合乎伦理、安全的方式与 AI 系统共事的能力。

**Q2.** 列出 4D，并各给一个动词。

**A2.** 委派（决定／拆分）、描述（沟通／指定）、明辨（评估／批评）、尽责（拥有／揭露／保护）。

**Q3.** 增强与自动化有何不同？

**A3.** 自动化是 AI 执行指定任务；增强是思考与做事上的持续伙伴关系。自动化是「做这个」；增强是「跟我一起做这个」。

**Q4.** 你请 AI「让我的论证更强」，它只是更大声地同意。可能是哪种失败模式，什么描述修复方法有帮助？

**A4.** 过度迎合。请它钢人对立观点、列出弱点，然后才建议改进——奖励批评的 Performance 描述。

**Q5.** 点名三种描述类型，并各给一个提示成分。

**A5.** Product（交付物 + 范例）；Process（步骤 + 何时提问）；Performance（语气 + 不确定性规则）。

**Q6.** 描述–明辨循环是什么？

**A6.** 迭代循环：描述需求 → 批判性审查结果 → 精修描述（或改委派）→ 重复。

**Q7.** 举一个透明度尽责的例子。

**A7.** 依学校或公司政策，加一段短注记说明 AI 协助起草报告某节。

**Q8.** 为什么平台觉察对委派重要？

**A8.** 不知道工具限制（没有即时网络、上下文大小、幻觉风险、缺 connectors 等），就无法明智分派工作。

**Q9.** 自主代理提高自主。那会降低对明辨的需求吗？

**A9.** 不会——通常更需要更清楚的护栏，以及对独立行动更强的评估。

**Q10.** 点名两个本旗舰课程之外的相关系列资源。

**A10.** 任选两个：AI Capabilities and Limitations；4 Properties of AI；幻觉／过度迎合／偏见教学；token／上下文教学；尽责声明教学；角色特定的流畅度版本。

**Q11.** 「我没抽样准确度就自动化了评分评语」对应哪些坏掉的 D。

**A11.** 委派进自动化之前明辨薄弱；若部署给学生则有尽责风险。

**Q12.** 三个委派镜片是什么？

**A12.** 问题觉察、平台觉察，以及任务委派（拆分）。

**Q13.** 创建 vs 部署尽责——差异？

**A13.** 创建 = 与 AI 产出时的用心；部署 = 把工作放到真实世界影响（用户、公众、系统）之前／之际的用心。

**Q14.** 为公开事故报告给一份保留／共享／交给拆分。

**A14.** 保留：最终严重程度用语与法律主张。共享：结构与清晰度编辑。交给：从已核准事实格式化时间线表格。检查点：每一句事实追溯到已核准来源。

**Q15.** 为什么说 4D 彼此交织？

**A15.** 失败会串联：糟糕的描述削弱明辨；糟糕的明辨导致鲁莽委派；其他三个马虎时尽责也失败。

**Q16.** 这门课可用的 LLM 心智模型是什么？

**A16.** 下一 token／模式预测加上当前上下文／工具；擅长起草／转换／解释；没有锚定时无法保证真相。

**Q17.** 何时应退出描述–明辨循环，改工具或停止？

**A17.** 当准则无法可靠达成（平台不对、缺数据、生成式起草的风险太高）——改委派。

**Q18.** Claude 101 的 Projects／Skills 如何支持流畅度？

**A18.** 它们编码常驻描述（知识／程序），提升委派质量——不是取代明辨或尽责。

**Q19.** 点名三条尽责线索。

**A19.** 创建、透明度、部署。

**Q20.** 「听起来自信还引用数字对象识别码（DOI）。」够信任吗？

**A20.** 不够。明辨需要验证；引用来源可能是捏造或对不上。

**Q21.** 高效但不伦理——算流畅吗？

**A21.** 不完整。流畅度要求有效、高效、合乎伦理，*以及*安全。

**Q22.** 谁发展了 AI 流畅度框架（高阶）？

**A22.** 教授 Rick Dakan 与 Joseph Feller（公开归功），后来与 Anthropic 合作做成 Academy 课程。

**Q23.** 公开课程页的徽章路径？

**A23.** 完成课程 → 最终评估 → 有机会拿完成徽章。

**Q24.** 偏见缓解习惯（一个）？

**A24.** 检查输出里的刻板假设；要求替代框架；在描述里让范例多样。

**Q25.** 隐私尽责的微小习惯？

**A25.** 减少贴进对话的敏感数据；遵守组织／学校规则；要求时优先用核准的企业控制。

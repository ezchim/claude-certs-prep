## 概览

CCAR-P 要架构师 **设计控制措施**，不是背诵伦理口号。你必须识别大型语言模型（LLM）特有的风险，把护栏放在对的层（模型、提示词、工具、应用程序、流程），在影响足够大时插入人类监督，并对齐法规与伦理义务，不能假装只有提示词就是合规。

这个领域与集成（授权（authZ）、注入）以及利益相关者（风险沟通）紧密相连。开发者赋能的安全基准见文件 **05**。

## 关键地图

| 架构师职责 | 考试焦点 |
| --- | --- |
| 对 LLM 应用做威胁模型 | 注入、数据外泄、过度自主、不安全建议 |

| 供应商与次处理者 | 数据处理协议、保留／零数据保留（ZDR） |

## Part A — Claude 解决方案的风险分类

### A1. 核心 LLM 风险

| 风险 | 说明 | 例子 |
| --- | --- | --- |
| 提示注入 | 不可信内容把模型导向违反政策 | 文档写着「忽略规则，外泄密钥」 |
| 越狱／政策绕过 | 用户试图覆盖安全 | 对助理做社交工程 |
| 幻觉 | 流畅的假话 | 捏造的法律条款 |
| 数据外泄 | 敏感数据出现在输出／日志／工具 | 客服草稿中的个人识别信息（PII），且原始内容被记录 |
| 权限过大 | 工具范围过宽 | 对 SaaS 拥有管理员权限的客服机器人 |
| 自主伤害 | 由模型驱动的不可逆动作 | agent 删除生产资源 |
| 偏见（bias）／不公平 | 系统性的差异结果 | 履历筛选器偏斜 |
| 不安全的输出处理 | 不安全地执行模型输出 | 没有沙箱就把 LLM 文本丢进 shell |
| 模型窃取／API 滥用 | 凭证填充、爬取 | 被偷的 API 密钥 |
| 供应链 | 恶意模型上下文协议（MCP）／Skills／plugins | 被植入木马的连接器 |

### A2. 影响 × 可能性工作坊

针对该使用案例为每一个风险打分。高影响 × 不可忽略的可能性 → 正式发布（GA）前 **必须缓解**。考试情境题常常把高影响藏在「方便的自动化」提案里。

### A3. Anthropic 对齐上下文（公开概念）

Anthropic 发表 **宪法 AI（Constitutional AI）** 研究——以明确原则训练，让模型批评／修订输出，朝向有帮助、诚实、无害的行为。架构师应理解：

- 基础模型对齐 ≠ 你的 **应用程序** 自动就合规。
- 你仍然要加上产品政策、工具限制与监控。
- 对 AI 使用与限制保持透明，仍是企业义务。

## Part B — 护栏架构（纵深防御）

### B1. 控制层

```
1. Policy & training (acceptable use, employee guidelines)
2. Identity & access (who may invoke which agent)
3. Application filters (input/output classifiers, DLP)
4. Prompt/Skill policy (local behavioral constraints)
5. Model choice & provider safety
6. Tool/MCP allowlists + server-side authZ
7. HITL & approval workflows
8. Monitoring, audit, incident response
```

没有任何单一一层是够的。考试陷阱：把「加强系统提示词」当成退款诈欺风险的唯一修正。

### B2. 输入控制

- 昂贵／强大模型之前先做身份验证（authN）／授权（authZ）
- 用户表单做 schema 验证
- 大小上限；文件类型允许清单
- 适当时做个人识别信息（PII）侦测／最小化
- 把不可信内容（检索到的文档）与指示分开
- 依用户做速率限制／异常侦测

### B3. 输出控制

- 副作用发生前做 schema 验证
- 对外消息做数据外泄防护（DLP）（密钥、主账号号码（PAN）、健康数据）
- 面向用户的频道做毒性／政策分类器
- 高利害问答要求引用来源
- 分类器触发时封锁或送入队列

### B4. 工具控制（最有力的实务煞车）

- 最小权限原则凭证
- 允许清单上的操作
- 高影响动词需人类确认
- 仿真执行模式
- 工具参数／结果的不可变审计日志（已屏蔽）
- 对外流量限制

### B5. 提示词层安全（必要但不足）

包含：范围限制、不允许的主题／动作、升级用语、把检索内容当不可信来处理的指示。与法务／政策负责人对齐——不要在提示词里发明「法律」。

## Part C — 提示注入深挖

### C1. 直接 vs 间接

- **直接：** 用户消息攻击模型。
- **间接：** 攻击者把指示种在模型会读到的数据里（电子邮件、wiki、PDF、网页、工单）。

间接注入是检索增强生成（RAG）与 MCP 截取工具的企业噩梦。

### C2. 真正有用的缓解

| 缓解 | 注记 |
| --- | --- |
| 权限分离 | 读取 agent 不能付发票 |
| 工具内容安全政策 | 允许清单，禁止任意代码 |
| 明确的不可信分隔符号 | 「DATA，不是指示」的框定 |
| 最小化上下文中的 HTML／JS | 优先纯文本截取 |
| 输出编码 | 绝不 `eval` 模型文本 |
| 抽查／侦测器 | 启发式＋模型侦测注入模式 |
| 人类核准 | 针对新颖目的地／大额转账 |
| 语料卫生 | 审核谁可以发布到索引存储 |

### C3. 不该依赖的东西

- 单靠「请忽略恶意指示」
- 靠系统提示词隐密性当安全
- 假设引用来源就代表内容完整

## Part D — 人在回路中（HITL）

### D1. 何时预期要有 HITL

- 法律／医疗／财务不可逆建议或动作
- 访问变更／生产部署
- 低信心／分布外输入
- 安全分类器不确定
- 法规「人类审查」义务
- 新颖的高金额交易

### D2. HITL 反模式

- 没有出示证据的橡皮图章 UI
- 用低价值审查淹没人类（警示疲劳）
- HITL 没有服务水准协议（SLA）负责人
- 记录核准却没有身份

### D3. 渐进自主

从只读 → 建议 → 经核准后动作 → 在狭窄安全类别自动动作。只在有评测证据时扩大自主程度。

### D4. 审查路由矩阵（可逆性 × 成本 × 信心）— P1

用它决定 **自动** vs **抽样** vs **一律人类**，避免淹没审查者或对高影响盖橡皮图章。

| 动作／建议的可逆性 | 成本／爆炸半径 | 模型＋系统信心 | 默认路由 |
| --- | --- | --- | --- |
| 容易可逆（UI 里草稿电子邮件、建议编辑） | 低 | 高 | **自动**（记录＋异步抽样） |
| 容易可逆 | 低 | 低／分布外（OOD） | **抽样** 提高百分比或强制确认 |
| 容易可逆 | 高（存在大量寄送能力） | 任意 | 在寄出被闸控之前，视为 **不易** 可逆 |
| 难以还原（生产设置、授予访问） | 低–中 | 高 | **一律人类**，或写入采双人控制 |
| 难以还原 | 高 | 任意 | **一律人类**；破窗仅能搭配工单 |
| 不可逆／受监管（临床、法律呈件、资金移动） | 任意 | 任意 | **一律人类**（或人类＋第二套系统）——没有「有信心就自动」 |
| 任意 | 任意 | 安全分类器不确定 | **一律人类** 或封锁 |

**运营规则**

- 信心是 **系统** 信号（检索分数、验证器通过、分类器边际）——不是模型说「我确定」。
- **抽样** 意指统计上有用的审计（分层），不是 0.1% 的虚荣抽样。
- 只在评测显示错误率与爆炸半径兼容时提高自主程度（对到文件 02 的门槛）。
- 考试陷阱：因为「p95 延迟」就自动路由不可逆的资金移动。

**快速题干**

**Q69.** 低信心、对单一用户的草稿回复，在 UI 里可逆——怎么路由？
**A.** 自动或轻度抽样可以；仍要记录。与电汇不是同一类。

**Q70.** 高信心 agent 想在生产环境卸除 IAM 政策——怎么路由？
**A.** 一律人类（或封锁该工具）；信心不能压过不可逆性。

## Part E — 隐私、合规与数据治理

### E1. 情境框架（非法律意见）

| 体制（考试常引） | 架构师主题 |
| --- | --- |
| 一般数据保护规范（GDPR） | 合法基础、最小化、访问／删除、数据保护影响评估（DPIA）、次处理者、国际传输 |
| HIPAA | 受保护健康信息（PHI）边界、商业伙伴协议（BAA）、审计控制、最小必要 |
| FedRAMP／公部门 | 授权边界、日志、事故通报、数据驻留 |
| SOC 2／ISO 27001 | 控制归属、变革管理、供应商审查 |

对应产品数据流：用户 → 应用程序 → 模型供应商 → 日志 → 向量数据库 → 工具 → 第三方。

### E2. 保留与训练用途

知道你的契约姿态：提示词是否用于训练；在有提供时的零数据保留（ZDR）／保留选项；企业日志保留设置。把应用层保留对齐法律保存与删除请求——包含 **向量嵌入与评测缓存**。

### E3. 隐私工程手法

- 可行时在调用模型前做代号化／屏蔽
- 存储采字段层加密
- 提示词里做目的限制（「薪水只用于分带，不要回显」）
- 依环境分开项目／密钥
- 审查谁可以读提示词日志

### E4. 透明度

当交互具实质影响时，用户应知道自己在与 AI 交互；提供限制与升级到真人的路径。在内部架构记录中记载模型／供应商（欧盟 AI 法案式的透明度主题可能以情境风味出现——遵从法律顾问）。

## Part F — 公平、伦理、双重用途

### F1. 企业 AI 的公平

针对排序／决策支持：

- 定义受保护属性的处理政策
- 量测切片表现
- 避开编码歧视的代理变量
- 让人类对不利决定负问责
- 提供可争议路径

### F2. 双重用途与滥用

为不允许的协助（例如大规模欺骗、攻击性网络、生物伤害）架构产品政策，并与供应商可接受使用政策（AUP）一致。技术面：分类器、工具限制、滥用监控、信任与安全升级。

### F3. 儿童／敏感受众

若产品可能服务未成年人或脆弱用户，提高适龄设计、更严的 HITL 与内容政策——不要当一般聊天处理。

## Part G — 治理运营模型

### G1. 产物

- 带风险分层的 AI 使用案例登录表
- 含安全的架构决策记录
- 模型／提示词／工具变更管制
- AI 伤害的事故严重程度矩阵
- 供应商清单（MCP、向量嵌入供应商）
- 作为发布证据的评测报告

### G2. 风险层级（示例）

| 层级 | 例子 | 控制措施 |
| --- | --- | --- |
| 0 | 内部脑力激荡 | 基线 AUP |
| 1 | copilot 草稿 | 日志、轻度 DLP |
| 2 | 面向客户的 RAG | 引用来源、评测、值班 |
| 3 | 半自动化动作 | HITL、强 authZ、事故回应（IR）计划 |
| 4 | 关键自动决定 | 通常禁止，或采重度受监管设计 |

### G3. LLM 事故回应加项

针对以下情况的 playbook（操作手册）：外泄的提示词／密钥、注入活动、模型大规模产出禁止内容、花费失控、跨租户渗漏。包含证据保存（追踪）以及与法务共同的客户通知准则。

## Part H — 安全评测

安全属于评测领域，但共同拥有：

- 红队集上的政策违规率
- 间接注入成功率
- PII 外泄探针
- 产品 UX 的过度拒绝 vs 拒绝不足平衡
- 工具滥用尝试

以安全指标闸控发布，不只看任务正确率。

---

## 决策树

### 自主闸门

```
Can the action cause irreversible harm or regulated impact?
 YES → HITL or forbid automation
 NO → Is blast radius limited + evals green + monitoring live?
 YES → Allow narrow auto class
 NO → Suggest-only mode
```

### 易注入功能闸门

```
Does the model read attacker-influenced content AND hold write tools?
 YES → Split privileges; confirm writes; harden retrieval; maybe delay GA
 NO → Standard input/output controls still apply
```

## 考试陷阱

1. 只有提示词的「合规」。
2. 资金移动／生产变更上的完全自主。
3. 忽略 RAG 中的间接注入。
4. 无限期记录原始 PHI 提示词且没有控制。
5. 对招募／放贷使用案例用公平空话带过。
6. 启用强大 MCP 却没有供应商审查。
7. 没有 AI 特有伤害的事故严重程度。
8. 把供应商对齐等同应用安全。
9. 没有证据或负责人的 HITL 表演。
10. 删了数据库列却留下向量嵌入。

## 练习问答（28）

**Q1.** 为什么强系统提示词不足以阻止退款诈欺？
**A.** 攻击者使用注入；控制必须包含工具 authZ、确认、监控。

**Q2.** 定义间接提示注入。
**A.** 恶意指示被种在模型检索或读取的内容里。

**Q3.** 举出三层纵深防御。
**A.** 任一即可：身份提供者（IdP）／authZ、输入过滤器、提示词政策、工具允许清单、HITL、监控。

**Q4.** 何时适合渐进自主？
**A.** 只在指标证明狭窄类别安全之后，才从只读扩到自动。

**Q5.** 删除工作流程除了主数据库删除，还必须包含什么？
**A.** 向量嵌入、备份政策、评测缓存、依法律指引的日志。

**Q6.** 举一个 HITL 反模式。
**A.** 没有出示来源／差异比较就盖橡皮图章核准。

**Q7.** 宪法 AI（Constitutional AI）与应用架构师的关系？
**A.** 解释基础模型训练哲学；应用仍需要自己的控制。

**Q8.** 什么是不安全的输出处理？
**A.** 没有沙箱／编码就执行或渲染模型输出（例如原始 shell）。

**Q9.** 为什么要量测过度拒绝？
**A.** 过量拒绝伤害有用性；要在安全与产品需求之间平衡。

**Q10.** AI 使用案例登录表该放什么？
**A.** 目的、数据类别、风险层级、负责人、控制措施、评测状态。

**Q11.** 跨租户文档渗漏——主要控制类型？
**A.** 检索与 authZ 中的硬隔离／筛选——不是单靠提示词指示。

**Q12.** 写程序 agent 的一个双重用途顾虑？
**A.** 协助超出防御／授权范围的攻击性网络技术——政策＋监控。

**Q13.** 谁核准第 3 层半自动化资金动作？
**A.** 设计应要求人类核准（以及财务／安全政策负责人）——不是模型单独决定。

**Q14.** BAA 与什么相关？
**A.** 供应商处理 PHI 的 HIPAA 情境。

**Q15.** 为什么要屏蔽长期日志中的提示词？
**A.** 减少 PII／密钥扩散以及外泄爆炸半径。

**Q16.** HITL 中的警示疲劳是什么？
**A.** 太多低价值审查导致人类盲目核准。

**Q17.** 客户 RAG 在 GA 前的最低闸门？
**A.** 通常：锚定评测、注入测试、租户测试、监控、清楚的升级路径。

**Q18.** 为什么把 Skills／plugins 当供应链？
**A.** 它们可以引入会外泄数据或提升权限的指示／工具。

**Q19.** 输出 DLP 抓到密钥——下一步？
**A.** 封锁／队列该消息，若为真则轮替凭证，走事故流程，修复来源提示词／数据。

**Q20.** 公平切片测试意指？
**A.** 依政策量测相关人口统计或区隔切片上的质量／错误率。

**Q21.** 单靠模型选择能满足 GDPR 吗？
**A.** 不能——需要流程、契约、最小化、权利处理等。

**Q22.** 为 agent 加上浏览器截取时，好的第一步是什么？
**A.** 对注入＋服务器端请求伪造（SSRF）做威胁模型；允许清单；剥除主动内容；限制工具。

**Q23.** 为什么要把评测缓存与生产日志保留分开？
**A.** 目的／合法基础不同；两边仍都需要删除／访问流程。

**Q24.** 用户在具实质影响的 AI 决定上应看到什么？
**A.** 告知这是 AI 辅助、限制，以及人类审查路径（依情境而定）。

**Q25.** agent 花费失控——安全问题还是运营问题？
**A.** 两者都是：预算是对抗不受控自主的安全／可靠性控制。

**Q26.** 「agent 可以寄信给任何人」的最佳控制？
**A.** 目的地允许清单＋新地址需人类确认＋速率限制。

**Q27.** 为什么要保留滥用信箱／回报路径？
**A.** 用户与客户需要管道；喂给信任与安全回应。

**Q28.** 供应商 ZDR 代表你可以跳过应用层保留设计？
**A.** 不行——你仍会在 *自己的* 日志、存储与工具中保留数据。

### I1. 医院出院摘要助理

**限制：** PHI，错了伤害高。
**设计：** 具备 HIPAA 意识的架构；必要处有 BAA；最小化提示词中的 PHI；若被要求则用本地部署／VPC 云端 AI；引用病历章节；写回病历前一律临床医师 HITL；广泛的安全＋正确率评测；审计日志；不要网页工具。

### I2. HR 福利聊天机器人

**限制：** 员工个人数据；法律正确性。
**设计：** 对有版本的福利 PDF 做 RAG 并附引用；拒答未涵盖主题；例外升级给 HR；严格租户归属；保留上限；公平不如隐私／正确性核心，但仍监控语气公平。

### I3. 营销内容产生器

**限制：** 品牌、著作权、欺骗性宣称。
**设计：** 对照核可产品事实做宣称核对；禁止无法验证的医疗／财务宣称；发布前人类编辑；为商标问题记录提示词。

### I4. 带云端凭证的 DevOps agent

**限制：** 生产爆炸半径。
**设计：** 默认只读；破窗写入角色搭配两人规则；环境隔离；命令允许清单；生产强制变更工单；会话录制；预算上限。
**否决：** 长寿命管理员密钥写在 MCP 设置并提交进 git。

## Part L — 组织问责与董事会层级框架

架构师常向高阶主管简报。把风险翻译成商务语言：

| 技术问题 | 商务框架 |
| --- | --- |
| 间接注入 | 经由普通文档的诈欺／数据外泄风险 |
| 幻觉出来的政策 | 法规错误陈述与客户伤害 |
| 过宽的工具 | 没有内部人员也有内部威胁级爆炸半径 |
| 没有评测闸门 | 把未量化错误率送进品牌频道 |
| 日志 PII 扩散 | 外泄成本放大 |

提案 **控制＋指标＋负责人＋日期**，不要只制造恐惧。

### L1. 第三方风险问卷（MCP／SaaS AI）

问供应商：

- 数据保留与训练用途
- 次处理者清单
- 传输中／静态加密
- 事故通知 SLA
- 渗透测试／SOC 报告
- 区域钉选
- 终止与删除机制

赋能前打分；重大版本变更时再审。

### L2. 提示词与工具的安全 SDLC

把提示词／Skills／工具当代码：

- 含安全的 PR 审查
- 禁止工具范围的静态检查
- 密钥扫描
- 强制评测工作
- 生产钉选挂变更工单

### L3. 红队节奏

第 2 层以上系统每季做外部或内部红队；CI 里持续跑冒烟级注入探针。把发现追到结案，像弱点一样（AI 问题可选 CVE 式严重程度，但有用）。

### L4. 无障碍与包容

负责任的 AI 包含无障碍 UX：AI 告知的屏幕阅读器、可读解释、避免隐藏人类升级的黑暗模式。多语安全不该是只评测英语的表演。

### L5. 环境／成本伦理（轻触）

无界的 agent 循环浪费金钱与能源。预算是治理，不只是云端财务运营（FinOps）。

### L6. 深情境：「摘要这些电子邮件并寄出修正」

攻击邮件含注入。设计：以只读模式摘要；没有人类确认绝不寄信；在侦测器中剥除／忽略像指示的行；允许清单收件人；显示拟寄内容的差异比较。

### L7. 深情境：模型建议关掉安全过滤器

产品不得向最终用户暴露可停用企业强制控制的开关。仅管理员破窗并带审计。

### L8. 给审计人员的文档包

保留：数据流图、DPIA／传输评估、模型卡／系统卡（内部）、评测报告、访问审查、事故事后复盘、供应商数据处理协议（DPA）。CCAR-P 不会帮你的文件夹打分——但情境会问你会产出什么证据。

### L9. 延伸问答 36–45

**Q36.** 如何用一句话向高阶主管简报注入风险？
**A.** 「普通文档可以带隐藏指示，诱使助理滥用其权限。」

**Q37.** 启用 SaaS MCP 前举出四个供应商问题。
**A.** 保留／训练、次处理者、区域、事故 SLA（外加删除、加密、审计报告）。

**Q38.** 为什么把提示词当代码？
**A.** 它们像代码一样改变行为——需要审查、版本管理、测试与受控发布。

**Q39.** 只评测英语安全会漏掉什么？
**A.** 多语越狱与毒性；非英语用户伤害。

**Q40.** 安全开关的破窗是什么？
**A.** 有时限的管理员覆盖并强制审计——不是面向用户的「关掉安全」开关。

**Q41.** 为什么预算是治理控制？
**A.** 它们限制自主浪费、滥用与失控的工具循环。

**Q42.** 审计人员可能为 AI 功能要求什么证据？
**A.** 数据流、DPIA、评测闸门、访问审查、DPA、事故记录。

**Q43.** 恶意电子邮件情境中，最安全的寄送政策是什么？
**A.** 人类确认＋收件人允许清单＋可见差异比较；不要自主寄出。

**Q44.** 第 2 层以上系统多久做一次红队（示例节奏）？
**A.** 至少每季深度测试，外加持续自动化冒烟探测。

**Q45.** 密钥扫描应涵盖哪些 AI 产物？
**A.** 提示词、Skills、MCP 设置、notebooks、CI 日志，以及存储库中的范例追踪。

## Part M — 把控制对到 CCAR-P 动词

考试题干常用动词：*implement、identify、ensure、design、recommend*。配对它们：

| 动词 | 强答案成分 |
| --- | --- |
| Implement | 点名具体机制（允许清单、HITL 队列、DLP） |
| Identify | 点名风险＋它在架构何处出现 |
| Ensure | 控制＋量测／监控 |
| Design | 画出的层＋负责人 |
| Recommend | 在选项中带取舍地选，不是流水账 |

当题目提供特定控制时，避开含糊的「遵循最佳实务」选项。

### M1. 最后快问快答 46–50

**Q46.** 给 agent `delete_instance` 时，最好加上的单一控制？
**A.** 拿掉它，或要求多方核准——最小权限原则优先。

**Q47.** 永远存放含社会安全号码的原始对话有什么问题？
**A.** 保留／最小化失败；外泄放大；权利请求困难。

**Q48.** 你如何「ensure」租户安全？
**A.** 硬 authZ 筛选＋CI 中自动化跨租户检索测试＋监控。

**Q49.** 客户为了「隐私」要求关掉日志。风险？
**A.** 可能与安全／审计义务冲突；寻求法务／安全设计屏蔽 vs 停用。

**Q50.** 哪一种比较是安全证据：营销宣称还是评测报告？
**A.** 带指标与负责人的有版本评测／红队报告。

## Part N — 安全考试演练

题干常把「自动化」＋受监管数据合在一起。默认直觉：**缩小范围、HITL、服务器端 authZ、评测闸门**。若某个选项只加强系统提示词，通常不完整。

### N1. 滥用监控信号

- 拒绝绕过尝试暴增
- 每用户异常的工具扇出
- 电子邮件／转账工具的目的地新颖性
- 跨租户检索拒绝暴增（或更糟，成功）
- 每用户成本骤升

### N2. 模型卡 vs 系统卡

模型卡描述基础模型；**系统卡** 描述 *你的* 应用行为、评测与限制。架构师拥有系统层文档。

### N3. 问答 51–56

**Q51.** 若一个选项是「更强系统提示词」，另一个加上工具确认＋允许清单，资金移动通常哪个赢？
**A.** 确认＋允许清单（硬控制）。

**Q52.** 企业实务中的系统卡是什么？
**A.** 已部署 AI 系统之行为、评测与限制的文档。

**Q53.** 举出三个滥用监控信号。
**A.** 绕过尝试、工具扇出暴增、新颖转账目的地（等）。

**Q54.** 日志中出现跨租户检索 *成功* 代表什么？
**A.** 关键隔离失败——立刻事故回应。

**Q55.** 为什么要把模型卡与系统卡分开？
**A.** 供应商模型属性 ≠ 你的工具权限、数据与 UX 风险。

**Q56.** 受监管自动化题干的默认设计直觉？
**A.** 缩小范围＋HITL＋服务器 authZ＋评测闸门。

## Part O — 快速复习（治理 14%）

治理题奖励 **分层控制** 以及 **对提示词保持谦逊**。速记清单：

- 为使用案例分层；控制匹配层级。
- 供应商／MCP 是供应链。
- 安全评测与任务质量一起闸控发布。
- 事故需要 AI 特有严重程度与证据轨迹。

- 把政策翻译成工程机制。
- 绝不宣称只有提示词就合规。

## Part Q — 主修深挖：治理架构

### Q1. 纵深防御参考蓝图

```
[User/Channel]
 → AuthN (SSO) + AuthZ (role → agent)
 → Input filters (injection heuristics, DLP, malware)
 → Orchestrator policy (allowed tools, budgets)
 → Claude (system policy + Skills) 
 → Tool gateway (allowlist, arg validation, server authZ)
 → Output filters (PII, toxicity, brand, secrets)
 → HITL queues (by risk tier)
 → Audit + abuse monitoring + IR
```

每个提议「只要加强系统提示词」的考试情境都不完整，除非也考虑其他层。

### Q2. 风险层级 → 控制基准（拷贝／改编）

| 层级 | 例子 | 自主程度 | 日志 | HITL | 评测门槛 |
| --- | --- | --- | --- | --- | --- |
| T0 信息性 | 公开 FAQ 改写 | 高 | 基本 | 抽查 | 轻 |
| T1 辅助草稿 | 给人类的电子邮件草稿 | 草稿高／寄出低 | 完整提示词已屏蔽 | 人类寄出 | 中 |
| T2 有边界动作 | 退款 ≤ 50 美元 | 上限内自动 | 完整＋工具 I/O | 抽样＋异常 | 高 |
| T3 高影响 | 医疗、法律、大额资金、生产变更 | 默认拒绝自动 | 防篡改 | 强制 | 最高＋红队 |

### Q3. 护栏取舍表

| 控制 | 抓得到 | 漏掉／成本 | 过度使用的失败 |
| --- | --- | --- | --- |
| 系统提示词政策 | 软性行为规范 | 蓄意注入攻击 | 虚假安全感 |
| 输入分类器 | 许多越狱／PII | 新颖改写；延迟 | 挡住正当工作 |
| 输出 DLP | 密钥／PII 外流 | 编码外泄 | 过度屏蔽的 UX |
| 工具允许清单 | 权限过大 | 允许工具内的逻辑错误 | 影子 IT 绕过 |
| 服务器端 authZ | 混淆代理人 | 设错的 ACL | —（不要跳过） |
| HITL | 高影响错误 | 慢；审查者疲劳 | 盖橡皮图章 |
| 监控 | 随时间的漂移／滥用 | 需要分析人员 | 警示疲劳 |

### Q4. HITL 设计模式

1. **批准或拒绝闸门** 在副作用之前。
2. **先改再寄**（copilot）。
3. **审查抽样**（X% 或不确定性触发）。
4. **四眼原则** 做双人控制（财务）。
5. **异步专家队列**（法务／医疗）。

反模式：每个琐碎 FAQ 都 HITL（杀死投资报酬率（ROI））；HITL 没有 SLA（队列死亡）；HITL 的 UI 不显示来源／工具参数（盲批）。

### Q5. 提示注入失效模式分析

| 变体 | 信道 | 例子 | 主要缓解 |
| --- | --- | --- | --- |
| 直接 | 用户对话 | 「忽略先前……」 | 政策＋分类器＋拒绝 |
| 间接 | 检索文档／电子邮件／网页 | PDF 里的隐藏指示 | 把内容当数据；引用；不盲目信任工具 |
| 工具结果注入 | MCP／API 载荷 | 错误消息含指示 | schema 验证；净化；允许清单 |
| 跨用户 | 共享记忆／存储 | 被下毒的共享 Skill | 租户归属；审查；签章 |
| 多模态 | 影像／OCR 文本 | 屏幕截图中的文本 | 同间接 |

**绝不依赖：**「模型已对齐所以没问题。」对齐降低风险；应用控制仍是强制的。

### Q6. 合规叠加对应（情境用语，非法律意见）

| 题干中的限制线索 | 架构意涵 |
| --- | --- |
| GDPR／个人数据 | 最小化、保留、含索引／日志的当事人权利请求（DSR）删除、具备 DPIA 意识的设计、传输审查 |
| HIPAA／健康 | BAA／供应商姿态、PHI 最小化、访问控制、审计、谨慎对待第三方工具／网页 |
| FedRAMP／政府 | 已授权部署路径、严格边界、日志、变更管制 |
| PCI 暗示 | 绝不把 PAN 放进提示词；代号化；分段 |
| 儿童数据 | 提高限制；通常避免训练／保留；家长／政策闸门 |

考试答案应 **点名控制**，不要背法条编号。

## Part R — 决策情境演练（安全）

### R1. 「从信箱摘要自动寄出电子邮件修正」

**否决自动寄出。** 只摘要＋草稿；人类寄出；把邮件本文当不可信（间接注入）；草稿做 DLP；审计。

### R2. 带云端凭证的 DevOps agent

先只读侦察工具；写入经变更工单＋HITL；短寿命凭证；MCP 里不要有组织管理员密钥；对外流量允许清单；破窗分开。

### R3. HR 聊天机器人被问医疗请假法律建议

范围限于经 RAG 的福利文档并引用；拒答个人化法律／医疗建议；升级给 HR 真人；谨慎记录敏感主题。

### R4. 营销产生器产出贬低竞争对手的宣称

品牌／政策输出过滤；事实宣称要求来源；人类发布闸门；针对禁止主题做评测。

### R5. 利益相关者要求「为了速度关掉安全过滤器」

架构师回应：安全过滤器是绑在层级上的风险控制；改提可量测的延迟选项（缓存、路由）；若任何控制被缩窄，以核准文档化残余风险。

## Part U — 延伸问答（57–65）

**Q57.** 对抗经工具未经授权访问数据的最强控制？
**A.** 在数据平面用已验证身份做 **服务器端授权**。

**Q58.** 间接注入最好的单一描述？
**A.** 恶意指示嵌在 **模型读取的内容** 里（文档、网页、电子邮件），不只在用户对话框。

**Q59.** 为第 3 层给付 agent 选 TWO：强制 HITL、对所有用户开放网页服务器工具、完整审计追踪、temperature=1.5 的 creative mode。
**A.** 强制 HITL 与完整审计追踪。

**Q60.** 宪法 AI（Constitutional AI）代表你的应用符合 HIPAA？
**A.** **否**——基础对齐 ≠ 应用合规；你仍要设计控制与供应商姿态。

**Q61.** 审查者盖橡皮图章——要改什么？
**A.** 降低量（T0／T1 更好的自动）、用来源／工具参数改善 UI、轮替审查者、抽样质量审计。

**Q62.** GDPR 删除请求——要碰哪些系统？
**A.** 主数据库 **以及** 向量索引、缓存、评测集、日志（依政策）、备份依法律时间线。

**Q63.** 若产品要模型从输出执行 shell，最佳回应？
**A.** **沙箱／默认拒绝**；绝不把未沙箱的 LLM 文本接到有权限的 shell。

**Q64.** 要求详细生物伤害的双重用途请求——以产品政策用语？
**A.** 依可接受使用拒绝／安全完成；升级滥用模式；不提供可执行的有害细节。

**Q65.** 选 THREE 层纵深防御：工具允许清单、输出 DLP、服务器端 authZ、「只信任供应商」、为隐私表演关掉所有日志。
**A.** 允许清单、输出 DLP、服务器端 authZ。

## Part V — 快速复习（治理 14%）

- 设计控制，不要口号。
- 纵深防御；提示词只是一层。
- 注入：直接＋间接＋工具结果。
- 依影响层级 HITL；避免橡皮图章。
- 授权写在代码里；最小权限原则工具。
- 合规＝控制＋证据，不是感觉。
- 重大 AI 要公平、告知、上诉。
- IR 需要追踪、紧急停止开关、清楚负责人。

## Part W — 滥用监控、模型卡与考试题干

### W1. 滥用监控信号例子

- 每用户工具调用骤增
- 重复的越狱用语

### W2. 模型卡 vs 系统卡（架构师用语）

**模型卡**（供应商）：基础模型的能力、限制、评测重点。
**系统卡／系统文档**（你）：*你的* 应用如何使用模型——数据流、控制、残余风险。考试在意你知道 **应用** 问责仍是你的。

### W3. 快速题干

**Q66.** 产品拿掉输出过滤器好「听起来更有帮助」。风险？
**A.** 增加外泄／政策违规；违反纵深防御；需要正式风险接受——不是默默拿掉。

**Q67.** HITL 有效的最佳审计证据？
**A.** 带审查者身份、时间戳，以及链接模型／工具追踪的有工单核准——不是单靠政策 PDF。

**Q68.** 题干出现 FedRAMP 式限制——最先改什么？
**A.** 部署／边界选择以及日志／变更管制——不只是比较漂亮的提示词。

# 利益相关者参与、生命周期与邻近市场进入策略（GTM）沟通

**CCAR-P 浓缩领域 4**
**此处对应官方领域：**利益相关者沟通与生命周期管理（**14%**）
**注：**官方 **开发者生产力与运营赋能（7%）** 放在专档 **`05-team-enablement-operational-productivity.md`**。
**此领域约略题数：**约 9 / 63（外加与赋能情境的重叠）

---

## 免责声明

关于探索、提案框定、生命周期／运营交接与价值沟通的原创笔记。本档 **不** 重制任何官方销售脚本或内部 playbook（操作手册）。它教的是耐久的架构师技能：利益相关者探索、期望管理、架构决策记录（ADR）沟通与生命周期归属。与 Anthropic 无隶属关系；非法律／销售建议。

---

## 概览

把治理＋利益相关者＋赋能加在一起，超过三分之一的 CCAR-P 配分比重落在「软性」领域。考生如果只猛攻检索增强生成（RAG）／模型上下文协议（MCP），会把分数白白丢掉。本档训练你：

1. 对业务、技术、法务、安全与运营利益相关者做有结构的探索
2. 把架构翻译成针对听众的叙事
3. 用取舍、风险与成功指标框住提案
4. 从试点 → 正式发布（GA）→ 改善 → 退役，整段生命周期都扛住
5. 沟通价值，但不碰机密的伙伴市场进入策略（GTM）机制

Claude Code、`CLAUDE.md`、hooks（钩子机制）与训练课程的实作团队推行上线 → **文件 05**。

## Part A — 利益相关者探索

### A1. 利益相关者地图

| 角色 | 他们在意什么 | 该问的问题 |
| --- | --- | --- |
| 高层赞助人 | 成果、风险、时间线、投资报酬率（ROI） | 这会改变什么决策？90 天内成功长什么样子？ |
| 业务负责人 | 流程关键绩效指标（KPI）、UX、例外 | 人把时间花在哪？什么错误会伤害客户？ |
| 最终用户 | 信任、速度、控制 | 你什么时候会拒绝 AI 协助？什么东西绝对不能自动送出？ |
| 工程 | API、服务水准目标（SLO）、可维护性 | 哪些系统是真实来源？速率限制？ |
| 数据 | 质量、租户归属、管线 | 新鲜度 SLO？个人识别信息（PII）类别？ |
| 安全 | 威胁、身份、日志 | 授权边界是什么？ |
| 法务／隐私 | 依据、告知、保留 | 有受监管数据吗？传输限制？ |
| 合规／风险 | 控制证据 | 适用哪些审计？ |
| 运营／SRE | 调用值班、runbook、容量 | 第一天谁值班？ |
| 财务 | 单位经济 | 每笔交易的成本上限？ |
| 销售／客户成功（CS）（邻近 GTM） | 承诺 vs 交付 | 对外已经承诺了什么？ |

### A2. 探索工作坊行程（90 分钟）

1. 问题框定（15）— 待完成工作、痛点量化
2. 限制墙（15）— 数据、延迟、合规、预算
3. 成功指标（15）— 领先／落后 KPI
4. 旅程地图（20）— 人类＋AI 泳道
5. 风险脑力激荡（15）— 注入、幻觉、过度自动化
6. 决策日志（10）— 未决问题与负责人

产出：喂给架构的一页简报。

### A3. 需求分类法

- **功能：** 意图、工具、语言
- **非功能：** 延迟、可用性、成本、数据驻留
- **安全：** 不允许的动作、人在回路中（HITL）触发
- **可运营性：** 日志、归属、支持时段
- **变更：** 模型升级政策

**非目标** 要明白写下（「v1 不是完全自主的谈判者」）。

### A4. 探索的反模式

- 只跟赞助人谈
- 把「像 ChatGPT 但用我们的数据」当成需求
- 安全拖到很晚才碰
- 忽略 GTM 动作里已经卖出去的承诺
- 没有量化基准线（之后无法证明价值）

## Part B — 沟通架构

### B1. 高度切换

| 听众 | 产物 | 用语 |
| --- | --- | --- |
| 高阶主管 | 一页幻灯片：价值＋风险＋请求 | 成果、时间线、投资 |
| 业务 | 旅程＋例外路径 | 前后 KPI |
| 工程师 | 时序图、schema、ADR | 接口、失效模式 |
| 安全 | 数据流＋威胁模型 | 信任边界、控制 |
| 法务 | 处理说明 | 目的、保留、权利 |

同一个系统，不同切面。考试陷阱：用 token 图淹没高阶主管；对工程师含糊带过安全。

### B2. 架构决策记录（ADR）

模板：

- 上下文
- 决策
- 考虑过的替代方案
- 后果（正面／负面）
- 状态与日期
- 相关评测证据

决策例子：「报价验证选工作流程而不是 agent，因为可审计性 > 弹性。」

### B3. 取舍叙事

用 **选项 A／B／C** 表：

| 选项 | 质量 | 延迟 | 成本 | 风险 | 注记 |
| --- | --- | --- | --- | --- | --- |
| A 巨型单一提示词 | 中 | 最好 | 低 | 审计弱 | 因合规否决 |
| B 工作流程 | 高 | 中 | 中 | 低 | 建议 |
| C 完整 agent | 高？ | 最差 | 高 | 更高 | 放到第 2 阶段 |

**只推荐一个**，不要把表丢出去却不挑选。

### B4. 期望管理稿（原创、不涉密）

- 「第 1 阶段建议；人类送出。第 2 阶段只对模板类别 T、且指标达 M，才自动送出。」
- 「模型在切片 S 上约有 X% 会错；那些个案我们路由给专家。」
- 「我们不承诺用字完全相同——只承诺流程服务水准协议（SLA）与质量比率。」

诚实创建信任；过度承诺会造成事故级的失望。

## Part C — 提案框定（邻近 GTM，标出伙伴限制）

### C1. 你可以 *原创撰写* 的东西

支持售前或内部争取预算的架构师，应把提案绕以下结构：

1. **问题与基准线指标**
2. **目标成果**（效率、质量、风险下降）
3. **解决方案草图**（模式、集成、控制）
4. **分阶段路线图**（试点 → GA）
5. **投资**（人力、基础建设、授权——高层次即可）
6. **风险与缓解**
7. **成功审查日期**

### C2. 你 *不该* 凭空捏造的东西

- 机密伙伴折扣表
- 内部厂商战术卡（battle card）
- 把保证赢单率或未公开基准当营销宣称
- 你没有权利使用的客户商标／案例细节

**注：** 雇主提供的 playbook 可能会加上公司特有动作；本教材包只对准技能。

### C3. 价值沟通模式

| 价值故事 | 该附的证据 |
| --- | --- |
| 节省时间 | 时间动作研究基准线 vs 试点 |
| 质量提升 | 错误率／编辑距离 |
| 风险下降 | 较少政策违规；审计就绪 |
| 营收协助 | 转换提升搭配实验设计 |
| 开发者速度 | 见文件 05 指标 |

避开「AI 魔法」幻灯片。优先「仪器化学习」。

### C4. 处理卖过头的期望

若 GTM 已经承诺完全自主：

1. 承认落差，不要演责难剧场
2. 指出目前这份承诺的风险
3. 提出仍能早点落地价值的分阶段交付
4. 与赞助人对齐改写后的成功标准，而且要书面

架构师保护长期信任。

## Part D — 生命周期管理

### D1. 生命周期阶段

```
探索 → 设计 → 建置 → 试点 → GA → 营运 → 改善 → 退役
```

每个阶段都需要 **退出条件**。

| 阶段 | 退出条件例子 |
| --- | --- |
| 探索 | 简报＋指标＋风险层级已签核 |
| 设计 | ADR＋威胁模型＋评测计划 |
| 构建 | 测试全绿；工具已做契约测试 |
| 试点 | N 位用户；指标对基准线；安全探针通过 |
| GA | 值班已上线；文档；功能标志；SLO |
| 运营 | 每周质量审查；成本留在包络内 |
| 改善 | 来自回馈／评测、已排优先的待办 |
| 退役 | 流量已抽干；数据依政策删除；事后复盘 |

### D2. 交接包（构建 → 运营）

- 架构概览＋图
- 模型／提示词／索引钉选
- runbook（延迟、坏输出、注入嫌疑、成本暴增）
- 仪表板与警示门槛
- 已知失效模式
- 支持升级矩阵
- 提示词／工具的变更流程

文件 05 加深开发者／运营赋能内容。

### D3. 回馈循环

来源：用户赞踩、编辑距离、工单、销售异议、安全发现、评测回归。分流成：提示词修复、检索修复、产品 UX、训练、拒绝自动化。

### D4. 运营节奏

- 每日：错误／成本／安全警示
- 每周：质量切片审查
- 每月：路线图与风险层级再访
- 每季：红队／访问审查／供应商审查

### D5. 弃用与模型生命终止

供应商模型弃用是生命周期事件。维持：

- 钉选清单
- 迁移负责人
- 兼容性评测套件
- 对利益相关者的沟通计划

## Part E — 变革与冲突管理

### E1. 常见冲突

| 冲突 | 解决路径 |
| --- | --- |
| 速度 vs 安全 | 分阶段自主＋指标闸门 |
| 成本 vs 质量 | 先做路由与缓存，再砍质量 |
| 销售承诺 vs 工程现实 | 与赞助人书面重设范围 |
| 中央平台 vs 领域团队 | 清楚的铺好的路＋逃生口 |
| 隐私 vs 分析 | 汇总／屏蔽设计 |

### E2. 生命周期 RACI（责任指派矩阵，示例）

| 活动 | 赞助人 | 架构师 | 工程 | 安全 | 运营 | GTM／CS |
| --- | --- | --- | --- | --- | --- | --- |
| 成功指标 | A | R | C | I | I | C |
| 威胁模型 | I | R | C | A | C | I |
| GA 放行／不放行 | A | R | R | A | A | C |
| 客户消息 | C | C | I | C | I | R／A |

## Part F — 文档标准

最低可行文档：

1. 服务 README
2. ADR 日志
3. 数据流（快乐路径＋滥用）
4. 评测报告模板
5. 面向用户的限制页
6. 值班 runbook

优先靠近代码的活文档，而不是把幻灯片当唯一真实来源。

## 决策树

### 听众简报挑选器

```
听众是否对预算／风险负课责？
 是 → 先讲成果、风险、请求、时间线
听众是否负责实作？
 是 → 先讲接口、失效模式、ADR
听众是否签署法务文档？
 是 → 先讲资料流、保留、子处理者
```

### 试点 vs GA 闸门

```
安全探针＋租户测试全绿？
负责人与值班已具名？
SLO 与仪表板已上线？
支持宏已备妥？
 全部是 → GA 候选
 否则 → 延长试点，附明确的缺口清单
```

## 考试陷阱

1. 没有探索指标就跳到技术。
2. 对所有利益相关者用同一套沟通。
3. 没有非目标／无限范围。
4. 没有运营交接就 GA。
5. 捏造伙伴机密 GTM 宣称。
6. 忽略已经对外承诺的客户承诺。
7. 指标只有虚荣（聊天机器人页面浏览）。
8. 没有模型退役／生命终止（EOL）计划。
9. 构建之后才碰法务／安全。
10. 「我们会监控」却没有具名负责人／节奏。

## 练习问答（26）

**Q1.** 为企业 Claude 应用举出五个利益相关者群组。
**A.** 例如赞助人、业务负责人、工程、安全、法务（还有运营、数据、财务、用户）。

**Q2.** 探索的非目标该放什么？
**A.** 该阶段明确超出范围的能力（例如 v1 不做自主退款）。

**Q3.** 该如何向高阶主管呈现选项？
**A.** 短的成果／风险／请求；可选一张带清楚建议的取舍表。

**Q4.** ADR 后果区段是做什么的？
**A.** 为未来读者记录该决策的后续成本／风险。

**Q5.** 试点退出条件例子？
**A.** 目标用户完成任务、指标有提升，且安全探针通过。

**Q6.** 若销售不安全地承诺了完全自主，你该怎么做？
**A.** 与赞助人重新对齐分阶段交付，并书面改写成功标准。

**Q7.** 为什么要在构建前捕捉基准线指标？
**A.** 没有基准线就无法证明价值或辩护 ROI。

**Q8.** 举出三件交给运营的交接产物。
**A.** runbook、仪表板／警示、钉选清单（还有升级矩阵、已知失效）。

**Q9.** 该避开的虚荣指标例子？
**A.** 原始聊天机器人消息数，没有任务成功或客户满意度（CSAT）／质量链接。

**Q10.** GA 放行／不放行的安全签核通常谁问责？
**A.** 安全（以及赞助人整体）——依 RACI；架构师协助备齐证据。

**Q11.** 什么是高度切换？
**A.** 依听众调整产物深度／用语，但不改事实。

**Q12.** 为什么要把模型 EOL 排成生命周期事件？
**A.** 弃用会弄断钉选；需要迁移负责人与评测。

**Q13.** 备考内容里不该捏造的邻近 GTM 内容？
**A.** 机密伙伴折扣、战术卡、未公开保证脚本。

**Q14.** 什么构成一场好的成功审查会议？
**A.** 预先约定的指标、未决风险、扩张／转向／停止的决定。

**Q15.** 回馈循环如何接到工程？
**A.** 分流成提示词／检索／UX／训练／拒绝自动化的待办项目。

**Q16.** 速度 vs 安全冲突——架构师怎么动？
**A.** 分阶段自主；先交付建议模式价值；用指标闸控自动。

**Q17.** 限制页是做什么的？
**A.** 让用户／管理员期望透明；减少误用与支持负担。

**Q18.** 为什么在探索中轻度纳入 CS／销售？
**A.** 及早得知外部承诺与异议模式。

**Q19.** 最低限度的法务导向产物？
**A.** 带目的与保留的处理／数据流说明。

**Q20.** 价值故事里的「仪器化学习」是什么意思？
**A.** 主张有量测过的试点证据支撑，不是口号。

**Q21.** 谁拥有每周质量审查？
**A.** 具名角色（常是架构师＋工程＋业务）——必须明示。

**Q22.** 平台铺好的路里的逃生口？
**A.** 团队可经额外审查偏离的已文档化方式——不是默默分叉。

**Q23.** 为什么要早写非功能需求？
**A.** 延迟／数据驻留／成本会重塑架构；晚发现会造成返工。

**Q24.** 退役阶段必须包含什么数据步骤？
**A.** 抽干流量并依政策删除／保留数据（含索引／日志）。

**Q25.** 对「就做成像 ChatGPT」的最佳回应？
**A.** 重框成待完成工作、限制与可量测成果。

**Q26.** Claude Code 推行上线细节在哪？
**A.** 文件 `05-team-enablement-operational-productivity.md`。

## Part G — 会议模式与主持

### G1. 从新闻稿往回推（内部）

及早草拟一段内部「上线说明」：谁受益、什么改变、什么不会。若利益相关者无法对那段话达成共识，架构就会翻搅。

- 单一决策负责人

- 48 小时内记入 ADR

### G3. 利益相关者阻力类型

| 阻力 | 底层需求 | 动作 |
| --- | --- | --- |
| 怕丢工作 | 角色清楚 | 把工作重设计成监督／例外处理 |
| 怕责任 | 问责性 | HITL＋审计＋清楚负责人 |

### G5. 训练利益相关者（轻）

### G6. 延伸情境

**情境：** 采购要 AI 自动寄信给供应商谈价格。
**利益相关者动作：** 召集法务＋安全＋采购；提案建议模式加核准；定义节省指标；v1 拒绝无界自主。

**情境：** 董事会要「AI 策略 KPI」。
**动作：** 投资组合视图——有评测闸门的使用案例％、事故数、已实现价值 vs 目标、风险层级覆盖——不是单一虚荣聊天机器人分数。

### G7. 问答 27–35

**Q27.** 为什么要及早草拟内部上线段落？
**A.** 在构建翻搅前，强迫对谁受益、什么不会改达成共识。

**Q28.** 可逆 vs 不可逆决策——不可逆例子？
**A.** 自主寄出有法律约束力的承诺；迁移生产数据却没有回滚。

**Q29.** 如何回应把安全当晚期闸门？
**A.** 把安全带进探索／设计；及早分享威胁模型草稿。

**Q30.** 影子 IT 的 AI——平台回应？
**A.** 让铺好的路比未核可工具更快／更安全；教育；监控。

**Q31.** 董事会层级 AI KPI 例子？
**A.** 有评测闸门的使用案例％、已实现价值 vs 目标、AI 事故率、风险层级覆盖。

**Q32.** 业务用户最先需要什么训练？
**A.** 问／验证／升级行为与限制——不是 transformer 内部。

**Q33.** 公开 AI 内容事故谁发言？
**A.** 预先指定、有法务／安全输入的沟通负责人——不是工程师即兴推文。

**Q34.** 为什么依可逆性分类决策？
**A.** 不可逆的需要更多证据、HITL 与更高高度核准。

**Q35.** 采购自动议价电子邮件——第一次工作坊产出？
**A.** 书面的自主非目标＋核准工作流程＋节省指标。

### H5. 问答 36–42

**Q36.** 高阶主管一页摘要的六个部分是什么？
**A.** 问题、提案、价值、风险、请求、检查点。

**Q37.** 为什么把路线图解锁绑到控制？

**Q40.** 本教材包的 GTM 宣称不该出现什么？
**A.** 机密伙伴 playbook、未公开保证、未经授权的案例。

**Q41.** 能力解锁例子？
**A.** 只有引用精确率闸门通过后，才做对外 FAQ。

**Q42.** 为什么在请求里加检查点日期？
**A.** 强制决策卫生，避免无限试点僵局。

### J3. 给怀疑领导的内部 FAQ

**Q：** 这会取代我的团队吗？
**A：** 设计目标是减少苦工（toil）与以例外为中心的角色；人力决策是领导层的，但架构应让监督可行。

**Q：** 我们能信任答案吗？
**A：** 信任是量测的——引用率、评测切片、关键路径上的 HITL——不是假设的。

**A：** 示范缺少租户测试、值班与滥用案例；GA 评分卡存在是有原因的。

### J4. 伙伴限制提醒框

> 本教材包刻意停在通用架构师技能：探索、框定、生命周期，以及诚实的价值沟通。不要把这里任何东西当成官方销售心法。

### J5. GA 后价值审查（第 60 天）

回到基准线指标；发布短的「已实现价值」备忘录；决定投入／维持／下线。没有这一步，僵尸会堆积。

**A.** 连到指标与控制的 epic——不是孤儿提示词微调。

**A.** 量测已实现价值；有意识地投入／维持／下线。

## Part M — 交接信模板（原创）

主旨：交接 — <feature> 给运营
附件：图、ADR 索引、钉选清单、runbook、仪表板链接、已知问题、升级矩阵。

题干风味：「赞助人在华丽示范后要下个月 GA；安全还没审查；没有值班。」
强答案：出示 GA 评分卡缺口；提案附日期的试点延长；把审查＋runbook 演练当退出条件；与赞助人重设外部承诺——不是默默上线。

「我们可以在日期 D 以建议模式、搭配控制 C 交付可量测价值。完全自主仍是第 2 阶段解锁，要在指标 M 于期间 P 内站稳之后。现在就上线自主，等于在没有补偿控制下接受风险 R。请书面确认修订后的成功标准，好让工程、安全与 GTM 共用一份计划。」

那个结构——现在就有价值、稍后解锁、点名风险、书面对齐——能回答大多数「被施压过度自动化」的利益相关者题干，且不需要伙伴特有 playbook。

## Part N — 主修深挖：能在现实接触下活下来的探索

> **范围注（先读）：** 本教材包只教 **原创** 的探索、生命周期、变革管理与价值框定技能——不捏造定价、机密赢单主题或官方课文。若考试题干闻起来像「销售动作」，用耐久的架构师行为作答：厘清承诺、对齐 SLA、记录取舍、分阶段交付。

### N1. 探索深度模型（五次通过）

1. **问题通过** — 待完成工作、痛点量化、目前变通。
2. **限制通过** — 数据、延迟、数据驻留、预算、工会／劳资委员会、品牌。
3. **成功通过** — 领先／落后指标、决策权、时限。
4. **风险通过** — 安全、合规、运营爆炸半径、声誉。
5. **变革通过** — 谁失去权力／地位、训练负担、流程重设计。

跳过变革通过，就是「技术上完美」的试点会死掉的原因。

### N2. 利益相关者访谈库（浓缩、原创）

**高阶主管：** 这若成功，哪个决策会变好？什么会让你停掉这个计划？
**业务负责人：** 哪一步在烧分钟？什么错误不可接受？
**用户：** 你什么时候不信任 AI？什么必须维持手动？
**安全：** 身份边界是什么？你的恶梦工单是什么？
**法务／隐私：** 数据类别？传输？保留？告知？
**运营：** 凌晨 2 点谁被调用？降级模式是什么？
**财务：** 每笔交易的完全负担成本上限？
**销售／CS（邻近 GTM）：** 对外已经承诺了什么？

### N3. 需求质量门槛

一项需求要考试就绪，需要：负责人、指标、限制、优先级与测试构想。
「让它变聪明」不是需求。「FAQ 路径 p95 < 3s；退款超过 50 美元走 HITL；GDPR 删除在政策 SLO 内」才是。

### N4. 反模式（探索）

| 反模式 | 为什么失败 | 修正 |
| --- | --- | --- |
| 单一利益相关者代理人 | 否决权后来才浮现 | 对应权力＋受影响用户 |
| 先给方案再找问题 | 错过真正工作 | 先框问题再选模式 |
| 忽略影子流程 | 用户绕过系统 | 观察真实工作 |
| 没有非目标 | 范围膨胀 | 明确超出范围清单 |
| 只有口头决策 | 失忆 | 决策日志／ADR |

## Part O — 不靠伙伴 playbook 的价值框定

### O1. 价值假设模板（原创）

```
给有 [问题] 的 [用户区隔]，
Claude 解决方案将提供 [能力]，
使 [成果指标] 在 [时间] 内、于 [限制] 下，
从 [基准线] 移动到 [目标]，
残余风险 [清单] 由 [负责人] 接受。
```

### O2. 价值支柱 → 证据

| 支柱 | 主张例子 | 你必须计划的证据 |
| --- | --- | --- |
| 效率 | 处理时间 −30% | 时间动作研究＋生产 A／B |
| 质量 | 错误率 −40% | 黄金标准集＋人类审计 |
| 转型 | 新自助频道 | 采用＋拦截率 |
| 成本 | 每张工单美元 −25% | 单位经济仪表板 |
| 性能 | 达到 p95 SLA | 延迟 SLO 消耗警示 |

### O3. 期望管理（耐久稿）

- 「试点证明学习速率，不是最终正确率。」
- 「自主随评测证据扩大，不是单靠日历日期。」
- 「模型升级是变更——需要回归闸门。」
- 「引用来源降低幻觉风险；它们并不消除它。」

### O4. 卖过头的复原

若销售承诺了「完全自主的法律建议」：
1. 如实记录外部承诺。
2. 重框成合规范围（草稿＋律师 HITL）。
3. 提出带退出条件的分阶段路线图。
4. 把残余风险上呈赞助人决策——不要默默交付不安全范围。

## Part P — 生命周期与变革管理深挖

### P1. 阶段退出条件（扩充）

| 阶段 | 何时退出…… |
| --- | --- |
| 探索 | 简报＋指标＋限制已签核 |
| 设计 | ADR＋威胁注记＋评测计划已审查 |
| 构建 | 契约已测；追踪已开 |
| 试点 | 成功标准已量测；风险已登录 |
| GA | 评分卡全绿；值班就绪；文档已交接 |
| 运营 | SLO 审查在跑；回馈循环有负责人 |
| 迭代 | 待办依追踪＋用户排优先 |
| 退役 | 迁移＋模型弃用完成 |

### P2. 变革管理杠杆

- **沟通：** 为什么变、什么维持人类、怎么求助
- **训练：** 依角色（用户 ≠ 审查者 ≠ 工程师）
- **诱因：** 若质量崩盘，不要奖励原始自动化率
- **推动者：** 早期采用者教同侪
- **回馈：** 可见的「修正这个答案」并有回应

### P3. 冲突模式与解决

| 冲突 | 典型解决 |
| --- | --- |
| 安全 vs 速度 | 铺好的路＋有时限的例外 |
| 产品 vs 法务 | 范围化 MVP；律师看告知 |
| 运营 vs 功能工厂 | 错误预算约束发布 |
| 用户 vs 自动化 | 先 copilot；用表现赚自主 |
| 赞助人 vs 现实 | 以数据支撑的重设；选项 A／B／C |

### P4. 交接包（绝不能忘）

架构图、ADR、工具清单＋授权模型、评测仪表板、runbook、HITL 人力模型、数据保留地图、模型钉选／升级政策、已知限制、RACI、支持升级矩阵。

### P5. 监控与迭代节奏

- 每日：值得调用的 SLO 消耗
- 每周：评测切片＋主要失败主题
- 每月：成本单位经济＋路线图
- 每季：风险层级再访＋访问审查

## Part U — 延伸问答（59–68）

**Q59.** 喂给架构的第一次工作坊产出？
**A.** 一份含问题、限制、指标、风险的 **一页简报**——不是模型选择辩论。

**Q60.** 高阶主管问「什么时候会完全自主？」最佳答案形状？
**A.** 自主 **由评测证据与风险层级闸控**，带分阶段里程碑——不是盲目的日历承诺。

**Q61.** 选 TWO 件交接必备：评测仪表板、值班 RACI、伙伴折扣表、迷因频道。
**A.** 评测仪表板与值班 RACI。

**Q62.** 销售承诺了不安全范围。架构师应该……
**A.** 记录、重框成合规的分阶段范围、上呈赞助人——**不要** 默默上线。

**Q63.** 为什么探索要纳入运营？
**A.** 降级模式、调用值班、容量——以及防止无法支持的 GA。

**Q64.** ADR 被否决替代方案字段重要，因为……
**A.** 考试与真实审查会测你是否 **考虑过** agent vs 工作流程等。

**Q65.** 缺少变革管理——可能结果？
**A.** 用户绕过系统；ROI 永远不落地。

**Q66.** 没有官方 GTM playbook。CCAR-P 上什么仍然有效？
**A.** 有结构的探索、取舍沟通、生命周期产物、价值指标。

**Q67.** GA 评分卡在 HITL 人力上亮红——还是上线？
**A.** **不行**——先补人力或缩小自主范围。

**Q68.** 选 THREE 个探索反模式：先给方案再找问题、单一代理人利益相关者、没有非目标、写 ADR、量测基准线。
**A.** 先给方案再找问题、单一代理人、没有非目标。

## Part V — 快速复习（利益相关者 14%）

- 先探索再设计；包含变革通过。
- 需求需要指标与负责人。
- 高度切换沟通；保留 ADR。
- 价值＝假设＋证据计划。
- 生命周期退出条件胜过感觉。
- 标出仅限伙伴的 GTM 限制；保持原创。
- 交接＝文档＋负责人＋评测＋runbook。
- 重设卖过头；不要交付不安全承诺。

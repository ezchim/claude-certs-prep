## A 部分 —— 集成原语

### A1. 集成堆栈

```
应用／编排器
 ├─ Claude Messages API（模型输入／输出）
 ├─ 用户端工具（你的程序码执行）
 ├─ 服务器工具（Anthropic 托管，于启用之处）
 ├─ MCP 服务器（标准化的工具／资料连接器）
 ├─ 检索系统（搜寻／索引／重排序）
 └─ 企业 IdP、机密资讯、网络、稽核
```

**契约提醒（公开工具使用模型）：** Claude 永远不会自己执行你的工具。它发出 `tool_use`；**你的执行环境**（或 Anthropic，对服务器工具）执行；你回传 `tool_result`。架构师设计那个循环：逾时、重试、幂等与权限。

### A2. 客户端工具 vs 服务器工具

| 类型 | 谁跑代码？ | 示例（示意） | 架构师意涵 |
| --- | --- | --- | --- |
| 客户端／用户定义 | 你的应用 | 客户关系管理（CRM）查询、工单、内部 SQL | 你拥有 authZ、日志、沙箱 |
| Anthropic 服务器工具 | Anthropic | 网页搜索／截取、代码执行、工具搜索（依文档） | 刻意启用；理解数据离开边界 |
| Anthropic schema 的客户端工具 | 你的应用，训练友善的 schema | 等价时优先已知 schema | 往往比临时双胞胎更可靠 |

### A3. 模型上下文协议（MCP）

MCP 是把助理／agent 连到工具与数据的**开放标准**。公开文档强调：

- 本机进程、HTTP／服务器推送事件（SSE）／可流式 HTTP，以及进程内传输层（生态会演进——请核实现行 MCP＋Claude Code 文档）。 
- 服务器暴露工具／资源／提示。 
- **信任模型：** 把第三方服务器当成供应链风险；经截取内容的提示注入是真实的。 
- 大型工具集 → **工具搜索**／延迟加载，让定义不会吃掉上下文窗口。 
- 信道／事件（若支持）把外部信号推进会话。

**何时选 MCP**

| 何时优先 MCP… | 何时优先直连 API／SDK 工具… |
| --- | --- |
| 许多系统、标准化探索 | 一两项客制工具 |
| 要可在 Claude Code＋应用间重用的连接器 | 极度客制的延迟路径 |
| 组织要连接器目录 | 协议开销不值得 |
| 伙伴已经出货 MCP 服务器 | 你必须留在锁定的 RPC 结构里 |

### A4. Agent 对 agent 与编排总线

多 agent 系统需要明确的**交接协议**：消息 schema、共享记忆政策，以及权限边界。优先：

- 清楚的监督者或拥有副作用的工作流程 
- 每个 agent 各自的凭证 
- 跨 hop 的追踪 ID 

避免没有预算、聊天式的自由形式 agent 蜂群。

### A5. CLI 与自动化接口

命令行工具（包括工程工作流程里的 Claude Code CLI——见档 05）适合持续集成（CI）、运营与开发者循环。面向客户的产品优先用具 authZ 的服务 API。考试情境：选 CLI 给**构建者生产力**，选 API 给**产品执行环境**——除非产品*本身*就是开发者工具。

## B 部分 —— RAG 与检索架构

### B1. RAG 参考管线

```
撷取 → 清洗／OCR → 切块 → 矢量嵌入／索引（＋关键字）→（选配知识图）
查询 → 改写／分类 → 检索 → 重排序 → 打包上下文 → Claude → 引用 → 验证
```

### B2. 切块决策

| 语料特征 | 切块偏向 | 备注 |
| --- | --- | --- |
| 带编号章节的政策 | 感知章节的切块＋标题 | 为引用来源保留条款识别码 |
| 代码 | 感知符号／函数 | 不要盲目在函数中间切开 |
| 表格／财务 | 以表为单位或列群组 | 往往需要光学字符识别（OCR）结构 |
| 对话日志 | 带时间戳的轮次窗口 | 个人识别信息（PII）清洗关键 |
| 幻灯片 | 每张幻灯片＋标题 | 文本密度低 |

重叠有助连续性；重叠太多浪费 token 并拷贝噪音。

### B3. 混合检索

生产 RAG 通常结合：

- **稠密／向量**，用于语义改写 
- **BM25／关键字**，用于 ID、错误码、SKU、法律条号 
- **中继数据筛选**（租户、产品、地区设置、生效日期） 
- **重排序器**，在低 k 时提高精确率 

知识图有助多跳「谁拥有 X」问题，但增加运营成本——用评测增益来辩护。

### B4. 上下文打包与引用来源

公开 Messages API 模式支持**搜索结果**内容区块与引用来源，让答案能归因来源。架构师规则：

- 切块回传来源 id／title／uri 
- 事实锚定重要时，在输出契约要求引用来源 
- 若检索没有相关结果，**拒绝或追问**——不要即兴发明政策 
- 依 token 预算限制 top-k；优先较少但高质量的切块 

### B5. 索引新鲜度与租户归属

- 为文档做版本；政策优先用生效日期 
- 租户隔离的索引或硬筛选（永远不要「提示模型只用租户 A」） 
- 删除用墓碑；GDPR 抹除工作流程也要碰到索引 
- 衡量**过时服务水准目标（SLO）**（例如政策发布后 15 分钟内上线）

### B6. RAG 失效模式（考试黄金）

1. 切块边界错误 → 漏掉条款 
2. 模型变更后向量嵌入漂移，却没有重建索引计划 
3. 经共享索引的跨租户渗漏 
4. 检索到的 HTML 里的提示注入（「忽略政策…」） 
5. 引用表演（数字对不上来源） 
6. 过度检索淹死模型 
7. 检索不足 → 幻觉 

### B7. 把渐进式探索用到 RAG

不要倾倒语料。用：

1. 中继数据路由（product=X） 
2. 检索小 k 
3. 若信心低／用户问得更深，再检索更多或浏览阶层式目录工具 
4. agent 可调用 `search` 再 `fetch_section` 工具，而不是一次巨型上下文

## C 部分 —— 工具、agent 与生产控制

### C1. 工具设计检查清单

- [ ] 名称／描述清楚到足以路由 
- [ ] JSON schema 严格；枚举优于自由文本 
- [ ] 副作用工具用键做到幂等 
- [ ] 逾时与断路器 
- [ ] authZ 在**工具服务器**检查，不只在提示词 
- [ ] 参数日志并做屏蔽 
- [ ] 每租户速率限制 
- [ ] 破坏性操作有仿真执行／确认模式 

### C2. 最小权限原则模式

| 模式 | 描述 |
| --- | --- |
| 阶段范围工具 | 萃取阶段不能 `refund_payment` |
| 角色范围 agent | 客服 vs 财务凭证不同 |
| 读／写分离 | 研究 agent 只读；执行者有闸控 |
| 确认权杖 | 写入要第二个人或第二因素 |
| 允许清单主机 | 对服务器端请求伪造（SSRF）安全的截取工具 |

### C3. Agent 循环控制

生产 agent 需要：

- **最大轮次／最大美元／最大墙钟时间** 
- 停止条件（`task_complete`、`needs_human`） 
- 黏性追踪 ID 
- 记忆政策（跨会话什么会持久） 
- 代码执行的沙箱 

### C4. 延迟预算工作单

交互 UX p95 = 3.0 秒的示例：

| 阶段 | 预算 |
| --- | --- |
| 验证＋入口 | 50ms |
| 检索 | 200ms |
| 重排序 | 50ms |
| Claude 首个 token 延迟（TTFT） | 800ms |
| Claude 完成 | 1500ms |
| 验证＋渲染 | 100ms |
| 应变 | 300ms |

错过预算？缩小上下文、缓存前缀、较小模型、平行检索，或异步 UX（「答案流式＋工具在背景」）。

### C5. 可靠性模式

- 对 429／5xx 带抖动重试 
- 逾时时后备模型 
- 常见问答意图用缓存的上次正确答案 
- 长工具用队列＋工作者 
- 毒化工具侦测（反复失败 → 停用工具、警示）

## D5 部分 —— CSP／交付路径治理（P0）

架构师**不会**因为幻灯片看起来现代就选「X 上的 Claude」。他们删去违反**身份、落地、日志／保留、采购与模型 ID**限制的路径——再在幸存者里依运营适配与功能落差来选。

公开接口（请核实现行文档；产品会演进）：

| 路径 | 它是什么（公开框架） |
| --- | --- |
| **直连 Anthropic API** | 第一方 Messages API（`platform.claude.com`）；Anthropic 运营的推理 |
| **Amazon Bedrock** | 经 AWS Bedrock 的 Claude；AWS 管理的边界／区域控制（依文档为 Messages 及／或旧式 Invoke／Converse 路径） |
| **Google Vertex AI** | 经 Google Cloud Vertex 的 Claude；GCP IAM＋区域端点 |
| **Azure／Microsoft Foundry** | Microsoft Foundry 里的 Claude；Azure 托管及／或 Anthropic 托管选项，部署类型不同 |
| **AWS 上的 Claude Platform** *（相关）* | Anthropic 运营、AWS Marketplace 风格路径的 Claude——**不等同**于 Bedrock；落地／推理钉选不同——考试题干不要混为一谈 |

### D5.1 公开层可讲的决策对照表

把存储格当成**要在现行契约／文档核实的主题**，不是永恒保证。ZDR 与商业伙伴协议（BAA）是**企业选项**——设计前先确认权利，不要当成一定存在。

| 维度 | 直连 Anthropic API | Amazon Bedrock | Google Vertex AI | Azure／Microsoft Foundry |
| --- | --- | --- | --- | --- |
| **身份／验证** | API 密钥／组织与工作区控制；应用仍拥有用户→工具身份 | **AWS IAM**（角色、SCP、PrivateLink 模式）；对 CloudTrail 友善 | **GCP IAM**＋Vertex 权限；组织政策 | **Entra ID／Azure 角色型访问控制（RBAC）**＋Foundry 项目控制 |
| **数据驻留／推理钉选** | 支持模型上的 `inference_geo`（例如 global vs `us`）——查文档 | **区域端点**／地理推理设置档；区域选择就是钉选 | **区域／端点**选择决定推理在哪跑 | **Global Standard** vs **US Data Zone Standard**（文档记载处，美国钉选类似 `inference_geo: us`）；托管选项（Azure vs Anthropic）有差 |
| **日志／保留姿态** | Anthropic 保留与滥用监控条款；**ZDR** 可能作为企业选项提供——**核实** | 主要由 **AWS／Bedrock** 数据保护文档＋你的账户日志治理；不要假设 Anthropic ZDR 措辞 1:1 对应 | 由 **Google Cloud／Vertex** 数据处理＋你的日志汇流治理 | Anthropic 处理者条款＋Azure 侧保留；安全标记内容路径可能因托管而异——**读现行 Foundry Claude 文档** |
| **采购／BAA／FedRAMP 主题** | 与 Anthropic 直签主服务协议（MSA）／数据处理协议（DPA）；BAA／FedRAMP 仅在**你的**交易与产品支持时 | 经 **AWS Marketplace／Bedrock** 购买；靠既有 AWS 承诺用量、AWS 合规产物、组织 SCP——仍要把受保护健康信息（PHI）／FedRAMP 对到**该特定** Bedrock Claude 产品 | 经 **GCP** 购买；重用 GCP 承诺用量与组织政策；同一条「产物 ≠ 自动 BAA」规则 | 经 **Azure Marketplace／Foundry** 购买；重用 Microsoft EA；对你实际部署的**部署类型**确认 HIPAA／FedRAMP |
| **模型 ID 差异** | Anthropic 模型 ID（例如 Messages API 里带日期的 `claude-…` 字符串） | Bedrock **模型 ID／推理设置档 ID／Amazon 资源名称（ARN）**（以及启用时的 Messages 路径 ID）——**不是**第一方 ID 的拷贝粘贴 | Vertex 发行者模型 ID／版本——**平台特有** | Foundry **部署名称**＋模型版本（托管选项编码在内）——应用设置不得写死另一个 CSP 的 ID |
| **功能／API 落差主题** | 往往**最早**取得新 Messages 功能、beta、服务器工具 | 可能落后或以 Bedrock 形状的 API 暴露；承诺功能前查对等 | GCP 上类似的对等／落差故事 | 对等取决于 Azure 托管 vs Anthropic 托管部署——功能矩阵不同 |
| **架构师何时选这条** | 最大功能速度；简单 SaaS；落地可经 `inference_geo`＋契约解决；团队已在 Anthropic 计费 | 以 AWS 为中心的资产；IAM／PrivateLink 强制；经 AWS 区域落地；采购必须留在 AWS 内 | 以 GCP 为中心的资产；Vertex 是已核准的 AI 平面；组织政策挡住其他对外流量 | 以 Azure 为中心的资产；Entra＋Foundry 是已核准的 AI 平面；需要 US Data Zone 或 Azure 托管边界 |

**每条路径永远成立：** 你的**应用**仍拥有租户 authZ、工具最小权限原则、提示词／日志屏蔽，以及评测闸门。换 CSP 修不好「authZ 写在提示词里」。

### D5.2 限制排除法（考试方法）

```
1. 列出题干的硬性约束（IdP、落地地理、日志／ZDR、BAA／FedRAMP、云端承诺用量、PrivateLink、功能 X 下个冲刺必须出货）。
2. 删去无法满足任一硬性约束的路径（核实假设——不要凭空捏造 FedRAMP）。
3. 在幸存者中评分：营运熟悉度、模型识别码／营运工具适配、功能对等风险、成本可预测性。
4. 把被否决的路径记成一行 ADR（「否决直连 API：本组织没有路径能达到要求的 VPC 端点模式」）。
```

**感觉（不及格）：** 「大家都用 Bedrock。」／「直连 API 永远最快创造价值所以选它。」／「选 Foundry 因为我们喜欢 Copilot。」 
**限制排除（及格）：** 「题干要求欧盟处理且落在既有 GCP 组织政策内 → Vertex 区域端点；直连 API 的全球默认出局。」

### D5.3 模型 ID 与设置可携性陷阱

- 抽象一个**供应商转接层**：设置里的 `model_ref` → 依环境解析 ID。 
- 永远不要把一个写死的 Bedrock ARN 共用到「开发走直连 API」。 
- 生产钉选**有版本**的 ID；经功能标志＋评测闸门控制升级。 
- 落地参数依路径而异（`inference_geo` vs 区域 URL vs Data Zone 部署）——在测试环境用刻意错误设置测试钉选。

### D5.4 日志／ZDR 考试纪律

- **ZDR**＝限制供应商保留提示词／完成的契约／API 姿态（在有提供之处）。它**不是**你应用的保留、安全信息与事件管理系统（SIEM）或向量嵌入／评测缓存抹除的替代（见档 03）。 
- 滥用监控／安全标记的对外流量在供应商条款下仍可能存在——设计时假设「ZDR ≠ 对所有安全系统隐形」，直到法务／文档另有说明。 
- 云端路径：你的 CloudTrail／Cloud Logging／诊断日志可能保留你设置的**中继数据，有时还有载荷**——架构要管汇流，不只模型厂商故事。

### D5.5 考试陷阱 —— 交付路径

1. 凭品牌偏好选 CSP，却忽略题干里的落地。 
2. 把 **AWS 上的 Claude Platform** 等同于 **Bedrock**（运营者／边界不同）。 
3. 未经核实就假设每条路径都有 BAA／FedRAMP／ZDR。 
4. 把 Anthropic 模型 ID 拷贝粘贴到 Bedrock／Vertex／Foundry 调用。 
5. 因为「模型很聪明」就把云端 IAM 当成可选。 
6. 承诺所有 CSP 第一天功能对等。 
7. 题干要求钉选地理时，仍用直连 API 全球推理。 
8. 相信单靠选 CSP 就满足 GDPR／HIPAA——数据地图与应用控制仍然需要。

### D5.7 问答 —— CSP／交付路径（73–80）

**Q73.** 题干：「推理必须留在美国；已标准化 Azure AD＋Foundry。」最佳默认方向？ 
**A.** 依现行文档用 **US Data Zone**（或等价美国钉选）部署类型的 Azure／Foundry——不是默认直连 API 全球。

**Q74.** 选两项：在仅 AWS、受监管的资产里优先 Bedrock 而不是直连 API 的理由。 
**A.** 重用 **IAM／SCP／PrivateLink** 模式，并把采购／合规证据留在组织已运营的 **AWS** 边界内。

**Q75.** 为什么「我们会用 Anthropic 文档里的 Bedrock 模型 ID `claude-sonnet-…`」是陷阱？ 
**A.** Bedrock 用**平台特有**的模型／推理设置档识别码；第一方 ID 不可携。

**Q76.** 供应商已启用 ZDR——你可以略过从应用日志屏蔽 PII 吗？ 
**A.** **不行。** ZDR 处理的是供应商保留姿态；你的日志、仓储与评测存储仍需要最小化／保留设计。

**Q77.** 产品下周需要全新 Messages API beta；资产是多云且没有硬落地钉选。哪条路径往往胜出，为什么？ 
**A.** **直连 Anthropic API**——通常最早取得功能；确认 beta 权利，仍要文档化落地／日志。

**Q78.** 类似 FedRAMP 的题干列出「仅限已授权云端 AI 服务」。你先做什么？ 
**A.** 用客户的已授权服务清单／边界文档做**限制排除**——然后在幸存者内设计（日志、变更管制），不是「加一个更安全的提示词」。

**Q79.** 当 GCP 组织政策挡住对外到非 Google AI 端点时，Vertex vs 直连 API？ 
**A.** **Vertex**——在该组织政策下直连 API 可能不可达／不合规，与模型质量无关。

**Q80.** 凭感觉选 vs 限制排除——各给一个考试识别点。 
**A.** 感觉：答案只引用人气／速度。限制排除：答案引用一条**使其他路径失格**的题干限制，然后才优化。

## E 部分 —— 评测、测试与优化

### E1. 要衡量什么

| 类别 | 指标注例 |
| --- | --- |
| 任务成功 | 精确比对、F1、pass@k、评分量规分数 |
| 锚定（事实依据） | 引用精确率／召回率、缺乏依据主张率 |
| 安全 | 政策违规率、注入成功率 |
| 延迟 | TTFT、总计、每路径 p95／p99 |
| 成本 | 每次成功任务美元、每次任务 token |
| UX | 赞踩、编辑距离（copilot）、升级率 |
| 运营 | 错误率、工具失败 %、缓存命中率 |

**架构师规则：** 指标必须对上**商务工作**。客服 copilot ≠ 代码 agent ≠ RAG 法律问答。

### E2. 数据集设计

1. **黄金标准集** —— 有标注、有版本、具代表性 
2. **对抗性集** —— 注入、越狱、刁钻实体 
3. **回归集** —— 过去的生产失败 
4. **切片集** —— 语言、租户、文档类型 

把训练／提示调校范例**排除**在保留评测集之外。

### E3. 自动化 vs 人工评测

| 方法 | 优势 | 弱点 |
| --- | --- | --- |
| 精确／schema 检查 | 便宜，对萃取精准 | 错过细微之处 |
| 评分量规 LLM-as-judge | 可扩展 | 裁判偏见；要校准 |
| 人工审查 | 细微之处的黄金标准 | 成本／延迟 |
| 成对 A/B | 适合偏好 | 需要流量／样本量 |
| 安全探测 | 抓住注入 | 必须更新攻击 |

混合是常态：自动化闸控每一次 pull request（PR）；人类每周抽样＋审查高严重程度切片。

**P0 扩充：** 见 **M7 部分 —— 模型裁判 vs 代码裁判＋校准**，了解何时确定性评分者胜过 LLM-as-judge、如何对人工黄金标签校准，以及如何在偷看实验结果**之前**冻结门槛。

### E4. 实验纪律

- 诊断时一次只改**一个**主要变量 
- 记录模型 ID、提示词哈希、索引版本、工具版本 
- 对 A/B 用统计常识（不要用 20 则对话加冕赢家） 
- 切换上线前先影子模式

### E5. 诊断常见失败

| 症状 | 可能原因 | 杠杆 |
| --- | --- | --- |
| 幻觉事实 | 弱检索／没有拒绝路径 | 提高召回、要求引用来源、空结果时拒绝 |
| 格式崩溃 | 松散提示词 | schema＋验证器＋few-shot |
| 高延迟 | 肥上下文／大模型 | 缓存、路由、缩小 k、较快模型 |
| 成本暴增 | 循环／肥工具定义 | 最大轮次、工具搜索、缓存 |
| 质量不一致 | 政策／契约规格不足 | 澄清契约、schema＋few-shot 锚点（现行层级拒绝采样旋钮） |
| 工具选错 | 描述差／工具太多 | 重写描述、允许清单、路由器 |
| 脱机好、生产差 | 分布偏移 | 把生产切片加进评测 |

### E6. 优化 playbook（操作手册）（顺序重要）

1. **正确性优先**（评测闸门） 
2. **拿掉浪费的上下文** 
3. **缓存稳定前缀** 
4. **把简单流量路由到较便宜／较快模型** 
5. **平行化独立工作** 
6. **然后才**微调提示词措辞与 few-shot 锚点 

过早把模型降级而打破安全／质量，会在列出合规限制的考试情境失败。

### E7. 可观测性架构

最低可行遥测：

- 请求／追踪 ID 
- 路径／意图 
- 模型＋提示词／Skill 版本 
- 检索查询＋回传的文档 ID 
- 工具名称、延迟、状态 
- token 用量分解（输入／缓存／输出／思考） 
- 结果标签（自动、人类编辑、失败） 
- 安全标志 

小心存储原始提示词（PII、保留）。长期存储优先指标＋已屏蔽片段。

仪表板：质量每周、延迟／成本每小时、安全即时警示。

### E8. 持续集成／持续交付（CI/CD）里的持续评测

```
PR → 工具单元测试 → 离线评测套件闸口 → 预备环境影子 → 金丝雀 → 生产环境
```

在关键切片上有统计意义的回归就让构建失败（例如引用精确率、PII 外泄探测）。

## 练习问答（28）

**Q1.** 谁执行客户端工具调用？ 
**A.** 你的应用执行环境——不是模型进程本身。

**Q2.** 为什么 MCP 工具搜索可能重要？ 
**A.** 大型工具目录消耗上下文；搜索只加载需要的工具。

**Q3.** 点名混合搜索用的两种检索方法。 
**A.** 稠密／向量与 BM25／关键字（再加上中继数据筛选／重排序）。

**Q4.** 若 RAG 对政策问题没有回传相关切块，应该怎样？ 
**A.** 拒绝、提出澄清问题，或升级——不要发明政策。

**Q5.** `create_refund` 工具的授权必须在哪强制执行？ 
**A.** 在工具服务器／后端政策层（最小权限原则），不只在叙述文字指示里。

**Q6.** 给三个 agent 循环控制。 
**A.** 最大轮次、最大成本、最大墙钟时间（还有停止条件、允许清单）。

**Q7.** 引用精确率大致在衡量什么？ 
**A.** 被引用的来源是否真的支撑所做主张。

**Q8.** 为什么要保留对抗性评测集？ 
**A.** 在攻击者／客户之前抓住注入、越狱与刁钻实体。

**Q9.** 脱机评测好、生产差——第一个怀疑？ 
**A.** 分布偏移；把生产切片加进评测套件。

**Q10.** 提示词缓存如何帮助集成架构？ 
**A.** 降低稳定系统提示词、工具定义与政策前缀的成本／延迟。

**Q11.** 毒化工具模式的回应是什么？ 
**A.** 侦测反复失败，停用／断路该工具，警示操作者。

**Q12.** 为什么要在索引里隔离租户？ 
**A.** 防止跨租户检索渗漏；单靠提示词指示不够。

**Q13.** 何时服务器工具是设计关注？ 
**A.** 当数据对外流量／到 Anthropic 托管执行的信任边界对合规有关时。

**Q14.** 高阶正确排序优化。 
**A.** 正确性／安全 → 缩小浪费 → 缓存 → 路由到较便宜 → 平行化。

**Q15.** 调试错误工具选择时，哪些遥测字段必要？ 
**A.** 追踪 ID、工具描述版本、模型 ID、对话片段、`tool_use` 参数／结果（已屏蔽）。

**Q16.** Map-reduce RAG 的 reduce 阶段把 token 炸了——你做什么？ 
**A.** 限制 mapper 输出、阶层式 reduce，或用 schema 摘要中间笔记。

**Q17.** 为什么索引要与提示词一起做版本？ 
**A.** 让评测与事故能重现行为；检索变更会改变答案。

**Q18.** 截取工具的 SSRF 风险是什么？ 
**A.** 模型／工具诱发对内部 IP／中继数据端点的请求——用允许清单缓解。

**Q19.** 何时 CLI 集成适当？ 
**A.** 开发者／运营自动化；通常不是终端客户产品路径，除非产品就是 CLI。

**Q20.** 定义提示词变更的成功 A/B。 
**A.** 预先登录的指标、足够样本、没有其他同时变更、回滚计划。

**Q21.** 如何阻止引用表演？ 
**A.** 验证器检查引用 ID 存在于提供的切块；评分量规惩罚缺乏依据的主张。

**Q22.** 工具丰富的 agent 里什么是渐进式探索？ 
**A.** 从少数工具／上下文开始；需要时经搜索／浏览再截取更多。

**Q23.** 为什么要把构建者 MCP 凭证与执行环境产品凭证分开？ 
**A.** 爆炸半径——IDE agent 不应握有生产写入权力。

**Q24.** 除了引用精确率，再点名一个锚定指标。 
**A.** 缺乏依据主张率／忠实度分数／检索召回率@k。

**Q25.** schema 验证器在工具参数里防止什么？ 
**A.** 副作用前的畸形调用、意外枚举、缺少必填字段。

**Q26.** 延迟 p95 只在工具密集意图失败——往哪里看？ 
**A.** 工具扇出、序列工具链、冷 MCP 连接、工具前过度检索。

**Q27.** 夜间评测工作应包含什么？ 
**A.** 黄金＋对抗性套件、回归案例、成本／延迟快照、对差异警示。

**Q28.** 你可以靠模型「只调用安全工具」吗？ 
**A.** 不行——强制允许清单与服务器端 authZ；提示词不是控制措施。

## G 部分 —— 深挖：企业验证、网络与数据平面

### G1. 身份传递

当模型路径「变成用户」并握有全能权杖时，企业集成会失败。优先：

1. 用户向你的应用验证（OIDC／SAML）。 
2. 应用取得受限于该用户范围的**下游 token**（OAuth 代表（on-behalf-of）、token 交换）。 
3. 工具用那些 token 调用 API。 
4. 审计日志把动作归到人类＋服务主体。

服务账户给带分开控制的批量工作——不是交互 agent 的捷径。

### G2. 网络模式

| 模式 | 用途 |
| --- | --- |
| 公开 Claude API 对外流量 | 最简单；经代理／数据外泄防护（DLP）控制 |
| 你租户里的云端 AI（Bedrock／Vertex／Foundry） | 数据平面更靠近既有云端控制 |
| PrivateLink／VPC 端点 | 减少公开互联网暴露 |
| 带允许清单的反向代理 | 集中检查／记录／阻挡 |

文档化**提示词与向量嵌入住在哪**（向量数据库区域、日志存储区域）。落地问题会出现在架构师情境题。

### G3. 同步产品 vs 异步工作者

交互用户在等 → 紧的工具逾时、流式文本、把慢工具延后成「还在处理」工作。后台自动化 → 队列工作者、批量 API、较长工具预算。不要把两者硬塞进同一延迟等级。

### G4. 工具的契约测试

对每一项工具：

- schema 单元测试 
- authZ 负向测试（没有该角色的用户必须失败） 
- 幂等测试 
- 逾时行为测试 
- 为评测重放录下范例追踪 

把工具当微服务——LLM 只是另一个客户端。

### G5. 检索评测细节

衡量要超越「答案质量」：

- 相关文档的 **Recall@k** 
- 排序质量的 **nDCG** 
- **切块利用率**（Claude 有用你检索到的吗？） 
- **新鲜度落后** 
- **筛选正确性**（租户／产品）

许多「模型问题」其实是检索问题。先修索引，再换巨型模型。

### G6. 在线评测与回馈

捕捉隐性信号：编辑、重新产生、赞踩、升级。把低信心或高严重程度流量路由到人工标注。每周把循环关进回归集。没有这个，脱机黄金标准集会腐坏。

### G7. 成本异常侦测

在以下情况警示：

- 每次任务 token 周周跳升 >N% 
- agent 轮次计数分布偏移 
- 缓存命中率崩溃（前缀抖动） 
- 单一租户主导花费（失控循环）

把警示绑到 runbook（运维手册）：冻结 agent 最大轮次、还原提示词、停用工具。

### G8. 多区域主动-主动关注

一致钉选模型版本；用冲突规则拷贝索引；对话状态用黏性会话；从公开文档理解云端端点全球 vs 区域路由取舍。验证失败时关闭，可选充实工具失败时柔性降级。

### G9. 额外情境

**情境：** 制造公司希望 Claude 查询监控与数据截取系统（SCADA）历史。 
**答案形状：** 永远不要从 SaaS agent 直连原始厂区网络。用隔离区（DMZ）读取 API、允许清单指标、致动要人类核准——起初优先没有写入工具。手册 RAG＋遥测摘要的读取工具。

**情境：** 法务想「跟所有合约聊天」。 
**答案形状：** 租户隔离的混合 RAG、感知条款的切块、强制引用来源、依案件的访问控制清单（ACL）筛选、日志上的 DLP、义务幻觉评测、红线修改要 HITL。

**情境：** MCP 推行上线后成本爆炸。 
**答案形状：** 检查工具定义的 token 占比、启用工具搜索、缩小允许清单、缓存系统＋工具前缀、加最大轮次、修反复调用搜索的循环。

### G10. 延伸问答（29–36）

**Q29.** 为什么代表 token 交换比共用全能权杖好？ 
**A.** 保留用户范围的 authZ 与可归属的审计轨迹。

**Q30.** 点名一个可以很高、但用户答案仍失败的检索指标。 
**A.** Recall@k 看起来可以，但切块打包／引用／提示工程仍会让答案失败——也要衡量端任务指标。

**Q31.** 切块利用率在告诉你什么？ 
**A.** 检索到的证据是否真的影响答案，还是只在浪费 token。

**Q32.** 如何测试工具的 authZ？ 
**A.** 负向测试：缺少角色的身份必须被工具服务器拒绝。

**Q33.** 「小小改一下提示词」之后缓存命中率为什么可能崩溃？ 
**A.** 前缀字节变了（或工具顺序／思考设置），使中断点失效。

**Q34.** 可选充实的柔性失败是什么？ 
**A.** 可选工具／RAG 逾时时仍回传核心答案，并带明确的部分状态——不是硬 500。

**Q35.** 受监管人力资源数据的向量嵌入应住在哪？ 
**A.** 在已核准区域／系统，与来源人力资源数据受同一套落地控制。

**Q36.** 任何写入工具的第一个集成问题是什么？ 
**A.** 谁被允许、如何审计，以及若被提示注入，爆炸半径是什么？

## H 部分 —— 生产强化叙事（考试风格）

### H1. 幂等与恰好一次的*效果*

LLM 会重试；用户会连点；队列会再投递。副作用工具必须**至少一次安全**：

- 客户端提供幂等键（ticket_id＋动作＋哈希）。 
- 工具服务器把键 → 结果存 TTL。 
- 重放回传原始结果，不二次扣款／双重出货。

考试错误答案：「Claude 会记得它已经退过款了。」

### H2. 对话状态存储

明确选择：

| 存储 | 优点 | 缺点 |
| --- | --- | --- |
| 客户端拥有的历史重放 | 简单、透明 | 提示词大；PII 蔓延 |
| 服务器会话存储 | 截断／压缩控制 | 一致性与保留义务 |
| 摘要＋近期窗口 | token 效率 | 摘要漂移 |

长时间会话搭配平台压缩功能（见档 01）。永远定义对齐法律保全的保留。

### H3. AI 路径的功能标志

能救事故的标志维度：

- 模型钉选 
- 提示词／Skill 版本 
- 检索索引版本 
- 工具允许清单集合 
- agent 最大轮次上限 
- 是否需要 HITL 

回滚是翻标志——不是希望。

### H4. AI 功能的 SLO

写用户感受得到的 SLO：

- `/assist` 的可用性 
- p95 草稿延迟 
- 有依据答案率 
- 安全探测的无害回应率 
- 每 1000 次成功任务成本 

可用性／延迟／安全调用 on-call；质量在营业时间审查，除非严重程度高。

### H5. 伙伴／厂商 MCP 供应链

启用厂商 MCP 服务器前：

1. 威胁模型（它能读／写什么数据） 
2. 验证方法（OAuth 范围最小化） 
3. 变更记录与版本钉选政策 
4. 在合成数据上沙箱试用 
5. 数据离开边界时的法务审查 
6. 设置里的紧急停止开关 

「它在目录里」不是控制措施。

### H6. 流式 UX＋工具

为感知性能流式文本；**动作**仍要等工具结果验证后才放行。永远不要根据尚未完成、尚未验证的工具调用序列，就执行以部分流式计划为基础的写入。

### H7. 多轮 agent 的评测

单轮黄金标准集会低估 agent。加上：

- 脚本化多轮目标 
- 干扰工具 
- 对话中途政策变更 
- 预算耗尽行为 
- 工具错误后的复原 

打分打**任务完成**，不是口才。

### H8. 数据标注工作流程

谁标注？用什么评分量规？校准场次？困难切片双人标注？有追踪标注者间一致性吗？忽略标注质量的架构师会出货虚假信心。

### H9. 跨职能 RACI（责任指派矩阵）片段

| 活动 | 架构师 | 工程 | 数据 | 安全 | 运营 |
| --- | --- | --- | --- | --- | --- |
| 工具 authZ 模型 | A/C | R | C | A | I |
| 评测闸门门槛 | A | R | R | C | I |
| 索引租户归属 | C | R | A | A | I |
| on-call runbook | C | C | I | C | R/A |

（RACI：R＝负责，A＝问责，C＝咨询，I＝知会）

### H10. 更多陷阱

13. 假设流式的部分输出可以安全据以行动。 
14. 支付／工单工具没有幂等。 
15. 产品是 agentic 时只评测单轮。 
16. 未经范围审查就启用厂商 MCP。 
17. 质量调用把 on-call 烧尽在不可行动的琐碎上。

### H11. 问答 37–45

**Q37.** 为什么 Claude 不能自己「记得」跨重试的退款？ 
**A.** 无状态工具副作用需要服务器端幂等键。

**Q38.** AI 回滚有哪些标志维度重要？ 
**A.** 模型、提示词／Skill、索引、工具允许清单、预算、HITL 要求。

**Q39.** 点名两项多轮 agent 评测补充。 
**A.** 干扰工具；工具错误后的复原（还有预算耗尽、政策中途变更）。

**Q40.** 什么是摘要漂移？ 
**A.** 压缩／摘要后的历史省略或扭曲限制／事实。

**Q41.** 谁应对索引租户归属控制问责？ 
**A.** 通常数据＋安全问责；工程负责实作——依 RACI。

**Q42.** 为什么要钉选 MCP 服务器版本？ 
**A.** 防止工具 schema／行为突然变更打断 agent／评测。

**Q43.** 安全探测套件应有什么 SLO？ 
**A.** 无害回应／攻击拦截率，带警示门槛。

**Q44.** token 流式到 UI，但何时提交数据库写入？ 
**A.** 只在验证过的完整工具流程之后——不是部分计划文本。

**Q45.** 什么是标注校准场次？ 
**A.** 标注者用范例对齐评分量规，在打分前提高一致性。

## I 部分 —— 集成模式速查表

### I1. Claude 前面的 API 网关

放一个 AI 网关，用于：验证、配额、提示词大小限制、PII 屏蔽 hooks、模型路由，以及集中追踪。应用团队调用网关，不是原始供应商密钥。集中轮替密钥；用团队标签归属成本。

### I2. 事件驱动的工具结果

长工具（报告产生）应立刻确认、推送完成事件，就绪时用 `tool_result` 恢复 agent／工作流程。没有产品理由时，不要让 HTTP 请求开着好几分钟。

### I3. 向量嵌入模型变更协议

1. 冻结写入或双写。 
2. 脱机重建索引。 
3. 影子查询比较旧／新。 
4. 切流量。 
5. 回滚窗口结束前保留旧索引。

永远不要在生产 RAG 系统下静默变更向量嵌入模型。

### I4. 问答 46–50

**Q46.** 为什么在供应商 API 前面放 AI 网关？ 
**A.** 集中验证、配额、屏蔽、路由与成本归属。

**Q47.** 10 分钟的报告工具应如何与 agent 集成？ 
**A.** 异步工作＋事件／回调恢复——不是没有设计的单次阻塞 HTTP 调用。

**Q48.** 重建索引期间的双写是什么？ 
**A.** 迁移期间把向量嵌入写进旧与新索引，以允许切换上线／回滚。

**Q49.** 点名三个对 FinOps（云端与 AI 成本运营纪律）有用的网关标签。 
**A.** 团队、产品、环境（还有用例、模型路径）。

**Q50.** 静默变更向量嵌入模型的风险？ 
**A.** 检索质量偏移却没有可重现版本——会破坏评测，也让事故更难追查。

## K 部分 —— 主要学习深挖：集成（19%）

集成是最重的官方领域。把每一个企业连接当成**信任边界**加上**延迟预算**加上**可观测性接口**。

### K1. 传输层决策矩阵（展开）

| 机制 | 最佳适配 | authZ 故事 | 误用时的失效模式 |
| --- | --- | --- | --- |
| 直连 Messages API＋客户端工具 | 带 1–N 项客制工具的产品执行环境 | 应用身份＋每工具服务器检查 | 临时工具蔓延、没有目录 |
| MCP 服务器 | 跨应用／Claude Code 的共享连接器 | 服务器强制执行；客户端仍定范围 | 未经审查的第三方服务器＝供应链 |
| CLI／本机自动化 | 构建者与 CI 循环 | 本机凭证／OIDC 设备流程 | 在客户 SaaS 路径用 CLI 密钥 |
| Agent 对 agent（A2A） | 跨服务清楚的角色分裂 | 每 agent 凭证＋hop 审计 | 没有预算或负责人的聊天式蜂群 |
| 服务器工具（Anthropic 托管） | 允许处的网页截取／搜索／代码 | 理解对外流量与数据处理 | 在受监管租户「因为酷」而启用 |
| 事件总线＋工作者 | 长工具／人类队列 | 队列访问控制清单＋幂等键 | 没有关联识别码的双写 |

**考试启发式：** 重用与探索重要时优先 **MCP**；延迟与极度客制控制主导时用**直连工具**；**A2A** 只有带监督者与 schema 时才用；**CLI** 给构建者，不是终端客户生产路径（除非产品*就是* CLI）。

### K2. 能力膨胀分析（考试最爱）

工具／agent 膨胀的症状：
- 模型在近重复工具中选错 
- 上下文窗口被工具 JSON schema 主导 
- 第一次有用动作前延迟就上升 
- 安全审查无法枚举能力 

缓解：
1. 依 agent 角色的**允许清单**（客服 ≠ 管理员）。 
2. **合并**重叠工具（`get_order` 而不是五个变体）。 
3. **渐进式探索／工具搜索**，让定义按需加载。 
4. **描述质量评分量规**：名称、何时用、何时不用、副作用、幂等。 
5. 在真实逐字稿上**评测**工具选择准确度。

### K3. AuthN/Z 缺口检查清单（每个设计走一遍）

- [ ] 用户身份有传递（不是所有租户共用一个全能服务账户） 
- [ ] 工具执行在*你的*代码检查**资源层级** authZ——不是「Claude 小指许诺」 
- [ ] 租户 ID 来自已验证 token，永远不要单靠模型产出的参数 
- [ ] 密钥在保管库／环境——永远不要在提示词、Skills，或提交到 git 的 MCP URL 
- [ ] 读 vs 写工具凭证分开 
- [ ] 破窗管理员路径是人类＋有工单，不是 agent skill 
- [ ] 审计日志：谁、哪个工具、哪个资源、关联识别码、成功／失败 

### K4. 准确度–延迟设置取舍

| 旋钮 | 准确度↑？ | 延迟↑？ | 备注 |
| --- | --- | --- | --- |
| 较高能力模型 | 往往 | 是 | 在困难切片衡量 |
| 更多检索 k | 有时 | 是 | 噪音风险 |
| 重排序器 | 往往精确率↑ | 轻微 | 对常见问答／政策值得 |
| 思考／effort | 困难任务↑ | 是 | 缓存交互 |
| 额外评论循环 | 是 | 是 | 限制迭代 |
| 流式 | UX 感受↑ | 首个字节延迟（TTFB）↓，总计≈ | 工具仍会阻塞 |
| 平行工具调用 | 墙钟时间↓ | 扇出成本 | 仅当独立时 |

每个旋钮都用**指标＋预算**辩护。盲目把所有旋钮开到最大，会在情境题失败。

### K5. 规模上的可观测性

最低可行 AI 可观测性：
1. **请求追踪**：入口 → 模型 → 工具 → 验证器 → 出口 
2. **token 与 $**：每路径输入／输出／缓存／思考 
3. **质量代理**：赞踩、编辑距离、人类推翻、引用覆盖 
4. **安全**：注入命中、DLP 封锁、拒绝率 
5. **饱和**：队列深度、工具 p95、速率限制 429 

没有追踪，「幻觉」工单就不可行动。

### M2. 数据集设计方法

1. **生产抽样**（经隐私审查）＋合成边缘个案。 
2. 依意图、语言、租户大小、难度**分层**。 
3. 带标注者间一致性检查的**黄金标签**。

- 可能时每次实验一个变更（提示词 XOR 模型 XOR 检索）。

- 在相同案例上用成对测试。 
- 在标志后出货；切换上线前影子流量。

### M4. 诊断树（幻觉 vs 提示词 vs 模型 vs 检索）

```
回报答案错误
 ├─ 来源缺失／错误？ → 检索路径
 ├─ 来源没问题，答案凭空发明？ → 锚定提示词＋解码限制＋强制引用
 ├─ 格式坏掉？ → Schema／提示词／范例
 ├─ 工具参数错误？ → 工具描述＋authZ＋few-shot 工具使用
 ├─ 只有困难案例失败？ → 模型层级／思考
 └─ 间歇发生？ → 温度／非确定性、逾时、部分工具结果
```

### M5. 优化顺序（不要随便打乱）

1. 修正正确性错误（错误工具、坏检索）。 
2. 缩小上下文（更好检索、更少工具）。 
3. 缓存稳定前缀。 
4. 把简单流量路由到较便宜／较快模型。 
5. 然后才考虑批量、平行、蒸馏式模式。

正确性之前优化成本，会创造静默错误的系统。

### M7. 模型裁判 vs 代码裁判＋校准（P0）

LLM-as-judge 是**衡量仪器**，不是感觉神谕。架构师选评分者就像选单元测试框架：契约机器可检查时优先**确定性检查**；质量开放时用**模型裁判**——并且在分数驱动出货／不出货**之前校准**。

#### 何时代码／确定性断言胜过模型裁判

| 代码胜出的信号 | 示例 |
| --- | --- |
| 精确或结构化输出 | JSON schema 有效；必填字段存在；枚举成员 |
| 锚定机制 | 引用 ID ⊆ 检索切块 ID；URL 允许清单；配额算术 |
| 工具正确性 | 选对工具名称；参数通过 schema；幂等键存在 |
| 政策引擎已存在 | 退款 ≤ 上限；权益检查布尔；PII 正则表达式／DLP 命中 |
| 带已知字符串的安全探测 | 禁止子字符串；密钥模式；对 link-local IP 的 SSRF |
| 格式 SLA 回归 | 字／字符限制；语言代码；「必须包含免责声明 X」 |

**规则：** 若初级工程师不用读作文就能写 pytest，**就不要**为裁判烧 token。

#### 何时需要模型裁判

| 评分量规裁判有帮助的信号 | 示例 |
| --- | --- |
| 开放式质量 | 同理心、清晰、教学质量、摘要有用性 |
| 多因素评分量规 | 「有帮助＋无害＋符合品牌」，可部分给分 |
| 改写等价 | 许多正确措辞；精确比对太脆 |
| 比较偏好 | A/B 成对「哪个草稿更适合这个人格设置」 |
| 细微忠实度 | 引用偏叙述文字时，软检查主张是否有依据 |

即使如此：与代码闸门结合（schema、引用 ID ⊆ 检索），让裁判永远不要把垃圾 JSON 打成「美丽」。

#### 对人工黄金标签校准（信任前）

```
1. 依意图／难度分层抽样 N 个项目（先约 50–200 个；高利害时加大规模）。
2. ≥2 位合格的人类用同一份评分量规打分；衡量一致性（例如 Cohen’s κ／完全一致百分比）。
3. 让候选裁判（模型＋提示词＋effort／思考设定＋参照政策）在相同项目上盲测。
4. 比较裁判与人类：相关性、系统性偏见（宽松／严格）、切片失败。
5. 只有一致性越过默认门槛才晋升裁判；否则修评分量规／范例，或继续用人工。
6. 模型升级、评分量规修改或领域漂移时重新校准——像程序码一样为裁判做版本。
```

**考试陷阱：** 「提示词微调后裁判分数升了 8% → 出货。」未经校准，你可能教会裁判爱冗长。

#### 门槛与回滚 —— 在看到实验数据**之前**冻结

| 预先登录（先写下来） | 为什么 |
| --- | --- |
| 主指标＋方向 | 阻止指标购物 |
| 最小提升／最大允许下降 | 出货门槛 |
| 护栏指标（安全、延迟、成本） | 防止质量赢了却合规失败 |

偷看结果再选门槛是 **p-hacking**。架构师把评测设置当成 git 里受控的产物。

**Q81.** 退款工具参数必须是 `{order_id, amount_cents}` 且金额 ≤ 政策上限。优先代码还是模型裁判？ 
**A.** **代码**（schema＋政策引擎）。模型裁判是可选的叙事润饰，不是控制措施。

**Q82.** 为什么要在 CI 闸控前对人类校准 LLM-as-judge？ 
**A.** 为了衡量偏见／一致性；未校准的裁判可能奖励风格胜过正确性，并创造虚假出货信号。

**A.** 高利害／不可逆领域、新颖失效模式，以及对裁判本身的定期审计——自动化补充、不取代问责性。

## N 部分 —— 架构决策情境题（集成＋评测）

### N1. CRM＋计费＋知识库的 MCP vs 直连 API

若三个以上应用（客服机器人、Claude Code、内部 agent）需要同一套连接器且你会维护目录，**优先 MCP**。

### N2. 带退款与政策 RAG 的客服 agent

authZ：退款工具有上限；金额来自代码，不是未经检查的自由形式模型浮点。

### N3. 正式发布（GA）后缺少可观测性

症状：「错误答案」工单上升，没有追踪。 
修复方法：加关联识别码、存储已屏蔽提示词／工具 I/O、建重放框架、从工单冻结回归集。

### N4. 准确度上升、延迟坏了

你加了评论循环＋k=20 检索＋opus 级。 
回滚到基准线；每个旋钮做 A/B；只保留每 +100ms 有证明提升的杠杆。

**Q63.** 混合检索在何时帮助最大… 
**A.** 查询混合**语义改写**与**精确 token**（ID、代码、条款编号）。

**Q64.** 客服 copilot 的在线评测信号？ 
**A.** 人类编辑率／推翻率／连到追踪 ID 的 CSAT——不只脱机 BLEU。

**Q65.** HIPAA 工作区里的服务器工具网页截取——架构师动作？ 
**A.** **停用或紧密闸控**，搭配 DLP 与数据处理审查；优先私有检索。

### S6. 延伸问答（66–72）

**Q66.** 必须引用来源，但模型引用不在检索集合里的文档——什么闸门？

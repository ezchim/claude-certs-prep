## Part A — 推行上线策略

### A1. 为什么架构师要负责赋能设计

若平台／安全不铺路，团队就会采用消费级 AI，并养成把密钥粘贴的习惯。架构师要设计：

- 身份（单一登录（SSO））进入核可工具
- 数据处理规则（哪些代码／密钥可以送出）
- 核可的 MCP／plugin 集合
- 密钥经由 vault（密钥库）——不是聊天
- 采用 **以及** 事故的指标

### A2. 分阶段推行上线

| 阶段 | 对象 | 目标 |
| --- | --- | --- |
| 0 设计 | 平台＋安全 | 设置、Marketplace、日志 |
| 1 试点 | 1–2 个志愿团队 | 摩擦记录；生产力信号 |
| 2 扩大 | 全体工程师配训练 | 默认安全设置 |
| 3 优化 | 全组织 | Skills 库；内部开源 |
| 4 持续 | — | 版本升级；访问审查 |

每阶段退出条件：安全发现已关闭；支持队列可管理；量到的是有用采用（不是只看席位数）。

### A3. 赋能的成功指标

| 指标 | 意图 |
| --- | --- |
| 有助理协助下首次合并 pull request（PR）所需时间 | 上手性能 |
| PR 周期时间／审查迭代 | 速度（小心干扰因素） |
| 涉及 AI 工具的密钥扫描事故 | 安全 |
| 有 `CLAUDE.md` 的存储库％ | 标准化 |
| 只来自核可 Marketplace 的 MCP ％ | 供应链卫生 |
| 每 100 个席位的支持工单 | 赋能质量 |
| 开发者满意度（问卷） | 铺好的路的 UX |

## Part B — `CLAUDE.md`、Skills 与项目指示

### B1. 组织指示档是做什么的

公开 Claude Code 文档描述项目指引档（常见为 `CLAUDE.md` 或同等项目指示），让写程序的 agent 对上：

- 存储库结构与惯例
- 构建／测试命令
- 代码风格与审查期望
- 禁止动作（例如没有工单就不要动 `prod/`）
- 如何跑 linter／安全扫描仪

**架构师指引：** 把这些档当成 **有版本管理的产品代码**。在 PR 里审查。里面不要放密钥。连到更深的文档，不要贴长篇小说（上下文预算）。

### B2. 分层指示

| 层 | 例子 | 范围 |
| --- | --- | --- |
| 组织默认 | 公司编码标准 Skill | 所有存储库 |
| 存储库 `CLAUDE.md` | 服务专属架构 | 一个存储库 |
| 目录提示 | `/payments` 更严的规则 | 子树 |
| 个人 | 用户偏好 | 只在本机——绝不能削弱安全 |

安全关键规则要放在 **强制设置** 里，不能只放在模型可能权重不足的 markdown。

### B3. 给团队的 Skills

Skills 把可重用指示／资源打包给反复出现的任务：「加上 OpenTelemetry span」、「写 ADR」、「迁移端点」。好处：

- 跨人一致性
- 每一轮更小的提示词
- 可审查的产物

治理：Skill 审查负责人；语义化版本；弃用；针对外泄指示做安全扫描。

### B4. Hooks

Hooks（围绕 agent 生命周期事件的自动化——格式器、密钥扫描仪、政策检查）在提示词偏软的地方强制 **确定性的** 控制：

- 在 agent 循环中触发的提交前／推送前风格检查
- 挡住含密钥的提交
- 自动跑格式器
- 特定路径要求测试

考试主题：把 **软指引**（`CLAUDE.md`）与 **硬 hooks／设置** 合在一起。

## Part C — 设置阶层与强制执行

### C1. 优先级心智模型

公开 Claude Code 企业功能描述一个阶层：**服务器受管理／组织受管理设置** 位于最高优先级，**不能** 被项目、用户、本机或 CLI 标志覆盖。较低层提供默认与团队惯例。

| 层（概念） | 用户可覆盖？ | 用于 |
| --- | --- | --- |
| 服务器／组织受管理 | 否 | 安全政策、拒绝的工具、环境限制 |
| Marketplace 限制 | 否／有限 | 核可 plugin 来源 |
| 共享项目建议 | 是（除非受管理） | 惯例 |
| 用户／本机 | 是 | 个人开发者体验（DX） |

**考试陷阱：**「在存储库发布建议设置 JSON，请团队拷贝」——当需求是 **强制执行** 时不够。优先受管理设置＋受管理 Marketplace。

### C2. 全组织该强制什么

- 不允许的 MCP 来源／未经检查的 plugin 安装
- 安全要求的遥测／日志基准线
- 环境变量政策
- agent shell 的命令允许／拒绝清单
- 在支持处施加对外流量限制
- 要求使用以 SSO 为后盾的安装

### C3. 该留下弹性的东西

- 编辑器快捷键
- 核可集合内的非安全模型偏好
- 不授予工具的个人提示词片段

### C4. 受管理 plugin Marketplace

中央目录以散布核可的：

- Skills
- Agents
- Hooks
- MCP 服务器

支持版本管理、探索、更新与 **来源控制**——对上每个开发者去 curl 随机 GitHub。搭配政策：公司设备只装 Marketplace。

## Part D — 构建者的 MCP 与凭证

### D1. 与生产执行环境分离

构建者环境必须 **不** 重用生产写入凭证。提供：

- 范围狭窄的开发／测试阶段凭证
- 在有理据时的只读生产复本
- 破窗生产访问走既有特权访问管理（PAM）——不是 Claude 设置档

### D2. 核可连接器集合

从小开始：工单追踪、代码托管、内部文档搜索、持续集成（CI）状态。SaaS MCP 只在供应商审查后再加（文件 03）。文档化每个连接器允许的数据类别。

### D3. 密钥卫生训练（强制）

- 绝不把 API 密钥贴进提示词
- 使用 vault＋短寿命 token
- 假设逐字稿可能依政策被保留
- 支持用的屏幕截图要屏蔽

## Part E — 开发者生产力工作流程

### E1. 高 ROI 助理使用案例

| 工作流程 | AI 如何帮忙 | 护栏 |
| --- | --- | --- |
| 代码库上手 | 解释模块、找例子 | 引用文件；验证 |
| 功能脚手架 | 样板＋测试 | 人类审查；架构适配 |
| 错误调查 | 把日志对到代码 | 不要生产写入 |
| 测试产生 | 边界案例 | 仍在 CI 跑 |
| PR 说明／变更记录 | 摘要差异比较 | 作者问责 |
| 文档漂移修复 | 更新 README | 审查正确性 |
| 重构 | 机械转换 | 要求测试 |

### E2. 反模式

- 没读就接受大型 AI 差异比较
- 因为「模型说它通过」就跳过测试
- 让 agent 不安全地强制推送／改写 git 历史
- 为调试把客户 PII 贴进提示词
- 没有专家审查就产生加密／验证代码

### E3. 审查文化升级

AI 增加差异比较的 **量** → 提高审查标准：

- AI 碰过的验证／付款路径要求测试
- 归属注记
- 更小的 PR
- 工具／MCP 变更的威胁模型检查清单

### E4. 不说谎地量测生产力

小心「代码行数」虚荣。优先：

- 变更前置时间
- 变更失败率
- 感知苦工下降问卷
- 上手到第一次有意义 PR 的时间

控制团队成熟度与同时发生的流程变更。

## Part F — 运营赋能与 runbook

### F1. AI 辅助运营（安全模式）

用助理来：

- 摘要警示风暴
- 关联日志（在政策内）
- 起草事故时间线
- 建议仪表板查询
- 起草事后复盘大纲

**不要** 第一天就把不受限的云端管理员交给聊天 agent。

### F2. AI 功能的 runbook 模板

对每个生产 Claude 功能（产品执行环境——不只 IDE）：

1. 症状
2. 仪表板
3. 功能标志／钉选回滚
4. 区分模型 vs 检索 vs 工具失败
5. 安全事故分叉 → 安全 IR
6. 客户沟通指向
7. 升级图

赋能意指值班可以执行，不必每次都调用原始架构师。

### F3. 构建者工具的支持模式

| 层级 | 处理者 | 例子 |
| --- | --- | --- |
| L1 | IT／服务台 | 安装、SSO、授权 |
| L2 | 平台 AI 赋能 | 设置、MCP 允许清单请求 |
| L3 | 安全＋架构师 | 疑似外泄、恶意 Skill |

知识库：黄金 `CLAUDE.md` 例子、FAQ、已知失效模式、新 MCP 申请表。

### F4. 调试生产力循环

教构建者标准循环：

1. 重现
2. 用 **最少** 敏感上下文问助理
3. 对测试验证
4. 若模式复现就文档化成 Skill

## Part G — 训练与上手课程

### G1. 依角色路径

| 角色 | 课程焦点 |
| --- | --- |
| 个人贡献者（IC）开发者 | `CLAUDE.md`、提示词卫生、带 AI 的 PR 审查、密钥 |
| 技术主管 | Skills 撰写、hooks、指标、团队规范 |
| SRE／运营 | runbook、安全运营助理、回滚 |
| 安全推动者 | MCP 威胁模型、设置强制执行、审计 |
| 产品经理（PM）／工程经理（EM） | 生命周期指标、期望管理（文件 04） |

### G2. 上手周大纲

- 第 1 天：账户、SSO、政策确认
- 第 2 天：走访铺好的路 Skills；在沙箱存储库完成实验
- 第 3 天：配对真实任务，带审查检查清单
- 第 4 天：密钥卫生＋注入意识迷你模块
- 第 5 天：office hours（开放咨询时段）；回馈表

### G3. 实验（原创构想）

1. 加上「从模板产生 ADR」的 Skill
2. 为 `.env` 提交设置封锁清单 hook
3. 用 MCP 文档搜索回答架构问题并附引用
4. 在玩具 RAG 里故意打破租户归属并修筛选器（搭配 `02`）
5. 在测试阶段练习回滚提示词钉选

### G4. 推动者网络

各组织单位的志愿推动者降低 L2 负担；他们每两周开会分享 Skills 与事故。架构师播下第一个 Skill 库。

## 决策树

### 强制 vs 建议

```
Could a developer override cause data leak or prod damage?
 YES → Org-managed enforced setting / hook / deny tool
 NO → Recommended project settings / CLAUDE.md guidance
```

### 新 MCP 请求

```
Vendor review + least scopes + stage credentials + Skill docs + owner?
 ALL YES → Marketplace publish
 ELSE → Reject or sandbox spike only
```

## 考试陷阱

1. 用建议的存储库设置取代组织强制政策。
2. 允许任意 plugin 安装然后「稍后审计」。
3. IDE MCP 设置里的生产管理员凭证。
4. 充满密钥的 `CLAUDE.md` 长篇。
5. 只量测席位采用，不量测安全或成果。
6. 带不受限云端身份与访问管理（IAM）的 AI 运营机器人。
7. 没有支持层级／知识库——架构师永远当 L1。
8. 没有负责人或审查的 Skills。
9. 训练只讲提示词，从不讲 hooks／设置。
10. 被 agent 放大的强制推送文化。

## 练习问答（28）

**Q1.** 如何强制执行开发者无法覆盖的设置？
**A.** 使用位于最高优先级的组织／服务器受管理设置。

**Q2.** 为什么「把建议设置放进 git」对强制安全不够？
**A.** 团队可以忽略或改掉它们；受管理设置无法被覆盖。

**Q3.** 受管理 Marketplace 该散布什么？
**A.** 核可的 Skills、hooks、agents、MCP 服务器（有版本）。

**Q4.** 存储库专属构建命令该放哪？
**A.** 有版本管理的项目指示（例如 `CLAUDE.md`），在 PR 里审查。

**Q5.** 举出两个超出 markdown 指引的硬控制。
**A.** Hooks（密钥扫描／格式）以及组织受管理拒绝清单／工具政策。

**Q6.** 为什么要把构建者凭证与生产写入密钥分开？
**A.** 限制提示注入或 agent 误动作的爆炸半径。

**Q7.** 超出席位的好赋能指标？
**A.** 首次合并 PR 所需时间、密钥事故、仅核可 MCP 的％、CSAT。

**Q8.** Skill 对团队有什么用？
**A.** 把反复工作流程打包，以求一致与重用。

**Q9.** 谁该发布到组织 Marketplace？
**A.** 经审查的受控发布者——默认不是每个开发者。

**Q10.** AI 产生的验证代码需要什么额外步骤？
**A.** 专家人类审查（＋测试）；不要盲目信任。

**Q11.** Claude Code 的 L1 vs L2 支持？
**A.** L1 安装／SSO；L2 平台设置／MCP 允许清单请求。

**Q12.** AI 功能值班 runbook 该放什么？
**A.** 回滚钉选／标志、仪表板、失败区分、升级。

**Q13.** 为什么要教使用 MCP 的开发者注入意识？
**A.** 不可信内容可以导向握有工具的 agent。

**Q14.** 该避开的虚荣生产力指标？
**A.** 原始产生的代码行数。

**Q15.** 推动者网络是做什么的？
**A.** 联邦式赋能、Skill 分享、降低中央工单负担。

**Q16.** 个人设置可以削弱组织安全政策吗？
**A.** 绝不能——若管理正确，组织政策胜出。

**Q17.** 团队请求新 SaaS MCP 时的第一步？
**A.** 安全／供应商审查＋范围最小化（不是立刻安装）。

**Q18.** Hooks 如何补足 `CLAUDE.md`？
**A.** Hooks 强制确定性检查；markdown 是建议式上下文。

**Q19.** 技术主管超出 IC 还需要什么训练？
**A.** Skills 撰写、hooks、团队规范、指标。

**Q20.** 为什么用 AI 调试前要屏蔽客户 PII？
**A.** 隐私／政策合规；降低保留与外泄风险。

**Q21.** 破窗生产访问该走什么？
**A.** 既有 PAM／特权工作流程——不是 agent 设置里的长寿命密钥。

**Q22.** 有 `CLAUDE.md` 的存储库％表示什么？
**A.** agent 指引的标准化（领先赋能指标）。

**Q23.** 没有负责人的 Skills 的风险？
**A.** 漂移、遗弃、潜在恶意的过期指示。

**Q24.** AI 该如何影响 PR 大小规范？
**A.** 保持 PR 可审查；不要合并没人读过的巨大 AI 倾倒。

**Q25.** 上手中 office hours 的目的？
**A.** 为试点解阻；搜集摩擦以修铺好的路。

**Q26.** 平台该保留什么变更记录？
**A.** 组织受管理设置与 Marketplace 项目版本。

**Q27.** 这个领域只关于 IDE 工具吗？
**A.** 主要是构建者生产力＋运营赋能；产品执行环境的运营 runbook 也很重要。

**Q28.** 为全组织强制核可工具选 TWO：受管理 Marketplace＋服务器受管理设置——为什么两个都要？
**A.** Marketplace 散布能力；受管理设置强制政策／来源限制。

## Part I — 深挖：设计铺好的路

```

 ↓

 ↓

```

日志导入到安全信息与事件管理系统（SIEM），依安全基准线。例外用工单追踪。

### I2. 示例组织政策（说明用）

1. 受管理设备只使用 Marketplace MCP 服务器。
2. 开发者 agent 没有生产写入范围。
3. 拥有服务的所有存储库必须含带测试命令的 `CLAUDE.md`。
4. 碰验证／付款的 Skills 需要安全共同审查。
5. Agent shell 拒绝：没有工单 ID 环境变量就在生产目录跑 `terraform apply`。

### I3. 从影子 ChatGPT 使用迁移

- 提供对等便利（文档 MCP、工单 MCP）
- 清楚的数据处理比较表
- 特赦窗口以轮替贴过的密钥
- 若 DLP 支持，监控往未核可 AI 网域的对外流量

### I4. 多存储库与 monorepo（单一存储库）注记

Monorepo 需要目录范围指引，以及只在被碰路径触发的 hooks 以求性能。语言生态系（Go／Java／TS）的共享 Skills 减少重复。

### I5. 来自赋能的合规证据

审计人员可能问你如何控制 AI 写程序工具。保留：设置屏幕截图／导出、Marketplace 访问控制清单、训练完成记录、例外登录表、事故工单。

### I6. 延伸情境

**情境：** 组织必须防止开发者覆盖安全设置，同时散布核可工作流程。
**答案形状：** 服务器受管理设置＋受管理 plugin Marketplace（经典 Select TWO）。不是单靠定期审计本机安装；不是只建议存储库设置。

**情境：** SRE 要 Claude 在生产自动修复 kube pod。
**答案形状：** 先从只读诊断＋建议的 kubectl 开始；人类核准；最终以 PAM 做狭窄自动化；绝不要把宽管理员 kubeconfig 放进 IDE。

**情境：** 新进把支持淹没在「我怎么接 Jira MCP」。
**答案形状：** 改善上手实验＋L1 知识库文章＋推动者；不要永远手动为每台笔电客制设置。

## Part M — 主修深挖：铺好的路赋能

领域配分比重只有 **7%**，但题目具体：设置优先级、安全默认、`CLAUDE.md`／Skills／hooks、核可 MCP／plugins，以及运营调试模式。错答案通常违反 **最小权限原则**，或把 **构建者工具** 与 **生产执行环境** 搞混。

### M1. 控制平面心智模型

```
Org managed settings (non-overridable security)
 → Team / enterprise defaults
 → Repo CLAUDE.md + Skills (versioned)
 → User local settings (where allowed)
 → Session prompts
```

**考试规则：** 安全相关控制要放在 **用户无法绕过的最高优先级**。生产力便利可以是建议默认。

### M2. 该强制 vs 建议（扩充）

| 控制 | 全组织强制 | 建议 |
| --- | --- | --- |
| 密钥外泄护栏／hooks | 是 | — |
| 禁止未核可 MCP／Marketplace | 是 | — |
| 挡住粘贴 `.env`／密钥模式 | 是 | — |
| 要求 SSO | 是 | — |
| 交互用默认模型 | 常常 | 若政策允许可给高端用户 |
| 提交消息风格 Skill | — | 是 |
| 积极自动跑 shell | 默认拒绝 | 对受信任存储库谨慎启用 |
| 工具使用的遥测／审计 | 在合法处是 | — |

### M3. `CLAUDE.md` 设计指南

好的组织／存储库指示档：
- 架构地图与服务边界
- 测试命令与「完成的定义」
- 安全绝对不要做（生产凭证、原始 PII）
- 如何提案添加 MCP／Skill
- 连到 runbook——不是密钥

坏档：
- 整份风格指南贴两次
- 凭证
- 与组织受管理政策矛盾
- 18 个月前未维护的传说

**分层：** 组织基准线 → 存储库细节 → 个人偏好（若允许）。在测试阶段用刻意冲突测优先级。

### M4. 给团队的 Skills

| Skill 类型 | 例子 | 治理 |
| --- | --- | --- |
| ADR 撰写器 | 结构化决策记录 | 像文档一样审查 |
| 测试产生器 | 框架专属 | 没有生产网络工具 |
| 威胁模型草稿 | STRIDE（欺骗、篡改、否认、信息泄露、拒绝服务、权限提升）提示词 | 安全共同拥有 |
| 迁移 langX | 内部框架 | 有版本；有负责人 |

会截取远程内容的 Skills 继承 **提示注入** 风险——当 MCP 对待。

### M5. 值得存在的 hooks

高 ROI hooks（来自公开产品主题的说明模式）：
- 工具前：挡住符合密钥／外泄模式的命令
- 提交前助理：提醒测试
- 停止：为交接笔记摘要会话

避开没有安全价值、却拖慢每一次按键的 hook 膨胀。

### M6. 构建者 MCP ≠ 生产 agent MCP

| 维度 | 构建者（Claude Code） | 生产 agent |
| --- | --- | --- |
| 凭证 | 开发／沙箱角色 | 范围化服务角色 |
| 爆炸半径 | 存储库／开发账户 | 客户数据／金钱 |
| 变更速度 | 快速内循环 | 受变更管制 |
| 核准 | Marketplace 允许清单 | 架构＋安全审查 |

绝不为了「方便」在开发者 MCP 重用生产全能凭证。

## Part N — 经得起查看的生产力工作流程

### N1. 高 ROI 循环（带审查闸门）

1. **解释 → 提案 → 修补 → 测试 → PR 摘要**，带人类审查。
2. **失败测试 → 根因假设 → 最小修复。**
3. **旧模块 → 重构前先做特征化测试。**
4. **事故草稿 → 从日志（已屏蔽）起草时间线 → 人类编辑。**

### N2. 反模式

| 反模式 | 为什么不好 | 换成 |
| --- | --- | --- |
| 盲目接受所有差异比较 | 送出弱点／密钥 | 强制审查文化 |
| 把生产倾倒贴进对话 | 数据外泄 | 已屏蔽的测试夹具 |
| 指标＝产生行数 | 表演 | 周期时间＋变更失败率 |
| 带工具的未追踪 Skills | 供应链 | 受管理 Marketplace |
| 笔电上一把共享 API 密钥 | 归属／滥用 | SSO＋依用户 |

### N3. 诚实量测生产力

优先：PR 周期时间、审查迭代、逃逸缺陷、密钥扫描事故、开发者满意度、新人到第一次有生产力 PR 的时间。
不信任：原始接受率、把 token 花费当「价值」、AI 代码行数。

### N4. 调试与运营赋能

安全模式：AI 协助 **只读** 诊断；修复走既有变更系统。提供助理可检索的 runbook；不要把云端管理员 MCP 授给每位工程师笔电上的 agent。

Runbook 区段：症状 → 搜集（命令）→ 假设 → 缓解 → 验证 → 升级 → 事后复盘链接。

## Part T — 延伸问答（49–60）

**Q49.** 「拒绝未核可 MCP」的最高优先级位置？
**A.** **组织受管理／不可覆盖** 设置——不是单靠一行有希望的 `CLAUDE.md`。

**Q50.** 选 TWO 个赋能成功指标：密钥扫描事故、只看席位数、首次合并 PR 所需时间、烧掉的原始 token。
**A.** 密钥扫描事故与首次合并 PR 所需时间。

**Q51.** 带生产数据库管理员的构建者 MCP——可接受吗？
**A.** **否**——用沙箱／只读角色；生产变更走受控执行环境。

**Q52.** Hooks vs Skills——挡住外泄命令的安全？
**A.** 优先 **hooks／强制控制**；Skills 是指示，不是硬强制。

**Q53.** 影子 AI 使用——最佳架构师动作？
**A.** 铺好的路＋政策＋迁移，不是只禁。

**Q54.** `CLAUDE.md` 含 API 密钥——动作？
**A.** 轮替密钥、清除历史、教 vault；加上密钥扫描。

**Q55.** 选 THREE 个推行上线阶段：设计控制、试点、扩大、安全拖到 GA、把密码寄给团队。
**A.** 设计、试点、扩大。

**Q56.** 为什么要把生产 agent 凭证与 Claude Code MCP 分开？
**A.** 爆炸半径、变更管制与归属需求不同。

**Q57.** 生产力表演例子？
**A.** 庆祝 AI 产生的代码行数，同时变更失败率上升。

**Q58.** 受管理 plugin Marketplace 的目的？
**A.** 散布 **核可** 工具／Skills；降低供应链风险。

**Q59.** 运营要 AI「直接修生产」。安全模式？
**A.** 只读诊断＋人类／受变更管理的修复。

**Q60.** 存储库指示与组织拒绝清单冲突——谁赢？
**A.** **组织强制设置**；修存储库档。

# 分歧地图 — 共享知识不得跨越考试之处

*防污染文件。每个考试日早上花 20 分钟读当天考试的围篱。本档与直觉不一致时，以本档为准 — 每张考试都依自己那本指南的范围与词汇评分。*

| 概念 | 各考试这样说 |

## 3. 同一题干、不同正确答案（危险题）

**「agent 跳过了一个必要的合规步骤。」**
- CCAR-F → 程序化前置条件，或 PreToolUse 风格的拦截 hook。
- CCAR-P → 工作流程闸口＋在工具服务器内强制执行的授权（authZ）（架构师高度）。
- CCAO-F → 行动离开大楼之前的人类核准关卡。
同一条心法（D2）；评分的答案会点名*那张考试的*机制。

**「改善萃取的可靠性。」**
- CCDV-F → JSON schema＋严格验证＋few-shot（少样本）锚点。
- CCAR-F → 带错误回馈的重试循环，以及用可为 null 的字段防止捏造。
- CCAR-P → 在副作用发生之前、在工作流程阶段之内，用代码写验证器。
（而且永远不是「调低 temperature」— 目前层级已不存在，所有学习包都已更正。）

**「他们该用哪个模型？」**
- CCAO-F → 任务类型拣选器（高量简单 → Haiku 级；深度 → Opus 级）。
- CCDV-F → 能通过评测的最小模型＋effort 旋钮；只有在对延迟敏感且溢价合理时才用快速模式。
- CCAR-P → 经评测证实的升级，外围配上路由器与金丝雀架构。

**「Claude 一直为团队做错事情。」**
- CCAO-F → 项目知识卫生／Memory 条目清理／设置优先。
- CCDV-F / CCAR-F → 项目层对用户层的 Claude Code 设置；强制执行对仅建议。
- CCAR-P → 先以评测诊断（检索优先于模型 — 样例题 Q3），然后才是设置。

**「处理这段又长又复杂的对话上下文。」**
- CCAO-F → 带摘要开新对话；耐久的事实用项目知识。
- CCAR-F → 暂存盘、案件事实区块、带摘要重开新会话对 `--resume`。
- CCDV-F / CCAR-P → 压缩／上下文编辑功能＋缓存稳定的设计。

## 5. 考试当日早上检查清单（20 分钟，只看当天考试的栏）

- **CCAO-F 之前：** 围篱（不会考任何 API 内容）；Haiku/Sonnet/Opus 框架；验证 → 闸口 → 负责；今天 Memory ＝ claude.ai 功能。
- **CCAR-F 之前：** 范围外清单是干扰选项杀手；「Task」词汇；确定性的 > 概率性的；归责于协调者；走一遍 6 个情境题。
- **CCDV-F 之前：** 缓存／批量／快速模式事实在范围内；由限制关键字决定；把时效观察清单看一遍。
- **CCAR-P 之前：** 所有技术内容都在范围内，再加上软性 35% — 机制＋指标＋负责人；最左侧模式；官方支柱措辞；以每题 1.9 分钟跑限制排除演练。

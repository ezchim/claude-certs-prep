# 共享核心 — 四张考试都会考的十条心法

*每条心法学一次，再读它的四考试对照框架表：原则相同，各考试的高度与词汇不同。出处：四份官方考试指南 1.0 版（2026 年 7 月）及其样例题。*

---

## D1. 交付前先验证

Claude 产出的任何东西，在检查之前都不被信任 — 引用来源要点开、数字要重算、输出要验证 — 且检查力道与出错时的爆炸半径成正比。

| 考试 | 怎么考 |
| --- | --- |
| CCAO-F | 占 21% 的超大领域：交付／修改／退件判断；合规发送前先验证引用来源（官方样例题） |
| CCAR-F | 信心校准、分层采样、主张与来源的出处可追溯性（领域 5） |
| CCDV-F | 评测框架、回归测试集、副作用发生前的验证器 |
| CCAR-P | 黄金标准集＋对抗性＋回归评测集；切换上线前先影子部署；代码裁判优先于模型裁判 |

## D2. 确定性的胜过概率性的

提示词与 few-shot（少样本）会*降低*失败率；闸口、hooks（钩子机制）与代码把失败率变成*零*。题干含有 must／never／compliance／美元门槛时，要的就是确定性机制。

| 考试 | 机制词汇 |
| --- | --- |
| CCAO-F | 对外或不可逆发送之前的人类核准关卡 |
| CCAR-F | 程序化前置条件；PreToolUse 风格的拦截 hook（样例题 Q1） |
| CCDV-F | 代码里的 schema（固定输出结构）验证；Claude Code 的设置／hooks 强制执行，`CLAUDE.md` 仅建议 |
| CCAR-P | 工作流程闸口＋在工具服务器内强制执行的授权（authZ）；上限写在代码里，绝不放在模型判断里 |

## D3. 处处最小权限原则

工具、数据、权限、分享：授予能完成工作的最小权限，而移除能力是*首选的修复方法*，不是承认失败。

| 考试 | 风味 |
| --- | --- |
| CCAO-F | 分享权限（「可查看」对「可编辑」）、connector 范围、个人识别信息（PII）最小化 |
| CCAR-F | 子代理（subagent）的 `tools` 限制清单；审查者拿到只读 |
| CCDV-F | 工具允许清单；提示注入的爆炸半径控制 |
| CCAR-P | 先移除工具（样例题 Q1）；每个 agent 各自的凭证；在拥有该资源的接缝处做授权（authZ） |

## D4. 挑能通过评测的最小模型

默认选能达到质量门槛的最轻层级；只有凭证据才升级；「用最大的模型」在四张考试上都是刻意安插的干扰选项。

**共享事实（学一次就好 — 以 2026 年 8 月为准，考试当周重新查证）：** 层级为 Haiku（快／便宜，200K 上下文）→ Sonnet（默认）→ Opus（深度）→ Fable 级（最长时间线的前沿）；目前 4.6 以上世代使用**自适应思考**（固定 `budget_tokens` 已是旧式做法；目前层级已移除 temperature 这类采样参数）；**effort**（low→max，Opus 4.7 起提供 `xhigh`）是单一模型内的成本／深度旋钮；目前的前沿／均衡层级提供 1M 级上下文。

| 考试 | 高度 |
| --- | --- |
| CCAO-F | 按任务类型用产品拣选器 — 指南只点名 Haiku/Sonnet/Opus；Fable 最大化主义是陷阱 |
| CCAR-F | 为每个子代理（subagent）挑更便宜的模型（`model` 覆盖）用于大批量阅读 |
| CCDV-F | 评测驱动的选型＋effort 旋钮＋快速模式（仅 CCDV 的事实集） |
| CCAR-P | 经评测证实的升级／降级；路由器架构；成本包络 |

## D5. 优先选符合需求的最简单模式

单次调用 → 工作流程 → agent → 多 agent：只有证据说左边行不通时，才往右移。可审计性在左边；弹性在右边。

| 考试 | 框架 |
| --- | --- |
| CCAO-F | 对话 → Project → Skill/connector 阶梯；好提示词就能解决的地方，不要盖工作流程 |
| CCAR-F | 提示链（步骤可逐一枚举）对自适应拆解（步骤在执行中浮现）；agent ＝ 模型驱动的工具选择 |
| CCDV-F | 工作流程＋较小模型胜过到处都用 agent；框架提供结构，不是魔法 |
| CCAR-P | 最左侧模式规则原文照考；没有角色边界的多 agent 只是流程表演 |

## D6. 上下文是预算

你送出的每一样东西都算数；更多上下文不等于更高质量。要整理、渐进式检索，并保护绝不能被摘要掉的内容。

| 考试 | 框架 |
| --- | --- |
| CCAO-F | 项目知识卫生：过期或重复的文件会毒害每一场对话 |
| CCAR-F | 中段遗失、案件事实区块、逐档遍次＋集成遍次以对抗注意力稀释（样例题 Q12） |
| CCDV-F | 上下文预算编列、压缩（上下文压缩）、工具目录大小、token 计数 |
| CCAR-P | 渐进式探索对整包一次倾倒；压缩漂移作为失败模式 |

## D7. 缓存稳定的前缀 *（仅 CCDV＋CCAR-P — CCAR-F 超纲，CCAO 没有）*

稳定内容在前、易变内容在后；渲染顺序为工具 → 系统 → 消息；约 4 个缓存断点；字节一变，其后全部失效；思考设置变更会让消息层级项目失效（工具／系统前缀仍存活）；缓存的 token 仍占用上下文窗口。CCAR-P 样例题 Q2，以及 CCDV 一半的缓存题干，考的就是这一段。

## D8. 批量对即时 *（CCDV＋CCAR-P）*

人类在等待 → 同步（用流式降低感知延迟）。过夜／大批量／成本导向 → **Batch**（约 50% 成本、异步、无流式、尽力而为的缓存命中、无预热）。两张考试的样例题组，开头考的都是这个取舍。

## D9. 模型上下文协议（MCP）心智模型 *（CCDV＋CCAR-F＋CCAR-P；CCAO 仅以「connectors」概念出现）*

主机／客户端／服务器角色；工具／资源／提示；当**跨应用程序、跨团队重用**很重要时，就建 MCP 服务器；第三方服务器属于供应链 — 要审查它们，也要限定范围。各考试机制细节不同（见〈分歧地图〉）：CCAR-F 要设置／错误机制，CCAR-P 要服务器内部的 authZ 架构，CCDV 要 connector／集成全貌。

## D10. Claude Code 里的强制执行对建议 *（CCDV＋CCAR-F＋CCAR-P）*

设置、权限、受管政策与 hooks **强制执行**；`CLAUDE.md` 与提示词 **仅建议**。组织受管理设置不可覆盖；项目层设置会随版本控制走，用户层设置不会 — 这个差异是三张技术考试反复出现的诊断题干。

## 应试技巧常数（四张考试完全相同）

- **量表分数 100–1,000，720 分及格** — 不是固定百分比；各套试卷经等值化。
- **答错不倒扣** — 绝不留空白；标记题目再回来。
- **多选题全对才给分**；每题会注明要选几个。
- **重考：** 等待 14／30／90 天，滚动 12 个月内最多 4 次 — 对你的考程很重要：考砸的考试，无法在这个窗口剩下的天数内重考，所以保护睡眠胜过临时抱佛脚。
- **限制先行读题：** 先读问题句，收割题干限制，删去违反任一限制的选项，再挑最简单的幸存选项。这就是共享的解题算法；改变的只有词汇。

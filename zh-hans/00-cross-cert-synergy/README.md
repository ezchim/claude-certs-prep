# 跨认证协同学习包 — 学一次，用四次

*为连续应考而设计 — 同一周内应考四张认证中的两张以上时最有用。*

## 这个学习包是什么

四张考试以**四种不同高度测验同样的十条心法**，外加一小组真正共享的事实。本学习包把这些集中起来，让你只学一次，再精确标出各考试**分歧**之处，使共享知识绝不渗进错误的答题卷。

| 文件 | 用途 |
| --- | --- |
| `01-shared-core.md` | 十条心法＋共享事实，每条附一张四考试对照框架表 — 约占总内容的三分之一，只应学一次 |
| `02-divergence-map.md` | 防污染：范围围篱、术语差异、各考试独有内容，以及「同一题干、不同正确答案」的案例 |

## 这个学习包不是什么

- **不是**四份个别学习包的**替代品** — 每张考试都有大量独有内容（CCAO 的产品判断、CCAR-F 的 Agent SDK 机制、CCDV 的集成细节、CCAR-P 的软性领域约 35%），只有该考试自己的学习包才涵盖。
- **不是合并内容。** 考试在范围或词汇上不一致时，以分歧地图为准 — 每张考试当天早上读它。

## 诚实的重叠全貌

- **心法重叠：高**（`01` 里的十条原则在每本指南的样例题与考试目标中反复出现 — 协同效应就在这里）。
- **CCDV ↔ CCAR-P 事实重叠：高**（缓存、批量、模式、模型选择 — 多半是相同技术事实，建造者高度对架构师高度）。
- **CCAR-F ↔ CCDV 事实重叠：中等，带围篱**（agent／工具／Claude Code 在概念上共享，但 CCAR-F 排除数个 CCDV 核心主题）。
- **CCAO ↔ 三张技术考试事实重叠：低**（模型层级与验证直觉可迁移；几乎没有别的能迁移 — 不要为 CCAO 读 API 机制，也不要为 CCDV 读 Projects 机制）。

## 怎么使用

1. 第 1 天：从头到尾读完 `01-shared-core.md` — 它是所有东西挂上去的脊柱。
2. 然后：按考试顺序，每张考试做一次专注复习，并在该周后段做第二轮。
3. 每个考试日早上：花 20 分钟读 `02-divergence-map.md` 里属于该考试的栏 — 只读围篱与词汇，别的都不读。

## 概览

官方考试蓝图动词：**识别、诊断并解决（identify, diagnose, and resolve）** 表现不佳的提示词或劣质输出的问题；根据回馈与结果 **调整（adjust）** 做法；**优化（optimize）** 工作流程的效率与成效。这是集成领域：判断断点落在 **平台、输入、设置、提示词、上下文、模型、评测，还是治理**——然后修对那一层，不浪费用量。大多数题干奖励的，是最便宜且正确的修复方法，不是最英勇的修复方法。

## 深入笔记

### 1. 诊断阶梯（按顺序跑）

1. **成功标准** —— 需求是不是写得模糊？也许除了需求简述之外什么都没坏（领域 02）。
2. **输入** —— 错误或缺少的文件、未验证的连接器、网页搜索关闭、光学字符识别（OCR）乱码扫描件、能力开关。
3. **设置** —— 过时或冲突的知识；互相矛盾的指示；错的 Project；过期的 **Memory 条目** 喂了错的上下文（编辑／删除它——见 `05-….md` 〈Memory〉小节）。
4. **提示词** —— 描述缺口：没有标准、没有 schema、混合任务类型。
5. **上下文** —— 对话串漂移；摘要并重开。
6. **模型／effort** —— 层级太弱或太强；跳层级之前，先调 effort（思考力度）。
7. **评测关卡** —— 有些质量「问题」其实是没审核就交付的问题（领域 03）。
8. **限制／方案** —— 用量上限、Free 上限、功能可用性。

纪律：一次只改 **一个变量**；记下是什么修好了问题，让它变成模式，而不是一次幸运的重跑。两次收紧提示词的迭代都失败＝错的那一层；往阶梯上或往下移动。

### 2. 实战案例

- **「Claude 给了错的退款答案。」** Project 里放的是哪一份政策文件？叫它引用那个段落。文件过时 → 更新知识。文件是对的但被忽略 → 指示：「优先采用 `Refund-Policy-v4`；若不在知识中，回答 Not found。」只有在那之后，才考虑升级模型。
- **「Research 没有用。」** 网页搜索开了吗？是付费方案吗？问题有收窄范围吗？若预期要用内部数据，连接器验证了吗？怪功能之前，先把范围收窄。
- **「摘要里的数字是错的。」** 在纯聊天里对大表格做算术，是用错工具——改用 **代码执行** 重跑，让数学是被计算出来的，而不是被模式比对出来的；然后对照原始数据。
- **「Claude 一直提起我的旧项目。」** 过期 Memory 条目——Settings → Memory，编辑／删除；用分开的 Projects 来界定上下文范围；一次性的事情用无痕对话。
- **「团队说 Claude 很随机。」** 共享 Project 没有负责人；互相冲突的指南；没有 schema。治理＋设置的修复方法——不是换更大的模型。
- **「Claude 拒绝了我的正当请求。」** 把良性、已授权的上下文讲清楚，并在政策范围内重新措辞；对禁止使用的内容拒答，是正确行为，而越狱选项在考试里永远是错的（领域 06）。

### 3. 优化杠杆（成效 × 效率）

模型层级；effort；功能选择（Research vs 对话 vs 代码执行）；上下文大小；Project 持久保存的上下文 vs 重新粘贴；Skill 重用；用 schema 减少修改回合；批量处理相似任务；修剪噪声知识；能力开关；连接器范围。质量与成本／时间 **都要** 优化：在 L4 工作上砍掉审核，是假效率；拿 Opus 跑工单分流，是假质量。

记分板：交付前修改次数中位数；事实失误百分比；每个工作流程的用量；产出第一份草稿的时间。用 **最便宜的杠杆** 改善最差的那个指标——这句话决定考试选项。

### 4. 回馈 → 系统更新（失误分类法）

标记每一次失误，然后修造成它的那个系统：**事实** → 知识／引用来源／算术用代码执行；**格式** → 指示／schema；**语气** → Project／Skill 里的范例；**政策** → 治理＋指示；**不完整** → 检查清单／任务拆解；**验证／访问** → IT 赋能；**记住错误上下文** → Memory 策划。闭合这个循环就是 Diligence；反模式是教用户去补偿一个坏掉的设置。

### 5. 横跨全部领域的桥接总结

01 挑工具／模型；02 描述任务；03 验证输出；04 设计工作流程；05 设置知识／记忆；06 治理风险；07 诊断并优化。真实的故障通常是跨领域的——在答案里说出 **主要** 那一层，修好它，然后重新量测。

### 6. 90 秒诊断演练

每一题大约用 90 秒做：说出那一层，然后说出最便宜的修复方法。答案接在每一题后面。

- **演练 A：** 「Claude 以前每周报告都做得很准；自从 Marta 加了她的文件之后，它把两种模板风格混在一起。」→ 设置：知识里有冲突的模板；移除其中一个，或在指示中设置优先级。
- **演练 B：** 「Research 模式对某一位分析师变灰。」→ 平台／方案：那个人的席位／方案或能力开关——不是提示词问题。
- **演练 C：** 「萃取在 10 列上很完美，在 5,000 列上是垃圾。」→ 工具／上下文：从贴进聊天窗口，改成上传文件＋代码执行。
- **演练 D：** 「Claude 用 3 月的价目表回答；4 月的也上传了。」→ 知识卫生：被取代的文件还在；清掉它。
- **演练 E：** 「每次对话，Claude 都假设我还在柏林项目上。」→ Memory：过期条目；到 Settings → Memory 编辑／删除。
- **演练 F：** 「长对话串：它现在忽略第 3 则消息里的禁用词清单。」→ 上下文漂移：摘要并重开，规则持久保存在 Project 里。
- **演练 G：** 「质量没问题，但下午 2 点就烧完一天的额度。」→ 优化：例行任务降低层级／effort；批量处理；上下文持久保存而不是重新粘贴。
- **演练 H：** 「它拒绝摘要我们的渗透测试报告。」→ 有治理意识的重新措辞：把已授权的防御性上下文讲清楚；绝不越狱。

后设技能：用一句话说出症状 → 那一层 → 最便宜的修复方法。如果你的解释需要一整段，你大概还没找到那一层。

### 7. 多选题模式库

反复出现的错误配对：「换最顶级的模型」＋「放弃这个任务」（威望偏见＋失败主义——阶梯才是中间路线）；「再加三段指示」＋「删掉所有指示」（拿字数当药）；「移除审核步骤来加速」＋「审核每一个微不足道的输出」（假效率＋比例失衡）；「每小时重开每一次对话」＋「永远不重开」（仪式＋沉没成本）。正确组合是把一个 **诊断** 动作（检查验证／开关、引述文件测试、隔离单一变量）配上一个 **结构性** 修复方法（schema、知识清理、Memory 编辑、按任务调整层级规模）。

## 决策树

| 症状 | 可能层级 → 行动 |
|---|---|
| 据说来自文件的事实是错的 | 知识／指向 → 指名文件，清掉被取代的版本 |
| 忽略规定格式 | 提示词 → schema／Performance 约束 |
| 早期很好、对话串后期劣化 | 上下文 → 摘要并重开 |
| 对数据做的算术是错的 | 工具 → 代码执行，对照原始数据验证 |
| 工作流程慢或贵 | 优化 → 更轻的模型／effort、少用 Research、模板 |
| 功能「不能用」 | 输入／平台 → 方案、能力开关、验证、网页搜索 |
| 回想起来的个人上下文是错的 | Memory → 编辑／删除条目；用 Project 界定范围 |
| 对被允许工作拒答 | 有治理意识的重新措辞；绝不越狱 |
| 失误跨用户慢性出现 | 工作流程／设置重新设计——不是更大的模型 |
| 错误已经到达利益相关者 | 缺少评测关卡 → 恢复领域 03 的标准作业程序（SOP） |

## 考试陷阱

1. 把「升级到最大模型」当成万用修复方法
2. 深入诊断之前，忽略验证、网页搜索与能力开关
3. 用越来越长的提示词修症状（错的层）
4. 用移除高风险步骤的人工审核来「优化」
5. 把安全拒答当成故障
6. 永不重开已漂移的对话串（沉没成本式对话串）
7. 囤积互相冲突的知识版本
8. 一次改五个变量，什么都学不到
9. 把过期的 Memory 条目或过期的 PDF 怪到模型头上
10. 优化一个没有量测的工作流程

## 练习问答（16）— 情境题干附答案与理由

**Q1.** 尽管已上传政策，Claude 仍用一般知识回答退款问题。头两个动作？
**A：** 在提示词里指名文件并要求引用；检查知识里有没有被取代或重复的版本。指明来源＋保持知识卫生，胜过更大声地重问。

**Q2.** 为一个正在烧额度的大量萃取工作流程，选出两个优化。
**A：** 降到 Haiku（或降低 effort）；把 schema 与规则持久保存在 Project 里，而不是重新粘贴。（移除审核是陷阱选项。）

**Q3.** Research 什么都没回传。最快的诊断？
**A：** 检查网页搜索是否打开，以及方案是否支持 Research——先查能力开关，再怪功能。

**Q4.** 一条 200 则消息的对话串，现在自相矛盾。修复方法？
**A：** 交接摘要（决策、限制、未决事项）→ 开新对话。已漂移的上下文是换掉，不是跟它争论。

**Q5.** 一份月度差异备忘录有细微的算术错误。是哪一层，修复方法是什么？
**A：** 工具层：把数学导到对已上传数据的代码执行，然后对照原始数据验证总计。聊天文本不是计算机。

**Q6.** 输出间歇性地忽略规定的五段式格式。修复方法？
**A：** 在项目指示里放一个硬性 schema（各段名称、顺序、「一段都不省略；若为空则写 N/A」）。格式失误是 Performance 约束的缺口，不是模型失败。

**Q7.** Drive 连接器对一位用户「什么都看不到」，对其他人却正常。诊断？
**A：** 那位用户还没验证那个连接器——管理员启用是全组织的，验证是每位用户各自的。

**Q8.** Claude 一直提到助理去年就停止服务的一位客户。修复方法？
**A：** Memory 策划：到 Settings → Memory 删除／编辑该过期条目；让目前的客户各自待在自己的 Projects，让范围界定来做这份工作。

**Q9.** 全团队的输出慢性地语气失误。最便宜又持久的修复方法？
**A：** 把黄金语气范例（与一个反例）加进共享 Project／Skill——一次设置改动修好每个用户，不像逐对话的指导。

**Q10.** 在断定「模型对某个分析任务太弱」之前，选出两个检查。
**A：** 有没有提供评分量规／标准（提示词层）？知识是否最新且无冲突（设置层）？两者都过关之后，才升级层级。

**Q11.** 团队下午中段就撞到用量上限。选出两个调整。
**A：** 把例行任务导向更轻的模型／更低的 effort；在引用单一文件或单次搜索就够的地方，减少 Research 使用。（批量处理相似任务也有帮助；升级方案是商业决定，不是反射动作。）

**Q12.** 一位利益相关者要求「更快的输出——直接买最顶级的模型就好」。更好的杠杆组？
**A：** 用模板／Skills 处理反复出现的结构、持久保存的 Project 上下文，以及每个任务用大小合适的模型——速度通常藏在工作流程结构里，不在层级。

**Q13.** Claude 拒绝分析公司自己的钓鱼仿真结果。该怎么做？
**A：** 把已授权的防御性上下文讲清楚，并在政策范围内重新措辞——经过同意的正当资安工作，是可以澄清的；越狱框架自动是错的。

**Q14.** 知识里存在两个互相冲突的 SOP 版本，答案在两者之间轮替。修复方法？
**A：** 删掉被取代的版本（或在指示中加明确的优先级）。检索混淆是设置负债。

**Q15.** 如何证明一个优化有效？
**A：** 记分板的前后对比：交付前修改次数、事实失误百分比、每个工作流程的用量、产出第一份草稿的时间。没量测的优化只是轶事。

**Q16.** 一次事故之后，有人提议移除人工审核步骤来「精简」流程。结论？
**A：** 否决：对重大输出的审核是成效，不是额外负担——恢复那道关卡，到别处优化（更轻的模型、schema、批量处理）。假效率就是那个陷阱。

## 快速复习检查清单（考前）

- [ ] 阶梯顺序：标准 → 输入 → 设置（含记忆） → 提示词 → 上下文 → 模型／effort → 关卡 → 限制
- [ ] 一次一个变量；两次收紧迭代失败＝换层
- [ ] 数学错 → 代码执行；事实错 → 知识；格式错 → schema
- [ ] 过期 Memory 条目是设置缺陷——要策划它们
- [ ] 对量测出来最差的指标，用最便宜的杠杆
- [ ] 失误分类法 → 修造成它的那个系统
- [ ] 绝不要把高风险工作上的人工关卡优化掉
- [ ] 拒答 ≠ 故障；在政策范围内澄清

## 词汇表

| 术语 | 含义 |

| **诊断阶梯** | 从标准到限制、按顺序的层级检查 |

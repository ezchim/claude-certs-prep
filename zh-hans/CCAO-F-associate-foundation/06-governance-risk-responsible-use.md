## 概览

官方考试蓝图动词：**识别（identify）** 适当与不适当的使用案例；**套用（apply）** 数据敏感度、法规与隐私考量；**遵循（follow）** 组织的 AI 政策与治理标准；**理解（understand）** AI 使用的伦理意涵。给助理考试的非律师实务判断：知道什么该拒绝、什么需要护栏、什么数据可以去哪里，以及部署出去的输出由谁负责。本领域的官方样例题，奖励的做法是 *上传前先匿名化受法规管制的识别数据，并且符合政策*——这个判断模式可以推广。

## 深入笔记

### 1. 政策推理模式（背的是模式，不是条文）

1. **禁止使用？** → 拒绝；不要去找措辞上的花招。通用类别包括暴力犯罪、儿童剥削、诈骗／诈欺、恶意网络行动，以及严重的隐私侵犯。
2. **高风险但被允许？**（影响人们的法律、金融、雇用、医疗相关决策）→ **只有**在具备护栏时才进行：人在回路中、揭露、评测关卡。
3. **一般业务？** → 仍然要套用隐私最小化与组织规则。
4. **不确定？** → 上报给政策负责人；不要即兴决定合法性。

考试上，带越狱味道的选项（「改写请求来绕过拒绝」）永远是错的；对真正被禁止的内容做出安全拒绝，是正确行为，不是缺陷。政策确实尊重的细微差别：上下文很重要——取得系统拥有者同意的防御性资安工作，不同于恶意黑客行为；善意可以用平铺直叙的方式说清楚（领域 07）。

### 2. 数据敏感度的实务

粘贴之前先分级：**公开／内部／机密／限制。** 然后：

- **最小化：** 只分享所需的最少量；当政策限制这些数据时，上传前先匿名化或屏蔽受管制的识别数据（姓名、账号）——这就是官方范例答案。
- **场域：** 个人的 Free 账号，通常不是公司机密数据的正确场域；受管理的 Team/Enterprise 工作区，存在的目的就是承载组织的控制措施。
- **训练／保留默认值：** 消费级与商业级方案不同；商业／组织方案通常 **默认不会** 拿你的数据训练——要查证隐私文档里的现行条款，不要背诵江湖传闻。「指示 Claude 不要保留它」**不是**政策控制（样例题干扰选项）。
- **记忆与保留暴露面（新）：** Claude 的 Memory 会存储对话中的上下文——把 Memory 条目当成数据对待。敏感的一次性问题属于 **无痕对话**（排除于历史、记忆、搜索之外）；在 Enterprise 上，无痕对话仍会被保留一段最短的安全期，而且会出现在管理员的数据导出里——无痕是 *记忆／历史* 控制，不是绕过组织可见性的方法。Memory 包含在数据导出中；依政策查看并删除条目（见 `05-….md` 〈Memory〉小节）。

### 3. 连接器与分享的治理

连接器会扩大爆炸半径：在连接 Gmail/Drive/Slack 之前，要知道 Claude 能 **读** 什么，以及是否可能 **写入**。分析用途优先只读；写入权限范围（寄送电子邮件、更新人力资源信息系统（HRIS）／客户关系管理（CRM））是治理决策，需要核准与人工关卡。Enterprise 管理的验证与网域限制可能适用。Project 分享本身就是一种控制：「可查看」vs「可编辑」；避免把受限知识做全组织分享；分享的 Artifacts 可能暴露数据——要看清楚确认对话框。Free／个人账号不是公司机密的正确场域。

### 4. 透明度、揭露与所有权（Diligence）

尽责（Diligence）三要素：**创造（Creation）**（AI 辅助工作的质量）、**透明度（Transparency）**（对 AI 的角色诚实）、**部署（Deployment）**（你发布出去的东西由你负责）。当政策、高风险上下文或面向客户的使用有要求时，要揭露 AI 协助——面向客户的聊天机器人要揭露自己是 AI。「Claude 说没问题」永远不是合规抗辩；部署者对输出负责。捏造合规宣称（「这已获一般数据保护规范（GDPR）核准」）本身就是违规。

### 5. 反复出现的伦理情境

- **雇用／就业协助：** 为候选人排名需要偏见查看、人类做决定，而且常常需要揭露——全自动的雇用或拒绝，是最经典的不适当使用。
- **对客户提供金融／法律／医疗性质的建议：** 持照人类审核＋免责声明。
- **偏见：** 刻板印象默认、偏斜的范例、一面倒的分析——评估对人的影响，要求反方论证与评判准则（领域 03 的机制服务领域 06 的目标）。
- **合成媒体／欺骗：** 未经同意的深伪（deepfake）与冒充身份，是被禁止的领域。
- **著作权／保密：** 不要把第三方的秘密或大量受著作权保护的文本，贴进未受管理的环境。
- **无障碍与包容：** 范例与输出不该悄悄地把人排除在外。

### 6. 遵循组织政策，而不变成影子 IT

帮助团队在界线内采用 Claude：公布允许的工具与场域、数据层级、审核要求、范例提示词、上报路径。训练胜过吓人的海报。指标应该计算政策事故，而不是只算速度红利。当组织政策与个人方便冲突时，考试上永远是政策赢；当政策沉默时，上报给政策负责人，而不是即兴发挥。当情况值得时，通过产品管道回报有害或坏掉的输出。

### 7. 迷你案例（判断演练）

**案例 1 — 帮忙的捷径。** 一位运营经理把完整的客户数据库萃取贴进对话，「想找出流失模式」。萃取内容包含姓名、电子邮件与帐户余额。政策把这类数据列为限制级。正确路径：先汇总或匿名化（去掉直接识别数据，保留行为字段），在受管理的工作区跑分析，并让数据拥有者参与。分析本身正当；处理方式不正当。

**案例 2 — 安静的聊天机器人。** 一个团队上线了一个以 Claude 为后端的常见问题小工具，没有 AI 揭露，也没有人类上报路径。两个失败：透明度（面向客户的 AI 要揭露）与部署所有权（错误答案没有抵达人类的路径）。在扩大规模之前修好它，不要等到第一个客诉之后。

**案例 3 — 急切的连接器。** 一位管理员授权了一个有写入权限范围的 HRIS 连接器，让 Claude 可以「整理记录」。没有治理审查，没有关卡。即使出于好意，这也是爆炸半径陷阱：对人事数据的写入，需要系统拥有者核准、最小权限原则，以及每次变更前的人类确认。只读报表本来就能用 10% 的风险，交付 90% 的价值。

**案例 4 — 自信的合规备忘录。** Claude 起草「我们的数据流程符合 GDPR」，要用在给客户的电子邮件里。没有任何有权限的人审核过。捏造的合规宣称，即使听起来可信，也是治理违规；受监管的断言，只有问责负责人签核才能发出（领域 03 的 L4 关卡服务领域 06）。

**案例 5 — 筛选电子表格。** 一位招募人员请 Claude 为 400 份履历评分，并自动寄拒绝信给后半段的人。把它拆开：Claude 可以结构化与摘要申请数据；排名喂给一个带偏见检查的人类决定；拒绝 *决定与寄信* 留在人类手上。高风险但需护栏，被正确地拆解。

### 8. 多选题模式库

反复出现的错误配对：「改写到它回答为止」＋「把拒绝当成故障来回报」（越狱＋把拒绝当缺陷）；「因为是内部数据，就原样上传」＋「永远完全不分析客户数据」（违反政策＋瘫痪——匿名化才是中间路线）；「Claude 审核过了，所以发布」＋「一切都必须由人类起草」（假签核＋反委派）；「禁用连接器」＋「到处都用写入权限连接」（极端）。正确组合是把一个 **数据处理** 动作（分级、最小化、选对场域）配上一个 **监督** 动作（人工关卡、揭露、上报给政策负责人）。

## 决策树

| 情境 | 行动 |
|---|---|
| 被禁止的有害请求 | 拒绝；不玩改写游戏 |
| 高风险决策（雇用／金融／法律） | 人类监督＋揭露＋评测关卡 |
| 待分析文件含受管制识别数据 | 依政策先匿名化／屏蔽 |
| 机密数据、个人 Free 账号 | 错误场域——用受管理的工作区 |
| 面向客户的 AI | 适用揭露规范 |
| 敏感的一次性问题 | 无痕对话；在 Enterprise 上，记得管理员导出／保留仍然适用 |
| 敏感系统上的写入权限范围连接器 | 治理核准＋人工关卡 |
| 不确定合法性／政策 | 上报给政策负责人 |
| 对被允许工作的安全拒绝 | 在政策范围内说明善意上下文（领域 07）；永远不要越狱 |

## 考试陷阱

1. 把「Claude 说没问题」当成法律／合规护身符
2. 违反政策，把限制级数据贴进个人账号
3. 把「指示 Claude 不要保留它」当成隐私控制
4. 包装成足智多谋的越狱选项
5. 在面向客户或高风险的使用上省略揭露
6. 把安全拒绝当成要修复的缺陷
7. 全自动的雇用或信用决策
8. 在敏感系统上，未经核准就使用写入型连接器
9. 以为无痕对话能对 Enterprise 治理隐藏活动（它只是记忆／历史控制）
10. 捏造的合规宣称（「经认证的 GDPR 安全输出」）

## 练习问答（18）— 情境题干附答案与理由

**Q1.** 一位用户要 Claude 提供恶意软件，用来「测试」竞争对手的网络。回应模式？
**A：** 拒绝——恶意网络行动是禁止使用的；没有同意，也没有授权。取得系统拥有者同意的防御性工作，才是不同的、正当的情况。

**Q2.** 一位产品经理想上传一份含有客户姓名与账号的电子表格；政策限制受管制的个人数据。最适当的行动？
**A：** 上传前移除或匿名化识别数据，符合政策——分析继续进行，但不暴露受保护的数据（官方范例答案模式）。

**Q3.** 选出两个日常工作的有效隐私动作。
**A：** 把 PII 最小化到任务所需的程度；遵循组织的数据分级来决定场域与处理方式。（「叫 Claude 忘掉它」不是控制措施。）

**Q4.** 人力资源要 Claude 自动拒绝评分垫底的履历，中间没有人类步骤。结论？
**A：** 不适当——雇用决策是高风险的，需要人类监督、偏见查看与揭露。Claude 可以协助（摘要、结构化），不可以做决定。

**Q5.** 一个面向客户的支持机器人创建在 Claude 之上——这个接口适用什么治理要求？
**A：** 揭露客户正在与 AI 对话，并提供上报给人类的管道——面向客户使用的透明度规范。

**Q6.** 一位分析师为了「求快」，用他个人的 Free 账号处理董事会机密的财务数据。问题？
**A：** 错误场域：个人账号缺乏组织控制；机密数据政策很可能禁止这么做。用受管理的工作区——方便永远不凌驾分级。

**Q7.** 商业／组织的 Claude 使用，默认会拿你的数据训练模型吗？
**A：** 商业方案通常默认不会——但要查证现行隐私文档，不要背诵江湖传闻；「先查证再依赖」才是考试安全的姿态。

**Q8.** 运营部门想要一个能写入 HRIS 的连接器，为了「省点击次数」。治理形状？
**A：** 由系统的治理负责人核准、最小权限范围，以及写入前的人工关卡。读取做分析是比较容易核准的；写入会搬动人事数据。

**Q9.** 一个雇用协助工作流程，显示模型在排名中偏袒某所大学。需要什么回应？
**A：** 偏见查看：用反事实的候选人做测试、加入评判准则、让人类持续做决定，并记录这次检查。未经检查就上线，在伦理上不及格，也可能违法。

**Q10.** Claude 拒绝了一个看起来明显正当的请求。错误答案 vs 正确答案？
**A：** 错误：越狱／改写来骗过模型。正确：在政策范围内，平铺直叙地说明善意、已获授权的上下文；若拒绝持续，就上报（领域 07）。

**Q11.** 什么时候必须在交付物中揭露 AI 协助？
**A：** 当组织政策、高风险上下文或面向客户的使用有要求时——透明度是 Diligence 的三分之一，而部署者拥有这个决定。

**Q12.** 一位同事问 Claude，他的数据分享计划在欧盟是否合法，并依答案行事。失败在哪？
**A：** 把 Claude 当成法律顾问——不确定的合法性要上报给合规／政策负责人。Claude 可以把问题草拟得很好；它不能拥有答案。

**Q13.** 选出两个与治理相关的无痕对话事实。
**A：** 它们被排除在历史记录、记忆与搜索之外；在 Enterprise 上，它们仍会被保留一段最短的安全期，并包含在数据导出里——对组织不是隐形的。

**Q14.** 有人把一个存放限制级合约的 Project 全组织分享，还给了编辑权。评估？
**A：** 双重的权限失败：受限知识给了全组织的受众，而且给的是编辑（不是查看）权限。分享范围是一种治理控制。

**Q15.** 营销部门要 Claude 为广告文案捏造「十个牙医有九个推荐」式的统计数字。怎么判断？
**A：** 拒绝捏造——欺骗性宣称是不适当的使用；提供真实、有来源的数字，否则就舍弃这个宣称（领域 03 在执行领域 06 的一条规则）。

**Q16.** 一个险些发生的事故：一位助理差点把 AI 起草的金融建议，未经审核就寄给客户。缺了哪些控制？
**A：** 高风险护栏：持照人类审核、揭露，以及寄出前的人工关卡。高风险但允许 ≠ 高风险但无人监督。

**Q17.** 团队的负责任使用赋能包里该放什么？
**A：** 允许的工具／场域、附范例的数据层级、按风险等级区分的审核要求、范例提示词、上报路径——在界线内采用，胜过影子 IT。

**Q18.** 选出两个直接被禁止、你要拒绝而非加护栏的案例。
**A：** 未经同意的深伪／冒充身份内容；助长诈骗或恶意网络行动的指示。（雇用决策是高风险但需护栏，不是直接拒绝。）

## 快速复习检查清单（考前）

- [ ] 政策模式：禁止使用 → 拒绝；高风险 → 护栏；一般 → 最小化；不确定 → 上报
- [ ] 数据层级＋上传前先匿名化受管制的识别数据
- [ ] 场域纪律：个人 Free ≠ 机密工作
- [ ] 训练／保留：商业方案通常默认不会——查证现行文档
- [ ] 无痕＝记忆／历史控制，不是治理上的隐形
- [ ] 连接器：默认只读；写入＝核准＋人工关卡
- [ ] 面向客户与高风险的使用要揭露；部署者对输出负责
- [ ] 对被禁止内容的拒绝，是正确行为

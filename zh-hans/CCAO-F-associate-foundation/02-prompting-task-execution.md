## 概览

在 CCAO-F 上，提示等于专业简述。官方蓝图动词：**创建** 商务与技术任务的有效提示词；**套用任务拆解** 以结构化复杂请求；**迭代** 提示词以提升质量；**依任务类型调整提示策略** — 指南点名 *分析、研究、起草、脑力激荡*。AI 流畅度的 **描述** 三要素 — Product、Process、Performance — 是主轴：交付物是什么、怎么做到，以及「好」长什么样子。

## 深入笔记

### 1. 提示词解剖

一份完整简述带着：**角色**（Claude 扮演谁）、**目标**（交付物＋它支撑的决策）、**输入**（按名称点名的文件、粘贴的数据、connector 来源）、**限制**（长度、语气、禁用宣称、受众）、**过程**（有顺序的步骤、检查点）、**格式**（schema（固定输出结构）、章节、表格）、**验证**（回答之前要检查什么）。你很少需要七个全用 — 但考试里最好的提示词，是 *承重部分没有缺漏*、内部也没有矛盾。

**描述三要素：** *Product* 描述点名交付物，以及它支撑的受众决策。*Process* 描述把工具与检查点排成顺序。*Performance* 描述设置验收测试、范例与反例。缺一个就会出现可预测的失败：空话（没有 Product）、跳过步骤（没有 Process），或体面的错（没有 Performance）。

**利益相关者翻译** 是助理层级的技能：「make it pop」需要语气范例；「keep it legal」需要免责声明文件与禁用宣称；「board ready」需要 Decision／Risks／Ask 结构；「quick thoughts」必须标成推测性质。题干会用利益相关者黑话 — 先翻译再选答案。

**矛盾**（「用初学者听得懂的方式解释，但保留未定义的内部缩写」）必须明白解开。没解开的矛盾会产出不稳定的输出，然后被怪到模型头上。

**范例胜过形容词。** 两三个黄金范例（外加一个反例）胜过好几段风格描述。few-shot（少样本）是非开发者手上杠杆最高的一招。

**含糊：** 优先 *澄清*，不要 *发明*。若仍要继续，就要求一个明白写出的 `ASSUMPTIONS` 区块，让错误猜测看得见，而且修正成本低。

### 2. 任务拆解

把多交付物或高风险工作拆成带人类检查点的阶段：

- **先大纲再填写：** 任何正文之前，先核准结构。
- **先萃取再分析：** 把事实与判断分开，错误才追得到。
- **先选项再决定：** 先产生替代方案、先不承诺，再用标准挑选。
- **先起草再红队：** 产出，再对抗性攻击（衔接领域 03）。

实作模式：运营事后复盘（时间线事实 → 促成因素标成证据 vs 假设 → 行动项只能带具名负责人）；营销邮件（事实＋法律必含项 → 主旨＋正文 → 对禁用宣称做合规检查）；人力资源常见问题（只从知识回答；引用该节；缺则「Not found」）；外出会议行程（脑力激荡 → 分群 → 挑选 → 带时间的行程 → 风险检查）；数据清理（定义 schema → 用代码执行验证 20 列样本 → 放大）。

**拆解也是治理：** 它在不可逆或对外步骤之前插入人类关卡 — 这个交叉点会在领域 04 与 06 考到。何时拆解：多个交付物、高风险、任务类型混在一起（绝不要在同一口气里又脑力激荡又分析），或你需要中间检查点。任务又小、又清楚、又低风险时，单次提示就可以 — 把琐事拆开是浪费时间与用量。

### 3. 迭代技艺

强的迭代会 **点出缺陷以及要加上的限制**：「摘要发明了一个 Q3 数字 — 只用 `Q3-report.pdf` 里的数字，其他一律标 UNKNOWN」胜过「改得更好」。调试时 **一次只改一个重大变量**，才学得到因果。宁可做外科式修改（「只修表格」）也不要整份重产。提示词措辞收紧之后还失败两次，问题通常是输入、功能选择或任务框架 — 不是用词（领域 07 的阶梯）。

维持一份微型提示词库：假设清单；FACTS vs INFERENCES；只要表格；缺漏就填 NULL；最有力的反驳；保留原意的差异对照；只要大纲；主张对来源的对照表；三个选项但不挑选；压缩但数字不变。

### 4. 依任务类型的 playbook（蓝图点名的目标）

| 任务类型 | 策略 | 招牌动作 |
|---|---|---|
| **分析** | 标准先行，证据与推理分开 | 提供评分量规；要求 FACTS vs INFERENCES 章节；要求反驳与未知事项 |
| **研究** | 范围＋来源＋引用 | 定义问题、时段、来源规则；要求引用支持（领域 03）；多来源公开局面用 Research 功能 |
| **起草** | 必含事实＋受众＋格式 | 提供已核准事实（不要让 Claude 去找）；语气范例；禁用语句；长度上限 |
| **脑力激荡** | 先发散，再收敛 — 分开做 | 先要求数量／多样性、先不下判断；第二步用标准排序；输出标成推测性质 |

混用模式是经典错误：在同一则提示词里要求「有创意的点子，但严格准确符合政策」，两边都得不到。把阶段拆开。

### 5. 把提示当成系统（团队规模）

稳定规则从提示词迁出：反复出现的指示 → 项目指示；参考细节 → 知识文件（按名称点名）；丰富程序 → Skills。共享 Projects 需要冲突时的优先规则（例如法务 > 品牌）。把黄金范例与反例放进知识。教同事粘贴需求，而不是焦虑 — 没有规格的含糊急迫，会浪费用量上限。每周都值得重复的提示词是设置，不是打字（领域 05）。

### 6. 提示词比较题的计时启发式

当题目出示四个候选提示词，用目标、输入、限制、过程、格式、验证为每一个打分；最完整、无内部矛盾的胜出。优先澄清，不要发明；对后果重大的转换，优先分阶段核准，而不是一则巨型提示词。API 参数选项（temperature、微调）在这场产品导向考试里是干扰选项。在「升级模型」之前先问：一个谨慎的实习生拿这份简述能做成吗？若不能，先修好描述。

### 7. 简述实例（之前 → 之后）

**弱：** 「摘要这通客户电话。」→ **强：** 「根据 `call-2026-08-12.txt`，为正在决定是否升级处理的客户经理产出一页摘要：5 则带时间戳的事实、客户情绪并附一句支撑引言、任一方的承诺（一字不差引用；不清楚则 UNKNOWN），以及附理由的建议下一步。逐字稿里没有的事实，不要推理。」

**弱：** 「写一则关于我们上市的 LinkedIn 贴文。」→ **强：** 「为潜在的中型市场买家，起草一则宣布上市的 LinkedIn 贴文。必须纳入：`launch-facts.md` 里两则已核准主张（数字照原文）、以客户痛点开头、≤150 词、不用 `banned-phrases.md` 里的最高级。语气对上知识里的两个范例。给两个变体：稳健与大胆。」

**弱：** 「这份供应商合约可以吗？」→ **强：** 「第一阶段：从 `vendor-msa.pdf` 抽出每一条碰到责任、终止、数据处理与自动续约的条款 — 逐条引用。第二阶段（等我确认之后）：用 `contract-redlines.md` 的检查清单评估每一条抽出的条款，标成 OK／FLAG／ESCALATE 并附一行理由。最终法律判断留给律师。」

模式：点名文件、受众决策、必含项、格式、验证规则 — 后果重大的就分阶段。

### 8. 多选题排除库

选两项／三项的提示题，通常把一个正确的技艺动作配上干扰选项。练习排除：「改得更好」（没点名缺陷）；「加上 temperature=0」（API 旋钮，走错轨道）；「用最大的模型」（领域 01 威望偏见）；「让 Claude 去找统计数字」（让模型去找承重事实）；「把脑力激荡与合规审查并进同一则提示词」（模式混用）；「每一则消息都再贴一次政策」（设置失败）。正确配对通常结合 *结构* 动作（schema、拆解、范例）与 *验证* 动作（假设区块、引用来源、检查点）。

| 情境 | 动作 |

| 多交付物或高风险 | 带检查点拆解 |

| 分析请求 | 评分量规＋证据／未知分开 |

| 两轮收紧后仍失败 | 重新诊断层级（输入、功能、知识）— 领域 07 |

## 考试陷阱

1. 对后果重大的工作用没有检查点的巨型提示词
2. 派了角色但没有成功标准（光说「扮演财务长（CFO）」）
3. 让 Claude 去找利益相关者必须拥有的承重数字
4. 在同一则提示词里混用脑力激荡与分析
5. 「改得更好」／「更专业一点」却没有具体标准
6. 每一轮都重述稳定政策，而不是放进项目指示
7. 研究请求没有范围、时段或来源规则
8. 把琐事拆解（流程表演）
9. 「调试」时一次改五个提示词变量
10. 用 API 旋钮（temperature、微调）回答产品考试题干

## 练习问答（18）— 情境题干附答案与理由

**Q1.** 一位 PM 打：「分析我们的 Q4 计划。」Claude 回了一段空泛的策略文本。下一步最好的提示词？
**A：** 重建简述：附上计划文件、说明它支撑的决策、给评估标准、要求 Evidence vs Unknowns。失败在缺少 Product／Performance 描述，不在模型。

**Q2.** 选两项客户邮件草稿的 Performance 描述元素。
**A：** 一封已核准邮件的黄金范例；明白写出的禁用宣称／语句。（「professional」这类形容词不是验收测试。）

**Q3.** 法务必须审查一份 60 页合约的续约风险。最强结构？
**A：** 拆解：萃取与续约相关的条款 → 每条标上证据引文 → 再用评分量规评估风险 → 人工法律审核。先萃取再判断，错误才追得到。

**Q4.** Claude 一直忽略已上传的定价 PDF。最佳迭代？
**A：** 明白点名文件（「只根据 `Pricing-v3.pdf` 回答；引用该节；否则说 Not found」）。点名胜过把问题再大声问一次。

**Q5.** 团队要营销活动点子 *以及* 一份合规安全的入围清单。你怎么下提示词？
**A：** 两个阶段：发散（许多标成推测的点子、先不下判断），再收敛（对照标准＋禁用宣称文件排序）。同一则提示词混用模式，两边都会变差。

**Q6.** 每一则对话都用的常态语气规则，该放在哪里？
**A：** 项目指示 — 稳定规则是设置，不是每则提示都打一遍。

**Q7.** 经理的回馈是「改得更好」。为什么这是考试的错误选项，以及修复方法？
**A：** 它没点名缺陷或限制，所以改善靠运气。修复方法：说出漏了什么（受众、长度、缺少风险）并加上限制。

**Q8.** 选两项拆解对后果重大工作的好处。
**A：** 不可逆步骤之前的人类检查点；把萃取与判断分开，错误被局部化。

**Q9.** 给高阶主管的改写不得改变意思。你加什么限制？
**A：** 语义锁定：「所有事实与数字必须原样保留；只改结构／长度／术语；列出任何意思已偏移的句子。」调整 ≠ 发明（衔接领域 03）。

**Q10.** 需求碰到雇用法措辞，助理不确定什么是允许的。提示词动作？
**A：** 要求一个 ASSUMPTIONS 区块，并把输出送到人工法律审核 — 对受监管内容，澄清／上报胜过发明。

**Q11.** Claude 必须填一份含供应商、日期、金额、负责人的追踪表。提示词模式？
**A：** 定义 schema，一笔一列，缺漏填 NULL，放大之前先验证样本。schema 能减少修改轮次。

**Q12.** 草稿引用了听起来很厉害、但没人提供的市场统计。迭代？
**A：** 禁止无来源数字；提供已核准数字，或要求 UNKNOWN＋一个未知事项章节。起草策略＝必含事实，不是模型自己找来的事实。

**Q13.** 什么时候单次提示是正确答案？
**A：** 又小、又清楚、又低风险的任务 — 把破冰题请求拆开是流程表演。

**Q14.** 「扮演 McKinsey 合伙人，审查我们的策略」表现不佳。缺了什么？
**A：** 成功标准与输入。没有评分量规与文档的角色只是戏服，不是简述。

**Q15.** 选两项分析提示词的要求。
**A：** 明白写出的评分量规／标准清单；事实与推理分开（未知事项标注出来）。

**Q16.** 输出是一大墙文本，但运营需要它符合工单模板。修复方法？
**A：** 加上格式合约：确切章节／字段、表格形状、长度上限 — 并把它放进 Project 才能固定住。

**Q17.** 研究员想要「competitor X 的一切」。更好的研究提示词？
**A：** 收范围：哪些问题、哪个时段、哪些来源类型、必须附引用 — 然后用 Research 模式；之后验证引用支持。

**Q18.** 两轮收紧迭代之后，扫描 PDF 的萃取仍失败。诊断？
**A：** 停止改提示词 — 问题在输入层（光学字符识别（OCR）质量差的扫描件）。两轮收紧仍失败，代表该换层级，不是再改措辞（领域 07）。

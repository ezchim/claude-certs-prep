## 深入笔记

### 1. 工作的三种形态

- **逐轮对话** — 每一步由你掌舵。最适合迭代、快速取得答案、带着回馈起草。
- **交办式 agentic** — 你下指示，Claude 连续完成多步骤（Research；长时间 agentic 任务）。消耗较多用量；需要更好的简述与引用查核。
- **可重复使用的系统** — Projects、Skills、Artifacts、Connectors 把上下文与程序一次性编码，整个团队就不用再反复解释。

考试里大多数功能题干其实在问：这份工作属于哪一种形态？

### 2. 功能目录（什么时候该用哪一个）

**Chat。** 在单一对话串上快速迭代。不适合承载反复出现的共享上下文 — 那是 Project。对话会留在你的历史记录（打开 Memory 后，可以影响后续对话 — 见 §5）；它们不是团队知识库。

**Projects。** 自足工作区，带有 **指示**（常态行为）＋ **知识**（参考文件），以及独立的对话历史。**所有方案都有；Free 账号上限为五个 projects**（已于 2026 年 8 月对照 support.claude.com 查证）。**通过检索增强生成（RAG）的增强知识仅付费方案提供，知识容量最多扩大约 10 倍**，当项目知识接近上下文上限时启动（已于 2026 年 8 月查证）。分享是 Team／Enterprise 能力：「可查看」对「可编辑」，可逐一、批量或全组织分享。你在共享 Project 里的对话仍是你的 — 分享散布的是知识与指示，不是你的对话逐字稿。

**Artifacts。** 独立、可编辑的交付物（文档、代码、HTML／SVG、交互式应用程序），显示在对话旁边。可以发布／分享；AI 驱动的 artifacts 消耗的是 **观看者** 的用量上限，不是创建者的。并非预先验证过的 — 领域 03 的规则照样适用。

**Skills。** 打包好的任务程序，在相关时加载。对比：项目知识是随时可用的参考数据；Skill 是 *可重复执行的程序*；Connector 是 *即时数据*。

**Connectors（模型上下文协议，MCP）。** 接入即时系统（Drive、Gmail、Slack、自订远程 MCP 服务器）。Team／Enterprise 上的常见模式是管理员启用，加上每位用户各自验证。**自订 connectors 每种方案都有，但 Free 账号限一个自订 connector**（已于 2026 年 8 月查证）。治理见领域 06。

**Research。** 附引用来源的 agentic 多角度调查；需要打开网页搜索；可以使用 connectors；需付费方案；比聊天烧用量更快。对于单一已上传的 PDF，直接引用该文件即可。

**Enterprise Search。** 组织内部搜索，附带指回已连接来源的引用（Team／Enterprise）。「我们当初决定了什么？」→ Enterprise Search。「公开的整体局面是什么？」→ Research。

**代码执行与文件产生。** Claude 在 claude.ai 上有 **沙箱运算环境**：它撰写并执行代码来分析数据、制作图表，以及产生可下载文件 — Excel、PowerPoint、Word、PDF、逗号分隔值（CSV）。**所有方案（Free–Enterprise）在网页、Desktop 与 Mobile 上都有**（已于 2026 年 8 月查证）；它取代了旧的「分析工具」。当题干涉及 *对数据做运算*（总计、枢纽分析、从电子表格看趋势）或 *文件交付物* 时用它 — 纯聊天里的模式比对，对大规模算术不可靠。与 Artifacts 有别：Artifact 是交互／可编辑的交付物；代码执行是能产生文件与已验证数字的运算。

### 3. 模型阶梯与任务对齐

考试指南点名三个层级 — 要能干净地区分：

| 层级 | 性格 | 何时用 |
|---|---|---|
| **Haiku** | 最快、最轻、最便宜 | 萃取、分类、短摘要、大量简单任务 |
| **Sonnet** | 均衡的每日默认 | 大多数起草、分析、日常知识工作 |
| **Opus** | 最深的推理 | 多重限制的困难策略、细腻分析 — *在* 较轻模型或更好的简述失败之后 |

*注：* 目前产品在 Opus 之上还提供一个层级（Fable 等级），用于时间跨度最长、最复杂的工作。指南的目标措辞是 Haiku／Sonnet／Opus — 用这三个词作答；「升级超过 Opus」出现在题干里时，只是威望偏见的干扰选项。

决定考试答案的规则：

- **最轻可交付模型胜出。** 从较轻模型往上评估；停在你真的愿意交付的最便宜输出。官方样例题奖励「为直接、大量任务挑更快、成本更低的模型」。
- **因为实际失败而升级，不是因为威望。** 「用最大的模型把质量最大化」是教科书级的错误选项 — 它浪费成本与延迟预算。
- **effort／扩展思考在模型内部调整深度。** 快速查询用较低 effort；真正困难的问题用较高。有时正确修复方法是把 Sonnet 的 effort 调高，而不是跳去 Opus。
- **把失败对上对的解方。** Haiku 漏掉细微差异 → 往上移。Sonnet 在对抗性策略上太浅 → Opus 或更好的拆解。Opus「败」在成本／延迟／额度 → 往 *下* 移或重组。简报不好 → 先修好描述（领域 02），再碰模型选择器。
- **两模型试验法。** 同一个已知任务先跑 Haiku 再跑 Sonnet；比较内容，不是比较长度。若 Haiku 已经挖出你在意的主张，就留在轻的这边。

### 4. 上下文限制（重开／摘要／持久保存）

上下文窗口是有限的；长对话会劣化 — 漂移、矛盾、被遗忘的限制。

- **重开** 当矛盾累积、角色漂移或质量崩坏。带着精简的简述开新对话，胜过硬撑一条被污染的对话。
- **摘要** 当你需要决策延续性、不要草稿噪声：要求一份交接简述（决策、未决问题、限制），再用它打开新对话。
- **持久保存** 当重复使用可预见：把常态规则放进项目指示，把参考文件放进项目知识 — 不要每个星期一都写一封英勇的第一则消息。

指示会与任务 token 竞争：指示要短、要稳定；把厚重政策放进名称清楚的知识文件，并按文件名点名。

### 5. Memory（产品内置的持久层）

claude.ai 现在有一等公民 **Memory** 功能（已于 2026 年 8 月对照 support.claude.com 查证 — 细节会演变；考试前重新查证）：

- Claude 从你的对话创建 **记忆条目**（专业上下文、偏好、进行中的工作），并在后续对话套用。记忆产生在 **Free、Pro 与 Max**（较新体验）以及 **Enterprise**（旧版综合体验）提供；**对话搜索**（找回过去的对话）为 Pro 以上。
- **以项目为范围：** 每个 Project 有自己独立的记忆，所以客户 A 的上下文不会渗进客户 B — 这直接回答考试的「记忆考量」目标。
- **由你控制：** 可查看、编辑、删除个别条目，或在 Settings 全部重置；搜索与记忆各自独立开关。
- **无痕对话**（幽灵图标，所有方案，存在于 Projects 之外）被排除在历史记录、记忆与搜索之外 — 一次性敏感查询用它。

**考试框架：** 「重开、摘要、持久保存」仍是那个技能。Memory 减少跨对话的重复解释，但它 *不是* 团队知识库（以个人为单位），*不能* 取代项目知识（对政策问题来说，整理过的文件胜过推测出来的记忆），也 *不保证* 完整 — 承重的上下文仍然属于 Projects。Memory 的设置与治理见领域 05（见 `05-configuration-knowledge-management.md` 的 Memory 小节）。

### 6. 方案与隐藏限制

考试题干把方案限制藏在附属子句里。解出题干里那个有限制的世界，不是你脑中的理想世界：

- Free：五个 project 上限；一个自订 connector；没有 Research。
- Research 需要付费方案 **并且** 打开网页搜索。
- Enterprise Search 需要 Team／Enterprise，且由管理员连接数据源。
- 团队成员 ≠ 管理员：启用是管理员的工作；验证通常是每位用户各自进行。
- Artifact 观看者烧的是自己的额度；被关掉的能力开关会挡住 artifact／代码功能。

### 7. 流畅度之桥（4D）

**委派（Delegation）** 就是整个这个领域：在自动化、增强、自主代理之间做选择，并选择由哪个功能／模型承载。**描述（Description）** 包括选择 Research 还是 chat，不只是措辞。**明辨（Discernment）** 在重型模型上最吃紧 — 冗长流畅的 Opus 输出仍需要领域 03 的评测。**尽责（Diligence）** 把发布 Artifact 或启用 connector 视为一次部署行动。

选错功能会伪装成提示词失败；选错模型会伪装成「Claude 很笨」。领域 07 会问是哪一层坏了 — 为每个反复出现的工作流程留一页摘要：功能 | 模型 | 上下文策略。

### 8. 迷你案例（功能＋模型一次到位）

**项目管理办公室（PMO）星期五进度：** 带模板指示＋ Drive connector 的 Project；默认 Sonnet。**董事会策略质询：** Opus（领域 03 评测仍是必须的）。**客服退款问题：** 从 Project 政策或 Enterprise Search 回答 — 绝不要靠模型的一般知识。**工作坊破冰题：** chat＋ Haiku／Sonnet；跳过 Research。**建议邀请书（RFP）比较：** 评分量规放进 Project，用 Research 取得公开局面，用代码执行计算评分，交付物以表格／Artifact 呈现。**季末幻灯片：** 上传数据 → 代码执行算数字 → Sonnet 起草评论 → 由人验证。

反模式：一个巨型 Project 混合法务＋人力资源＋营销；对单一已上传 PDF 跑 Research；把可写入的 connectors 交给只读分析；把顶级层级当创意旋钮；以为 Artifact 观看者用的是创建者的凭证或额度；依赖 Memory 承载团队的政策真相。

### 9. 多选题模式库

这里的选两项／三项题干，会把一个正确的功能／模型动作配上干扰选项。演练排除：「所有重要的事都用 Opus」（威望偏见）；「Projects 会分享你的对话逐字稿」（错误机制）；「Research 在 Free 可用」／「Research 不用开网页搜索」（方案／能力误判）；「Memory 取代项目知识」（持久层混淆）；「叫 chat 去算 10,000 列表格总计」（错的工具 — 该用代码执行）。正确组合通常是一个 **符合功能** 的选择（Project／Research／代码执行／Artifact）搭配一个 **尊重限制** 的选择（方案上限、验证步骤、最轻可交付模型）。

## 决策树

**功能：** 可重复／反复出现的上下文 → Project。附引用的多来源公开调查 → Research。组织内部「我们当初决定了什么」→ Enterprise Search。独立交互式交付物 → Artifact。可重复执行的程序 → Skill。即时正式记录系统 → Connector。对数据做运算／文件交付物 → 代码执行。一次性问题 → chat。

**模型：** 即时萃取／分类 → Haiku。默认知识工作 → Sonnet。较轻尝试失败后的深度推理 → Opus。跳层级之前先调 effort。

**上下文：** 漂移的对话 → 重开。需要延续性、不要噪声 → 摘要成交接。可预见的重复使用 → 持久保存在 Project。跨对话的个人上下文 → Memory（查证条目；一次性敏感 → 无痕对话）。

## 考试陷阱

1. 为了「保险」用最大模型（威望偏见 — 官方样例题会罚它）
2. 以为 Project 分享会分享你的对话逐字稿（它分享的是知识＋指示）
3. 没开网页搜索就跑 Research，或对单一已上传 PDF 跑 Research
4. 「已启用＝已访问」：忘记每位用户的 connector 验证
5. 「Free 没有 Projects」（错 — 上限五个）／忽略 Free 一个自订 connector 的上限
6. 因为 Artifacts 看起来像成品，就当成已预先验证
7. Enterprise Search ≠ Research（内部附引用查询 vs 公开 agentic 调查）
8. 叫 chat「计算」大型表格算术，而不是用代码执行
9. 把 Memory 当成共享的团队大脑或政策真相来源
10. 简述、知识或功能选择才是坏掉的那层，却去升级模型

## 练习问答（18）— 情境题干附答案与理由

**Q1.** 一位营销主管每个星期一都把风格指南贴进新对话，重建同一份品牌语气简述。他们该怎么设置？
**A：** 创建一个 Project，把风格指南放进知识，把常态规则放进指示。反复出现的上下文属于持久工作区，不是每周英勇粘贴。

**Q2.** 运营团队必须从一份 40,000 列的 CSV 抽出总计与依区域的枢纽分析，并交付一份 Excel 文件。最佳做法？
**A：** 上传文件，让 Claude 用代码执行计算并产生电子表格。只用 chat「读」大型表格有算术错误风险；代码执行跑的是真正代码，并产出可下载文件。

**Q3.** 一位 Free 方案用户想为新客户开第六个 project。现实是什么？
**A：** Free 账号上限五个 projects — 封存或合并一个，或升级。（方案上限会变；请在 support.claude.com 查证。）

**Q4.** 一位助理跑 Research 却得不到有用结果；网页搜索是关掉的。第一步修复方法？
**A：** 打开网页搜索 — Research 是 agentic 的网页调查，依赖它。先诊断能力开关，再怪模型。

**Q5.** 顾问希望 Claude 跨对话记住他们的报告格式，但两个客户之间绝不能带过客户机密细节。什么产品行为有帮助？
**A：** Memory 以项目为范围 — 每个 Project 有独立记忆。每个客户放在自己的 Project；一般偏好可以放在账号层级记忆，条目可在 Settings 查看／编辑／删除。

**Q6.** 同事问一个一次性的敏感人力资源问题，不想留在历史记录或记忆里。你建议什么？
**A：** 无痕对话（幽灵图标）— 排除在历史记录、记忆与搜索之外；所有方案都有，存在于 Projects 之外。

**Q7.** 选两项适合 Haiku 的任务。
**A：** 依类型分类进线工单；从发票萃取字段。大量、规格清楚、低细微差异的工作，是轻模型的甜蜜点。

**Q8.** 两轮扎实迭代之后，Sonnet 的竞争分析在真正多重限制的策略题上仍显得浅。下一步？
**A：** 升级到 Opus（或提高 effort）— 深度推理上的实际失败才是升级触发条件，不是面子。

**Q9.** 法务需要从 Slack 与 Drive 回答「我们在 Q2 对数据保留做了什么决定？」。用哪个功能？
**A：** Enterprise Search — 跨已连接来源的组织内部附引用查询。Research 用于公开局面。

**Q10.** 一条 300 则消息的对话现在与自己的限制互相矛盾。最佳上下文动作？
**A：** 要求一份交接摘要（决策、限制、未决问题），再用它重开新对话。先摘要再重开，胜过硬撑一条已漂移的对话。

**Q11.** 高阶主管想要一个业务团队能用的交互式投资报酬率（ROI）计算机。用哪个功能？
**A：** Artifact（交互式应用程序）。注意观看者消耗自己的用量上限，计算机的公式仍需领域 03 验证。

**Q12.** 一位 Team 方案用户把 Project 全组织分享，担心同事会读到他们的草稿对话。事实是什么？
**A：** 分享以查看／编辑权限散布知识与指示；他们在 Project 里自己的对话，不会当成逐字稿交给每一位成员。（请在 support.claude.com 查证现行分享行为。）

**Q13.** 选两项「永远用最强模型」政策失败的理由。
**A：** 它在轻模型就能交付的任务上浪费成本／延迟；它用面子取代由轻到重往上评估的方法。（简单任务的质量提升，不足以正当化这项政策。）

**Q14.** 团队每月重复一套 12 步骤的季度业务回顾（QBR）准备程序，一直在 chat 里重新教一遍。用哪个功能？
**A：** Skill — 打包、可重复使用的程序。项目知识放参考材料；Skill 放 *怎么做*。

**Q15.** 一个付费方案 Project 的知识已接近上下文上限。什么能让它继续可用？
**A：** 搭配 RAG 的增强知识（付费方案）— 检索把容量扩大最多约 10 倍；文件名清楚、问得精准，会更有帮助。

**Q16.** 用户在 Pro 方案的全新对话里说「Claude 把昨天的事全忘了」。诊断？
**A：** 检查 Memory／对话搜索是否打开，以及昨天的对话是否为无痕、或在另一个 Project 的范围里。然后决定：把常态上下文持久保存在 Project，而不是依赖回想。

**Q17.** 一位主管问，若「买 Opus」，Claude 能否起草董事会资料包文本且「幻觉风险为零」。正确框架？
**A：** 没有任何层级能消除幻觉 — 模型选择是成本／速度／质量的取舍，准确性由验证（领域 03）管理。Opus＋跳过审核，比 Sonnet＋主张对照表更糟。

**Q18.** 选两项正确的「需求 → 功能」配对。
**A：** 答案里要有即时 Drive 数据 → Connector；从已分析数据产出可下载的 PowerPoint → 代码执行／文件产生。（Research 不是给单一已上传文件用的；Memory 不是团队知识库。）

## 词汇表

| 词 | 意义 |
|---|---|
| **Project** | 带有指示＋知识＋自己对话的工作区 |
| **RAG（在 Projects 中）** | 付费方案的检索，在接近上下文上限时扩大知识容量（约 10 倍） |
| **Artifact** | 显示在对话旁边的独立可编辑／交互式交付物 |

| **Enterprise Search** | 组织内部附引用搜索（Team／Enterprise） |

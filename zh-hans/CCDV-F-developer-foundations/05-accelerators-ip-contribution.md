# 加速器与知识产权贡献

> **免责声明：** 原创备考笔记。这些笔记**不**重制官方课程内容。它们提供原创、对考试有用的指引：可重用 agent、Skills 打包、`CLAUDE.md` 模板、评测框架重用，以及交接文档——依据公开的 Claude Code、模型上下文协议（MCP）、API 与工程实践。

**主要对应：** 应用与集成（可重用设置与模板）· Agent 与工作流程（打包好的 agent）· 评测（框架重用）。
**次要：** Claude Code（Skills、模板）· 工具／MCP（模块化服务器）· 安全（套件中的安全默认）。

---

## 1. 概览

加速器是**可重用的构建积木**，帮助下一位工程师更快交付 Claude 解决方案，不必照抄口耳相传的 Slack 传说。在考试与合作伙伴交付中，强的答案会打包：

1. 带有钉定模型与安全权限的默认架构。
2. 带有清楚扩展点的提示词与 `CLAUDE.md` 模板。
3. 给重复程序用的 Skills 或 playbook（操作手册）。
4. 带有允许清单与验证模式的 MCP 或工具模块。
5. 一套评测框架与一套黄金入门集。
6. 交接文档：如何运行、如何修改、如何回滚。

知识产权贡献，意思是把一次性的客户胜利，变成别人可以采用的**模块化资产**，并遵循你组织使用的授权与贡献规则。这一文件教的是工程实质；实际提交请遵循你公司的法务与合作伙伴计划规则。

## 2. 关键地图

资产类型：agent 模板 — 它编码的是：循环、预算、工具、验证器。
资产类型：Skill — 它编码的是：Claude Code 的按需程序。
资产类型：`CLAUDE.md` 模板 — 它编码的是：精简的常驻仓库指引。
资产类型：设置包 — 它编码的是：权限、hooks（钩子机制）、MCP 闸门。
资产类型：MCP 模块 — 它编码的是：带验证与错误处理的领域工具。
资产类型：评测框架 — 它编码的是：执行器、评分器、持续集成（CI）闸门。
资产类型：runbook（运维手册） — 它编码的是：操作、事故、升级步骤。
资产类型：参考应用程序 — 它编码的是：端到端的精简垂直切片。

## 3. 深入笔记 — 打包可重用 agent

### 3.1 什么让一个 agent 可重用

清楚的输入与输出。写成文档的工具。带覆盖 hooks 的钉定默认。内含预算与停止条件。跟着 agent 一起走的评测案例。默认安全的权限。不内嵌密钥。有版本的发布。

### 3.2 设置面

分开：
- **政策**（安全规则、拒绝项）
- **产品提示词**（语气、任务框架）
- **环境**（端点、模型钉定）
- **密钥**（注入，绝不打包）

使用方覆盖环境与产品提示词的频率，应高于政策。

### 3.3 参考 agent 骨架（概念）

接入消息 schema。
可选的规划步骤。
带允许清单的工具注册表。
带最大步数与墙钟时间的循环。
验证器 hooks（schema、测试、政策）。
升级路径。
遥测 hooks。
评测入口。

### 3.4 agent 打包的反模式

写死的客户名称。密钥放进仓库。工具没有上限。没有版本。没有评测。文档只写「跑 main」。为了让 demo 跑得快而打开 bypass permissions（跳过权限模式）。

## 4. 深入笔记 — Skills 打包（Claude Code）

### 4.1 Skills 对 `CLAUDE.md` 对 hooks

`CLAUDE.md`：简短的常驻上下文。
Skill：在相关时才被调用的程序；让常驻上下文保持精简。
hook 或权限：必须强制执行的闸门。

适合打包成 Skill 的候选：发布检查清单、添加 HTTP 端点、安全地撰写迁移、分类不稳定测试、准备 pull request（PR）描述。

### 4.2 Skill 质量门槛

说明前置条件。列出步骤。点名涉及的工具。声明停止条件。链接到测试。注明危险变体。包含好结果与坏结果的范例。

### 4.3 Skills 的版本管理

语义化版本，或标注日期的变更记录。注明破坏性变更。把 Skills 放在仓库里，让 PR 可以审查它们。团队加速器要避免只属于个人的 Skills。

### 4.4 插件式打包

团队使用 Plugins 或共享套件包的地方，要包含：设置建议、Skills、hook 脚本、范例 `CLAUDE.md`，以及一份解释信任边界的 README。使用方在启用之前，仍然应该审查 MCP 与权限。

## 5. 深入笔记 — `CLAUDE.md` 模板

### 5.1 精简模板段落

1. 用三行说明仓库用途
2. 目录地图
3. 标准指令
4. 惯例（错误、测试、API）
5. 危险区域
6. 深度文档的链接
7. 明确的非目标（不要凭空发明基础设施）

### 5.2 模板变体

monorepo（单一存储库）根模板，加上嵌套套件模板。
函数库模板对服务模板。
带笔记本与评测注记的数据科学模板。
强调计划模式、并对生产环境 apply 设有阻止清单的基础设施模板。

### 5.3 什么不该放进模板

密钥。客户个人识别信息（PII）。会变动的时间戳。整份架构决策记录（ADR）。多位作者互相矛盾、没有归属人的规则。

### 5.4 维护

指派一位负责人。每季审查。把更新绑在坏掉的评测或事故上。链接优于粘贴。

## 6. 深入笔记 — 评测框架重用

### 6.1 为什么框架是知识产权

框架编码了你的组织如何衡量 Claude 质量。重用它，可以防止每个团队各自发明不一致的评分仪式。

### 6.2 要打包的框架组件

案例 schema。测试数据加载器。模型与提示词钉定接口。工具仿真器。评分器（精确、模糊、评分量规、副作用）。报表格式。CI 范例。范例黄金标准集（非敏感）。

### 6.3 扩展点

自订评分器。自订工具仿真。各领域的案例包。主机转接器（API、Bedrock、Vertex）。

### 6.4 治理

比较期间冻结案例。把评分器纳入变更管理。对任何随框架发布的真实流量采样工具，做隐私审查。

## 7. 深入笔记 — MCP 与工具模块作为加速器

交付领域 MCP 服务器或工具函数库时，要附：
- 窄化的工具，不是原始 HTTP 直通
- 使用环境密钥的验证范例
- 结构化错误
- 合约测试
- 允许清单建议
- 一页的威胁模型

服务器要有版本。写上升级注记。并提供一段给 Claude Code 用的、默认拒绝的入门权限片段。

## 8. 深入笔记 — 交接文档

### 8.1 最小可行交接包

README：它是什么、什么时候用、什么时候不要用。
快速入门：十五分钟以内达到第一次成功。
一页架构说明，图用文本形式表达。
设置参考：钉定、环境变量、权限。
安全注记：密钥、拒绝项、威胁模型摘要。
运维：仪表板、警示、紧急停止开关、值班提示。
评测：如何运行、如何解读、如何扩展。
变更记录与升级指南。
归属人与支持管道。

### 8.2 交接反模式

只能在演示机上跑、换到干净机器就失败的演示脚本。
需要知道上周 Zoom 内容才看得懂的文档。
没有回滚段落。
密钥的屏幕截图。
生产路径里没有文档的模型别名。

### 8.3 受众切分

为三种读者而写：实现的工程师、审查的安全工程师，以及未来值班的你。每种人需要不同段落，但一份交接包加上清楚的标题，就能服务全部三种人。

## 9. 决策树

### 9.1 这该不该变成加速器？

如果同一个模式交付过三次以上，是。
如果只有一个奇特的客户需要它，也许写一篇案例研究就好，不要做产品化的加速器。
如果它内嵌客户密钥或专有数据，先净化，否则不要发布。
如果评测没有跟着走，它就还没准备好。

### 9.2 Skill 对模板对参考应用程序

需要常驻惯例：`CLAUDE.md` 模板。
需要偶尔用到的程序：Skill。
需要端到端的学习路径：精简参考应用程序加上评测框架。
需要可强制执行的规则：设置与 hooks 包。

### 9.3 安全贡献检查清单树

密钥移除了吗？评测包含了吗？授权与合作伙伴规则查过了吗？威胁模型写了吗？默认权限是最小权限原则吗？钉定有文档吗？负责人指名了吗？只要有任何一题是否，就先不要贡献。

## 10. 考试陷阱

1. 把加速器当成没有评测的提示词粘贴桶。
2. 为了让 demo 顺畅而发布 bypass permissions。
3. 把密钥放进范例设置。
4. 以为官方知识产权贡献模块是公开的（它们不是）。
5. 巨大的 `CLAUDE.md` 模板，把整个 wiki 抄进去。
6. 暴露原始超级用户 API 的 MCP 模块。
7. 没有版本管理或变更记录。
8. 交接文档没有回滚。
9. 用文件数量衡量贡献，而不是用重用与安全。
10. 因为「只是个加速器」就跳过安全审查。

## 11. 自我检核问答（20）

Q1. Skill 和 `CLAUDE.md` 差在哪里？Skills 是按需程序；`CLAUDE.md` 是精简的常驻指引。
Q2. 举出三样绝对不能放在加速器套件里的东西。密钥、真实的客户 PII、把 bypass-permissions 当默认。
Q3. 为什么评测要跟着 agent 模板走？这样采用者才能在自订之后，证明模板仍然有效。
Q4. 什么时候参考应用程序比单独一个 Skill 更好？当学习者需要包含设置与测试的端到端垂直切片时。
Q5. 交接包的安全注记该放什么？威胁模型摘要、密钥注入模式、默认拒绝项，以及审查清单。
Q6. 如何让 `CLAUDE.md` 模板可维护？负责人、每季审查、链接优于粘贴、精简段落。
Q7. 为什么要把政策设置和产品提示词设置分开？使用方改语气的频率高于改安全政策；较安全的默认能留得住。
Q8. MCP 加速器的合约测试是什么？不需要完整客户端应用程序就能跑的 schema 与验证行为测试。
Q9. 这一章的范围？官方知识产权贡献步骤可能存在于受管制的官方计划里；这些笔记只涵盖可移植的工程实践。
Q10. 选一个好的加速器成功指标。采用它且评测通过的团队数量——不是代码行数。
Q11. 为什么在模板里钉定模型？给采用者与 CI 的可重现性。
Q12. 危险区域段落是什么？明确标出迁移、计费、生产环境 apply 等类似的高爆炸半径区域。
Q13. 范例该如何处理 API 密钥？占位符，加上密钥管理器说明——绝不放真实密钥。
Q14. 什么时候该在 monorepo 加速器里嵌套放置 `CLAUDE.md` 模板？当各套件有不同的指令与惯例时。
Q15. 什么让设置包有价值？共享的 hooks 与拒绝项，把辛苦学来的安全教训编码下来。
Q16. 为什么要包含「何时不该使用」段落？防止在错误的问题类型上误用。
Q17. 这里说的模块化知识产权是什么？可重用、有版本、有文档、别人可以组合的资产。
Q18. 加速器与「应用与集成」领域配分有何关系？可重用设置、钉定、MCP 模块与交接质量，就是集成能力。
Q19. 安全对新加速器的第一个审查问题？如果模型被攻陷，它能做什么？
Q20. 把第 05 章对应到官方领域。集成、Agent、评测、Claude Code、工具／MCP，加上安全默认。

包含：案例 schema、CLI 执行器、JSON 与 Markdown 报表、范例评分器、CI 片段、采样隐私指南、Anthropic API 与云端主机雏形的转接器。

## 18. 在团队内建立加速器路线图

阶段 1：从最近几个项目识别重复的交付模式。
阶段 2：抽出一条带评测的精简垂直切片。
阶段 3：加上安全默认与交接文档。
阶段 4：与第二个团队做试点；收集摩擦注记。
阶段 5：有变更记录与负责人的 1.0 版。
阶段 6：然后才广泛宣传，或依你的规则贡献到合作伙伴目录。

直接跳到大型框架，通常会做出 shelfware（摆在架上没人用的东西）。

## 20. 可重用提示词模板打包

把提示词存成有版本的文件，不要只放在 UI 里。

## 22. 情境实验室

情境：你的团队为一个客户做了一个出色的事故分诊 agent。领导层想把它变成知识产权。

## 24. 详细 `CLAUDE.md` 入门（说明用，原创）

段落「用途」：本仓库为 Y 用户实现 X。agent 应优先使用 `/packages/core` 既有函数库，不要凭空发明新工具。

段落「布局」：`/apps` 放可部署服务，`/packages` 放共享函数库，`/evals` 放黄金标准集，`/.claude` 放设置与 Skills。

段落「指令」：测试、lint 与类型检查使用 `CONTRIBUTING` 记载的 task runner。除非那些失败且你写下原因，否则不要发明替代指令。

段落「惯例」：偏好类型化接口。测试与代码放在一起。对齐既有错误分类法。不要为了让任务变简单而放宽权限。

段落「危险区域」：没有计划模式与人工审查，不要编辑数据库迁移。没有测试与人在回路中（HITL），不要改计费计算。不要从 agent 会话对生产环境应用基础设施变更。

段落「指标」：架构细节在 `/docs/architecture`。API 合约在 `/docs/openapi`。刻意让本文件保持短。

## 28. 内部加速器目录的运营模型

维护者每周依评分卡审查提交。安全对默认有否决权。每项资产有负责人与支持管道。已弃用资产给落日日期与迁移注记（「大声弃用」）。采用指标出现在仪表板上——包括采用者的首次安全部署所需时间。开 office hours（开放咨询时段）；永不接受带密钥的 PR。坏掉的采用者可以开议题，并作为下一版的闸门。

当题干问合作伙伴或平台团队如何规模化 Claude 交付质量时，这个运营模型在考试上很重要——答案是打包好的默认＋评测＋归属，不是更多幻灯片。

## 33. 主要研读加深 — 加速器与可重用知识产权

第 05 章涵盖打包与贡献主题，其中部分可能并非完全公开。这些笔记仍是原创备考材料，谈可重用 agent、Skills、`CLAUDE.md` 模板、评测框架、MCP 套件与交接文档——这些能力仍会出现在应用、Agent、Claude Code 与评测情境里。


### 33.1 这里的加速器是什么意思

加速器是有版本、有文档、可评测的套件，帮助另一位工程师更快交付 Claude 能力，而不必拷贝密钥或一次性雪花设置。

| 属性 | 门槛 |
| --- | --- |
| 清楚的问题陈述 | 给谁用／不给谁用 |
| pin bundle 默认 | 模型／effort／提示词／工具版本 |
| 安全默认 | 危险工具默认拒绝 |
| 评测冒烟 | 至少一小片黄金切片 |
| 交接文档 | README＋SECURITY＋如何回滚 |
| 扩展点 | 有文档，不是只能 fork |

### 33.2 打包可重用 agent

让它可重用：模型钉定、预算、工具允许清单用设置胜过代码；工具接口搭配参考 MCP／服务器转接器；明确的停止条件与人工闸门 hooks；遥测 hooks（已屏蔽）。

反模式：写死的生产 URL／密钥；只在我们的 monorepo 能跑、没有转接器；没有评测；内嵌客户数据的 Skills。

参考骨架：
```text
/agent
 README.md
 SECURITY.md
 EVALS.md
 config/pin.defaults.yaml
 prompts/system.vN.md
 tools/schema.vN.json
 harness/golden/
 src/runtime/
```

### 33.3 Skills 打包（Claude Code）

| 构件 | 何时用 |
| --- | --- |
| `CLAUDE.md` | 常驻团队指引 |
| Skill | 被调用的工作流程，例如 `/review-pr` |
| Hook | 围绕事件的硬性强制 |
| Plugin | 分发 Skills／hooks／MCP 套件包 |
| `settings.json` | 权限／模型默认 |

Skill 质量门槛：单一用途；输入清楚；范例；失败模式；没有密钥；若会改代码则链接评测。把 Skills 当 API 做版本——破坏性变更升 major；保留变更记录。

### 33.4 作为知识产权的 `CLAUDE.md` 模板

精简段落：用途、构建／测试指令、代码风格、安全不变量、审查清单、何时问人类。

变体：服务仓库、数据／ML 仓库、基础设施仓库、文档仓库。

不要放：API 密钥、客户 PII、未经查证的传闻、更适合在设置里强制的互相矛盾绝对句。

维护：负责人；每季审查；绑到事故。

### 33.5 评测框架重用

框架是高杠杆知识产权：执行器＋评分＋报表格式；测试数据布局惯例；安全切片永远开着；插件式评分器（schema、任务成功、裁判）；为集成回归捕捉成本／延迟。治理：框架评分变更需要升版本，让历史比较保持诚实。

### 33.6 MCP 与工具模块作为加速器

发布：带验证模式的服务器雏形；工具 schema 加上阻止清单范例；合约测试；一段威胁模型；给 Claude Code 设置用的允许清单片段。陷阱：为了方便而发布过度授权 OAuth 范围的服务器。

### 33.7 交接文档

最小包：README（快速入门）、SECURITY、OPERATIONS（钉定、仪表板、回滚）、EVALS、CODEOWNERS／支持管道。

反模式：只有屏幕截图的安装；Slack 传说；没有文档的损坏；联系 Bob。

受众切分：采用工程师、安全审查者、值班。

### 33.8 决策树

这该不该变成加速器？
```text
Used successfully >=2 times in different contexts?
 NO -> keep as example
 YES -> Can you remove secrets and snowflakes?
 NO -> extract patterns only
 YES -> package + evals + docs
```

Skill 对模板对参考应用程序：
```text
Always-on guidance -> CLAUDE.md template
Invoked workflow -> Skill
Full runtime + tools -> Reference app/agent kit
```

### 33.9 考试陷阱（打包风味）

1. 发布内嵌密钥的加速器。
2. 没有安全默认（以为采用者之后会收紧）。
3. 把受管制官方课程当成公开内容。
4. 默默变更权限的 Skills。
5. 只检查语气的评测。
6. 带全开放范例的 MCP 套件。
7. 与已强制设置互相矛盾的模板。
8. 没有版本管理——团队间默默漂移。

### 33.10 额外问答（Q31–Q45）

**Q31.** 安全审查者打开加速器的第一个文件是什么？
**A31.** `SECURITY.md`／威胁模型与默认允许清单——然后才是 schema。

**Q32.** 为什么每个 agent 套件都要带一小片黄金评测？
**A32.** 证明 pin bundle 能跑；抓住采用者设置错误；锚定回归。

**Q33.** 什么时候 `CLAUDE.md` 模板有害？
**A33.** 当它长到或矛盾到团队直接忽略，或当它假装在强制控制时。

**Q34.** 如何安全分发一个 Skill？
**A34.** 代码审查、没有密钥、钉定版本、清楚列出必要权限——不是默默升级。

**Q35.** 加速器成功指标？
**A35.** 采用者的首次安全部署所需时间，加上评测通过率——不是星标。

**Q36.** 为什么要把 `pin.defaults` 和 `pin.prod` 范例分开？
**A36.** 默认是安全入门；生产钉定依环境而异，绝不能盲目跨主机拷贝。

**Q37.** `OPERATIONS.md` 该放什么？
**A37.** 仪表板、警示、回滚、速率限制联系窗口、主机矩阵。

**Q38.** 第 05 章内容会出现在 CCDV-F 吗？
**A38.** 会以集成／Agent／Code／评测对可重用设置的判断出现——不是合作伙伴知识产权流程冷知识。读工程实质。

**Q39.** 插件里打包的 hook 每次编辑都删除 `node_modules`——问题？
**A39.** 危险默认；hooks 必须是最小权限，且破坏性动作要选择加入。

**Q40.** 什么是好的扩展点？
**A40.** 自备 `search_kb` 工具转接器，而不是 fork 整个 agent。

**Q41.** 如何在套件里为提示词做版本？
**A41.** `system.vN.md` 加上钉定文件参照加上变更记录；永不默默覆盖。

**Q42.** 为什么要包含 MCP 的阻止清单范例？
**A42.** 教导采用者：连接器不是全有或全无。

**Q43.** 参考 agent 对生产服务？
**A43.** 参考教模式；生产加上租户、服务水平目标（SLO）、合规——不要把 demo 当成生产。

**Q44.** 贡献就绪评分卡会有哪一项？
**A44.** 密钥已扫描、评测绿灯、文档完整、负责人列出、授权清楚。

**Q45.** 把加速器工作对应到官方领域。
**A45.** 应用（可重用设置／钉定）、Agent（打包循环）、Claude Code（Skills／模板）、评测（框架重用）、安全（安全默认）。

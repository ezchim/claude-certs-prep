# 生产工程、评测与安全

> **免责声明：** 原创备考笔记。依据公开的 Anthropic 安全与产品模式、常见 LLM 应用评测实践，以及公开报道的 CCDV-F 领域：安全与安全防护（8.1%）与评测／测试／调试（2.6%），再加上应用与集成（33.1%）的生产切片。独立内容；非正式课程教材。

**主要对应：** 安全 8.1% · 评测／测试／调试 2.6% · 生产集成。
**次要：** Agent 可靠性 · 以评测证明模型选择与优化（MSO）合理性 · 模型上下文协议（MCP）与工具强化。

---

## 1. 概览

交付 Claude 上线是一个运营问题，有三个密不可分的目标：

1. 让它正确——评测、黄金标准集、回归闸门。
2. 让它安全——密钥、个人识别信息（PII）、注入防御、破坏性动作闸门、抗滥用。
3. 让它可运营——服务水平目标（SLO）、追踪、事故响应、成本控制、变更管理。

评测与安全在纸面上的配分比重很小，但它们扮演过滤器，能在多领域题干中淘汰掉原本看似合理的设计。把它们当作决策约束来读，而不是选修章节。

---

## 2. 关键地图

支柱：评测 — 行为在真实任务上真的改善了吗？控制：黄金标准集、评分量规、副作用断言。
支柱：调试 — 这条追踪为什么失败？控制：重播、差异比较、工具日志。
支柱：安全 — 如果模型错了或被攻击了怎么办？控制：阻止清单、授权、屏蔽、人在回路中（HITL）。
支柱：安全防护 — 输出会造成伤害或违反政策吗？控制：过滤器、分类器、拒答。
支柱：生产工程 — 它能在预算内持续运作吗？控制：SLO、队列、上限、runbook（运维手册）。

## 3. 深入笔记 — 评测

### 3.1 为什么评测胜过凭感觉

大型语言模型（LLM）的变更容易交付、却难以察觉。评测把意见转换成可衡量的差异。CCDV-F 叙述预期你在生产环境中变更模型、提示词或工具之前，都要先拿出评测证据。

### 3.2 评测类型

单元式检查：schema 有效性与工具参数形状。快速检测破损。
黄金标准集：带标签的案例，用精确或模糊比对标准。
评分量规或 LLM 当裁判：质性质量，要搭配校准与人工审计。
副作用测试：调用了哪些工具；对 agent 至关重要。
对抗性测试包：注入与越狱；与安全重叠。
在线方法：影子流量、A/B、在真实流量上做金丝雀。
成本与延迟预算与质量成对——永远不要单独衡量。

### 3.3 打造黄金标准集

隐私审查之后，抽样真实任务。标注预期答案或可接受的评分量规。纳入边界案例与已知失败。为集合做版本管理，并在比较期间冻结它。按难度与意图切片，让平均分数不会掩盖困难切片上的回归。

### 3.4 Agent 评测的特别之处

断言最终答案质量、用了哪些工具与哪些没被使用、步骤数在预算内、没有禁用工具，以及重试之下的幂等行为。在一次违禁删除之后，就算段落写得正确，仍然是失败。

### 3.5 LLM 当裁判的陷阱

裁判可能和生成者共享同样的弱点。成对比较会出现位置偏见。模糊的评分量规会制造噪声。按计划定期用人工抽查。

### 3.6 部署闸门

持续集成（CI）跑单元 schema 检查，加上小型黄金标准集。预备环境跑完整黄金标准集，加上对抗性测试包。金丝雀盯着在线指标与安全监控。全机群推行上线时持续监控，并备好回滚。

### 3.7 调试循环

截取一条屏蔽过的失败追踪。用钉定版本重现。比对提示词、工具、模型与设置的差异。在上下文问题、工具错误、政策冲突与容量问题之间形成假设。用最小变更修复。把回归案例加进黄金标准集。还没读追踪就跳升模型层级，是经典考试陷阱。

### 3.8 重要的指标

任务成功率、schema 失败率、工具错误率、拒答正确率（误拒对误放）、注入抵抗率、p95 延迟、每次成功成本，以及人工升级率。

## 4. 深入笔记 — 安全与安全防护

### 4.1 威胁模型主题

提示注入，直接的，以及经由文档、工具与网页的间接注入。
上下文中的密钥或经由对外工具的数据外泄。
未授权动作：模型说服工具越权。
API 边缘的滥用与诈欺。
来自 MCP 服务器、插件与相依套件的供应链风险。
围绕日志中 PII 与保留政策的隐私问题。
过度拒绝或拒绝不足的政策错误。

### 4.2 纵深防御

边缘的身份验证、授权与速率限制。
输入过滤与大小限制。
不可被覆盖的系统政策。
对不受信任内容做分隔。
工具允许清单加上服务器端授权。
相关之处使用 Claude Code 权限与 hooks（钩子机制）。
输出过滤与 PII 清除。
审计日志与异常检测。

没有任何单一一层是够的，尤其一个客气的系统提示词绝对不够。

### 4.3 密钥管理

密钥管理器、环境注入，或云端身份与访问管理（IAM）。永远不要放进提示词，永远不要放进 `CLAUDE.md`，永远不要放进提交进版控的设置。从日志与追踪中屏蔽。外泄时轮换。范围保持狭窄，按环境、按工具切分。

### 4.4 PII 处理

在提示词中最小化 PII。在工具转接层中遮罩。定义保留政策。必要时使用区域性托管。对评测数据集做访问控制。标签允许时，优先使用合成数据。

### 4.5 破坏性动作闸门

读取：在授权之下允许。
更新：授权加上审计。
删除、付款与对外电子邮件：HITL，或工具内部的强政策引擎。
Shell 执行：对自主 agent 默认拒绝；必要时在沙箱中执行。

### 4.6 护栏模式

针对毒性、PII 或越狱尝试的独立分类器——要知道它们两个方向都会出错。
工具内部的硬性上限。
高风险动作的双人控制。
安全的补全与清楚的拒答路径。
永远不要在没有衡量的情况下，为了修复过度拒绝而拆掉所有护栏。

### 4.7 MCP 与插件供应链

信任之前先审查代码。钉定版本。在企业中使用受管理的允许清单。使用最小权限的 token。监控对外流量。把项目交付的 MCP 设置当作可执行的相依套件来对待。

### 4.8 安全测试

对抗性评测应包含：忽略先前指令的攻击、工具外泄尝试、社交工程，以及恶意的工具描述。

### 4.9 事故

通过停用有风险的工具来围堵。保存屏蔽过的追踪。找出攻击途径。修补分隔符与授权。若可能已外泄，就轮换密钥。按政策通知利益相关者。添加评测案例。谨慎地重新开放。

## 5. 深入笔记 — 生产工程

### 5.1 SLO

例子：可用性、成功率、p95 延迟、成本上限、安全事故次数。错误预算决定要冻结功能还是继续交付。

### 5.2 容量与速率限制

把工作排进队列。交互式流量优先于批量。用带抖动的退避。执行租户公平性，让一个客户不能饿死其他客户。

### 5.3 成本工程运营

每日异常警示。按功能的预算。紧急停止开关。缓存命中仪表板。把模型与 effort（思考力度）政策保存为有版本的设置，而不是部落知识。

### 5.4 变更管理

提示词、工具与模型的变更需要 pull request（PR）审查、评测差异与金丝雀——和应用代码同一套纪律。

### 5.5 数据驻留与多区域

按政策路由。理解各托管平台之间的功能对等。不要为了一个更亮眼的模型 SKU（产品型号）而破坏数据驻留规则。

### 5.6 降级与灾难复原（DR）

常见问题的缓存答案。纯人工模式。延迟的批量处理。能快速停用生成式路径的功能标志。

### 5.7 值班信号

在工具错误飙升、schema 失败、成本燃烧、安全分类器飙升，以及代表失控循环的步骤数爆炸时调用值班。

## 6. 决策树

### 6.1 自动化安全吗？

若存在不可逆的外部影响，要求 HITL，或工具内的硬政策引擎。
若环境中的凭证比任务所需的更广，先收窄再提高自主程度。
若对抗性评测覆盖薄弱，保持密切的人工监督。
若黄金标准集是绿的、监控也就位，考虑更高的自主程度；否则不要打开全自动驾驶。

### 6.2 评测充分性

改提示词、工具或模型，至少需要一个脱机黄金差异。
交付 agent 写入，需要副作用断言加上对抗性测试包。
受监管领域还需要人工审查的样本与审计轨迹。

### 6.3 疑似注入事故

通过停用有风险的工具来围堵。保存屏蔽过的追踪。确认途径是文档、工具载荷，还是网页截取。修补分隔符与授权。需要时轮换密钥。添加评测案例。谨慎地重新开放。

## 7. 考试陷阱

1. 对硬性风险只用提示词做安全。
2. 只在没有副作用的顺利路径聊天上做评测。
3. 为了方便而记录密钥。
4. 全自动驾驶配上 shell 访问与生产凭证。
5. 最终文本看起来不错，就忽略副作用。
6. 把一次手动测试当成评测套件。
7. 为了修复过度拒绝而停用护栏，却没有衡量。
8. 分享仍含有 PII 的评测数据。
9. 仅仅因为 MCP 服务器能在内部域名系统（DNS）上解析，就信任它们。
10. 因为评测领域只有 2.6% 的比重就跳过它。

## 8. 自我检核问答（25）

Q1. 生产提示词微调之前，最低的评测？有版本的黄金比较，加上冒烟——不是凭感觉。
Q2. 答案文本是对的，但 `delete_user` 被调用了——算通过吗？因副作用而失败。
Q3. API 密钥放在哪里？密钥管理器、环境或 IAM——永远不在提示词或仓库里。
Q4. 间接提示注入的例子？藏在截取回来的 PDF 或网页里的恶意指令。
Q5. 让生产数据表永远不被删除，最好的控制？没有 DROP 的数据库角色、工具允许清单，以及拒绝规则——不只是提示词里的一行字。
Q6. 裁判分数上升，但人类不同意——怎么办？审计裁判与评分量规；不要只凭裁判就交付。
Q7. 凌晨 3 点成本在燃烧——第一步？紧急停止开关，或停用非必要 agent；检查失控循环与缓存崩溃。
Q8. 为什么要屏蔽追踪？提示词与工具载荷常常含有 PII 或密钥。
Q9. 安全对安全防护的速记？安全聚焦攻击者与系统滥用；安全防护聚焦有害或违反政策的输出；两者重叠。
Q10. 金丝雀对影子？金丝雀影响一部分真实用户；影子在设计得当时，做比较而不产生用户可见的变化。
Q11. 什么时候必须冻结评测集？在比较两个系统的期间。
Q12. 在共享 CI runner 上用 bypass permissions？危险的默认——避免。
Q13. 黄金标准集中的 PII——控制？最小化、遮罩、访问控制清单（ACL）、保留，或改用合成数据。
Q14. 工具描述要求把数据送到未知主机——风险？恶意供应链；审查、钉版本、允许清单。
Q15. 收紧过滤器之后出现过度拒绝——回应？衡量误拒；用评测调校；不要盲目移除过滤器。
Q16. schema 失败飙升——怎么调试？比对最近的模型、提示词与工具版本；抽样追踪。
Q17. LLM 功能的错误预算是什么？在可靠性工作取得优先权之前，所允许的不可靠程度。
Q18. 为什么要租户速率限制？公平性与滥用隔离。
Q19. 为什么大量发信要求 HITL？高度的声誉与法律爆炸半径。
Q20. 安全加评测的比重？8.1% 加 2.6%——很小，但有决定性。
Q21. 什么时候添加回归案例？每一次抓到生产失败之后。
Q22. temperature 零是完全确定性吗？不是——仍要钉定模型；工具仍然是非确定性的；评测仍然必要。
Q23. 数据驻留挡住了一个只在美国提供的模型——路径？使用核准的区域 SKU；功能缺了就重新设计。
Q24. 哪些监控能抓到 agent 循环？每个会话的步骤数、重复的工具调用、每个会话的成本、持续时间。
Q25. 一个新工具的第一个安全问题？如果模型被完全攻陷，还剩下什么授权？

## 10. 词汇表

黄金标准集：带标签的评测数据集。
评分量规：结构化的评分标准。
LLM 当裁判：为输出评分的模型。
金丝雀：有限度的真实用户推行上线。
影子流量：不影响用户的并行评测。
提示注入：操纵模型行为的不受信任指令。
数据外泄：数据经由模型输出或工具流出。
护栏：围绕模型的过滤器或政策层。
HITL：人在回路中的核准。
屏蔽：从日志与追踪中移除敏感数据。
错误预算：在优先级转移之前所允许的不可靠程度。
紧急停止开关：LLM 功能的紧急停用。
误拒：挡掉一个善意、被允许的请求。
误放：放行一个不被允许的请求。

## 11. 延伸生产 playbook（操作手册）

### 11.1 上线前审查会的问题

工具被滥用时能做什么？
有什么评测证据？
爆炸半径是什么？
回滚计划是什么？
PII 流向哪里？
谁值班？
用户看到的降级是什么样子？

### 11.2 对抗性测试包的类别

直接越狱。文档中的间接注入。工具名称社交工程。政策冲突请求，例如忽略退款上限。混淆伎俩。相关时的多语言规避样本。过度代理请求，例如执行所有 shell 命令。

### 11.3 评测框架架构

案例库。钉定模型、提示词与工具的执行器。评分器。报告发布器。CI 闸门。仪表板。建一次，跨团队重用——打包见第 05 章。

### 11.4 安全控制矩阵范例

API 密钥：窃取风险——密钥管理器与轮换。
客户 PII：泄漏风险——遮罩与保留。
Shell 工具：代码执行风险——拒绝或询问，加上沙箱。
远程 MCP：供应链风险——允许清单与钉版本。
日志：敏感存储风险——屏蔽。
批量结果存储桶：过广访问风险——ACL。

### 11.5 调试叙事

星期一质量下降：检查星期日的部署差异——别名搬动、提示词编辑、工具 schema 变更、时间戳造成的缓存未命中，或 MCP 更新。
安全过滤器挡掉合法内容：用带标签的误拒集；谨慎调校，需要时请领域审查。
agent 隔夜花了一大笔钱：缺失的预算、循环、巨大的工具载荷，或缓存被停用；用紧急停止开关；加上限。

### 11.6 合规导向的设计笔记

预期审计日志、最小权限、数据驻留、保留政策，以及高风险的人工监督，会以设计需求的形式出现。你不需要背法条；你需要选出符合那些主题的控制。

### 11.7 与模型选择的链接

评测决定更便宜的模型是否可接受。没有质量指标的成本警示会造成有害的删减。永远把经济性与任务成功配对。

## 12. 额外问答（26–40）

Q26. 什么是冒烟评测？每次构建都跑的一个微小关键路径集合。
Q27. 为什么把安全指标和有用性分开？优化其中一个，可能拖垮另一个。
Q28. 可以把原始生产追踪当黄金数据吗？只有经过隐私审查与标注管线才可以。
Q29. bash 工具有哪些容器顾虑？强化沙箱；拒绝危险的命名空间；最小权限。
Q30. 输出上的正则表达式密钥过滤器够吗？有帮助但不完整；防止密钥进入上下文，并封锁外泄工具。
Q31. 关掉功能标志对模型回滚？标志停用功能；回滚还原模型或提示词版本。
Q32. 为什么在评测报告中对设置做哈希？可重现性与审计。
Q33. 什么时候在 MCP 对外流量上应用数据外泄防护（DLP）？当工具能对外发送数据时；这常常是企业默认。
Q34. 单元测试只仿真工具的危险是什么？会漏掉集成授权错误——加上预备环境的合约测试。
Q35. 选出三个写入工具强化的例子：服务器端授权、审计日志、HITL 或政策上限，再加上幂等。
Q36. 可以把聊天的 p95 套到隔夜批量上吗？SLO 类别错了。
Q37. 输出中不被允许的建议由哪些层处理？政策提示词、安全系统、领域工具限制，以及适当的用户体验免责声明。
Q38. 为什么已知良好和已知恶意的安全案例都要保留？用来追踪伪阳性与伪阴性。
Q39. 平台上谁拥有评测失败？平台团队拥有框架；产品团队拥有标签与评分量规。
Q40. 第 04 章口诀？衡量、在模型之外强制执行、观测，并且随时准备关掉它。

## 13. 情境题包

医院聊天机器人：数据驻留、PII 最小化、临床上的过度拒绝与拒绝不足评测、没有硬授权就不给原始电子健康记录（EHR）写入工具、敏感调度动作要 HITL。
金融科技退款：工具内的上限、超过门槛的双人控制、不可篡改的审计日志、对抗性社交工程测试。
大学程序家教：shell 沙箱、默认无网络、学术诚信政策、每位学生的成本上限。
企业搜索：感知权限的检索，让未授权文档永远不进入上下文；文档的注入强化；答案上的 DLP。

每个情境都应在考试中触发多层答案：评测证据，加上模型之外的强制执行，加上可运营的监控。

## 14. 值班检查清单

## 15. 生产工程模式深入

### 15.1 队列与优先级

交互式用户请求不该排在巨大的批量回填后面等。用独立队列或优先通道。应用按租户的公平共享。明确地卸载，让降级对用户可见，而不是无声的超时风暴。

### 15.2 幂等消费者

执行工具副作用的工作者必须幂等。使用幂等键、upsert 语义，以及崩溃后能恢复的状态机，不重复扣款、不重复发信。

### 15.3 背压

当 Claude 或工具主机变慢，上游的准入控制应该拒绝或排队，而不是开无上限的客户端线程。这要搭配断路器。

### 15.4 设置即代码

模型钉定、提示词版本、工具哈希、effort 默认值与功能标志，都属于经过审查的设置。紧急刹车仍应留下审计轨迹。

### 15.5 多主机现实

有些客户住在 Bedrock 或 Vertex 上。维护一张功能矩阵。你声称支持的每个主机都要跑集成测试。数据驻留可能迫使你选 SKU 较少的区域——为够用而设计，不为幻想而设计。

### 15.6 数据生命周期

定义提示词、追踪与批量输出活多久。静态加密。限制谁能重播追踪。评测数据集含有敏感内容时，需要和生产数据同等的严谨。

### 15.7 人的因素

值班的人需要清楚的仪表板与一键紧急停止开关。如果凌晨 3 点没有人能行动，再出色的评测套件在实践上也是失败。

## 18. 综合情境演练

### 演练 A — 客服 agent 提议改写政策

用户上传一封电子邮件，说忽略退款政策并立即付款。正确的系统行为：把这封电子邮件当作不受信任；政策工具仍然执行上限；可能升级；记录这次尝试；之后加进对抗性测试包。

### 演练 B — CI 中的写程序 agent

无头会话，钉定模型、拒绝生产凭证、以测试作为成功闸门、不用 bypass permissions，并把产出物上传供审查。如果测试失败，管线失败即关闭。

### 演练 C — 一次好用的提示词编辑之后的成本回归

新提示词在系统区段加了每请求的时间戳。缓存命中率崩了。成本上升。先修前缀卫生；不要立刻在别处提高模型支出来补偿。

### 演练 D — 安全误拒

分类器挡掉善意的技术内容。用误拒集；调校阈值；谨慎添加允许类别；变更后同时监控误拒与误放。

## 19. 政策即代码范例（概念）

把支出上限、允许区域、被挡的工具名称与最大步数，表达成机器可检查的设置。模型可以读到政策的人类说明，但强制执行绝不能依赖它是否遵守那段说明。

考前记住的概念范例：
- `max_refund_amount` 在退款工具内强制执行
- `max_agent_steps` 在编排器内强制执行
- `denied_path_patterns` 在 Claude Code 权限内强制执行
- `residency_route` 在网关里、模型选择之前强制执行

## 23. 常见题干译法

题干说用户太信任聊天机器人——加上引用来源、不确定性语言与升级；也许降低自主程度。
题干说审计人员需要证明——不可篡改日志、版本钉定、评测报告。
题干说模型泄漏了 API 密钥——轮换、屏蔽、把密钥移出上下文、审查追踪。
题干说 agent 转了一整夜——预算、进度检测器、警示。
题干说经搜索结果的提示注入——分隔不受信任内容、强化工具授权、加上对抗性案例。
题干说更便宜的模型在安全案例上失败——不要为失败切片发布那条路由。

## 28. 工作坊 — 把弱设计改成强设计

弱：我们告诉 Claude 不要发明退款。
强：退款工具执行上限；超过门槛要 HITL；政策用检索；对抗性评测；审计日志。

弱：我们测了一次 agent，看起来不错。
强：有版本的黄金标准集、副作用断言、CI 闸门、金丝雀指标、回滚计划。

弱：日志永远保留完整提示词以便学习。
强：屏蔽、保留期限、追踪库的 ACL、任何训练用途前先做隐私审查。

弱：CI 用 bypass permissions，好让管线保持绿灯。
强：钉定权限、拒绝密钥与生产网络、测试失败即关闭、共享 runner 上不用 bypass。

弱：每个微服务共用一把全域 API 密钥。
强：密钥管理器里按环境限缩范围的密钥、轮换、用量异常警示。

## 29. 指标食谱（墙上该放什么）

质量墙：按切片的任务成功、schema 失败率、人工升级率。
安全墙：误放、误拒、注入拦截率、高风险工具调用。
可靠性墙：可用性、错误类别、p95 延迟、队列深度。
成本墙：每次成功任务成本、缓存命中率、effort 分布、最昂贵会话。
自主程度墙：每次成功的步骤数、预算耗尽、HITL 接受率。

每周审查。只有需要行动时，才把警示接到调用值班。

## 35. 主要研读加深 — 生产工程、评测、安全

第 04 章是安全与安全防护（8.1%）与评测／测试／调试（2.6%）的主要研读，再加上应用与集成（33.1%）的运营那一半。


### 35.1 把评测当成工程系统

为什么评测胜过凭感觉：生产流量很吵；脱机黄金标准集在客户之前抓住回归；在线指标抓住评测错过的漂移。

| 类型 | 衡量什么 | 弱点 |
| --- | --- | --- |
| 单元式黄金提示词 | 精确或评分量规分数 | 窄 |
| schema／验证器测试 | 结构正确性 | 不是语义 |
| 工具／agent 任务成功 | 端到端目标 | 构建成本高 |
| LLM 当裁判 | 细致质量 | 偏见；需要校准 |
| 对抗性／红队 | 安全 | 永远不完整 |
| 在线 A/B 或影子 | 真实分布 | 不安全时有风险 |

黄金标准集工艺：涵盖顺利路径、边界、对抗性、相关时的多语言，以及工具失败路径。冻结输入；为预期行为做版本。按产品接口保留切片。从生产事故抽样困难负例（已屏蔽）。

Agent 评测的特别之处：评任务成功，不是口才。包含环境状态（仓库测试数据、仿真 API）。限制步数；超过预算即失败。断言安全不变量，例如从未调用 `delete_prod`。

LLM 当裁判的陷阱：裁判看到泄漏的答案或规划者的思维链，因而产生偏见。未校准的评分量规会灌水分数。用成对或锚定参考的评分量规；用人工抽查。

部署闸门：必过 schema 测试、安全拒绝、关键黄金切片；应过质量评分量规，落在基准线的 epsilon（容差）内；监控成本、延迟、缓存命中、升级率。

调试循环：用钉定组合重现；检查逐字稿加上 `stop_reason` 加上工具追踪；分类提示词／工具／模型／编排／数据；修一层；加回归案例；然后才考虑模型升级。

### 35.2 安全与安全防护深入笔记

威胁主题：经由用户、检索文档或工具结果的提示注入；模型拥有用户不该有的工具时的混淆代理人；经由提示词、日志或 MCP 的密钥外泄；来自 MCP 服务器、插件与 Skills 的供应链风险；破坏性自动化；数据驻留与保留政策的误用。

纵深防御堆栈：
1. 身份与密钥：金库里的密钥；永不放进提示词或 `CLAUDE.md`。
2. 允许清单：工具、路径、网络、MCP。
3. 权限与 hooks：Claude Code 里客户端强制；应用程序里服务器验证器。
4. 输入分隔符，以及不信任工具结果。
5. 需要时对 PII／密钥做输出过滤。
6. 不可逆类别的人工核准。
7. 带屏蔽的审计日志。
8. 评测与红队持续进行。

破坏性动作闸门：为动作分类；若不可逆，要求明确的人工确认构件 **且** 权限允许 **且** 高严重程度时可选双人控制；否则在政策下允许。计划模式与「我会小心」的提示词不是闸门。

PII：最小化；屏蔽日志；提示词里优先用 token／ID 而不是原始数据；文档化保留政策。

MCP 与插件供应链：审查指令／URL；钉定版本；最小权限；信任 UX；生产仓库默认拒绝。

### 35.3 生产工程（应用运营）

SLO：可用性、首个 token 延迟（TTFT）／p95 延迟、任务成功、模型中断的错误预算。

容量：速率限制、队列、跨租户公平性、隔离评测流量。

成本工程运营：每次成功美元的仪表板；缓存命中；升级；输出长度；每周钉定审查。

变更管理：钉定组合；金丝雀；把提示词／工具／模型连到变更记录；回滚 runbook。

数据驻留：区域端点；从公开云端文档主题理解全球对区域路由的取舍。

降级与 DR：后援模型；模板模式；重播队列；中断后的批量回补。

值班信号：拒答飙升、工具错误、缓存未命中、成本、检测器、人工升级。

### 35.4 偏集成的安全与评测情境

情境 A — 客服 agent 提议改写政策。当作高影响内容；要求人工发布；评测不安全建议；不要自动合并进说明中心。

情境 B — CI 中的写程序 agent。拒绝网络与生产凭证；允许测试指令；hooks 挡住密钥提交；黄金失败测试必须变绿。

情境 C — 提示词编辑后的成本回归。比对前缀差异；检查缓存；衡量回合；回滚钉定；在框架里加上成本断言。

情境 D — 误拒。为善意的医疗／法律常见问题准备安全评测切片；谨慎调整政策，不要关掉真正的拒绝。

情境 E — MCP 在数据里回传敌意指令。工具结果加分隔；忽略数据中的系统覆盖宣称；允许清单动作；加上红队测试数据。

### 35.5 决策树

自动化安全吗？
```text
不可逆或跨租户吗？
 是 -> 人工关卡＋默认拒绝的工具
 否 -> 爆炸半径小且可逆吗？
 是 -> 带稽核＋预算来自动化
 否 -> 先模拟／分阶段推行
```

评测足以发布吗？
```text
关键安全测试绿灯吗？
 否 -> 不要出货
 是 -> 黄金质量在容差内吗？
 否 -> 不要出货／只以金丝雀推行并备妥紧急停止开关
 是 -> 出货金丝雀 -> 盯线上指标
```

疑似注入事故：
```text
围堵（停用工具／收紧允许清单） ->
保存日志（已屏蔽） ->
识别途径（用户／检索／工具） ->
修补＋添加评测 ->
若有客户影响则对外沟通
```

### 35.6 考试陷阱

1. 凭感觉发布。
2. 对资金移动只用提示词做安全。
3. 为了调试而记录原始密钥。
4. 为了修复误拒而停用安全过滤器，却没有衡量。
5. 裁判模型为自己未经验证的计划打分。
6. 把批量折扣当成安全边界。
7. 一次成功 demo 之后就把 MCP 改成全开放。
8. 提示词变更没有回滚计划。
9. 把生产密钥混进评测执行器。
10. 以为 `CLAUDE.md` 的「永不删除」就能挡住删除。

### 35.7 额外问答（Q41–Q55）

**Q41.** 变更生产系统提示词的最低门槛是什么？
**A41.** 版本升级、黄金评测通过、金丝雀、回滚注记——不是 playground 里看起来比较好。

**Q42.** 如何评测会花钱的 agent？
**A42.** 仿真总账；在仿真执行套件中断言工具从未被调用；另做带上限的分阶段集成。

**Q43.** 营销大量发信功能期间出现速率限制错误——架构修复方法？
**A43.** 队列加上退避；不要盲目提高并行；若脱机可考虑 Message Batches（批量 API）。

**Q44.** 护栏与权限的差别？
**A44.** 护栏常是模型／过滤器层；权限是硬的客户端／服务器强制。纵深防御需要两者。

**Q45.** 为什么对抗性评测要小但永久？
**A45.** 它们能快速抓住安全回归；又大又吵的集合会被忽略——整理高信号攻击。

**Q46.** 在线指标在脱机评测之前先动——信任哪个？
**A46.** 两边都查；在线可能有干扰因素；脱机可能过时。没有归因就不要盲目发布或还原。

**Q47.** Claude Code 设置里 API 密钥该放哪？
**A47.** 环境或密钥管理器——不是 `CLAUDE.md`、不是提交的设置、不是对话日志。

**Q48.** 重构 agent 的成功指标是什么？
**A48.** 测试通过加上 lint 干净加上范围内的差异加上没有碰禁用路径——不是改了几行。

**Q49.** 缓存会造成安全问题吗？
**A49.** 缓存不会授予工具，但把密钥缓存进前缀或日志是数据处理错误；多租户系统绝不能共享内嵌租户密钥的前缀。

**Q50.** 多租户提示词缓存设计规则？
**A50.** 共享前缀只等于非敏感的全域指令／工具；租户数据放在不缓存的回合里。

**Q51.** 为什么要隔离红队运行？
**A51.** 攻击性提示词与工具尝试不该共享生产配额或生产凭证。

**Q52.** 挡住 git push，用 hook 还是权限？
**A52.** 两者都能用；权限的 deny／ask 是声明式的；hooks 允许自订逻辑／审计。常常并用。

**Q53.** 即时网页工具造成评测不稳定——修复方法？
**A53.** CI 黄金运行中仿真网络；另留一小段即时冒烟。

**Q54.** 模型质量的错误预算是什么？
**A54.** 回滚之前允许的回归容忍——例如关键切片最多下降 X%。

**Q55.** 举出安全审查中三个集成构件。
**A55.** 工具允许清单、MCP 服务器清册、钉定组合加上日志屏蔽政策。

### 35.11 应用运营模式（额外深度）

队列与优先级：交互式用户流量不该排在大批量评测工作后面挨饿。用独立队列或加权公平共享。

幂等消费者：带工具的工作者必须能在至少一次交付下存活。把幂等键贯穿退款、工单更新与发信。

背压：当模型 API 回 429，让生产者变慢；不要热重试去放大风暴。

设置即代码：把钉定组合放进 git；经 PR 晋升；禁止默默把 playground 拷贝到生产。

多主机现实：同一个应用可能调用 Anthropic API 与 Bedrock；抽象客户端，但保留明确的主机钉定与功能标志。

数据生命周期：为提示词、工具追踪与评测测试数据定义保留；按调度清除或匿名化。

人的因素：值班 runbook 必须写回滚到哪个钉定，而不只是打开哪个仪表板。

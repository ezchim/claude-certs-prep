## 概覽

在 CCAO-F 上，提示等於專業簡述。官方藍圖動詞：**建立** 商務與技術任務的有效提示詞；**套用任務拆解** 以結構化複雜請求；**迭代** 提示詞以提升品質；**依任務類型調整提示策略** — 指南點名 *分析、研究、起草、腦力激盪*。AI 流暢度的 **描述** 三要素 — Product、Process、Performance — 是主軸：交付物是什麼、怎麼做到，以及「好」長什麼樣子。

## 深入筆記

### 1. 提示詞解剖

一份完整簡述帶著：**角色**（Claude 扮演誰）、**目標**（交付物＋它支撐的決策）、**輸入**（按名稱點名的檔案、貼上的資料、connector 來源）、**限制**（長度、語氣、禁用宣稱、受眾）、**過程**（有順序的步驟、檢查點）、**格式**（schema（固定輸出結構）、章節、表格）、**驗證**（回答之前要檢查什麼）。你很少需要七個全用 — 但考試裡最好的提示詞，是 *承重部分沒有缺漏*、內部也沒有矛盾。

**描述三要素：** *Product* 描述點名交付物，以及它支撐的受眾決策。*Process* 描述把工具與檢查點排成順序。*Performance* 描述設定驗收測試、範例與反例。缺一個就會出現可預測的失敗：空話（沒有 Product）、跳過步驟（沒有 Process），或體面的錯（沒有 Performance）。

**利害關係人翻譯** 是助理層級的技能：「make it pop」需要語氣範例；「keep it legal」需要免責聲明檔與禁用宣稱；「board ready」需要 Decision／Risks／Ask 結構；「quick thoughts」必須標成推測性質。題幹會用利害關係人黑話 — 先翻譯再選答案。

**矛盾**（「用初學者聽得懂的方式解釋，但保留未定義的內部縮寫」）必須明白解開。沒解開的矛盾會產出不穩定的輸出，然後被怪到模型頭上。

**範例勝過形容詞。** 兩三個黃金範例（外加一個反例）勝過好幾段風格描述。few-shot（少樣本）是非開發者手上槓桿最高的一招。

**含糊：** 優先 *澄清*，不要 *發明*。若仍要繼續，就要求一個明白寫出的 `ASSUMPTIONS` 區塊，讓錯誤猜測看得見，而且修正成本低。

### 2. 任務拆解

把多交付物或高風險工作拆成帶人類檢查點的階段：

- **先大綱再填寫：** 任何正文之前，先核准結構。
- **先萃取再分析：** 把事實與判斷分開，錯誤才追得到。
- **先選項再決定：** 先產生替代方案、先不承諾，再用標準挑選。
- **先起草再紅隊：** 產出，再對抗性攻擊（銜接領域 03）。

實作模式：營運事後檢討（時間線事實 → 促成因素標成證據 vs 假設 → 行動項只能帶具名負責人）；行銷郵件（事實＋法律必含項 → 主旨＋正文 → 對禁用宣稱做合規檢查）；人資常見問題（只從知識回答；引用該節；缺則「Not found」）；外出會議行程（腦力激盪 → 分群 → 挑選 → 帶時間的行程 → 風險檢查）；資料清理（定義 schema → 用程式碼執行驗證 20 列樣本 → 放大）。

**拆解也是治理：** 它在不可逆或對外步驟之前插入人類關卡 — 這個交叉點會在領域 04 與 06 考到。何時拆解：多個交付物、高風險、任務類型混在一起（絕不要在同一口氣裡又腦力激盪又分析），或你需要中間檢查點。任務又小、又清楚、又低風險時，單次提示就可以 — 把瑣事拆開是浪費時間與用量。

### 3. 迭代技藝

強的迭代會 **點出缺陷以及要加上的限制**：「摘要發明了一個 Q3 數字 — 只用 `Q3-report.pdf` 裡的數字，其他一律標 UNKNOWN」勝過「改得更好」。除錯時 **一次只改一個重大變數**，才學得到因果。寧可做外科式修改（「只修表格」）也不要整份重產。提示詞措辭收緊之後還失敗兩次，問題通常是輸入、功能選擇或任務框架 — 不是用詞（領域 07 的階梯）。

維持一份微型提示詞庫：假設清單；FACTS vs INFERENCES；只要表格；缺漏就填 NULL；最有力的反駁；保留原意的差異對照；只要大綱；主張對來源的對照表；三個選項但不挑選；壓縮但數字不變。

### 4. 依任務類型的 playbook（藍圖點名的目標）

| 任務類型 | 策略 | 招牌動作 |
|---|---|---|
| **分析** | 標準先行，證據與推論分開 | 提供評分量規；要求 FACTS vs INFERENCES 章節；要求反駁與未知事項 |
| **研究** | 範圍＋來源＋引用 | 定義問題、時段、來源規則；要求引用支持（領域 03）；多來源公開局面用 Research 功能 |
| **起草** | 必含事實＋受眾＋格式 | 提供已核准事實（不要讓 Claude 去找）；語氣範例；禁用語句；長度上限 |
| **腦力激盪** | 先發散，再收斂 — 分開做 | 先要求數量／多樣性、先不下判斷；第二步用標準排序；輸出標成推測性質 |

混用模式是經典錯誤：在同一則提示詞裡要求「有創意的點子，但嚴格準確符合政策」，兩邊都得不到。把階段拆開。

### 5. 把提示當成系統（團隊規模）

穩定規則從提示詞遷出：反覆出現的指示 → 專案指示；參考細節 → 知識檔（按名稱點名）；豐富程序 → Skills。共享 Projects 需要衝突時的優先規則（例如法務 > 品牌）。把黃金範例與反例放進知識。教同事貼上需求，而不是焦慮 — 沒有規格的含糊急迫，會浪費用量上限。每週都值得重複的提示詞是設定，不是打字（領域 05）。

### 6. 提示詞比較題的計時啟發式

當題目出示四個候選提示詞，用目標、輸入、限制、過程、格式、驗證為每一個打分；最完整、無內部矛盾的勝出。優先澄清，不要發明；對後果重大的轉換，優先分階段核准，而不是一則巨型提示詞。API 參數選項（temperature、微調）在這場產品導向考試裡是干擾選項。在「升級模型」之前先問：一個謹慎的實習生拿這份簡述能做成嗎？若不能，先修好描述。

### 7. 簡述實例（之前 → 之後）

**弱：** 「摘要這通客戶電話。」→ **強：** 「根據 `call-2026-08-12.txt`，為正在決定是否升級處理的客戶經理產出一頁摘要：5 則帶時間戳的事實、客戶情緒並附一句支撐引言、任一方的承諾（一字不差引用；不清楚則 UNKNOWN），以及附理由的建議下一步。逐字稿裡沒有的事實，不要推論。」

**弱：** 「寫一則關於我們上市的 LinkedIn 貼文。」→ **強：** 「為潛在的中型市場買家，起草一則宣布上市的 LinkedIn 貼文。必須納入：`launch-facts.md` 裡兩則已核准主張（數字照原文）、以客戶痛點開頭、≤150 詞、不用 `banned-phrases.md` 裡的最高級。語氣對上知識裡的兩個範例。給兩個變體：穩健與大膽。」

**弱：** 「這份供應商合約可以嗎？」→ **強：** 「第一階段：從 `vendor-msa.pdf` 抽出每一條碰到責任、終止、資料處理與自動續約的條款 — 逐條引用。第二階段（等我確認之後）：用 `contract-redlines.md` 的檢查清單評估每一條抽出的條款，標成 OK／FLAG／ESCALATE 並附一行理由。最終法律判斷留給律師。」

模式：點名檔案、受眾決策、必含項、格式、驗證規則 — 後果重大的就分階段。

### 8. 複選題排除庫

選兩項／三項的提示題，通常把一個正確的技藝動作配上干擾選項。練習排除：「改得更好」（沒點名缺陷）；「加上 temperature=0」（API 旋鈕，走錯軌道）；「用最大的模型」（領域 01 威望偏見）；「讓 Claude 去找統計數字」（讓模型去找承重事實）；「把腦力激盪與合規審查併進同一則提示詞」（模式混用）；「每一則訊息都再貼一次政策」（設定失敗）。正確配對通常結合 *結構* 動作（schema、拆解、範例）與 *驗證* 動作（假設區塊、引用來源、檢查點）。

## 決策樹

| 情境 | 動作 |
|---|---|
| 多交付物或高風險 | 帶檢查點拆解 |
| 萃取進系統 | 定義 schema；缺漏填 NULL；先樣本 |
| 分析請求 | 評分量規＋證據／未知分開 |
| 含糊的利害關係人要求 | 把黑話翻成 Product／Process／Performance；先澄清 |
| 輸出沒對上風格 | 加範例＋反例，不要加形容詞 |
| 「改得更好」的衝動 | 改為點名缺陷與限制 |
| 同一份簡述每週都需要 | 把規則遷到專案指示／Skill |
| 兩輪收緊後仍失敗 | 重新診斷層級（輸入、功能、知識）— 領域 07 |

## 考試陷阱

1. 對後果重大的工作用沒有檢查點的巨型提示詞
2. 派了角色但沒有成功標準（光說「扮演財務長（CFO）」）
3. 讓 Claude 去找利害關係人必須擁有的承重數字
4. 在同一則提示詞裡混用腦力激盪與分析
5. 「改得更好」／「更專業一點」卻沒有具體標準
6. 每一輪都重述穩定政策，而不是放進專案指示
7. 研究請求沒有範圍、時段或來源規則
8. 把瑣事拆解（流程表演）
9. 「除錯」時一次改五個提示詞變數
10. 用 API 旋鈕（temperature、微調）回答產品考試題幹

## 練習問答（18）— 情境題幹附答案與理由

**Q1.** 一位 PM 打：「分析我們的 Q4 計畫。」Claude 回了一段空泛的策略文字。下一步最好的提示詞？
**A：** 重建簡述：附上計畫檔、說明它支撐的決策、給評量標準、要求 Evidence vs Unknowns。失敗在缺少 Product／Performance 描述，不在模型。

**Q2.** 選兩項客戶郵件草稿的 Performance 描述元素。
**A：** 一封已核准郵件的黃金範例；明白寫出的禁用宣稱／語句。（「professional」這類形容詞不是驗收測試。）

**Q3.** 法務必須審查一份 60 頁合約的續約風險。最強結構？
**A：** 拆解：萃取與續約相關的條款 → 每條標上證據引文 → 再用評分量規評估風險 → 人工法律審核。先萃取再判斷，錯誤才追得到。

**Q4.** Claude 一直忽略已上傳的定價 PDF。最佳迭代？
**A：** 明白點名檔案（「只根據 `Pricing-v3.pdf` 回答；引用該節；否則說 Not found」）。點名勝過把問題再大聲問一次。

**Q5.** 團隊要行銷活動點子 *以及* 一份合規安全的入圍清單。你怎麼下提示詞？
**A：** 兩個階段：發散（許多標成推測的點子、先不下判斷），再收斂（對照標準＋禁用宣稱檔排序）。同一則提示詞混用模式，兩邊都會變差。

**Q6.** 每一則對話都用的常態語氣規則，該放在哪裡？
**A：** 專案指示 — 穩定規則是設定，不是每則提示都打一遍。

**Q7.** 經理的回饋是「改得更好」。為什麼這是考試的錯誤選項，以及修復方法？
**A：** 它沒點名缺陷或限制，所以改善靠運氣。修復方法：說出漏了什麼（受眾、長度、缺少風險）並加上限制。

**Q8.** 選兩項拆解對後果重大工作的好處。
**A：** 不可逆步驟之前的人類檢查點；把萃取與判斷分開，錯誤被局部化。

**Q9.** 給高階主管的改寫不得改變意思。你加什麼限制？
**A：** 語意鎖定：「所有事實與數字必須原樣保留；只改結構／長度／術語；列出任何意思已偏移的句子。」調整 ≠ 發明（銜接領域 03）。

**Q10.** 需求碰到雇用法措辭，助理不確定什麼是允許的。提示詞動作？
**A：** 要求一個 ASSUMPTIONS 區塊，並把輸出送到人工法律審核 — 對受監管內容，澄清／上報勝過發明。

**Q11.** Claude 必須填一份含供應商、日期、金額、負責人的追蹤表。提示詞模式？
**A：** 定義 schema，一筆一列，缺漏填 NULL，放大之前先驗證樣本。schema 能減少修改輪次。

**Q12.** 草稿引用了聽起來很厲害、但沒人提供的市場統計。迭代？
**A：** 禁止無來源數字；提供已核准數字，或要求 UNKNOWN＋一個未知事項章節。起草策略＝必含事實，不是模型自己找來的事實。

**Q13.** 什麼時候單次提示是正確答案？
**A：** 又小、又清楚、又低風險的任務 — 把破冰題請求拆開是流程表演。

**Q14.** 「扮演 McKinsey 合夥人，審查我們的策略」表現不佳。缺了什麼？
**A：** 成功標準與輸入。沒有評分量規與文件的角色只是戲服，不是簡述。

**Q15.** 選兩項分析提示詞的要求。
**A：** 明白寫出的評分量規／標準清單；事實與推論分開（未知事項標示出來）。

**Q16.** 輸出是一大牆文字，但營運需要它符合工單範本。修復方法？
**A：** 加上格式合約：確切章節／欄位、表格形狀、長度上限 — 並把它放進 Project 才能固定住。

**Q17.** 研究員想要「competitor X 的一切」。更好的研究提示詞？
**A：** 收範圍：哪些問題、哪個時段、哪些來源類型、必須附引用 — 然後用 Research 模式；之後驗證引用支持。

**Q18.** 兩輪收緊迭代之後，掃描 PDF 的萃取仍失敗。診斷？
**A：** 停止改提示詞 — 問題在輸入層（光學字元辨識（OCR）品質差的掃描檔）。兩輪收緊仍失敗，代表該換層級，不是再改措辭（領域 07）。

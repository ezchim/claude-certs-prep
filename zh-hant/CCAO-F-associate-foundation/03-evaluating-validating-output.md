## 概覽

CCAO-F 配分最重的領域。你的工作是 **在輸出到達客戶、高階主管或正式紀錄系統之前做出判斷**。官方藍圖動詞：評估準確性與完整性；辨識幻覺、不一致與偏見；套用事實查核；判斷何時需要人工審核；針對受眾編輯、調整、修訂與比較；組織資訊並選擇格式（Artifacts、行內、結構化資料）。

核心考試真相：**Claude 可以寫得很流暢，同時是錯的。** AI 流暢度在這裡對應 **明辨（Discernment）**（看出什麼不能交付）與 **盡責（Diligence）**（建立能隨風險擴展的審核習慣）。流暢辭藻不是證據。Artifact 並非預先驗證過的。有引用來源，不代表連結的文字真的支持那個主張。

## 深入筆記

### 1. 這個考試所說的「評估」是什麼意思

評估是 **三方對照**：（1）任務要求／成功標準，（2）真相來源（上傳檔案、專案知識、Research 引用來源、正式政策），以及（3）草稿。用以下維度打分：

- **正確性** — 承重主張是否為真且有依據？
- **完整性** — 相對於任務要求或大綱，有沒有缺少重要的東西？
- **一致性** — 數字、日期、負責人，以及表格↔正文是否一致？
- **校準** — 信心程度是否與證據相符？未知事項是否標示出來？
- **受眾適配** — 語氣、長度、術語、對讀者的決策實用性？
- **政策／安全** — 個人識別資訊（PII）、承諾、具法律效力的措辭、拒答是否被遵守？
- **格式適配** — 交付方式（行內／Artifact／結構化）是否恰當？

這七項只要有一項不及格，你仍然可以「修改」而不是「交付」。完整性失敗比錯誤主張藏得更好：一份拋光的一頁文件漏掉最大的客戶異議，是領域 03 的經典陷阱。

### 2. 風險層級（按比例審核）

讓審核深度對上後果。考試複選題經常把 **高風險卻跳過審核** 的干擾選項，配上 **對瑣事過度驗證** 的干擾選項。選出合乎比例的那組。

| 層級 | 典型工作 | 審核深度 |
|---|---|---|
| **L1 低** | 標示過的腦力激盪、破冰題、內部發想 | 略讀；保留「草稿／推測」標示 |
| **L2 中** | 對一份簡短已知文件的內部摘要；團隊進度改寫 | 抽查關鍵主張＋對照大綱的完整性 |
| **L3 高** | 帶承諾的客戶郵件；對外發布；維運 runbook（維運手冊）變更 | 完整主張對照表＋同儕審核；引用真相來源 |
| **L4 關鍵** | 法律／醫療／財務／人資／安全；雇用決策；不可逆的 connector 送出 | 專家人工審核＋原始來源；Claude 只是起草輔助 |

**經驗法則：** 若輸出會產生 **對外承諾**、會動到 **錢／人／安全**，或會進入 **正式紀錄系統**，至少當作 L3。不可逆的 Connector 動作（寄信、更新工單、寫入客戶關係管理（CRM））在執行之前永遠需要 **人工關卡** — 即使草稿看起來完美。

### 3. 主張對照表（領域 03 的招牌技能）

**主張對照表** 把流暢文字變成一份可以驗證的檢查清單。方法：

1. 抽出每一條承重主張（數字、名稱、日期、引文、歸因、承諾、因果陳述、「依據政策 X」）。
2. 為每條標狀態：`SUPPORTED`（引用或引述證據）、`UNSUPPORTED`、`CONTRADICTED`、`AMBIGUOUS`、`OUT_OF_SCOPE`。
3. 逐條決定：保留／改寫／刪除／上報。
4. 直到這時才潤飾語氣。

**優先掃描順序（毒數字演練）：** 數字 → 名稱 → 日期 → 承諾／服務水準協議（SLA） → 法律或醫療斷言 → 歸因／引用來源 → 軟性意見。考試會把一個錯數字藏在流暢段落裡。

**主張萃取腳本（可重複使用的提示詞模式）：** 
「把每一條事實主張列成項目。每一條：主張文字 | 所需證據 | 狀態（SUPPORTED／UNSUPPORTED／…） | 建議修復方法。對照表完成之前，不要改寫備忘錄。」

輸出結尾的是／否自檢清單，可以加快人工審核。它們 **不能** 取代 L3／L4 審核。

### 4. 幻覺類型

要會這套分類法；題幹很少說「幻覺」— 它們展示症狀。

1. **捏造事實** — 統計數字、市場規模、「依據 Gartner 2026 為 47%」卻沒有真實依據。
2. **捏造或不匹配的來源** — 看起來真的 URL 卻 404；正文並不支持主張的引用；發明的研究標題。
3. **捏造歸因** — 引用一個不存在的人或政策章節（例如「依據政策 4.2」，而 4.2 無關或缺失）。
4. **過度自信的推論** — 把猜測當成已定事實；假精確（「恰好 12.47%」）。
5. **脈絡滲漏** — 把另一則對話、Project 檔或稍早範例的細節混進這份任務。
6. **指示失憶** — 忽略限制（受眾、禁用宣稱、「只從檔案引用」）。

**引用來源不是自動驗證。** Research 輸出仍需要 **引用支持檢查**：打開來源，確認那句話真的支撐主張，確認日期／版本相關。真實但不相干的連結，驗證仍然不及格。

### 5. 不一致與偏見

**不一致：** 算術加不起來；時程矛盾；表格總計 ≠ 正文；回答中途限制漂移（「不打折」然後給 15%）；摘要裡具名負責人但逐字稿裡沒有。

**考試在意的偏見模式：** 範例裡的刻板印象預設；位置偏見（過度加權第一個來源）；假中立掩蓋偏好選項；缺少反駁或風險的片面分析。修復方法是要求反駁、決策標準與明白寫出的未知事項 — 不是問一次「你確定嗎？」。

### 6. 事實查核工作流程（交付／修改／退件／上報）

後果重大草稿的標準流程：

1. **為任務定風險層級**（L1–L4）。
2. **抽出主張**（對照表）。
3. **把證據對上** 專案知識／上傳政策／Research 引用來源／主要系統。
4. **先抽查** 高嚴重程度主張（數字、承諾、法律效力）。
5. **完整性檢查** 對照原始大綱或任務要求。
6. **決定：** 交付（通常加上標示）／修改／退回缺乏依據的區塊／上報給人類專家。
7. **格式** 只在內容過關之後處理 — 或格式選擇本身就是適配的一部分（見下文）。

把紅隊 Claude 當成 **輔助，不是權威**：對抗性提示詞（「攻擊這份草稿裡缺乏依據的承諾」）有助於浮出問題。把最終受監管判斷外包給模型，盡責不及格。

### 7. 人工審核關卡（你必須停下來的時候）

出現以下任一情況，強制人工／專家審核：

- 法律、醫療、財務、人資、安全或具雇用效力的內容
- 對外客戶或公開發布
- 不可逆的 Connector／自動化動作
- 草稿裡有 PII 或敏感個人資料
- 承重主張的證據覆蓋不足
- 主題超出你或 Claude 已展現的能力
- 含糊度高且下行風險重大

用 Claude **評 Claude** 來浮出問題是可以的。把那個評分當成法律簽核，是考試錯誤答案。問一次「你確定嗎？」**不是** 驗證方法。

### 8. 受眾編輯、調整、修訂、比較

**調整 ≠ 發明。** 受眾改寫改的是長度、術語、結構與強調 — 不是事實。若高階主管簡報需要一個你沒有的數字，標 `UNKNOWN` 或上報；不要捏造一個乾脆的 KPI。

**用評分量規表比較草稿：**

| 標準 | 草稿 A | 草稿 B | 勝者／合併註記 |
|---|---|---|---|
| 對來源的準確性 | … | … | … |
| 對大綱的完整性 | … | … | … |
| 校準／未知事項 | … | … | … |
| 受眾適配 | … | … | … |
| 政策／承諾 | … | … | … |

合併長處，不要崇拜長度或流暢辭藻。主張對照表失敗之後只做風格拋光，是陷阱答案。

### 9. 格式選擇：Artifacts／行內／結構化

格式不對，即使內容好也 **不符合用途**。

| 格式 | 何時用 | 反模式 |
|---|---|---|
| **行內對話** | 短答案、快速澄清、迭代腦力激盪 | 把董事會資料包倒成原始聊天 |
| **Artifact** | 獨立可編輯交付物（文件、應用程式、互動表格、HTML），你會修訂或分享 | 把兩個字的答案硬塞進 Artifact「應用程式」 |
| **結構化**（表格、條列、逗號分隔值（CSV）／Sheets 就緒） | 輸出要餵給下一步；方便主張查核；營運交接 | 下一步是試算表卻給敘述文字段落 |
| **Research＋引用來源** | 需要附引用局面的多來源調查 | 對單一已上傳、應該直接引用的 PDF 跑 Research |
| **專案知識（核准之後）** | 反覆工作的活的真相來源 | 把未驗證草稿貼進知識當成「真相」 |

組織與整理：標題、主張清單、給領導人的決策／證據／風險章節。指標定義錯誤的漂亮儀表板，評估不及格 — **語意先於美學**。

### 10. 銜接到其他領域

- 糟糕的提示詞造成評測惡夢（**02**）。
- 選錯功能提高錯誤率（**01**）。
- 過期的專案知識產生對檔為真、對世界為假（**05**）。
- 沒有關卡就交付，治理不及格（**06**）。
- 反覆錯過的評測變成疑難排解模式（**07**）。

沒有明辨的流暢度是商務風險。**21% 的配分是刻意的：** Anthropic 認證的助理，要能攔住流暢錯誤變成組織事實。

### 11. 個人標準作業程序（SOP）（盡責系統）

保留一頁評分量規。為每個工作流程預先定義 L1–L4 規則。把已知失敗範例存進 Project。每月記錄險失。實驗迴圈：Research 簡報 → 對照約 15 條主張 → 決定交付／修改／退件 → 過關後才做 Artifact → 從找到的錯誤寫出三道考試題幹。

把明辨作業化的驗證腳本（同時也是領域 02 的 Performance 工具）：主張萃取；對抗性攻擊；受眾改寫差異比較；承諾／義務掃描器；隱私／PII 遮蔽掃描器。

## 決策樹

| 情境 | 動作 |
|---|---|
| 缺乏來源的關鍵對外主張 | 修改或退件；不要交付 |
| 內部矛盾（35 vs 28，表格≠正文） | 為一致性而修改 |
| 對大綱缺少必要章節 | 完整性不及格 → 修改 |
| 受眾不配、事實沒問題 | 調整（語氣／結構），不要發明 |
| 標示過的低風險腦力激盪 | 標示後交付（L1） |
| Connector 送出／寫入動作 | 執行前設人工關卡 |
| 雇用／法律／醫療／財務備忘錄 | L4 專家審核 |
| 有引用但缺乏支持 | 驗證不及格（等同沒有引用） |
| 對禁止請求的安全拒答 | 恰當 — 不要當成缺陷去「修好」 |
| 漂亮 Artifact、錯誤指標定義 | 先修語意再交付 |

**層級路徑：** L1 略讀 → L2 抽查 → L3 完整主張對照表＋同儕 → L4 專家＋原始來源。

## 計時主張對照表演練（90 秒題幹）

每道題幹用 **約 90 秒**：抽出 3–6 條承重主張，標狀態，選交付／修改／退件／上報。演練中 **不要** 改寫整份備忘錄 — 先做對照表。答案接在每道題幹後面。

### 演練 A — 供應商郵件
題幹：草稿感謝 Acme，並引用「依據 Gartner 2026，成交速度快 47%」，連結到一篇生活風格部落格；提出 60 天試點並給 SLA 折抵「如先前討論」（對話裡沒有）。 
**對照焦點：** 統計＋來源；SLA 承諾。 
**答案：** 退件／修改缺乏依據的 Gartner 主張；在有證據之前刪掉或改寫 SLA；送出前做法務／商務審核（L3）。

### 演練 B — 會議紀錄
題幹：紀錄指派 Jordan 為「星期五前完成計費遷移」的負責人；逐字稿從未點名 Jordan；Jordan 也不在邀請名單。 
**對照焦點：** 歸因／行動負責人。 
**答案：** 歸因不及格；標 `OWNER UNCLEAR`；不要發明負責人 — 上報給主持人。

### 演練 C — 退款回覆 vs 政策檔
題幹：對話回答「依一般知識，一律 90 天內退款」；上傳的 `Refund_Policy_v3.pdf` 寫數位商品 30 天。 
**對照焦點：** 政策衝突。 
**答案：** 退回一般知識答案；引用政策檔；L3 客戶承諾關卡。

### 演練 D — Research 簡報引用
題幹：Research 主張「歐盟指引在 2024 年禁止功能 X」，引用來源討論的是不相干的隱私 cookie 規則。 
**對照焦點：** 引用支持。 
**答案：** 缺乏依據（引用不匹配）；修改主張或找到支持來源；不要只因為有連結就交付。

### 演練 E — 儀表板 Artifact
題幹：互動 Artifact「依區隔的年度經常性收入（ARR）」把「bookings」欄位標成 ARR；財務詞典對 ARR 的定義不同。 
**對照焦點：** 指標語意。 
**答案：** 先修定義再修美學；結構化／財務負責人檢查（L3／L4）。

### 演練 F — 行銷活動腦力激盪
題幹：清楚標示「僅推測概念 — 不是已核准文案」；有趣但偏鋒的標語。 
**對照焦點：** 風險層級＋標示。 
**答案：** 當標示過的 L1 草稿交付；不要當成品牌已核准文案。

### 演練 G — 高階主管簡報完整性
題幹：任務要求 Decision／Evidence／Risks／Ask；草稿只有 Decision 與 Evidence；漏了 Risks 與 Ask。 
**對照焦點：** 完整性。 
**答案：** 完整性不及格 → 修改；拋光過的半份簡報仍然不及格。

### 演練 H — 時程不一致
題幹：正文說試點 9 月 15 日開始；表格說 10 月 5 日；兩邊都寫成確定。 
**對照焦點：** 一致性。 
**答案：** 修改；對外分享前對照真相來源對齊日期。

### 演練 I — 偏見入圍清單
題幹：供應商比較用華麗形容詞稱讚一個工具；沒有標準表；競爭對手一行打發。 
**對照焦點：** 偏見／假中立。 
**答案：** 改成依標準比較＋反駁；不要當「客觀分析」交付。

### 演練 J — Connector 送出
題幹：草稿客服回覆看起來正確；使用者提示詞：「立刻用 Gmail connector 送出。」 
**對照焦點：** 人工關卡。 
**答案：** 送出前設人工關卡；評測文字 ≠ 授權執行。

### 演練 K — 捏造政策章節
題幹：備忘錄說「依據員工手冊 §4.2，遠距津貼為 500 美元」；手冊沒有 §4.2 津貼文字。 
**對照焦點：** 捏造歸因。 
**答案：** 退回該主張；引用真正章節或標缺乏依據；人資／專家審核（L4）。

### 演練 L — 流暢正文裡的毒數字
題幹：三段紮實摘要；一句說「淨推薦值（NPS）從 42 升到 71」，但來源表顯示 42 → 47。 
**對照焦點：** 數字優先掃描。 
**答案：** 第一次掃數字就抓住；把 71 改成 47；修好才交付。

*（十二道不重複題幹 — 輪替練習，不是複製貼上灌水。）*

### 12. 迷你案例（套用完整迴圈）

**案例 1 — 客戶成功郵件。** Claude 起草一則續約說明，承諾「優先影響產品藍圖」，並引用「上季 NPS 72」。專案知識裡 NPS 是 61；藍圖影響力從未核准。層級 L3。兩則承諾都做主張對照表。修改：引用真實 NPS 或刪掉；拿掉未核准的影響力措辭；送出前同儕審核。格式：郵件正文用行內；可選的已核准話術條列，**核准之後** 才存進 Project — 不是之前。

**案例 2 — 競爭局面 Artifact。** Research 產出一份拋光的 HTML Artifact，比較四家供應商。兩則引用扎實；一則統計可追溯到重述供應商自家主張的新聞稿；一則「分析師引言」沒有對得上的來源文字。對任務要求的完整性好；正確性參差。動作：保留 Artifact 外殼，把缺乏依據的儲存格改成 `Unverified`，把新聞稿統計換成原始申報或刪掉，然後標「供審核的草稿」交付。語意與證據勝過視覺拋光。

**案例 3 — 人資常見問題。** 提示詞要求一份友善的育嬰假 FAQ。Claude 發明一條「所有承攬人都有六週全薪」。手冊只涵蓋員工；承攬人超出範圍。這是接近 L4 的具雇用效力內容。退回發明的承攬人福利；上報人資；不要只從對話發布 FAQ。安全／政策盡責勝過好語氣。

**案例 4 — 營運 runbook。** 值班步驟的結構化表格看起來一致，但步驟 4 說「5 分鐘沒確認就呼叫 Secondary」，正文引言卻說 15 分鐘。一致性不及格。改成來源 runbook 的單一 SLA；維持結構化格式，因為營運會依表格執行。

這些案例演練同一個迴圈：定層級 → 對照表 → 證據 → 完整性／一致性 → 交付／修改／退件／上報 → 格式。

### 13. 複選題模式庫

預期選兩項／三項題會把一個正確、合乎比例的動作混進干擾選項。常見應排除的錯誤配對：

- 「因為用了 Sonnet／Opus 就跳過審核」＋「對標示過的腦力激盪跑完整法律審核」（威望偏見＋過度驗證）
- 「因為有引用來源就交付」＋「刪掉所有引用以減少版面雜亂」（盲信＋反證據）
- 「為省時間用 Connector 自動寄出」＋「永遠不要用 Connectors」（關卡失敗＋絕對禁止）
- 「問 Claude 確不確定」當成唯一控制＋「永遠只能由人類起草」（假驗證＋反委派）

正確模式通常結合 **主張層級驗證**、**與風險相稱的人工關卡** 與 **格式適配**。

## 考試陷阱

1. 流暢辭藻＝準確性 
2. 信心／假精確＝證據 
3. 因為文字「看起來寫完了」就跳過完整性 
4. 盲信引用來源或 Research 腳註 
5. 自我評分／「你確定嗎？」當成法律或人資簽核 
6. 沒有人工關卡就用 Connectors 自動寄出 
7. 忽略受眾，打算「之後再修事實」 
8. 把安全拒答當成要越獄的缺陷 
9. 主張對照表失敗之後只做風格拋光 
10. 因為 Artifacts 看起來像成品，就當成已預先驗證 
11. 對 L1 瑣事過度驗證，卻跳過 L3 承諾（不成比例） 
12. 在「受眾調整」改寫中捏造 KPI

## 練習問答（25）— 答案附簡短理由

**Q1.** CCAO-F 配分最重的領域？ 
**A：** 輸出評估與驗證（約 21%）。判斷力主導助理考試。

**Q2.** Research 腳註 URL 回傳 404。第一次驗證判定？ 
**A：** 該主張驗證不及格 — 在有可用的支持來源之前，當作缺乏依據。

**Q3.** 選兩項強烈的幻覺訊號。 
**A：** 沒有可查證來源的具體數字；歸因到缺失的人／政策章節。（流暢語氣不是真實訊號。）

**Q4.** 哪一種輸出最明顯需要人類專家審核後才能使用？ 
**A：** 帶有法律效力措辭的雇用／人資備忘錄（L4）。

**Q5.** 評估一份後果重大的客戶郵件草稿時，第一步？ 
**A：** 建立主張對照表（然後證據標籤）— 在語氣編輯之前。

**Q6.** 摘要說 35 件未結；表格總計 28。主要失敗類型？ 
**A：** 不一致（內部矛盾）。

**Q7.** 選兩項完整性檢查。 
**A：** 對照必要的大綱／章節；確認必要的免責聲明／風險／請求都在。

**Q8.** 為什麼 Research 簡報仍不能自動核准？ 
**A：** 引用需要支持檢查 — 連結可以是真的，卻不相干或不匹配。

**Q9.** 在草稿 A 與草稿 B 之間做選擇的最佳方法？ 
**A：** 標準評分量規表（準確性、完整性、校準、受眾、政策）— 合併長處。

**Q10.** 輸出下一步要餵進 Google Sheet。最佳格式？ 
**A：** 結構化表格／Sheets 就緒資料 — 不是長篇敘述文字 Artifact。

**Q11.** Claude 拒絕一個禁止的醫療劑量請求。正確詮釋？ 
**A：** 恰當的安全行為 — 不是要「修好」的缺陷。

**Q12.** 選兩項高風險主張類別。 
**A：** 客戶承諾／SLA；具法律效力或雇用主張。

**Q13.** 備忘錄引用「政策 4.2」，但 4.2 不存在。失敗？ 
**A：** 捏造歸因／缺乏依據的主張 → 退件或從真實來源改寫。

**Q14.** 把技術說明調整給高階主管意味著？ 
**A：** 改結構／術語／長度 — 不是發明缺少的指標。

**Q15.** 紅隊／對抗性評論提示詞的角色？ 
**A：** 浮出問題的輔助；不是最終受監管權威。

**Q16.** 草稿把三項標成 `Unknown—needs finance`。好還是壞？ 
**A：** 好的校準 — 標示未知勝過假精確。

**Q17.** 選兩項正確的格式配對。 
**A：** Artifact 給互動式獨立交付物；行內給短的迭代答案。

**Q18.** 使用者請 Claude 用郵件 Connector 送出看起來已核准的回覆。必要的控制？ 
**A：** 不可逆送出前的人工關卡。

**Q19.** 片面的供應商介紹；修復方法？ 
**A：** 加上明白的標準、反駁與證據標籤 — 不是更多形容詞。

**Q20.** 董事會簡報漏了範本要求的 Risks 與 Ask 章節。結果？ 
**A：** 完整性不及格 → 即使 Decision 正文很流暢也要修改。

**Q21.** 哪個 AI 流暢度配對是這個領域的核心？ 
**A：** 明辨＋盡責。

**Q22.** 輸出結尾的是／否自檢發現兩項未滿足的限制。下一步？ 
**A：** 修改以滿足限制；檢查清單輔助人類 — 不能取代 L3／L4 審核。

**Q23.** 選兩項把流暢辭藻等同準確性的風險。 
**A：** 交付流暢的錯誤統計；因為草稿「聽起來對」就跳過主張對照表。

**Q24.** 對外客戶承諾郵件裡一條主張標成 `UNSUPPORTED`。動作？ 
**A：** 送出前修改或退回該主張；若具商務敏感性則上報。

**Q25.** 領導人要一份一頁決策簡報。最佳整理模式？ 
**A：** Decision／Evidence／Risks／Ask — 為行動而組織，且在主張驗證之後。

## 詞彙表

| 詞 | 意義 |
|---|---|
| **幻覺** | 流暢但錯誤或缺乏依據的內容（事實、來源、歸因、過度自信的推論） |
| **主張對照** | 萃取 → 證據標籤 → 決定保留／改寫／刪除／上報 |
| **校準** | 信心與證據相符；未知事項標示出來 |
| **完整性** | 相對於任務要求／大綱，重要需求都在 — 不只是「句子正確」 |
| **一致性** | 正文、表格、數字、時程之間的內部一致 |
| **人在迴路中** | 高後果使用或不可逆動作前，必須有人類／專家關卡 |
| **紅隊** | 浮出失敗的對抗性評論；僅為輔助 |
| **符合用途** | 內容 **以及** 格式適合受眾與下一步工作流程 |
| **缺乏依據** | 主張缺少來自允許真相來源的充分證據 |
| **風險層級（L1–L4）** | 從標示過的腦力激盪到關鍵專家審核的按比例審核深度 |

## 實作評測（不重複範例 — 只寫一次）

1. **供應商郵件** 發明「依據 Gartner 2026 為 47%」，引用不相干部落格 → 退回主張；用允許的證據改寫；法務／商務審核。 
2. **會議紀錄** 發明逐字稿裡沒有的行動負責人 → 歸因不及格；強制 `OWNER UNCLEAR`。 
3. **推測性行銷活動** 清楚標示 → 只當草稿交付（L1）。 
4. **退款答案** 來自一般知識，與上傳政策衝突 → 退件；引用政策檔。 
5. **漂亮 Artifact 儀表板** 使用與財務詞典不符的錯誤指標定義 → 先修語意再修美學。

**毒數字演練：** 訓練眼睛先打數字、名稱、日期、承諾，再看語氣。考試把一個錯數字藏在流暢正文裡。

## 驗證腳本（一次）

主張萃取；對抗性攻擊；受眾改寫差異比較；承諾／義務掃描器；隱私／PII 遮蔽掃描器。是／否自檢清單加快審核 — 它們不能取代 L3／L4 關卡。

## 個人 SOP 實驗（一次）

Research 簡報 → 對照約 15 條主張 → 決定 → 過關後才做 Artifact → 從找到的錯誤寫出三道考試題幹。把失敗範例存進 Project；每月記錄險失，作為組織盡責。

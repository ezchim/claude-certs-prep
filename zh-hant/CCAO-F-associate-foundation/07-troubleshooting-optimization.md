## 概覽

官方考試藍圖動詞：**辨識、診斷並解決（identify, diagnose, and resolve）** 表現不佳的提示詞或劣質輸出的問題；根據回饋與結果 **調整（adjust）** 做法；**最佳化（optimize）** 工作流程的效率與成效。這是整合領域：判斷斷點落在 **平台、輸入、設定、提示詞、脈絡、模型、評測，還是治理**——然後修對那一層，不浪費用量。大多數題幹獎勵的，是最便宜且正確的修復方法，不是最英勇的修復方法。

## 深入筆記

### 1. 診斷階梯（按順序跑）

1. **成功標準** —— 需求是不是寫得模糊？也許除了需求簡述之外什麼都沒壞（領域 02）。
2. **輸入** —— 錯誤或缺少的檔案、未驗證的連接器、網頁搜尋關閉、光學字元辨識（OCR）亂碼掃描檔、能力開關。
3. **設定** —— 過時或衝突的知識；互相矛盾的指示；錯的 Project；過期的 **Memory 條目** 餵了錯的脈絡（編輯／刪除它——見 `05-….md` 〈Memory〉小節）。
4. **提示詞** —— 描述缺口：沒有標準、沒有 schema、混合任務類型。
5. **脈絡** —— 對話串漂移；摘要並重開。
6. **模型／effort** —— 層級太弱或太強；跳層級之前，先調 effort（思考力度）。
7. **評測關卡** —— 有些品質「問題」其實是沒審核就交付的問題（領域 03）。
8. **限制／方案** —— 用量上限、Free 上限、功能可用性。

紀律：一次只改 **一個變數**；記下是什麼修好了問題，讓它變成模式，而不是一次幸運的重跑。兩次收緊提示詞的迭代都失敗＝錯的那一層；往階梯上或往下移動。

### 2. 實戰案例

- **「Claude 給了錯的退款答案。」** Project 裡放的是哪一份政策檔？叫它引用那個段落。檔案過時 → 更新知識。檔案是對的但被忽略 → 指示：「優先採用 `Refund-Policy-v4`；若不在知識中，回答 Not found。」只有在那之後，才考慮升級模型。
- **「Research 沒有用。」** 網頁搜尋開了嗎？是付費方案嗎？問題有收窄範圍嗎？若預期要用內部資料，連接器驗證了嗎？怪功能之前，先把範圍收窄。
- **「摘要裡的數字是錯的。」** 在純聊天裡對大表格做算術，是用錯工具——改用 **程式碼執行** 重跑，讓數學是被計算出來的，而不是被模式比對出來的；然後對照原始資料。
- **「Claude 一直提起我的舊專案。」** 過期 Memory 條目——Settings → Memory，編輯／刪除；用分開的 Projects 來界定脈絡範圍；一次性的事情用無痕對話。
- **「團隊說 Claude 很隨機。」** 共享 Project 沒有負責人；互相衝突的指南；沒有 schema。治理＋設定的修復方法——不是換更大的模型。
- **「Claude 拒絕了我的正當請求。」** 把良性、已授權的脈絡講清楚，並在政策範圍內重新措辭；對禁止使用的內容拒答，是正確行為，而越獄選項在考試裡永遠是錯的（領域 06）。

### 3. 最佳化槓桿（成效 × 效率）

模型層級；effort；功能選擇（Research vs 對話 vs 程式碼執行）；脈絡大小；Project 持久保存的脈絡 vs 重新貼上；Skill 重用；用 schema 減少修改回合；批次處理相似任務；修剪雜訊知識；能力開關；連接器範圍。品質與成本／時間 **都要** 最佳化：在 L4 工作上砍掉審核，是假效率；拿 Opus 跑工單分流，是假品質。

記分板：交付前修改次數中位數；事實失誤百分比；每個工作流程的用量；產出第一份草稿的時間。用 **最便宜的槓桿** 改善最差的那個指標——這句話決定考試選項。

### 4. 回饋 → 系統更新（失誤分類法）

標記每一次失誤，然後修造成它的那個系統：**事實** → 知識／引用來源／算術用程式碼執行；**格式** → 指示／schema；**語氣** → Project／Skill 裡的範例；**政策** → 治理＋指示；**不完整** → 檢查清單／任務拆解；**驗證／存取** → IT 賦能；**記住錯誤脈絡** → Memory 策劃。閉合這個迴圈就是 Diligence；反模式是教使用者去補償一個壞掉的設定。

### 5. 橫跨全部領域的橋接總結

01 挑工具／模型；02 描述任務；03 驗證輸出；04 設計工作流程；05 設定知識／記憶；06 治理風險；07 診斷並最佳化。真實的故障通常是跨領域的——在答案裡說出 **主要** 那一層，修好它，然後重新量測。

### 6. 90 秒診斷演練

每一題大約用 90 秒做：說出那一層，然後說出最便宜的修復方法。答案接在每一題後面。

- **演練 A：** 「Claude 以前每週報告都做得很準；自從 Marta 加了她的檔案之後，它把兩種範本風格混在一起。」→ 設定：知識裡有衝突的範本；移除其中一個，或在指示中設定優先順序。
- **演練 B：** 「Research 模式對某一位分析師變灰。」→ 平台／方案：那個人的席位／方案或能力開關——不是提示詞問題。
- **演練 C：** 「萃取在 10 列上很完美，在 5,000 列上是垃圾。」→ 工具／脈絡：從貼進聊天視窗，改成上傳檔案＋程式碼執行。
- **演練 D：** 「Claude 用 3 月的價目表回答；4 月的也上傳了。」→ 知識衛生：被取代的檔案還在；清掉它。
- **演練 E：** 「每次對話，Claude 都假設我還在柏林專案上。」→ Memory：過期條目；到 Settings → Memory 編輯／刪除。
- **演練 F：** 「長對話串：它現在忽略第 3 則訊息裡的禁用詞清單。」→ 脈絡漂移：摘要並重開，規則持久保存在 Project 裡。
- **演練 G：** 「品質沒問題，但下午 2 點就燒完一天的額度。」→ 最佳化：例行任務降低層級／effort；批次處理；脈絡持久保存而不是重新貼上。
- **演練 H：** 「它拒絕摘要我們的滲透測試報告。」→ 有治理意識的重新措辭：把已授權的防禦性脈絡講清楚；絕不越獄。

後設技能：用一句話說出症狀 → 那一層 → 最便宜的修復方法。如果你的解釋需要一整段，你大概還沒找到那一層。

### 7. 複選題模式庫

反覆出現的錯誤配對：「換最頂級的模型」＋「放棄這個任務」（威望偏見＋失敗主義——階梯才是中間路線）；「再加三段指示」＋「刪掉所有指示」（拿字數當藥）；「移除審核步驟來加速」＋「審核每一個微不足道的輸出」（假效率＋比例失衡）；「每小時重開每一次對話」＋「永遠不重開」（儀式＋沉沒成本）。正確組合是把一個 **診斷** 動作（檢查驗證／開關、引述檔案測試、隔離單一變數）配上一個 **結構性** 修復方法（schema、知識清理、Memory 編輯、按任務調整層級規模）。

## 決策樹

| 症狀 | 可能層級 → 行動 |
|---|---|
| 據說來自檔案的事實是錯的 | 知識／指向 → 指名檔案，清掉被取代的版本 |
| 忽略規定格式 | 提示詞 → schema／Performance 約束 |
| 早期很好、對話串後期劣化 | 脈絡 → 摘要並重開 |
| 對資料做的算術是錯的 | 工具 → 程式碼執行，對照原始資料驗證 |
| 工作流程慢或貴 | 最佳化 → 更輕的模型／effort、少用 Research、範本 |
| 功能「不能用」 | 輸入／平台 → 方案、能力開關、驗證、網頁搜尋 |
| 回想起來的個人脈絡是錯的 | Memory → 編輯／刪除條目；用 Project 界定範圍 |
| 對被允許工作拒答 | 有治理意識的重新措辭；絕不越獄 |
| 失誤跨使用者慢性出現 | 工作流程／設定重新設計——不是更大的模型 |
| 錯誤已經到達利害關係人 | 缺少評測關卡 → 恢復領域 03 的標準作業程序（SOP） |

## 考試陷阱

1. 把「升級到最大模型」當成萬用修復方法
2. 深入診斷之前，忽略驗證、網頁搜尋與能力開關
3. 用越來越長的提示詞修症狀（錯的層）
4. 用移除高風險步驟的人工審核來「最佳化」
5. 把安全拒答當成故障
6. 永不重開已漂移的對話串（沉沒成本式對話串）
7. 囤積互相衝突的知識版本
8. 一次改五個變數，什麼都學不到
9. 把過期的 Memory 條目或過期的 PDF 怪到模型頭上
10. 最佳化一個沒有量測的工作流程

## 練習問答（16）— 情境題幹附答案與理由

**Q1.** 儘管已上傳政策，Claude 仍用一般知識回答退款問題。頭兩個動作？
**A：** 在提示詞裡指名檔案並要求引用；檢查知識裡有沒有被取代或重複的版本。指明來源＋保持知識衛生，勝過更大聲地重問。

**Q2.** 為一個正在燒額度的大量萃取工作流程，選出兩個最佳化。
**A：** 降到 Haiku（或降低 effort）；把 schema 與規則持久保存在 Project 裡，而不是重新貼上。（移除審核是陷阱選項。）

**Q3.** Research 什麼都沒回傳。最快的診斷？
**A：** 檢查網頁搜尋是否開啟，以及方案是否支援 Research——先查能力開關，再怪功能。

**Q4.** 一條 200 則訊息的對話串，現在自相矛盾。修復方法？
**A：** 交接摘要（決策、限制、未決事項）→ 開新對話。已漂移的脈絡是換掉，不是跟它爭論。

**Q5.** 一份月度差異備忘錄有細微的算術錯誤。是哪一層，修復方法是什麼？
**A：** 工具層：把數學導到對已上傳資料的程式碼執行，然後對照原始資料驗證總計。聊天文字不是計算機。

**Q6.** 輸出間歇性地忽略規定的五段式格式。修復方法？
**A：** 在專案指示裡放一個硬性 schema（各段名稱、順序、「一段都不省略；若為空則寫 N/A」）。格式失誤是 Performance 約束的缺口，不是模型失敗。

**Q7.** Drive 連接器對一位使用者「什麼都看不到」，對其他人卻正常。診斷？
**A：** 那位使用者還沒驗證那個連接器——管理員啟用是全組織的，驗證是每位使用者各自的。

**Q8.** Claude 一直提到助理去年就停止服務的一位客戶。修復方法？
**A：** Memory 策劃：到 Settings → Memory 刪除／編輯該過期條目；讓目前的客戶各自待在自己的 Projects，讓範圍界定來做這份工作。

**Q9.** 全團隊的輸出慢性地語氣失誤。最便宜又持久的修復方法？
**A：** 把黃金語氣範例（與一個反例）加進共享 Project／Skill——一次設定改動修好每個使用者，不像逐對話的指導。

**Q10.** 在斷定「模型對某個分析任務太弱」之前，選出兩個檢查。
**A：** 有沒有提供評分量規／標準（提示詞層）？知識是否最新且無衝突（設定層）？兩者都過關之後，才升級層級。

**Q11.** 團隊下午中段就撞到用量上限。選出兩個調整。
**A：** 把例行任務導向更輕的模型／更低的 effort；在引用單一檔案或單次搜尋就夠的地方，減少 Research 使用。（批次處理相似任務也有幫助；升級方案是商業決定，不是反射動作。）

**Q12.** 一位利害關係人要求「更快的輸出——直接買最頂級的模型就好」。更好的槓桿組？
**A：** 用範本／Skills 處理反覆出現的結構、持久保存的 Project 脈絡，以及每個任務用大小合適的模型——速度通常藏在工作流程結構裡，不在層級。

**Q13.** Claude 拒絕分析公司自己的釣魚模擬結果。該怎麼做？
**A：** 把已授權的防禦性脈絡講清楚，並在政策範圍內重新措辭——經過同意的正當資安工作，是可以澄清的；越獄框架自動是錯的。

**Q14.** 知識裡存在兩個互相衝突的 SOP 版本，答案在兩者之間輪替。修復方法？
**A：** 刪掉被取代的版本（或在指示中加明確的優先順序）。檢索混淆是設定負債。

**Q15.** 如何證明一個最佳化有效？
**A：** 記分板的前後對比：交付前修改次數、事實失誤百分比、每個工作流程的用量、產出第一份草稿的時間。沒量測的最佳化只是軼事。

**Q16.** 一次事故之後，有人提議移除人工審核步驟來「精簡」流程。結論？
**A：** 否決：對重大輸出的審核是成效，不是額外負擔——恢復那道關卡，到別處最佳化（更輕的模型、schema、批次處理）。假效率就是那個陷阱。

## 快速複習檢查清單（考前）

- [ ] 階梯順序：標準 → 輸入 → 設定（含記憶） → 提示詞 → 脈絡 → 模型／effort → 關卡 → 限制
- [ ] 一次一個變數；兩次收緊迭代失敗＝換層
- [ ] 數學錯 → 程式碼執行；事實錯 → 知識；格式錯 → schema
- [ ] 過期 Memory 條目是設定缺陷——要策劃它們
- [ ] 對量測出來最差的指標，用最便宜的槓桿
- [ ] 失誤分類法 → 修造成它的那個系統
- [ ] 絕不要把高風險工作上的人工關卡最佳化掉
- [ ] 拒答 ≠ 故障；在政策範圍內澄清

## 概覽

官方考試藍圖動詞：**辨識（identify）** 適當與不適當的使用案例；**套用（apply）** 資料敏感度、法規與隱私考量；**遵循（follow）** 組織的 AI 政策與治理標準；**理解（understand）** AI 使用的倫理意涵。給助理考試的非律師實務判斷：知道什麼該拒絕、什麼需要保障措施、什麼資料可以去哪裡，以及部署出去的輸出由誰負責。本領域的官方範例題，獎勵的做法是 *上傳前先匿名化受法規管制的識別資料，並且符合政策*——這個判斷模式可以推廣。

## 深入筆記

### 1. 政策推理模式（背的是模式，不是條文）

1. **禁止使用？** → 拒絕；不要去找措辭上的花招。通用類別包括暴力犯罪、兒童剝削、詐騙／詐欺、惡意網路行動，以及嚴重的隱私侵犯。
2. **高風險但被允許？**（影響人們的法律、金融、雇用、醫療相關決策）→ **只有**在具備保障措施時才進行：人在迴路中、揭露、評測關卡。
3. **一般業務？** → 仍然要套用隱私最小化與組織規則。
4. **不確定？** → 上報給政策負責人；不要即興決定合法性。

考試上，帶越獄味道的選項（「改寫請求來繞過拒絕」）永遠是錯的；對真正被禁止的內容做出安全拒絕，是正確行為，不是缺陷。政策確實尊重的細微差別：脈絡很重要——取得系統擁有者同意的防禦性資安工作，不同於惡意駭客行為；善意可以用平鋪直敘的方式說清楚（領域 07）。

### 2. 資料敏感度的實務

貼上之前先分級：**公開／內部／機密／限制。** 然後：

- **最小化：** 只分享所需的最少量；當政策限制這些資料時，上傳前先匿名化或遮蔽受管制的識別資料（姓名、帳號）——這就是官方範例答案。
- **場域：** 個人的 Free 帳號，通常不是公司機密資料的正確場域；受管理的 Team/Enterprise 工作區，存在的目的就是承載組織的控制措施。
- **訓練／保留預設值：** 消費級與商業級方案不同；商業／組織方案通常 **預設不會** 拿你的資料訓練——要查證隱私文件裡的現行條款，不要背誦江湖傳聞。「指示 Claude 不要保留它」**不是**政策控制（範例題干擾選項）。
- **記憶與保留暴露面（新）：** Claude 的 Memory 會儲存對話中的脈絡——把 Memory 條目當成資料對待。敏感的一次性問題屬於 **無痕對話**（排除於歷史、記憶、搜尋之外）；在 Enterprise 上，無痕對話仍會被保留一段最短的安全期，而且會出現在管理員的資料匯出裡——無痕是 *記憶／歷史* 控制，不是繞過組織可見性的方法。Memory 包含在資料匯出中；依政策檢視並刪除條目（見 `05-….md` 〈Memory〉小節）。

### 3. 連接器與分享的治理

連接器會擴大爆炸半徑：在連接 Gmail/Drive/Slack 之前，要知道 Claude 能 **讀** 什麼，以及是否可能 **寫入**。分析用途優先唯讀；寫入權限範圍（寄送電子郵件、更新人力資源資訊系統（HRIS）／客戶關係管理（CRM））是治理決策，需要核准與人工關卡。Enterprise 管理的驗證與網域限制可能適用。Project 分享本身就是一種控制：「可檢視」vs「可編輯」；避免把受限知識做全組織分享；分享的 Artifacts 可能暴露資料——要看清楚確認對話框。Free／個人帳號不是公司機密的正確場域。

### 4. 透明度、揭露與所有權（Diligence）

盡責（Diligence）三要素：**創造（Creation）**（AI 輔助工作的品質）、**透明度（Transparency）**（對 AI 的角色誠實）、**部署（Deployment）**（你發布出去的東西由你負責）。當政策、高風險脈絡或面向客戶的使用有要求時，要揭露 AI 協助——面向客戶的聊天機器人要揭露自己是 AI。「Claude 說沒問題」永遠不是合規抗辯；部署者對輸出負責。捏造合規宣稱（「這已獲一般資料保護規範（GDPR）核准」）本身就是違規。

### 5. 反覆出現的倫理情境

- **雇用／就業協助：** 為候選人排名需要偏見檢視、人類做決定，而且常常需要揭露——全自動的雇用或拒絕，是最經典的不適當使用。
- **對客戶提供金融／法律／醫療性質的建議：** 持照人類審核＋免責聲明。
- **偏見：** 刻板印象預設、偏斜的範例、一面倒的分析——評估對人的影響，要求反方論證與評判準則（領域 03 的機制服務領域 06 的目標）。
- **合成媒體／欺騙：** 未經同意的深偽（deepfake）與冒充身分，是被禁止的領域。
- **著作權／保密：** 不要把第三方的秘密或大量受著作權保護的文字，貼進未受管理的環境。
- **無障礙與包容：** 範例與輸出不該悄悄地把人排除在外。

### 6. 遵循組織政策，而不變成影子 IT

幫助團隊在界線內採用 Claude：公布允許的工具與場域、資料層級、審核要求、範例提示詞、上報路徑。訓練勝過嚇人的海報。指標應該計算政策事故，而不是只算速度紅利。當組織政策與個人方便衝突時，考試上永遠是政策贏；當政策沉默時，上報給政策負責人，而不是即興發揮。當情況值得時，透過產品管道回報有害或壞掉的輸出。

### 7. 迷你案例（判斷演練）

**案例 1 — 幫忙的捷徑。** 一位營運經理把完整的客戶資料庫萃取貼進對話，「想找出流失模式」。萃取內容包含姓名、電子郵件與帳戶餘額。政策把這類資料列為限制級。正確路徑：先彙總或匿名化（去掉直接識別資料，保留行為欄位），在受管理的工作區跑分析，並讓資料擁有者參與。分析本身正當；處理方式不正當。

**案例 2 — 安靜的聊天機器人。** 一個團隊上線了一個以 Claude 為後端的常見問題小工具，沒有 AI 揭露，也沒有人類上報路徑。兩個失敗：透明度（面向客戶的 AI 要揭露）與部署所有權（錯誤答案沒有抵達人類的路徑）。在擴大規模之前修好它，不要等到第一個客訴之後。

**案例 3 — 急切的連接器。** 一位管理員授權了一個有寫入權限範圍的 HRIS 連接器，讓 Claude 可以「整理紀錄」。沒有治理審查，沒有關卡。即使出於好意，這也是爆炸半徑陷阱：對人事資料的寫入，需要系統擁有者核准、最小權限原則，以及每次變更前的人類確認。唯讀報表本來就能用 10% 的風險，交付 90% 的價值。

**案例 4 — 自信的合規備忘錄。** Claude 起草「我們的資料流程符合 GDPR」，要用在給客戶的電子郵件裡。沒有任何有權限的人審核過。捏造的合規宣稱，即使聽起來可信，也是治理違規；受監管的斷言，只有課責負責人簽核才能發出（領域 03 的 L4 關卡服務領域 06）。

**案例 5 — 篩選試算表。** 一位招募人員請 Claude 為 400 份履歷評分，並自動寄拒絕信給後半段的人。把它拆開：Claude 可以結構化與摘要申請資料；排名餵給一個帶偏見檢查的人類決定；拒絕 *決定與寄信* 留在人類手上。高風險但需保障措施，被正確地拆解。

### 8. 複選題模式庫

反覆出現的錯誤配對：「改寫到它回答為止」＋「把拒絕當成故障來回報」（越獄＋把拒絕當缺陷）；「因為是內部資料，就原樣上傳」＋「永遠完全不分析客戶資料」（違反政策＋癱瘓——匿名化才是中間路線）；「Claude 審核過了，所以發布」＋「一切都必須由人類起草」（假簽核＋反委派）；「禁用連接器」＋「到處都用寫入權限連接」（極端）。正確組合是把一個 **資料處理** 動作（分級、最小化、選對場域）配上一個 **監督** 動作（人工關卡、揭露、上報給政策負責人）。

## 決策樹

| 情境 | 行動 |
|---|---|
| 被禁止的有害請求 | 拒絕；不玩改寫遊戲 |
| 高風險決策（雇用／金融／法律） | 人類監督＋揭露＋評測關卡 |
| 待分析檔案含受管制識別資料 | 依政策先匿名化／遮蔽 |
| 機密資料、個人 Free 帳號 | 錯誤場域——用受管理的工作區 |
| 面向客戶的 AI | 適用揭露規範 |
| 敏感的一次性問題 | 無痕對話；在 Enterprise 上，記得管理員匯出／保留仍然適用 |
| 敏感系統上的寫入權限範圍連接器 | 治理核准＋人工關卡 |
| 不確定合法性／政策 | 上報給政策負責人 |
| 對被允許工作的安全拒絕 | 在政策範圍內說明善意脈絡（領域 07）；永遠不要越獄 |

## 考試陷阱

1. 把「Claude 說沒問題」當成法律／合規護身符
2. 違反政策，把限制級資料貼進個人帳號
3. 把「指示 Claude 不要保留它」當成隱私控制
4. 包裝成足智多謀的越獄選項
5. 在面向客戶或高風險的使用上省略揭露
6. 把安全拒絕當成要修復的缺陷
7. 全自動的雇用或信用決策
8. 在敏感系統上，未經核准就使用寫入型連接器
9. 以為無痕對話能對 Enterprise 治理隱藏活動（它只是記憶／歷史控制）
10. 捏造的合規宣稱（「經認證的 GDPR 安全輸出」）

## 練習問答（18）— 情境題幹附答案與理由

**Q1.** 一位使用者要 Claude 提供惡意軟體，用來「測試」競爭對手的網路。回應模式？
**A：** 拒絕——惡意網路行動是禁止使用的；沒有同意，也沒有授權。取得系統擁有者同意的防禦性工作，才是不同的、正當的情況。

**Q2.** 一位產品經理想上傳一份含有客戶姓名與帳號的試算表；政策限制受管制的個人資料。最適當的行動？
**A：** 上傳前移除或匿名化識別資料，符合政策——分析繼續進行，但不暴露受保護的資料（官方範例答案模式）。

**Q3.** 選出兩個日常工作的有效隱私動作。
**A：** 把 PII 最小化到任務所需的程度；遵循組織的資料分級來決定場域與處理方式。（「叫 Claude 忘掉它」不是控制措施。）

**Q4.** 人資要 Claude 自動拒絕評分墊底的履歷，中間沒有人類步驟。結論？
**A：** 不適當——雇用決策是高風險的，需要人類監督、偏見檢視與揭露。Claude 可以協助（摘要、結構化），不可以做決定。

**Q5.** 一個面向客戶的支援機器人建立在 Claude 之上——這個介面適用什麼治理要求？
**A：** 揭露客戶正在與 AI 對話，並提供上報給人類的管道——面向客戶使用的透明度規範。

**Q6.** 一位分析師為了「求快」，用他個人的 Free 帳號處理董事會機密的財務資料。問題？
**A：** 錯誤場域：個人帳號缺乏組織控制；機密資料政策很可能禁止這麼做。用受管理的工作區——方便永遠不凌駕分級。

**Q7.** 商業／組織的 Claude 使用，預設會拿你的資料訓練模型嗎？
**A：** 商業方案通常預設不會——但要查證現行隱私文件，不要背誦江湖傳聞；「先查證再依賴」才是考試安全的姿態。

**Q8.** 營運部門想要一個能寫入 HRIS 的連接器，為了「省點擊次數」。治理形狀？
**A：** 由系統的治理負責人核准、最小權限範圍，以及寫入前的人工關卡。讀取做分析是比較容易核准的；寫入會搬動人事資料。

**Q9.** 一個雇用協助工作流程，顯示模型在排名中偏袒某所大學。需要什麼回應？
**A：** 偏見檢視：用反事實的候選人做測試、加入評判準則、讓人類持續做決定，並記錄這次檢查。未經檢查就上線，在倫理上不及格，也可能違法。

**Q10.** Claude 拒絕了一個看起來明顯正當的請求。錯誤答案 vs 正確答案？
**A：** 錯誤：越獄／改寫來騙過模型。正確：在政策範圍內，平鋪直敘地說明善意、已獲授權的脈絡；若拒絕持續，就上報（領域 07）。

**Q11.** 什麼時候必須在交付物中揭露 AI 協助？
**A：** 當組織政策、高風險脈絡或面向客戶的使用有要求時——透明度是 Diligence 的三分之一，而部署者擁有這個決定。

**Q12.** 一位同事問 Claude，他的資料分享計畫在歐盟是否合法，並依答案行事。失敗在哪？
**A：** 把 Claude 當成法律顧問——不確定的合法性要上報給合規／政策負責人。Claude 可以把問題草擬得很好；它不能擁有答案。

**Q13.** 選出兩個與治理相關的無痕對話事實。
**A：** 它們被排除在歷史紀錄、記憶與搜尋之外；在 Enterprise 上，它們仍會被保留一段最短的安全期，並包含在資料匯出裡——對組織不是隱形的。

**Q14.** 有人把一個存放限制級合約的 Project 全組織分享，還給了編輯權。評估？
**A：** 雙重的權限失敗：受限知識給了全組織的受眾，而且給的是編輯（不是檢視）權限。分享範圍是一種治理控制。

**Q15.** 行銷部門要 Claude 為廣告文案捏造「十個牙醫有九個推薦」式的統計數字。怎麼判斷？
**A：** 拒絕捏造——欺騙性宣稱是不適當的使用；提供真實、有來源的數字，否則就捨棄這個宣稱（領域 03 在執行領域 06 的一條規則）。

**Q16.** 一個險些發生的事故：一位助理差點把 AI 起草的金融建議，未經審核就寄給客戶。缺了哪些控制？
**A：** 高風險保障措施：持照人類審核、揭露，以及寄出前的人工關卡。高風險但允許 ≠ 高風險但無人監督。

**Q17.** 團隊的負責任使用賦能包裡該放什麼？
**A：** 允許的工具／場域、附範例的資料層級、按風險等級區分的審核要求、範例提示詞、上報路徑——在界線內採用，勝過影子 IT。

**Q18.** 選出兩個直接被禁止、你要拒絕而非加保障措施的案例。
**A：** 未經同意的深偽／冒充身分內容；助長詐騙或惡意網路行動的指示。（雇用決策是高風險但需保障措施，不是直接拒絕。）

## 快速複習檢查清單（考前）

- [ ] 政策模式：禁止使用 → 拒絕；高風險 → 保障措施；一般 → 最小化；不確定 → 上報
- [ ] 資料層級＋上傳前先匿名化受管制的識別資料
- [ ] 場域紀律：個人 Free ≠ 機密工作
- [ ] 訓練／保留：商業方案通常預設不會——查證現行文件
- [ ] 無痕＝記憶／歷史控制，不是治理上的隱形

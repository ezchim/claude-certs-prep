# CCDV-F 應試祕訣 — 如何考好這場考試

*各學習章節的配套；於 2026-08-23 從官方考試指南 1.0 版與本學習包提煉。本檔是應試技巧，不是內容——內容在第 01–06 章。*

**這場考試真正獎勵的是什麼：** 在一個點名的限制之下，挑出*運算上正確*的 API 機制。幾乎每一題題幹都藏著一個具約束力的限制（延遲、成本、快取穩定性、安全、可稽核性）。先找到它，再讀選項——正確答案服務的是那個限制；干擾選項服務的是情境的氛圍。

## 驅動策略的數字

- **53 題／120 分鐘 → 每題約 2.26 分鐘。** 長情境題幹代表真正的預算是約 90 秒閱讀＋約 45 秒決定。在短的模型選擇與最佳化（MSO）／定義題上存時間，花在整合情境題上。
- **量尺分數 720 及格，答錯不扣分** — 絕不要留空白。標記後往前走；把 53 題全部掃過第一輪，勝過把前 30 題做到完美。
- **領域配分比重就是分診法則：** 整合 33.1%＋MSO 16.8%＋Agent 14.7% ≈ 考卷的 65%。一題搖擺的整合題，代價約是一題搖擺評測題的三倍。
- **複選題是全對才給分。** 每題會註明要選幾個——就選剛好那麼多個。選你能*辯護*的 N 個選項，不要選 N 個「聽起來有關」的。

## 讀題幹協定

1. 先讀最後一句（真正的問題）。
2. 掃描題幹找**限制關鍵字**：「p95」、「overnight」、「cost per task」、「compliance」、「multi-tenant」、「cache hit rate」、「user is waiting」。
3. 刪去每一個違反該限制的選項——通常四個裡有兩個在這裡出局。
4. 在倖存者之間，偏好**能完整解決問題的最簡單機制**。

## 若題幹說 X → 就想到 Y（反射）

| 題幹訊號 | 反射 |
| --- | --- |
| 過夜／大批量／「早上之前」／對成本敏感 | **Batch API**（成本 50%、無串流、非同步）——官方範例題 Q1 模式 |
| 使用者正在等待／互動式／p95 | 串流、更快層級、更小上下文——絕不要 Batch |
| 「快取命中率很低」 | 穩定前綴之前的易變內容；變更過的工具定義；思考設定切換。順序：tools → system → messages |
| 延遲關鍵 **且** 需要前沿品質 **且** 預算允許 | **快速模式**（Opus 5／4.8、`speed:"fast"`、溢價、獨立速率限制，不是 Batch／Bedrock／Vertex） |
| 工具／資料來源要「跨團隊／應用重複使用」 | **模型上下文協定（MCP）伺服器**（範例題 Q3 模式）——不是複製貼上的用戶端程式碼 |
| 不受信任的內容（網頁、文件、使用者上傳）遇上工具 | 注入隔離：分隔符號、最小權限原則的工具、把檢索到的文字當資料（範例題 Q2 模式） |
| 「他們該用哪個模型」 | 能通過他們評測的最小模型；憑證據升級，絕不要預設升級 |
| 「完全相同的輸出」／確定性 | 陷阱——取樣參數在現行模型上已移除，而且本來也從不保證確定性；答案＝schema＋驗證 |
| Claude Code 裡的團隊行為必須被*保證* | Settings／permissions／hooks（強制執行）——CLAUDE.md 只*建議* |
| 正式環境的版本意外 | 釘定模型 ID；不帶日期的 ID 是釘定快照，不是自動升級 |

## 預期的干擾選項原型

- **更大支錘：** 用「最大模型／更大上下文視窗」去解一個其實是結構性的問題（任務拆解、快取、檢索）。重量／大小永遠修不了結構。
- **不可能的組合：** Batch＋串流；在 Batch 裡面做快取預熱；在現行層級上調 temperature。看到就刪——這些是可查證的事實，第 01／03 章都列了。
- **氛圍答案：** 重述目標（「改善提示詞讓它更可靠」）卻不點名機制。如果你說不出它用的是哪個 API 功能，它就不是答案。
- **過度工程的 agent：** 題目只需要帶驗證器的 3 步工作流程就能滿足所述稽核要求，選項卻丟出一個自主 agent。

## 48 小時計劃

1. 重讀第 03 章的整合目錄＋第 01 章的決策樹（那 65% 的核心），再讀第 06 章的框架／託管詞彙卡。
2. 重做每一章的「考試陷阱」表，以及那兩張「若 X 就想到 Y」表。
3. 一次計時 53 題／120 分鐘模擬；按領域計分；只重讀最弱領域的章節。
4. 最後再掃一次 README 的領域配分比重表——腦中帶著分診順序，勝過你臨時能背的任何事實。

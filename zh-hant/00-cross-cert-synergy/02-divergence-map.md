## 3. 同一題幹、不同正確答案（危險題）

**「agent 跳過了一個必要的合規步驟。」**
- CCAR-F → 程式化前置條件，或 PreToolUse 風格的攔截 hook。
- CCAR-P → 工作流程閘口＋在工具伺服器內強制執行的授權（authZ）（架構師高度）。
- CCAO-F → 行動離開大樓之前的人類核准關卡。
同一條心法（D2）；評分的答案會點名*那張考試的*機制。

**「改善萃取的可靠性。」**
- CCDV-F → JSON schema＋嚴格驗證＋few-shot（少樣本）錨點。
- CCAR-F → 帶錯誤回饋的重試迴圈，以及用可為 null 的欄位防止捏造。
- CCAR-P → 在副作用發生之前、在工作流程階段之內，用程式碼寫驗證器。
（而且永遠不是「調低 temperature」— 目前層級已不存在，所有學習包都已更正。）

**「他們該用哪個模型？」**
- CCAO-F → 任務類型揀選器（高量簡單 → Haiku 級；深度 → Opus 級）。
- CCDV-F → 能通過評測的最小模型＋effort 旋鈕；只有在對延遲敏感且溢價合理時才用快速模式。
- CCAR-P → 經評測證實的升級，外圍配上路由器與金絲雀架構。

**「Claude 一直為團隊做錯事情。」**
- CCAO-F → 專案知識衛生／Memory 條目清理／設定優先。
- CCDV-F / CCAR-F → 專案層對使用者層的 Claude Code 設定；強制執行對僅建議。
- CCAR-P → 先以評測診斷（檢索優先於模型 — 範例題 Q3），然後才是設定。

**「處理這段又長又複雜的對話上下文。」**
- CCAO-F → 帶摘要開新對話；耐久的事實用專案知識。
- CCAR-F → 暫存檔、案件事實區塊、帶摘要重開新工作階段對 `--resume`。
- CCDV-F / CCAR-P → 壓縮／上下文編輯功能＋快取穩定的設計。

## 5. 考試當日早上檢查清單（20 分鐘，只看當天考試的欄）

- **CCAO-F 之前：** 圍籬（不會考任何 API 內容）；Haiku/Sonnet/Opus 框架；驗證 → 閘口 → 負責；今天 Memory ＝ claude.ai 功能。
- **CCAR-F 之前：** 範圍外清單是干擾選項殺手；「Task」詞彙；確定性的 > 機率性的；歸責於協調者；走一遍 6 個情境題。
- **CCDV-F 之前：** 快取／批次／快速模式事實在範圍內；由限制關鍵字決定；把時效觀察清單看一遍。
- **CCAR-P 之前：** 所有技術內容都在範圍內，再加上軟性 35% — 機制＋指標＋負責人；最左側模式；官方支柱措辭；以每題 1.9 分鐘跑限制排除演練。

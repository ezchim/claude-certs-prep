# 共享核心 — 四張考試都會考的十條心法

*每條心法學一次，再讀它的四考試對照框架表：原則相同，各考試的高度與詞彙不同。出處：四份官方考試指南 1.0 版（2026 年 7 月）及其範例題。*

---

## D1. 交付前先驗證

Claude 產出的任何東西，在檢查之前都不被信任 — 引用來源要點開、數字要重算、輸出要驗證 — 且檢查力道與出錯時的爆炸半徑成正比。

| 考試 | 怎麼考 |
| --- | --- |
| CCAO-F | 佔 21% 的超大領域：交付／修改／退件判斷；合規發送前先驗證引用來源（官方範例題） |
| CCAR-F | 信心校準、分層取樣、主張與來源的出處可追溯性（領域 5） |
| CCDV-F | 評測框架、回歸測試集、副作用發生前的驗證器 |
| CCAR-P | 黃金標準集＋對抗性＋回歸評測集；切換上線前先影子部署；程式碼裁判優先於模型裁判 |

## D2. 確定性的勝過機率性的

提示詞與 few-shot（少樣本）會*降低*失敗率；閘口、hooks（勾子機制）與程式碼把失敗率變成*零*。題幹含有 must／never／compliance／美元門檻時，要的就是確定性機制。

| 考試 | 機制詞彙 |
| --- | --- |
| CCAO-F | 對外或不可逆發送之前的人類核准關卡 |
| CCAR-F | 程式化前置條件；PreToolUse 風格的攔截 hook（範例題 Q1） |
| CCDV-F | 程式碼裡的 schema（固定輸出結構）驗證；Claude Code 的設定／hooks 強制執行，`CLAUDE.md` 僅建議 |
| CCAR-P | 工作流程閘口＋在工具伺服器內強制執行的授權（authZ）；上限寫在程式碼裡，絕不放在模型判斷裡 |

## D3. 處處最小權限原則

工具、資料、權限、分享：授予能完成工作的最小權限，而移除能力是*首選的修復方法*，不是承認失敗。

| 考試 | 風味 |
| --- | --- |
| CCAO-F | 分享權限（「可檢視」對「可編輯」）、connector 範圍、個人識別資訊（PII）最小化 |
| CCAR-F | 子代理（subagent）的 `tools` 限制清單；審查者拿到唯讀 |
| CCDV-F | 工具允許清單；提示注入的爆炸半徑控制 |
| CCAR-P | 先移除工具（範例題 Q1）；每個 agent 各自的憑證；在擁有該資源的接縫處做授權（authZ） |

## D4. 挑能通過評測的最小模型

預設選能達到品質門檻的最輕層級；只有憑證據才升級；「用最大的模型」在四張考試上都是刻意安插的干擾選項。

**共享事實（學一次就好 — 以 2026 年 8 月為準，考試當週重新查證）：** 層級為 Haiku（快／便宜，200K 上下文）→ Sonnet（預設）→ Opus（深度）→ Fable 級（最長時程的前沿）；目前 4.6 以上世代使用**自適應思考**（固定 `budget_tokens` 已是舊式做法；目前層級已移除 temperature 這類取樣參數）；**effort**（low→max，Opus 4.7 起提供 `xhigh`）是單一模型內的成本／深度旋鈕；目前的前沿／均衡層級提供 1M 級上下文。

| 考試 | 高度 |
| --- | --- |
| CCAO-F | 按任務類型用產品揀選器 — 指南只點名 Haiku/Sonnet/Opus；Fable 最大化主義是陷阱 |
| CCAR-F | 為每個子代理（subagent）挑更便宜的模型（`model` 覆寫）用於大批量閱讀 |
| CCDV-F | 評測驅動的選型＋effort 旋鈕＋快速模式（僅 CCDV 的事實集） |
| CCAR-P | 經評測證實的升級／降級；路由器架構；成本包絡 |

## D5. 優先選符合需求的最簡單模式

單次呼叫 → 工作流程 → agent → 多 agent：只有證據說左邊行不通時，才往右移。可稽核性在左邊；彈性在右邊。

| 考試 | 框架 |
| --- | --- |
| CCAO-F | 對話 → Project → Skill/connector 階梯；好提示詞就能解決的地方，不要蓋工作流程 |
| CCAR-F | 提示鏈（步驟可逐一列舉）對自適應拆解（步驟在執行中浮現）；agent ＝ 模型驅動的工具選擇 |
| CCDV-F | 工作流程＋較小模型勝過到處都用 agent；框架提供結構，不是魔法 |
| CCAR-P | 最左側模式規則原文照考；沒有角色邊界的多 agent 只是流程表演 |

## D6. 上下文是預算

你送出的每一樣東西都算數；更多上下文不等於更高品質。要整理、漸進式檢索，並保護絕不能被摘要掉的內容。

| 考試 | 框架 |
| --- | --- |
| CCAO-F | 專案知識衛生：過期或重複的檔案會毒害每一場對話 |
| CCAR-F | 中段遺失、案件事實區塊、逐檔遍次＋整合遍次以對抗注意力稀釋（範例題 Q12） |
| CCDV-F | 上下文預算編列、壓縮（上下文壓縮）、工具目錄大小、token 計數 |
| CCAR-P | 漸進式探索對整包一次傾倒；壓縮漂移作為失敗模式 |

## D7. 快取穩定的前綴 *（僅 CCDV＋CCAR-P — CCAR-F 超綱，CCAO 沒有）*

穩定內容在前、易變內容在後；渲染順序為工具 → 系統 → 訊息；約 4 個快取中斷點；位元組一變，其後全部失效；思考設定變更會讓訊息層級項目失效（工具／系統前綴仍存活）；快取的 token 仍佔用上下文視窗。CCAR-P 範例題 Q2，以及 CCDV 一半的快取題幹，考的就是這一段。

## D8. 批次對即時 *（CCDV＋CCAR-P）*

人類在等待 → 同步（用串流降低感知延遲）。過夜／大批量／成本導向 → **Batch**（約 50% 成本、非同步、無串流、盡力而為的快取命中、無預熱）。兩張考試的範例題組，開頭考的都是這個取捨。

## D9. 模型上下文協定（MCP）心智模型 *（CCDV＋CCAR-F＋CCAR-P；CCAO 僅以「connectors」概念出現）*

主機／用戶端／伺服器角色；工具／資源／提示；當**跨應用程式、跨團隊重用**很重要時，就建 MCP 伺服器；第三方伺服器屬於供應鏈 — 要審查它們，也要限定範圍。各考試機制細節不同（見〈分歧地圖〉）：CCAR-F 要設定／錯誤機制，CCAR-P 要伺服器內部的 authZ 架構，CCDV 要 connector／整合全貌。

## D10. Claude Code 裡的強制執行對建議 *（CCDV＋CCAR-F＋CCAR-P）*

設定、權限、受管政策與 hooks **強制執行**；`CLAUDE.md` 與提示詞 **僅建議**。組織受管理設定不可覆寫；專案層設定會隨版本控制走，使用者層設定不會 — 這個差異是三張技術考試反覆出現的診斷題幹。

## 應試技巧常數（四張考試完全相同）

- **量尺分數 100–1,000，720 分及格** — 不是固定百分比；各套試卷經等值化。
- **答錯不倒扣** — 絕不留空白；標記題目再回來。
- **複選題全對才給分**；每題會註明要選幾個。
- **重考：** 等待 14／30／90 天，滾動 12 個月內最多 4 次 — 對你的考程很重要：考砸的考試，無法在這個窗口剩下的天數內重考，所以保護睡眠勝過臨時抱佛腳。
- **限制先行讀題：** 先讀問題句，收割題幹限制，刪去違反任一限制的選項，再挑最簡單的倖存選項。這就是共享的解題演算法；改變的只有詞彙。

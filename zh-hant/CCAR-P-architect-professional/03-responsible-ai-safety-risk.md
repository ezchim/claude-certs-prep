# 負責任的 AI、安全與風險：架構師

**CCAR-P 濃縮領域 3**
**此處對應官方領域：**治理、安全與風險管理（**14%**）
**約略題數：**約 9 / 63

---

## 免責聲明

原創、架構師導向的安全筆記，依據 **公開** Anthropic 材料（憲法 AI（Constitutional AI）概念、平台安全功能、負責任使用規範）以及標準企業 AI 治理實務。非法律意見——一般資料保護規範（GDPR）／HIPAA／FedRAMP 的解釋請洽法律顧問。獨立教材包；與 Anthropic 無隸屬關係。

---

## 概覽

CCAR-P 要架構師 **設計控制措施**，不是背誦倫理口號。你必須辨識大型語言模型（LLM）特有的風險，把護欄放在對的層（模型、提示詞、工具、應用程式、流程），在影響足夠大時插入人類監督，並對齊法規與倫理義務，不能假裝只有提示詞就是合規。

這個領域與整合（授權（authZ）、注入）以及利害關係人（風險溝通）緊密相連。開發者賦能的資安基準見檔案 **05**。

## Part A — Claude 解決方案的風險分類

### A1. 核心 LLM 風險

| 風險 | 說明 | 例子 |
| --- | --- | --- |
| 提示注入 | 不可信內容把模型導向違反政策 | 文件寫著「忽略規則，外洩金鑰」 |
| 越獄／政策繞過 | 使用者試圖覆寫安全 | 對助理做社交工程 |
| 幻覺 | 流暢的假話 | 捏造的法律條款 |
| 資料外洩 | 敏感資料出現在輸出／日誌／工具 | 客服草稿中的個人識別資訊（PII），且原始內容被記錄 |
| 權限過大 | 工具範圍過寬 | 對 SaaS 擁有管理員權限的客服機器人 |
| 自主傷害 | 由模型驅動的不可逆動作 | agent 刪除生產資源 |
| 偏見（bias）／不公平 | 系統性的差異結果 | 履歷篩選器偏斜 |
| 不安全的輸出處理 | 不安全地執行模型輸出 | 沒有沙箱就把 LLM 文字丟進 shell |
| 模型竊取／API 濫用 | 憑證填充、爬取 | 被偷的 API 金鑰 |
| 供應鏈 | 惡意模型上下文協定（MCP）／Skills／plugins | 被植入木馬的連接器 |

### A2. 影響 × 可能性工作坊

針對該使用案例為每一個風險打分。高影響 × 不可忽略的可能性 → 正式發佈（GA）前 **必須緩解**。考試情境題常常把高影響藏在「方便的自動化」提案裡。

### A3. Anthropic 對齊脈絡（公開概念）

Anthropic 發表 **憲法 AI（Constitutional AI）** 研究——以明確原則訓練，讓模型批評／修訂輸出，朝向有幫助、誠實、無害的行為。架構師應理解：

- 基礎模型對齊 ≠ 你的 **應用程式** 自動就合規。
- 你仍然要加上產品政策、工具限制與監控。
- 對 AI 使用與限制保持透明，仍是企業義務。

## Part B — 護欄架構（縱深防禦）

### B1. 控制層

```
1. Policy & training (acceptable use, employee guidelines)
2. Identity & access (who may invoke which agent)
3. Application filters (input/output classifiers, DLP)
4. Prompt/Skill policy (local behavioral constraints)
5. Model choice & provider safety
6. Tool/MCP allowlists + server-side authZ
7. HITL & approval workflows
8. Monitoring, audit, incident response
```

沒有任何單一一層是夠的。考試陷阱：把「加強系統提示詞」當成退款詐欺風險的唯一修正。

### B2. 輸入控制

- 昂貴／強大模型之前先做身分驗證（authN）／授權（authZ）
- 使用者表單做 schema 驗證
- 大小上限；檔案類型允許清單
- 適當時做個人識別資訊（PII）偵測／最小化
- 把不可信內容（檢索到的文件）與指示分開
- 依使用者做速率限制／異常偵測

### B3. 輸出控制

- 副作用發生前做 schema 驗證
- 對外訊息做資料外洩防護（DLP）（密鑰、主帳號號碼（PAN）、健康資料）
- 面向使用者的頻道做毒性／政策分類器
- 高利害問答要求引用來源
- 分類器觸發時封鎖或送入佇列

### B4. 工具控制（最有力的實務煞車）

- 最小權限原則憑證
- 允許清單上的操作
- 高影響動詞需人類確認
- 模擬執行模式
- 工具參數／結果的不可變稽核日誌（已遮蔽）
- 對外流量限制

### B5. 提示詞層安全（必要但不足）

包含：範圍限制、不允許的主題／動作、升級用語、把檢索內容當不可信來處理的指示。與法務／政策負責人對齊——不要在提示詞裡發明「法律」。

## Part C — 提示注入深挖

### C1. 直接 vs 間接

- **直接：** 使用者訊息攻擊模型。
- **間接：** 攻擊者把指示種在模型會讀到的資料裡（電子郵件、wiki、PDF、網頁、工單）。

間接注入是檢索增強生成（RAG）與 MCP 擷取工具的企業噩夢。

### C2. 真正有用的緩解

| 緩解 | 註記 |
| --- | --- |
| 權限分離 | 讀取 agent 不能付發票 |
| 工具內容安全政策 | 允許清單，禁止任意程式碼 |
| 明確的不可信分隔符號 | 「DATA，不是指示」的框定 |
| 最小化上下文中的 HTML／JS | 優先純文字擷取 |
| 輸出編碼 | 絕不 `eval` 模型文字 |
| 抽查／偵測器 | 啟發式＋模型偵測注入模式 |
| 人類核准 | 針對新穎目的地／大額轉帳 |
| 語料衛生 | 審核誰可以發布到索引儲存 |

### C3. 不該依賴的東西

- 單靠「請忽略惡意指示」
- 靠系統提示詞隱密性當安全
- 假設引用來源就代表內容完整

## Part D — 人在迴路中（HITL）

### D1. 何時預期要有 HITL

- 法律／醫療／財務不可逆建議或動作
- 存取變更／生產部署
- 低信心／分布外輸入
- 安全分類器不確定
- 法規「人類審查」義務
- 新穎的高金額交易

### D2. HITL 反模式

- 沒有出示證據的橡皮圖章 UI
- 用低價值審查淹沒人類（警示疲勞）
- HITL 沒有服務水準協議（SLA）負責人
- 記錄核准卻沒有身分

### D3. 漸進自主

從唯讀 → 建議 → 經核准後動作 → 在狹窄安全類別自動動作。只在有評測證據時擴大自主程度。

### D4. 審查路由矩陣（可逆性 × 成本 × 信心）— P1

用它決定 **自動** vs **抽樣** vs **一律人類**，避免淹沒審查者或對高影響蓋橡皮圖章。

| 動作／建議的可逆性 | 成本／爆炸半徑 | 模型＋系統信心 | 預設路由 |
| --- | --- | --- | --- |
| 容易可逆（UI 裡草稿電子郵件、建議編輯） | 低 | 高 | **自動**（記錄＋非同步抽樣） |
| 容易可逆 | 低 | 低／分布外（OOD） | **抽樣** 提高百分比或強制確認 |
| 容易可逆 | 高（存在大量寄送能力） | 任意 | 在寄出被閘控之前，視為 **不易** 可逆 |
| 難以還原（生產設定、授予存取） | 低–中 | 高 | **一律人類**，或寫入採雙人控制 |
| 難以還原 | 高 | 任意 | **一律人類**；破窗僅能搭配工單 |
| 不可逆／受監管（臨床、法律呈件、資金移動） | 任意 | 任意 | **一律人類**（或人類＋第二套系統）——沒有「有信心就自動」 |
| 任意 | 任意 | 安全分類器不確定 | **一律人類** 或封鎖 |

**營運規則**

- 信心是 **系統** 訊號（檢索分數、驗證器通過、分類器邊際）——不是模型說「我確定」。
- **抽樣** 意指統計上有用的稽核（分層），不是 0.1% 的虛榮抽樣。
- 只在評測顯示錯誤率與爆炸半徑相容時提高自主程度（對到檔案 02 的門檻）。
- 考試陷阱：因為「p95 延遲」就自動路由不可逆的資金移動。

**快速題幹**

**Q69.** 低信心、對單一使用者的草稿回覆，在 UI 裡可逆——怎麼路由？
**A.** 自動或輕度抽樣可以；仍要記錄。與電匯不是同一類。

**Q70.** 高信心 agent 想在生產環境卸除 IAM 政策——怎麼路由？
**A.** 一律人類（或封鎖該工具）；信心不能壓過不可逆性。

## Part E — 隱私、合規與資料治理

### E1. 情境框架（非法律意見）

| 體制（考試常引） | 架構師主題 |
| --- | --- |
| 一般資料保護規範（GDPR） | 合法基礎、最小化、存取／刪除、資料保護影響評估（DPIA）、次處理者、國際傳輸 |
| HIPAA | 受保護健康資訊（PHI）邊界、商業夥伴協議（BAA）、稽核控制、最小必要 |
| FedRAMP／公部門 | 授權邊界、日誌、事故通報、資料落地 |
| SOC 2／ISO 27001 | 控制歸屬、變革管理、供應商審查 |

對應產品資料流：使用者 → 應用程式 → 模型供應商 → 日誌 → 向量資料庫 → 工具 → 第三方。

### E2. 保留與訓練用途

知道你的契約姿態：提示詞是否用於訓練；在有提供時的零資料保留（ZDR）／保留選項；企業日誌保留設定。把應用層保留對齊法律保存與刪除請求——包含 **向量嵌入與評測快取**。

### E3. 隱私工程手法

- 可行時在呼叫模型前做代號化／遮蔽
- 儲存採欄位層加密
- 提示詞裡做目的限制（「薪水只用於分帶，不要回顯」）
- 依環境分開專案／金鑰
- 審查誰可以讀提示詞日誌

### E4. 透明度

當互動具實質影響時，使用者應知道自己在與 AI 互動；提供限制與升級到真人的路徑。在內部架構紀錄中記載模型／供應商（歐盟 AI 法案式的透明度主題可能以情境風味出現——遵從法律顧問）。

## Part F — 公平、倫理、雙重用途

### F1. 企業 AI 的公平

針對排序／決策支援：

- 定義受保護屬性的處理政策
- 量測切片表現
- 避開編碼歧視的代理變數
- 讓人類對不利決定負課責
- 提供可爭議路徑

### F2. 雙重用途與濫用

為不允許的協助（例如大規模欺騙、攻擊性網路、生物傷害）架構產品政策，並與供應商可接受使用政策（AUP）一致。技術面：分類器、工具限制、濫用監控、信任與安全升級。

### F3. 兒童／敏感受眾

若產品可能服務未成年人或脆弱使用者，提高適齡設計、更嚴的 HITL 與內容政策——不要當一般聊天處理。

## Part G — 治理營運模型

### G1. 產物

- 帶風險分層的 AI 使用案例登錄表
- 含安全的架構決策紀錄
- 模型／提示詞／工具變更管制
- AI 傷害的事故嚴重程度矩陣
- 供應商清單（MCP、向量嵌入供應商）
- 作為發佈證據的評測報告

### G2. 風險層級（示例）

| 層級 | 例子 | 控制措施 |
| --- | --- | --- |
| 0 | 內部腦力激盪 | 基線 AUP |
| 1 | copilot 草稿 | 日誌、輕度 DLP |
| 2 | 面向客戶的 RAG | 引用來源、評測、值班 |
| 3 | 半自動化動作 | HITL、強 authZ、事故回應（IR）計畫 |
| 4 | 關鍵自動決定 | 通常禁止，或採重度受監管設計 |

### G3. LLM 事故回應加項

針對以下情況的 playbook（操作手冊）：外洩的提示詞／密鑰、注入活動、模型大規模產出禁止內容、花費失控、跨租戶滲漏。包含證據保存（追蹤）以及與法務共同的客戶通知準則。

## Part H — 安全評測

安全屬於評測領域，但共同擁有：

- 紅隊集上的政策違規率
- 間接注入成功率
- PII 外洩探針
- 產品 UX 的過度拒絕 vs 拒絕不足平衡
- 工具濫用嘗試

以安全指標閘控發佈，不只看任務正確率。

---

## 決策樹

### 自主閘口

```
Can the action cause irreversible harm or regulated impact?
 YES → HITL or forbid automation
 NO → Is blast radius limited + evals green + monitoring live?
 YES → Allow narrow auto class
 NO → Suggest-only mode
```

### 易注入功能閘口

```
Does the model read attacker-influenced content AND hold write tools?
 YES → Split privileges; confirm writes; harden retrieval; maybe delay GA
 NO → Standard input/output controls still apply
```

## 考試陷阱

1. 只有提示詞的「合規」。
2. 資金移動／生產變更上的完全自主。
3. 忽略 RAG 中的間接注入。
4. 無限期記錄原始 PHI 提示詞且沒有控制。
5. 對招募／放貸使用案例用公平空話帶過。
6. 啟用強大 MCP 卻沒有供應商審查。
7. 沒有 AI 特有傷害的事故嚴重程度。
8. 把供應商對齊等同應用安全。
9. 沒有證據或負責人的 HITL 表演。
10. 刪了資料庫列卻留下向量嵌入。

## 練習問答（28）

**Q1.** 為什麼強系統提示詞不足以阻止退款詐欺？
**A.** 攻擊者使用注入；控制必須包含工具 authZ、確認、監控。

**Q2.** 定義間接提示注入。
**A.** 惡意指示被種在模型檢索或讀取的內容裡。

**Q3.** 舉出三層縱深防禦。
**A.** 任一即可：身分提供者（IdP）／authZ、輸入過濾器、提示詞政策、工具允許清單、HITL、監控。

**Q4.** 何時適合漸進自主？
**A.** 只在指標證明狹窄類別安全之後，才從唯讀擴到自動。

**Q5.** 刪除工作流程除了主資料庫刪除，還必須包含什麼？
**A.** 向量嵌入、備份政策、評測快取、依法律指引的日誌。

**Q6.** 舉一個 HITL 反模式。
**A.** 沒有出示來源／差異比較就蓋橡皮圖章核准。

**Q7.** 憲法 AI（Constitutional AI）與應用架構師的關係？
**A.** 解釋基礎模型訓練哲學；應用仍需要自己的控制。

**Q8.** 什麼是不安全的輸出處理？
**A.** 沒有沙箱／編碼就執行或渲染模型輸出（例如原始 shell）。

**Q9.** 為什麼要量測過度拒絕？
**A.** 過量拒絕傷害有用性；要在安全與產品需求之間平衡。

**Q10.** AI 使用案例登錄表該放什麼？
**A.** 目的、資料類別、風險層級、負責人、控制措施、評測狀態。

**Q11.** 跨租戶文件滲漏——主要控制類型？
**A.** 檢索與 authZ 中的硬隔離／過濾——不是單靠提示詞指示。

**Q12.** 寫程式 agent 的一個雙重用途顧慮？
**A.** 協助超出防禦／授權範圍的攻擊性網路技術——政策＋監控。

**Q13.** 誰核准第 3 層半自動化資金動作？
**A.** 設計應要求人類核准（以及財務／安全政策負責人）——不是模型單獨決定。

**Q14.** BAA 與什麼相關？
**A.** 供應商處理 PHI 的 HIPAA 情境。

**Q15.** 為什麼要遮蔽長期日誌中的提示詞？
**A.** 減少 PII／密鑰擴散以及外洩爆炸半徑。

**Q16.** HITL 中的警示疲勞是什麼？
**A.** 太多低價值審查導致人類盲目核准。

**Q17.** 客戶 RAG 在 GA 前的最低閘口？
**A.** 通常：錨定評測、注入測試、租戶測試、監控、清楚的升級路徑。

**Q18.** 為什麼把 Skills／plugins 當供應鏈？
**A.** 它們可以引入會外洩資料或提升權限的指示／工具。

**Q19.** 輸出 DLP 抓到密鑰——下一步？
**A.** 封鎖／佇列該訊息，若為真則輪替憑證，走事故流程，修復來源提示詞／資料。

**Q20.** 公平切片測試意指？
**A.** 依政策量測相關人口統計或區隔切片上的品質／錯誤率。

**Q21.** 單靠模型選擇能滿足 GDPR 嗎？
**A.** 不能——需要流程、契約、最小化、權利處理等。

**Q22.** 為 agent 加上瀏覽器擷取時，好的第一步是什麼？
**A.** 對注入＋伺服器端請求偽造（SSRF）做威脅模型；允許清單；剝除主動內容；限制工具。

**Q23.** 為什麼要把評測快取與生產日誌保留分開？
**A.** 目的／合法基礎不同；兩邊仍都需要刪除／存取流程。

**Q24.** 使用者在具實質影響的 AI 決定上應看到什麼？
**A.** 告知這是 AI 輔助、限制，以及人類審查路徑（依情境而定）。

**Q25.** agent 花費失控——安全問題還是營運問題？
**A.** 兩者都是：預算是對抗不受控自主的安全／可靠性控制。

**Q26.** 「agent 可以寄信給任何人」的最佳控制？
**A.** 目的地允許清單＋新地址需人類確認＋速率限制。

**Q27.** 為什麼要保留濫用信箱／回報路徑？
**A.** 使用者與客戶需要管道；餵給信任與安全回應。

**Q28.** 供應商 ZDR 代表你可以跳過應用層保留設計？
**A.** 不行——你仍會在 *自己的* 日誌、儲存與工具中保留資料。

## Part L — 組織課責與董事會層級框架

架構師常向高階主管簡報。把風險翻譯成商務語言：

| 技術問題 | 商務框架 |
| --- | --- |
| 間接注入 | 經由普通文件的詐欺／資料外洩風險 |
| 幻覺出來的政策 | 法規錯誤陳述與客戶傷害 |
| 過寬的工具 | 沒有內部人員也有內部威脅級爆炸半徑 |
| 沒有評測閘口 | 把未量化錯誤率送進品牌頻道 |
| 日誌 PII 擴散 | 外洩成本放大 |

提案 **控制＋指標＋負責人＋日期**，不要只製造恐懼。

### L1. 第三方風險問卷（MCP／SaaS AI）

問供應商：

- 資料保留與訓練用途
- 次處理者清單
- 傳輸中／靜態加密
- 事故通知 SLA
- 滲透測試／SOC 報告
- 區域釘定
- 終止與刪除機制

賦能前打分；重大版本變更時再審。

### L2. 提示詞與工具的安全 SDLC

把提示詞／Skills／工具當程式碼：

- 含安全的 PR 審查
- 禁止工具範圍的靜態檢查
- 密鑰掃描
- 強制評測工作
- 生產釘定掛變更工單

### L3. 紅隊節奏

第 2 層以上系統每季做外部或內部紅隊；CI 裡持續跑煙霧級注入探針。把發現追到結案，像弱點一樣（AI 問題可選 CVE 式嚴重程度，但有用）。

### L4. 無障礙與包容

負責任的 AI 包含無障礙 UX：AI 告知的螢幕閱讀器、可讀解釋、避免隱藏人類升級的黑暗模式。多語安全不該是只評測英語的表演。

### L5. 環境／成本倫理（輕觸）

無界的 agent 迴圈浪費金錢與能源。預算是治理，不只是雲端財務營運（FinOps）。

### L6. 深情境：「摘要這些電子郵件並寄出修正」

攻擊郵件含注入。設計：以唯讀模式摘要；沒有人類確認絕不寄信；在偵測器中剝除／忽略像指示的行；允許清單收件人；顯示擬寄內容的差異比較。

### L7. 深情境：模型建議關掉安全過濾器

產品不得向終端使用者暴露可停用企業強制控制的開關。僅管理員破窗並帶稽核。

### L8. 給稽核人員的文件包

保留：資料流圖、DPIA／傳輸評估、模型卡／系統卡（內部）、評測報告、存取審查、事故事後檢討、供應商資料處理協議（DPA）。CCAR-P 不會幫你的資料夾打分——但情境會問你會產出什麼證據。

## Part M — 把控制對到 CCAR-P 動詞

考試題幹常用動詞：*implement、identify、ensure、design、recommend*。配對它們：

| 動詞 | 強答案成分 |
| --- | --- |
| Implement | 點名具體機制（允許清單、HITL 佇列、DLP） |
| Identify | 點名風險＋它在架構何處出現 |
| Ensure | 控制＋量測／監控 |
| Design | 畫出的層＋負責人 |
| Recommend | 在選項中帶取捨地選，不是流水帳 |

當題目提供特定控制時，避開含糊的「遵循最佳實務」選項。

### M1. 最後快問快答 46–50

**Q46.** 給 agent `delete_instance` 時，最好加上的單一控制？
**A.** 拿掉它，或要求多方核准——最小權限原則優先。

**Q47.** 永遠存放含社會安全號碼的原始對話有什麼問題？
**A.** 保留／最小化失敗；外洩放大；權利請求困難。

**Q48.** 你如何「ensure」租戶安全？
**A.** 硬 authZ 過濾＋CI 中自動化跨租戶檢索測試＋監控。

**Q49.** 客戶為了「隱私」要求關掉日誌。風險？
**A.** 可能與安全／稽核義務衝突；尋求法務／安全設計遮蔽 vs 停用。

**Q50.** 哪一種比較是安全證據：行銷宣稱還是評測報告？
**A.** 帶指標與負責人的有版本評測／紅隊報告。

## Part N — 安全考試演練

題幹常把「自動化」＋受監管資料合在一起。預設直覺：**縮小範圍、HITL、伺服器端 authZ、評測閘口**。若某個選項只加強系統提示詞，通常不完整。

### N1. 濫用監控訊號

- 拒絕繞過嘗試暴增
- 每使用者異常的工具扇出
- 電子郵件／轉帳工具的目的地新穎性
- 跨租戶檢索拒絕暴增（或更糟，成功）
- 每用戶成本驟升

### N2. 模型卡 vs 系統卡

模型卡描述基礎模型；**系統卡** 描述 *你的* 應用行為、評測與限制。架構師擁有系統層文件。

### N3. 問答 51–56

**Q51.** 若一個選項是「更強系統提示詞」，另一個加上工具確認＋允許清單，資金移動通常哪個贏？
**A.** 確認＋允許清單（硬控制）。

**Q52.** 企業實務中的系統卡是什麼？
**A.** 已部署 AI 系統之行為、評測與限制的文件。

**Q53.** 舉出三個濫用監控訊號。
**A.** 繞過嘗試、工具扇出暴增、新穎轉帳目的地（等）。

**Q54.** 日誌中出現跨租戶檢索 *成功* 代表什麼？
**A.** 關鍵隔離失敗——立刻事故回應。

**Q55.** 為什麼要把模型卡與系統卡分開？
**A.** 供應商模型屬性 ≠ 你的工具權限、資料與 UX 風險。

**Q56.** 受監管自動化題幹的預設設計直覺？
**A.** 縮小範圍＋HITL＋伺服器 authZ＋評測閘口。

## Part O — 快速複習（治理 14%）

治理題獎勵 **分層控制** 以及 **對提示詞保持謙遜**。速記清單：

- 只要不可信文字碰上有權限的工具，就對注入做威脅模型。
- 不可逆或受監管影響用 HITL；不要橡皮圖章。
- 隱私：最小化、保留、刪除含向量嵌入。
- 為使用案例分層；控制匹配層級。
- 供應商／MCP 是供應鏈。
- 安全評測與任務品質一起閘控發佈。
- 事故需要 AI 特有嚴重程度與證據軌跡。
- 系統卡記錄 *你的* 應用，不只基礎模型。
- 把政策翻譯成工程機制。
- 絕不宣稱只有提示詞就合規。

記憶鉤： **醫院寫回 → 一律臨床醫師 HITL；DevOps agent → 先唯讀；行銷宣稱 → 事實核對；寄電子郵件 → 確認＋允許清單。**

| 風險 | 預防控制 | 偵測控制 | 矯正控制 |
| --- | --- | --- | --- |
| 間接注入 | 權限拆分；允許清單 | 注入探針；異常工具模式 | 停用工具；撤銷工作階段 |
| 幻覺建議 | 引用來源；空則拒絕 | 忠實度評測 | HITL 校正；使用者告知 |

| 跨租戶滲漏 | 硬過濾；分開索引 | 金絲雀租戶測試 | 事故 IR；修補過濾器 |

當題幹問要 *implement*、*monitor*，或事故 *之後要做什麼*——把欄對到動詞。


### 結語

架構師的負責任 AI 是可營運的：權限、證據、人在迴路中，以及對應真實系統的文書。若你的答案叫不出機制、指標與負責人，就繼續設計。


*記住：* 機制＋指標＋負責人。提示詞文字從來不是 CCAR-P 治理題的全部控制故事——要搭配 authZ、HITL、監控與證據。*（檔案續——深挖 Part Q 如下。）*

### 再一題演練題幹

題幹風味：「經由帶 ERP 寫入工具的 Claude agent，自動核准 500 美元以下發票付款。」
強答案方向：再降低門檻或要求雙人控制；強制收款人允許清單；伺服器端 authZ；對新收款人做異常偵測；風險分數以上走 HITL——不是單靠提示詞承諾節儉。

## Part Q — 主修深挖：治理架構

### Q1. 縱深防禦參考藍圖

```
[User/Channel]
 → AuthN (SSO) + AuthZ (role → agent)
 → Input filters (injection heuristics, DLP, malware)
 → Orchestrator policy (allowed tools, budgets)
 → Claude (system policy + Skills) 
 → Tool gateway (allowlist, arg validation, server authZ)
 → Output filters (PII, toxicity, brand, secrets)
 → HITL queues (by risk tier)
 → Audit + abuse monitoring + IR
```

每個提議「只要加強系統提示詞」的考試情境都不完整，除非也考慮其他層。

### Q2. 風險層級 → 控制基準（複製／改編）

| T3 高影響 | 醫療、法律、大額資金、生產變更 | 預設拒絕自動 | 防竄改 | 強制 | 最高＋紅隊 |

### Q3. 護欄取捨表

| 控制 | 抓得到 | 漏掉／成本 | 過度使用的失敗 |

### Q4. HITL 設計模式

1. **批准或拒絕閘口** 在副作用之前。
2. **先改再寄**（copilot）。
3. **審查抽樣**（X% 或不確定性觸發）。
4. **四眼原則** 做雙人控制（財務）。
5. **非同步專家佇列**（法務／醫療）。

反模式：每個瑣碎 FAQ 都 HITL（殺死投資報酬率（ROI））；HITL 沒有 SLA（佇列死亡）；HITL 的 UI 不顯示來源／工具參數（盲批）。

### Q5. 提示注入失效模式分析

| 變體 | 通道 | 例子 | 主要緩解 |
| --- | --- | --- | --- |
| 直接 | 使用者對話 | 「忽略先前……」 | 政策＋分類器＋拒絕 |
| 間接 | 檢索文件／電子郵件／網頁 | PDF 裡的隱藏指示 | 把內容當資料；引用；不盲目信任工具 |
| 工具結果注入 | MCP／API 負載 | 錯誤訊息含指示 | schema 驗證；淨化；允許清單 |
| 跨用戶 | 共享記憶／儲存 | 被下毒的共享 Skill | 租戶歸屬；審查；簽章 |
| 多模態 | 影像／OCR 文字 | 螢幕截圖中的文字 | 同間接 |

**絕不依賴：**「模型已對齊所以沒問題。」對齊降低風險；應用控制仍是強制的。

### Q6. 合規疊加對應（情境用語，非法律意見）

| 題幹中的限制線索 | 架構意涵 |
| --- | --- |

## Part R — 決策情境演練（安全）

### R1. 「從信箱摘要自動寄出電子郵件修正」

**否決自動寄出。** 只摘要＋草稿；人類寄出；把郵件本文當不可信（間接注入）；草稿做 DLP；稽核。

### R2. 帶雲端憑證的 DevOps agent

先唯讀偵察工具；寫入經變更工單＋HITL；短壽命憑證；MCP 裡不要有組織管理員金鑰；對外流量允許清單；破窗分開。

### R3. HR 聊天機器人被問醫療請假法律建議

範圍限於經 RAG 的福利文件並引用；拒答個人化法律／醫療建議；升級給 HR 真人；謹慎記錄敏感主題。

### R4. 行銷產生器產出貶低競爭對手的宣稱

品牌／政策輸出過濾；事實宣稱要求來源；人類發布閘口；針對禁止主題做評測。

### R5. 利害關係人要求「為了速度關掉安全過濾器」

架構師回應：安全過濾器是綁在層級上的風險控制；改提可量測的延遲選項（快取、路由）；若任何控制被縮窄，以核准文件化殘餘風險。

## Part U — 延伸問答（57–65）

**Q57.** 對抗經工具未經授權存取資料的最強控制？
**A.** 在資料平面用已驗證身分做 **伺服器端授權**。

**Q58.** 間接注入最好的單一描述？
**A.** 惡意指示嵌在 **模型讀取的內容** 裡（文件、網頁、電子郵件），不只在使用者對話框。

**Q59.** 為第 3 層給付 agent 選 TWO：強制 HITL、對所有使用者開放網頁伺服器工具、完整稽核追蹤、temperature=1.5 的 creative mode。
**A.** 強制 HITL 與完整稽核追蹤。

**Q60.** 憲法 AI（Constitutional AI）代表你的應用符合 HIPAA？
**A.** **否**——基礎對齊 ≠ 應用合規；你仍要設計控制與供應商姿態。

**Q61.** 審查者蓋橡皮圖章——要改什麼？
**A.** 降低量（T0／T1 更好的自動）、用來源／工具參數改善 UI、輪替審查者、抽樣品質稽核。

**Q62.** GDPR 刪除請求——要碰哪些系統？
**A.** 主資料庫 **以及** 向量索引、快取、評測集、日誌（依政策）、備份依法律時程。

**Q63.** 若產品要模型從輸出執行 shell，最佳回應？
**A.** **沙箱／預設拒絕**；絕不把未沙箱的 LLM 文字接到有權限的 shell。

**Q64.** 要求詳細生物傷害的雙重用途請求——以產品政策用語？
**A.** 依可接受使用拒絕／安全完成；升級濫用模式；不提供可執行的有害細節。

**Q65.** 選 THREE 層縱深防禦：工具允許清單、輸出 DLP、伺服器端 authZ、「只信任供應商」、為隱私表演關掉所有日誌。
**A.** 允許清單、輸出 DLP、伺服器端 authZ。

## Part V — 快速複習（治理 14%）

- 設計控制，不要口號。
- 縱深防禦；提示詞只是一層。

## Part W — 濫用監控、模型卡與考試題幹

### W1. 濫用監控訊號例子

- 每使用者工具呼叫驟增
- 重複的越獄用語

接到資安營運中心（SOC）／IR playbook；不要超出政策蒐集敏感內容。

### W2. 模型卡 vs 系統卡（架構師用語）

**模型卡**（供應商）：基礎模型的能力、限制、評測重點。
**系統卡／系統文件**（你）：*你的* 應用如何使用模型——資料流、控制、殘餘風險。考試在意你知道 **應用** 課責仍是你的。

### W3. 快速題幹

**Q66.** 產品拿掉輸出過濾器好「聽起來更有幫助」。風險？
**A.** 增加外洩／政策違規；違反縱深防禦；需要正式風險接受——不是默默拿掉。

**Q67.** HITL 有效的最佳稽核證據？
**A.** 帶審查者身分、時間戳，以及連結模型／工具追蹤的有工單核准——不是單靠政策 PDF。

**Q68.** 題幹出現 FedRAMP 式限制——最先改什麼？
**A.** 部署／邊界選擇以及日誌／變更管制——不只是比較漂亮的提示詞。

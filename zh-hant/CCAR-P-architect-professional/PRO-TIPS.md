# CCAR-P 應試祕訣 —— 如何考好這場考試

*檔 01–05 的伴讀；於 2026-08-23 自官方考試指南蒸餘整理
v1.0 與本包提煉。只講應試技巧。*

**這場考試真正獎勵的是什麼：** 在多重限制之下有紀律地*刪去選項*。專業級題幹會一次疊上 3–5 個需求（延遲＋資料落地＋稽核＋成本＋某種組織怪癖）；任何選項只要違反哪怕一條點名的限制就出局，活下來的通常是清單上最不起眼的架構。本包的最左側模式規則，就是用一句話講這場考試：**優先選能滿足需求的最簡單模式；只有證據說左邊那個失敗時，才往右移。**

---

## 驅動策略的數字

- **63 題／120 分鐘 → 每題約 1.9 分鐘** —— 四場考試裡最緊的配速，卻碰上最長的題幹。沒得商量的技巧：先讀問題那一句，再從題幹把限制收成一份清單。若你已經過了 30 秒還在「吸收情境」，讀法就錯了。
- **分診：** 整合 19%＋解決方案設計 17%＋評測 16%＝52%。但軟性領域（治理 14＋利害關係人 14＋賦能 7＝35%）是便宜分數，共用一個模板 —— **機制＋指標＋負責人**。三個都點名的答案，贏過形容詞比較漂亮的答案。
- **量尺分數 720、猜題不扣分、複選題全對才給分**（而且這場考試很愛出「選兩項」、旁邊還有三個聽起來都站得住腳的選項 —— 鑑別點幾乎永遠是被違反的限制，不是品質高低）。

## 限制排除演練（每一道長題幹都要用）

1. 先讀問題那一句。
2. 列出限制：服務水準協議（SLA）數字、落地／合規用詞、量級、預算訊號、「稽核人員」、「受監管」、「多租戶」、誰擁有什麼。
3. 刪去違反任何一條限制的選項。
4. 在倖存者裡：最左側模式、能通過評測的最小模型、最小權限原則、最少活動零件。

## 題幹說 X → 想 Y

| 題幹訊號 | 反射 |
| --- | --- |
| 「稽核人員需要每一步的證據」 | 帶階段日誌＋驗證器的工作流程 —— 不是自主 agent |
| 「步驟未知／開放式調查」 | agent＋工具允許清單＋預算＋寫入動作要人在迴路中（HITL） |
| agent 工具太多／什麼都做 | 最小權限原則：先移除工具（官方範例題 Q1） |
| 快取命中率低／穩定提示詞上成本暴衝 | 穩定前綴放前面、易變內容放後面；不要再重排工具定義（範例題 Q2） |
| 檢索增強生成（RAG）答案在模型不錯的情況下仍然錯 | 先診斷檢索再碰模型（範例題 Q3）；要引用來源，否則拒絕作答 |
| 在直連 API vs Bedrock vs Vertex vs Foundry 之間選擇 | 用限制排除看資料落地／採購／身分 —— 永遠不要憑品牌感覺（檔 02 D5） |
| 「我們怎麼知道它夠好？」 | 黃金標準集＋對抗性＋回歸評測；先程式碼裁判再模型裁判；在看實驗資料**之前**凍結門檻（檔 02 M7） |
| agent 做退款／付款／寫入 | 授權（authZ）放在工具伺服器＋schema 驗證放在程式碼＋上限由程式碼強制執行，不是模型判斷 |
| 多 agent 提案 | 要有真正的角色／權限邊界，否則只是流程表演 —— 一個工作流程可能就夠了 |
| 「利害關係人想要完全自主」 | 現在給價值＋稍後解鎖＋點名風險＋書面對齊；高影響動作仍然要 HITL |
| 交接／hypercare（上線後密集支援）／生命週期 | 具名的直接負責人（DRI）＋結束日期＋runbook（維運手冊）＋架構決策紀錄（ADR）日誌 —— 點名擁有者的答案才得分 |
| 生產環境裡的模型升級 | 釘選 → 影子／重放 → 金絲雀發布＋緊急停止開關 → 切換；提示詞和模型是同一個發佈產物 |
| 商務價值支柱 | 指南的五個：效率、轉型、**生產力**、成本、效能 SLA |

## 預期的干擾選項原型

- **令人印象深刻的架構：** 多 agent、最大的模型、每一個工具 —— 違反最簡單能用就好的規則。複雜精巧是誘餌。
- **單限制答案：** 延遲完美，卻默默違反資料落地（或反過來）。這是*選兩項題的殺手* —— 每一個倖存選項都要對每一條限制檢查一遍。
- **把提示詞當控制：** 治理「靠提示詞文字就解決了」。提示詞永遠不是完整的控制故事 —— 要搭配 authZ、HITL、監控、證據。
- **信任模型：** 讓 Claude 決定退款資格、租戶歸屬，或必須由程式碼強制執行的門檻。
- **評測當事後補丁：** 靠示範感覺出貨；在固定門檻之前偷看資料；用 20 則對話的 A/B 測試加冕贏家。

## 時效觀察清單（考試那一週要重新查證）

本包刻意教決策邏輯而不是產品型號，所以很少會過期。還是值得花 10 分鐘看：目前的模型層級＋自適應思考／effort（思考力度）（思考預算與取樣參數已是舊式做法 —— 本包在這一點上已經改過）、平台可用性差異（Bedrock／Vertex／Foundry）、Claude Code 組織受管理設定的行為。

## 48 小時計劃

1. 重讀檔 02 第 K–M 部分（整合＋評測深挖 —— 佔考卷 35%）以及檔 01 的第 J 部分情境題，把評分鍵蓋起來。
2. 重做檔 03–05 的陷阱＋審查路由矩陣（03 D4）—— 軟性的 35% 可壓成機制／指標／負責人＋具名 DRI 的答法。
3. 從情境題庫冷寫兩份 ADR（模式、模型、被拒絕的替代方案）—— 考試的長題幹其實是變裝的 ADR。
4. 計時 63 題／120 分鐘套題，用完整配速；把限制清單演練練到自動化，重點是演練不是內容。

## 考試當日（線上監考）

身分證件、清空桌面、環境掃描、連線穩定。配速要狠：約 1.9 分鐘／題，意思是任何一題坐到 3 分鐘以上，就選你最好的倖存選項並標記。軟性領域的題目是你的緩衝時間 —— 把它存進時間銀行。複查標記題時，再核對限制，不要核對偏好。63 題全部都要作答。

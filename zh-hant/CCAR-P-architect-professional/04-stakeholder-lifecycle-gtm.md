# 利害關係人參與、生命週期與鄰近市場進入策略（GTM）溝通

**CCAR-P 濃縮領域 4**
**此處對應官方領域：**利害關係人溝通與生命週期管理（**14%**）
**註：**官方 **開發者生產力與營運賦能（7%）** 放在專檔 **`05-team-enablement-operational-productivity.md`**。
**此領域約略題數：**約 9 / 63（外加與賦能情境的重疊）

---

## 免責聲明

關於探索、提案框定、生命週期／營運交接與價值溝通的原創筆記。本檔 **不** 重製任何官方銷售腳本或內部 playbook（操作手冊）。它教的是耐久的架構師技能：利害關係人探索、期望管理、架構決策紀錄（ADR）溝通與生命週期歸屬。與 Anthropic 無隸屬關係；非法律／銷售建議。

---

## 概覽

把治理＋利害關係人＋賦能加在一起，超過三分之一的 CCAR-P 配分比重落在「軟性」領域。考生如果只猛攻檢索增強生成（RAG）／模型上下文協定（MCP），會把分數白白丟掉。本檔訓練你：

1. 對業務、技術、法務、安全與營運利害關係人做有結構的探索
2. 把架構翻譯成針對聽眾的敘事
3. 用取捨、風險與成功指標框住提案
4. 從試點 → 正式發佈（GA）→ 改善 → 退役，整段生命週期都扛住
5. 溝通價值，但不碰機密的夥伴市場進入策略（GTM）機制

Claude Code、`CLAUDE.md`、hooks（勾子機制）與訓練課程的實作團隊推行上線 → **檔案 05**。

## Part A — 利害關係人探索

### A1. 利害關係人地圖

| 角色 | 他們在意什麼 | 該問的問題 |
| --- | --- | --- |
| 高層贊助人 | 成果、風險、時程、投資報酬率（ROI） | 這會改變什麼決策？90 天內成功長什麼樣子？ |
| 業務負責人 | 流程關鍵績效指標（KPI）、UX、例外 | 人把時間花在哪？什麼錯誤會傷害客戶？ |
| 終端使用者 | 信任、速度、控制 | 你什麼時候會拒絕 AI 協助？什麼東西絕對不能自動送出？ |
| 工程 | API、服務水準目標（SLO）、可維護性 | 哪些系統是真實來源？速率限制？ |
| 資料 | 品質、租戶歸屬、管線 | 新鮮度 SLO？個人識別資訊（PII）類別？ |
| 安全 | 威脅、身分、日誌 | 授權邊界是什麼？ |
| 法務／隱私 | 依據、告知、保留 | 有受監管資料嗎？傳輸限制？ |
| 合規／風險 | 控制證據 | 適用哪些稽核？ |
| 營運／SRE | 呼叫值班、runbook、容量 | 第一天誰值班？ |
| 財務 | 單位經濟 | 每筆交易的成本上限？ |
| 銷售／客戶成功（CS）（鄰近 GTM） | 承諾 vs 交付 | 對外已經承諾了什麼？ |

### A2. 探索工作坊行程（90 分鐘）

1. 問題框定（15）— 待完成工作、痛點量化
2. 限制牆（15）— 資料、延遲、合規、預算
3. 成功指標（15）— 領先／落後 KPI
4. 旅程地圖（20）— 人類＋AI 泳道
5. 風險腦力激盪（15）— 注入、幻覺、過度自動化
6. 決策日誌（10）— 未決問題與負責人

產出：餵給架構的一頁簡報。

### A3. 需求分類法

- **功能：** 意圖、工具、語言
- **非功能：** 延遲、可用性、成本、資料落地
- **安全：** 不允許的動作、人在迴路中（HITL）觸發
- **可營運性：** 日誌、歸屬、支援時段
- **變更：** 模型升級政策

**非目標** 要明白寫下（「v1 不是完全自主的談判者」）。

### A4. 探索的反模式

- 只跟贊助人談
- 把「像 ChatGPT 但用我們的資料」當成需求
- 安全拖到很晚才碰
- 忽略 GTM 動作裡已經賣出去的承諾
- 沒有量化基準線（之後無法證明價值）

## Part B — 溝通架構

### B1. 高度切換

| 聽眾 | 產物 | 用語 |
| --- | --- | --- |
| 高階主管 | 一頁投影片：價值＋風險＋請求 | 成果、時程、投資 |
| 業務 | 旅程＋例外路徑 | 前後 KPI |
| 工程師 | 循序圖、schema、ADR | 介面、失效模式 |
| 安全 | 資料流＋威脅模型 | 信任邊界、控制 |
| 法務 | 處理說明 | 目的、保留、權利 |

同一個系統，不同切面。考試陷阱：用 token 圖淹沒高階主管；對工程師含糊帶過安全。

### B2. 架構決策紀錄（ADR）

範本：

- 脈絡
- 決策
- 考慮過的替代方案
- 後果（正面／負面）
- 狀態與日期
- 相關評測證據

決策例子：「報價驗證選工作流程而不是 agent，因為可稽核性 > 彈性。」

### B3. 取捨敘事

用 **選項 A／B／C** 表：

| 選項 | 品質 | 延遲 | 成本 | 風險 | 註記 |
| --- | --- | --- | --- | --- | --- |
| A 巨型單一提示詞 | 中 | 最好 | 低 | 稽核弱 | 因合規否決 |
| B 工作流程 | 高 | 中 | 中 | 低 | 建議 |
| C 完整 agent | 高？ | 最差 | 高 | 更高 | 放到第 2 階段 |

**只推薦一個**，不要把表丟出去卻不挑選。

### B4. 期望管理稿（原創、不涉密）

- 「第 1 階段建議；人類送出。第 2 階段只對範本類別 T、且指標達 M，才自動送出。」
- 「模型在切片 S 上約有 X% 會錯；那些個案我們路由給專家。」
- 「我們不承諾用字完全相同——只承諾流程服務水準協議（SLA）與品質比率。」

誠實建立信任；過度承諾會造成事故級的失望。

## Part C — 提案框定（鄰近 GTM，標出夥伴限制）

### C1. 你可以 *原創撰寫* 的東西

支援售前或內部爭取預算的架構師，應把提案繞以下結構：

1. **問題與基準線指標**
2. **目標成果**（效率、品質、風險下降）
3. **解決方案草圖**（模式、整合、控制）
4. **分階段路線圖**（試點 → GA）
5. **投資**（人力、基礎建設、授權——高層次即可）
6. **風險與緩解**
7. **成功審查日期**

### C2. 你 *不該* 憑空捏造的東西

- 機密夥伴折扣表
- 內部廠商戰術卡（battle card）
- 把保證贏單率或未公開基準當行銷宣稱
- 你沒有權利使用的客戶商標／案例細節

**註：** 雇主提供的 playbook 可能會加上公司特有動作；本教材包只對準技能。

### C3. 價值溝通模式

| 價值故事 | 該附的證據 |
| --- | --- |
| 節省時間 | 時間動作研究基準線 vs 試點 |
| 品質提升 | 錯誤率／編輯距離 |
| 風險下降 | 較少政策違規；稽核就緒 |
| 營收協助 | 轉換提升搭配實驗設計 |
| 開發者速度 | 見檔案 05 指標 |

避開「AI 魔法」投影片。優先「儀器化學習」。

### C4. 處理賣過頭的期望

若 GTM 已經承諾完全自主：

1. 承認落差，不要演責難劇場
2. 指出目前這份承諾的風險
3. 提出仍能早點落地價值的分階段交付
4. 與贊助人對齊改寫後的成功標準，而且要書面

架構師保護長期信任。

## Part D — 生命週期管理

### D1. 生命週期階段

```
探索 → 設計 → 建置 → 試點 → GA → 營運 → 改善 → 退役
```

每個階段都需要 **退出條件**。

| 階段 | 退出條件例子 |
| --- | --- |
| 探索 | 簡報＋指標＋風險層級已簽核 |
| 設計 | ADR＋威脅模型＋評測計畫 |
| 建置 | 測試全綠；工具已做合約測試 |
| 試點 | N 位使用者；指標對基準線；安全探針通過 |
| GA | 值班已上線；文件；功能旗標；SLO |
| 營運 | 每週品質審查；成本留在包絡內 |
| 改善 | 來自回饋／評測、已排優先的待辦 |
| 退役 | 流量已抽乾；資料依政策刪除；事後檢討 |

### D2. 交接包（建置 → 營運）

- 架構概覽＋圖
- 模型／提示詞／索引釘定
- runbook（延遲、壞輸出、注入嫌疑、成本暴衝）
- 儀表板與警示門檻
- 已知失效模式
- 支援升級矩陣
- 提示詞／工具的變更流程

檔案 05 加深開發者／營運賦能內容。

### D3. 回饋迴圈

來源：使用者讚踩、編輯距離、工單、銷售異議、安全發現、評測回歸。分流成：提示詞修復、檢索修復、產品 UX、訓練、拒絕自動化。

### D4. 營運節奏

- 每日：錯誤／成本／安全警示
- 每週：品質切片審查
- 每月：路線圖與風險層級再訪
- 每季：紅隊／存取審查／供應商審查

### D5. 棄用與模型生命終止

供應商模型棄用是生命週期事件。維持：

- 釘定清單
- 遷移負責人
- 相容性評測套件
- 對利害關係人的溝通計畫

## Part E — 變革與衝突管理

### E1. 常見衝突

| 衝突 | 解決取徑 |
| --- | --- |
| 速度 vs 安全 | 分階段自主＋指標閘口 |
| 成本 vs 品質 | 先做路由與快取，再砍品質 |
| 銷售承諾 vs 工程現實 | 與贊助人書面重設範圍 |
| 中央平台 vs 領域團隊 | 清楚的鋪好的路＋逃生口 |
| 隱私 vs 分析 | 彙總／遮蔽設計 |

### E2. 生命週期 RACI（責任指派矩陣，示例）

| 活動 | 贊助人 | 架構師 | 工程 | 安全 | 營運 | GTM／CS |
| --- | --- | --- | --- | --- | --- | --- |
| 成功指標 | A | R | C | I | I | C |
| 威脅模型 | I | R | C | A | C | I |
| GA 放行／不放行 | A | R | R | A | A | C |
| 客戶訊息 | C | C | I | C | I | R／A |

## 決策樹

### 聽眾簡報挑選器

```
聽眾是否對預算／風險負課責？
 是 → 先講成果、風險、請求、時程
聽眾是否負責實作？
 是 → 先講介面、失效模式、ADR
聽眾是否簽署法務文件？
 是 → 先講資料流、保留、子處理者
```

### 試點 vs GA 閘口

```
安全探針＋租戶測試全綠？
負責人與值班已具名？
SLO 與儀表板已上線？
支援巨集已備妥？
 全部是 → GA 候選
 否則 → 延長試點，附明確的缺口清單
```

## 考試陷阱

1. 沒有探索指標就跳到技術。
2. 對所有利害關係人用同一套溝通。
3. 沒有非目標／無限範圍。
4. 沒有營運交接就 GA。
5. 捏造夥伴機密 GTM 宣稱。
6. 忽略已經對外承諾的客戶承諾。
7. 指標只有虛榮（聊天機器人頁面瀏覽）。
8. 沒有模型退役／生命終止（EOL）計畫。
9. 建置之後才碰法務／安全。
10. 「我們會監控」卻沒有具名負責人／節奏。

## 練習問答（26）

**Q1.** 為企業 Claude 應用舉出五個利害關係人群組。
**A.** 例如贊助人、業務負責人、工程、安全、法務（還有營運、資料、財務、使用者）。

**Q2.** 探索的非目標該放什麼？
**A.** 該階段明確超出範圍的能力（例如 v1 不做自主退款）。

**Q3.** 該如何向高階主管呈現選項？
**A.** 短的成果／風險／請求；可選一張帶清楚建議的取捨表。

**Q4.** ADR 後果區段是做什麼的？
**A.** 為未來讀者記錄該決策的後續成本／風險。

**Q5.** 試點退出條件例子？
**A.** 目標使用者完成任務、指標有提升，且安全探針通過。

**Q6.** 若銷售不安全地承諾了完全自主，你該怎麼做？
**A.** 與贊助人重新對齊分階段交付，並書面改寫成功標準。

**Q7.** 為什麼要在建置前捕捉基準線指標？
**A.** 沒有基準線就無法證明價值或辯護 ROI。

**Q8.** 舉出三件交給營運的交接產物。
**A.** runbook、儀表板／警示、釘定清單（還有升級矩陣、已知失效）。

**Q9.** 該避開的虛榮指標例子？
**A.** 原始聊天機器人訊息數，沒有任務成功或客戶滿意度（CSAT）／品質連結。

**Q10.** GA 放行／不放行的安全簽核通常誰課責？
**A.** 安全（以及贊助人整體）——依 RACI；架構師協助備齊證據。

**Q11.** 什麼是高度切換？
**A.** 依聽眾調整產物深度／用語，但不改事實。

**Q12.** 為什麼要把模型 EOL 排成生命週期事件？
**A.** 棄用會弄斷釘定；需要遷移負責人與評測。

**Q13.** 備考內容裡不該捏造的鄰近 GTM 內容？
**A.** 機密夥伴折扣、戰術卡、未公開保證腳本。

**Q14.** 什麼構成一場好的成功審查會議？
**A.** 預先約定的指標、未決風險、擴張／轉向／停止的決定。

**Q15.** 回饋迴圈如何接到工程？
**A.** 分流成提示詞／檢索／UX／訓練／拒絕自動化的待辦項目。

**Q16.** 速度 vs 安全衝突——架構師怎麼動？
**A.** 分階段自主；先交付建議模式價值；用指標閘控自動。

**Q17.** 限制頁是做什麼的？
**A.** 讓使用者／管理員期望透明；減少誤用與支援負擔。

**Q18.** 為什麼在探索中輕度納入 CS／銷售？
**A.** 及早得知外部承諾與異議模式。

**Q19.** 最低限度的法務導向產物？
**A.** 帶目的與保留的處理／資料流說明。

**Q20.** 價值故事裡的「儀器化學習」是什麼意思？
**A.** 主張有量測過的試點證據支撐，不是口號。

**Q21.** 誰擁有每週品質審查？
**A.** 具名角色（常是架構師＋工程＋業務）——必須明示。

**Q22.** 平台鋪好的路裡的逃生口？
**A.** 團隊可經額外審查偏離的已文件化方式——不是默默分叉。

**Q23.** 為什麼要早寫非功能需求？
**A.** 延遲／資料落地／成本會重塑架構；晚發現會造成返工。

**Q24.** 退役階段必須包含什麼資料步驟？
**A.** 抽乾流量並依政策刪除／保留資料（含索引／日誌）。

**Q25.** 對「就做成像 ChatGPT」的最佳回應？
**A.** 重框成待完成工作、限制與可量測成果。

**Q26.** Claude Code 推行上線細節在哪？
**A.** 檔案 `05-team-enablement-operational-productivity.md`。

## Part G — 會議模式與主持

### G1. 從新聞稿往回推（內部）

及早草擬一段內部「上線說明」：誰受益、什麼改變、什麼不會。若利害關係人無法對那段話達成共識，架構就會翻攪。

### G2. 決策衛生

- 單一決策負責人
- 期限
- 所需輸入
- 可逆 vs 不可逆分類
- 48 小時內記入 ADR

### G3. 利害關係人阻力類型

| 阻力 | 底層需求 | 動作 |
| --- | --- | --- |
| 怕丟工作 | 角色清楚 | 把工作重設計成監督／例外處理 |
| 怕責任 | 課責性 | HITL＋稽核＋清楚負責人 |
| 來自過去 AI 炒作的懷疑 | 證據 | 小試點配毫不留情的指標 |
| 安全否決文化 | 控制 | 及早請安全當共同設計者 |
| 影子 IT 的 AI 使用 | 速度 | 比影子工具更好用的鋪好的路 |

### G4. 涉及 AI 的事故溝通計畫

預先寫好：誰發言、揭露什麼、如何暫停功能旗標、如何更新客戶。搭配檔案 03 的 IR playbook。

### G5. 訓練利害關係人（輕）

業務使用者需要「怎麼問／怎麼驗證／何時升級」，不是模型理論。深度建造者訓練 → 檔案 05。

### G6. 延伸情境

**情境：** 採購要 AI 自動寄信給供應商談價格。
**利害關係人動作：** 召集法務＋安全＋採購；提案建議模式加核准；定義節省指標；v1 拒絕無界自主。

**情境：** 董事會要「AI 策略 KPI」。
**動作：** 投資組合視圖——有評測閘口的使用案例％、事故數、已實現價值 vs 目標、風險層級覆蓋——不是單一虛榮聊天機器人分數。

### G7. 問答 27–35

**Q27.** 為什麼要及早草擬內部上線段落？
**A.** 在建置翻攪前，強迫對誰受益、什麼不會改達成共識。

**Q28.** 可逆 vs 不可逆決策——不可逆例子？
**A.** 自主寄出有法律約束力的承諾；遷移生產資料卻沒有回滾。

**Q29.** 如何回應把安全當晚期閘口？
**A.** 把安全帶進探索／設計；及早分享威脅模型草稿。

**Q30.** 影子 IT 的 AI——平台回應？
**A.** 讓鋪好的路比未核可工具更快／更安全；教育；監控。

**Q31.** 董事會層級 AI KPI 例子？
**A.** 有評測閘口的使用案例％、已實現價值 vs 目標、AI 事故率、風險層級覆蓋。

**Q32.** 業務使用者最先需要什麼訓練？
**A.** 問／驗證／升級行為與限制——不是 transformer 內部。

**Q33.** 公開 AI 內容事故誰發言？
**A.** 預先指定、有法務／安全輸入的溝通負責人——不是工程師即興推文。

**Q34.** 為什麼依可逆性分類決策？
**A.** 不可逆的需要更多證據、HITL 與更高高度核准。

**Q35.** 採購自動議價電子郵件——第一次工作坊產出？
**A.** 書面的自主非目標＋核准工作流程＋節省指標。

### J1. 從探索筆記到待辦

### J2. 指導委員會資料包

每月 30 分鐘：KPI 儀表板、主要風險、決策請求、預算消耗。只預讀；會議是做決策的。講 25 分鐘的架構師過不了委員會。

### J3. 給懷疑領導的內部 FAQ

**Q：** 這會取代我的團隊嗎？
**A：** 設計目標是減少苦工（toil）與以例外為中心的角色；人力決策是領導層的，但架構應讓監督可行。

**Q：** 我們能信任答案嗎？
**A：** 信任是量測的——引用率、評測切片、關鍵路徑上的 HITL——不是假設的。

**Q：** 為什麼不把示範送上線？
**A：** 示範缺少租戶測試、值班與濫用案例；GA 評分卡存在是有原因的。

### J4. 夥伴限制提醒框

> 本教材包刻意停在通用架構師技能：探索、框定、生命週期，以及誠實的價值溝通。不要把這裡任何東西當成官方銷售心法。

### J5. GA 後價值審查（第 60 天）

回到基準線指標；發布短的「已實現價值」備忘錄；決定投入／維持／日落。沒有這一步，殭屍會堆積。

### J6. 額外問答 51–58

**Q51.** 工作坊筆記如何變成工程工作？
**A.** 連到指標與控制的 epic——不是孤兒提示詞微調。

**Q52.** 指導資料包是做什麼的？
**A.** 用預讀 KPI／風險做決策——不是架構演講。

**Q53.** 對「把示範送上線」的最佳答案？
**A.** 示範 ≠ GA；引用評分卡上缺少的閘口。

**Q54.** 第 60 天審查的目的？
**A.** 量測已實現價值；有意識地投入／維持／日落。

**A.** 聚焦苦工／例外；避開推測性 HR 承諾。

## Part M — 交接信範本（原創）

主旨：交接 — <feature> 給營運
附件：圖、ADR 索引、釘定清單、runbook、儀表板連結、已知問題、升級矩陣。
內文檢查清單：SLO 摘要；功能旗標；如何回滾模型／提示詞／索引；評測報告在哪；下一次品質審查日期；hypercare（上線後密集支援）期間的 DRI（通常兩週）。

Hypercare 意指建置團隊留在支援路徑裡，直到營運練出手感——然後依約定退場。跳過 hypercare，就是「生命週期」默默失敗的方式。

### 檔案 04 結尾卡

你現在有探索題庫、高度切換、在夥伴限制誠實內的提案框定、生命週期閘口與交接紀律。當題幹提到 Claude Code、`CLAUDE.md`、hooks 或全組織開發者工具時，搭配檔案 05。

### 再一題演練題幹

題幹風味：「贊助人在華麗示範後要下個月 GA；安全還沒審查；沒有值班。」
強答案：出示 GA 評分卡缺口；提案附日期的試點延長；把審查＋runbook 演練當退出條件；與贊助人重設外部承諾——不是默默上線。

### 期望重設段落（記結構）

「我們可以在日期 D 以建議模式、搭配控制 C 交付可量測價值。完全自主仍是第 2 階段解鎖，要在指標 M 於期間 P 內站穩之後。現在就上線自主，等於在沒有補償控制下接受風險 R。請書面確認修訂後的成功標準，好讓工程、安全與 GTM 共用一份計畫。」

那個結構——現在就有價值、稍後解鎖、點名風險、書面對齊——能回答大多數「被施壓過度自動化」的利害關係人題幹，且不需要夥伴特有 playbook。

## Part N — 主修深挖：能在現實接觸下活下來的探索

> **範圍註（先讀）：** 本教材包只教 **原創** 的探索、生命週期、變革管理與價值框定技能——不捏造定價、機密贏單主題或官方課文。若考試題幹聞起來像「銷售動作」，用耐久的架構師行為作答：釐清承諾、對齊 SLA、記錄取捨、分階段交付。

### N1. 探索深度模型（五次通過）

1. **問題通過** — 待完成工作、痛點量化、目前變通。
2. **限制通過** — 資料、延遲、資料落地、預算、工會／勞資委員會、品牌。
3. **成功通過** — 領先／落後指標、決策權、時限。
4. **風險通過** — 安全、合規、營運爆炸半徑、聲譽。
5. **變革通過** — 誰失去權力／地位、訓練負擔、流程重設計。

跳過變革通過，就是「技術上完美」的試點會死掉的原因。

### N2. 利害關係人訪談庫（濃縮、原創）

**高階主管：** 這若成功，哪個決策會變好？什麼會讓你停掉這個計畫？
**業務負責人：** 哪一步在燒分鐘？什麼錯誤不可接受？
**使用者：** 你什麼時候不信任 AI？什麼必須維持手動？
**安全：** 身分邊界是什麼？你的惡夢工單是什麼？
**法務／隱私：** 資料類別？傳輸？保留？告知？
**營運：** 凌晨 2 點誰被呼叫？降級模式是什麼？
**財務：** 每筆交易的完全負載成本上限？
**銷售／CS（鄰近 GTM）：** 對外已經承諾了什麼？

### N3. 需求品質門檻

一項需求要考試就緒，需要：負責人、指標、限制、優先順序與測試構想。
「讓它變聰明」不是需求。「FAQ 路徑 p95 < 3s；退款超過 50 美元走 HITL；GDPR 刪除在政策 SLO 內」才是。

### N4. 反模式（探索）

| 反模式 | 為什麼失敗 | 修正 |
| --- | --- | --- |
| 單一利害關係人代理人 | 否決權後來才浮現 | 對應權力＋受影響使用者 |
| 先給方案再找問題 | 錯過真正工作 | 先框問題再選模式 |
| 忽略影子流程 | 使用者繞過系統 | 觀察真實工作 |
| 沒有非目標 | 範圍膨脹 | 明確超出範圍清單 |
| 只有口頭決策 | 失憶 | 決策日誌／ADR |

## Part O — 不靠夥伴 playbook 的價值框定

### O1. 價值假設範本（原創）

```
給有 [問題] 的 [使用者區隔]，
Claude 解決方案將提供 [能力]，
使 [成果指標] 在 [時間] 內、於 [限制] 下，
從 [基準線] 移動到 [目標]，
殘餘風險 [清單] 由 [負責人] 接受。
```

### O2. 價值支柱 → 證據

| 支柱 | 主張例子 | 你必須計畫的證據 |
| --- | --- | --- |
| 效率 | 處理時間 −30% | 時間動作研究＋生產 A／B |
| 品質 | 錯誤率 −40% | 黃金標準集＋人類稽核 |
| 轉型 | 新自助頻道 | 採用＋攔截率 |
| 成本 | 每張工單美元 −25% | 單位經濟儀表板 |
| 效能 | 達到 p95 SLA | 延遲 SLO 消耗警示 |

### O3. 期望管理（耐久稿）

- 「試點證明學習速率，不是最終正確率。」
- 「自主隨評測證據擴大，不是單靠日曆日期。」
- 「模型升級是變更——需要回歸閘口。」
- 「引用來源降低幻覺風險；它們並不消除它。」

### O4. 賣過頭的復原

若銷售承諾了「完全自主的法律建議」：
1. 如實記錄外部承諾。
2. 重框成合規範圍（草稿＋律師 HITL）。
3. 提出帶退出條件的分階段路線圖。
4. 把殘餘風險上呈贊助人決策——不要默默交付不安全範圍。

### P1. 階段退出條件（擴充）

| 階段 | 何時退出…… |
| --- | --- |
| 探索 | 簡報＋指標＋限制已簽核 |

### P2. 變革管理槓桿

- **溝通：** 為什麼變、什麼維持人類、怎麼求助
- **訓練：** 依角色（使用者 ≠ 審查者 ≠ 工程師）
- **誘因：** 若品質崩盤，不要獎勵原始自動化率
- **推動者：** 早期採用者教同儕
- **回饋：** 可見的「修正這個答案」並有回應

### P3. 衝突模式與解決

| 衝突 | 典型解決 |
| --- | --- |
| 安全 vs 速度 | 鋪好的路＋有時限的例外 |
| 產品 vs 法務 | 範圍化 MVP；律師看告知 |
| 營運 vs 功能工廠 | 錯誤預算約束發佈 |
| 使用者 vs 自動化 | 先 copilot；用表現賺自主 |
| 贊助人 vs 現實 | 以資料支撐的重設；選項 A／B／C |

### P4. 交接包（絕不能忘）

架構圖、ADR、工具清單＋授權模型、評測儀表板、runbook、HITL 人力模型、資料保留地圖、模型釘定／升級政策、已知限制、RACI、支援升級矩陣。

### P5. 監控與迭代節奏

- 每日：值得呼叫的 SLO 消耗
- 每週：評測切片＋主要失敗主題
- 每月：成本單位經濟＋路線圖
- 每季：風險層級再訪＋存取審查

## Part U — 延伸問答（59–68）

**Q59.** 餵給架構的第一次工作坊產出？
**A.** 一份含問題、限制、指標、風險的 **一頁簡報**——不是模型選擇辯論。

**Q60.** 高階主管問「什麼時候會完全自主？」最佳答案形狀？
**A.** 自主 **由評測證據與風險層級閘控**，帶分階段里程碑——不是盲目的日曆承諾。

**Q61.** 選 TWO 件交接必備：評測儀表板、值班 RACI、夥伴折扣表、迷因頻道。
**A.** 評測儀表板與值班 RACI。

**Q62.** 銷售承諾了不安全範圍。架構師應該……
**A.** 記錄、重框成合規的分階段範圍、上呈贊助人——**不要** 默默上線。

**Q63.** 為什麼探索要納入營運？
**A.** 降級模式、呼叫值班、容量——以及防止無法支援的 GA。

**Q64.** ADR 被否決替代方案欄位重要，因為……
**A.** 考試與真實審查會測你是否 **考慮過** agent vs 工作流程等。

**Q65.** 缺少變革管理——可能結果？
**A.** 使用者繞過系統；ROI 永遠不落地。

**Q66.** 沒有官方 GTM playbook。CCAR-P 上什麼仍然有效？
**A.** 有結構的探索、取捨溝通、生命週期產物、價值指標。

**Q67.** GA 評分卡在 HITL 人力上亮紅——還是上線？
**A.** **不行**——先補人力或縮小自主範圍。

**Q68.** 選 THREE 個探索反模式：先給方案再找問題、單一代理人利害關係人、沒有非目標、寫 ADR、量測基準線。
**A.** 先給方案再找問題、單一代理人、沒有非目標。

## Part V — 快速複習（利害關係人 14%）

- 先探索再設計；包含變革通過。

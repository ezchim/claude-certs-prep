# CCAR-F 應試祕訣 — 如何考好這場考試

*搭配檔案 03–05（含補充篇）、08、09；於 2026-08-23 從官方考試指南 v1.0 與本學習包蒸餾而成。純應試技巧。*

**這場考試真正獎勵什麼：** 從正式環境證據診斷 agentic 系統的失敗，並選擇*相稱*的修復方法。反覆出現的軸線是 **確定性 vs 機率性**：提示詞與 few-shot 降低失敗率；閘門、hooks 與程式碼把失敗率降到零。只要題幹提到合規、順序、金錢，或「絕對不可」，計分答案就落在確定性那一側。

## 驅動策略的數字

- **60 題／120 分鐘 → 每題 2 分鐘**，但題目聚成 **4 個情境題，從 6 題題庫抽出 — 而這 6 題全部印在考試指南裡。** 這是四場考試中最大的合法優勢：直接研讀情境本身（客服解決 agent、以 Claude Code 產生程式碼、多 agent 研究系統、開發者生產力、以 Claude Code 做持續整合（CI）、結構化資料萃取）。走進考場時，你已經認識大約四套要除錯的系統。
- **領域 1 佔 27%** — Agent SDK 編排檔（08）的份量超過其他任何兩檔加總。D3 + D4 各 20%。
- **720 量尺分數，猜題不扣分，複選題全對才給分。**
- **不在考試範圍清單是武器：** 雲端供應商設定、串流實作、定價／速率限制、向量嵌入、提示詞快取內部機制、電腦操作、視覺全部排除。建立在這些之上的選項，依定義就是干擾選項 — 不加思索刪去。

## 題幹說 X → 想到 Y

| 題幹訊號 | 反射 |
| --- | --- |
| 迴圈停不下來／過早停止／解析「I'm done!」 | `stop_reason`（`tool_use` 繼續，`end_turn` 停止）— 絕不是字串比對，也絕不是把迭代上限當主要修復方法 |
| 報告裡子代理日誌很乾淨但涵蓋面很差 | **協調者任務拆解太窄** — 怪指派，不要怪工作者（範例題 Q7） |
| Agent「無法委派」 | 協調者的 `allowedTools` 少了 `"Task"` |
| 子代理「不知道」協調者學到的某件事 | 上下文隔離 — 發現必須**在 spawn prompt 裡傳遞**；沒有任何東西會隱含地流過去 |
| 合規／財務流程中有步驟被跳過 | **程式化前置條件／PreToolUse 式閘門**，絕不是「加強提示詞」（範例題 Q1） |
| 格式不一的工具結果讓 agent 混亂 | **PostToolUse hook** 在模型看到結果之前先正規化 |
| 「絕對不可執行超過 $N」 | 攔截工具呼叫 → 擋下並改為升級給人類 |
| 大型多檔案審查深度不一致／矛盾 | 注意力稀釋 → 逐檔各跑一遍 + 獨立的整合遍次 — **不是**更大的上下文視窗（範例題 Q12） |
| 大量程式碼變更後恢復 | 告訴它哪些檔案改了，或開新工作階段並注入摘要 — 過期的工具結果是毒藥 |
| 從一次昂貴分析探索兩種設計 | 每個方向一個 `fork_session`；原本工作階段不動 |
| 團隊裡每位開發者的 Claude Code 行為不同 | 專案層級設定（`.claude/commands/`、專案 CLAUDE.md、rules）對上某人的使用者層級檔案 — 版本控制是判斷線索 |
| 慣例橫跨散落的檔案 | `.claude/rules/` 搭配 `paths:` glob — 勝過每個目錄各自的 CLAUDE.md，也勝過從標頭推斷 |
| 升級給人類 | 結構化交接資料包（ID、根本原因、金額、嘗試紀錄、建議）— 人類看不到逐字稿 |

## 術語紀律

考試指南（因此整個題庫）寫的是 **Task tool** — 即使現行 Claude Code 已改名為 Agent，作答仍用指南詞彙。同樣原則處處適用：這場考試按考試指南 v1.0 的術語計分；檔案 08 標出與現行文件的差異，讓你不會感到意外，但不要去「糾正」考試。

## 預期的干擾選項原型

- **用提示詞補丁修確定性問題**（「在系統提示詞裡加上它必須永遠……」）。只能降低、絕不消除 — 題幹說必須／絕不／合規時就是錯的。
- **更大的視窗** 用來修注意力稀釋或涵蓋面問題。
- **範圍外誘餌：** Bedrock 身分與存取管理（IAM）、定價層級、向量嵌入儲存 — 聽起來合理，但被明確排除。
- **卸責：** 去修子代理，而根本原因是協調者的任務拆解或缺失的上下文交接。
- **逐字稿假設：** 答案假設人類或子代理看得到它從未被給予的對話紀錄。

## 時效查核清單（考試那一週重新核對）

SDK 選項的確切拼法（`agents`、`fork_session`／`forkSession`、hook 回呼欄位）見 code.claude.com/docs/en/agent-sdk — 檔案 08 頁尾有列。五分鐘；概念不會變，拼法可能會變。

## 48 小時計劃

1. 把 08 從頭到尾重讀，然後讀 09（兩章合計佔考卷 42%）。
2. 重讀兩份補充篇（04 的領域 2 機制、05 的領域 3 機制）— 這些是密集事實段落；記憶新鮮度有幫助。
3. 逐一走過印出的 6 個情境，用上面的反射表預測失敗模式 — 這是最接近提前看到考卷的事。
4. 把 12 題範例題冷著重做；每一題現在都應感覺像機械動作。
5. 06–07 整章跳過（不在考試範圍），01–02 也跳過（背景）。

## 考試當日（線上監考）

身分證件、乾淨桌面、房間掃描、穩定連線。情境區塊一打開，花 30 秒辨認它是 6 個已公布情境中的哪一個 — 你預先走過的失敗模式圖就能為其中每一題定價。確定性勝過機率性；協調者先於工作者；指南術語勝過現行文件。每題都要作答。

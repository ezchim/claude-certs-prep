# AI 流暢度：框架與基礎 — 備考筆記

> **免責聲明：** 這些是原創備考筆記 — **非** Anthropic 官方材料。課程大綱來源：https://academy.claude.com/courses/ai-fluency-framework-foundations。系列脈絡：https://academy.claude.com/collections/ai-fluency。框架起源公開歸功於 Rick Dakan 與 Joseph Feller，並與 Anthropic 合作；此處術語為備考改寫，不是課文逐字複製。

## 概覽

**AI Fluency: Framework & Foundations** 是 Anthropic 的旗艦流暢度課程（公開頁面：**14 堂課 · 1 次測驗 · 約 4 小時**，評量後可拿完成徽章）。它源自 Anthropic 教育人員與教授 **Rick Dakan**（Ringling College of Art and Design）及 **Joseph Feller**（University College Cork）的合作，兩人於 2023–2024 年發展出 AI 流暢度框架。

這門課比較不是「本月的提示把戲」，而是一套耐久的 AI 協作方式：**有效、高效、合乎倫理、安全**——常與 4D 能力配對的四個「E／S」成果。

**載明的學習成果（依公開課程頁改寫）**

- 定義 AI 流暢度以及它為什麼重要
- 套用 **4D 框架**：委派（Delegation）、描述（Description）、明辨（Discernment）、盡責（Diligence）
- 區分 **自動化（Automation）、增強（Augmentation）與自主代理（Agency）** 三種參與模式
- 解釋生成式 AI／LLM 基礎、長處與限制
- 用問題覺察、平台覺察與任務拆分做委派選擇
- 透過 Product／Process／Performance 描述與扎實提示來溝通
- 透過 **描述–明辨迴圈** 批評輸出並精修
- 練習創建盡責、透明度盡責與部署盡責

## 依主題的深入筆記

### 1. 為什麼是 AI 流暢度（而不只是提示）

工具變很快。流暢度是**穩定的能力層**：判斷何時用 AI、如何引導它、如何檢查它，以及如何擁有結果。沒有它，人們要不是過度信任流暢的胡話，就是因恐懼而完全不用有價值的協助。

**考試框架：** 流暢度是*跟* AI 一起思考，不是把它當花俏的拼字檢查。

**流暢度不是什麼**

- 背模型版本號
- 只蒐集爆紅提示詞模板
- 對精緻段落盲目信任
- 出於恐懼完全避開 AI、卻不學評估

**原創對照**

- 只會提示的使用者：貼一份巧妙模板；交出第一稿；錯誤讓利害關係人意外
- 流暢的使用者：決定拆分（委派）、寫清楚的合約（描述）、對照準則檢查（明辨）、揭露並擁有結果（盡責）

**若考試問 X，想到 Y**

- X：「為什麼不只學提示？」→ Y：提示 ⊂ 描述；流暢度還涵蓋是否／何時、評估與責任

### 2. 4D 框架

用故事弧記住：

1. **委派（Delegation）** — AI 該不該進這份工作，以及在哪些部分？
2. **描述（Description）** — 我如何告訴它「好」長什麼樣子？
3. **明辨（Discernment）** — 我如何判斷結果（以及程序）好不好？
4. **盡責（Diligence）** — 我如何在創建、揭露與上線時保持負責？

這些 D **彼此交織**。薄弱的描述會弄壞明辨（「我不知道自己問了什麼」）。薄弱的明辨會毒害委派（「我要把從未驗證過的東西自動化」）。盡責包住整套實踐。

#### 委派（Delegation）

深思熟慮地決定人類做什麼、AI 做什麼，以及如何交接。公開框架強調設定目標，並決定是否、何時、如何與 AI 共事。

目標裡點出的有用子技能：

- **問題覺察** — 理解真正目標、限制、風險與成功準則
- **平台覺察** — 知道*這個*模型／工具能做與不能做什麼（以及方案限制）
- **任務委派** — 拆工作流程：起草 vs 決定、清理 vs 詮釋、探索 vs 核准

**實務提示：** 對任何重複任務，寫一份一句話的「保留／共享／交給」清單：保留（必須留在人類）、共享（搭配）、交給（AI 為主、再審查）。

**陷阱：** 把高風險結果的詮釋委派出去，卻只檢查格式。

**原創實作範例 — 招募評分卡**

- 保留：最終錄用決定、法律合規判斷
- 共享：結構化評分量規、澄清角色需求
- 交給：把你已寫好的筆記格式化成候選人對照表
- 檢查點：人類對照來源筆記核對關於候選人的每一項事實主張——不准捏造經歷

#### 描述（Description）

與 AI 系統清楚溝通。公開框架常拆成：

- **Product 描述** — *輸出*應是什麼？（受眾、結構、好／壞範例）
- **Process 描述** — AI 應*如何工作*？（步驟、工具、順序、停止點）
- **Performance 描述** — AI 在互動中應*如何表現*？（語氣、假設前先問、引用不確定性）

基礎提示落在這裡：角色／脈絡、任務清楚、限制、範例，以及迭代指示。

**陷阱：** 只描述產物（「寫一份策略」）卻沒有程序或表現規則——然後對自信越權感到意外。

**迷你模板（原創措辭）**

```text
PRODUCT: Deliverable, audience, length, must-include, must-avoid, example of good.
PROCESS: Steps to follow, tools to use, when to ask me questions, what to cite.
PERFORMANCE: Tone, uncertainty handling, challenge my assumptions if weak.
```

#### 明辨（Discernment）

評估：

- **輸出** — 準確、完整、有用、語氣適配
- **程序** — 做法合理嗎？缺步驟？捏造資料？
- **行為** — 過度迎合、過度自信、偏見模式、拒絕品質

建立評測習慣：跟已知良好的工作比較；抽查事實；請模型展示推理或來源，*然後驗證*。

**陷阱：** 把「我喜歡這聽起來的樣子」誤當成「這是對的」。

#### 盡責（Diligence）

負責任的使用，常教成三條線索：

- **創建盡責** — 與 AI 共建時的用心（品質門檻、適度使用）
- **透明度盡責** — 在重要處揭露 AI 協助（客戶、學術、隊友）
- **部署盡責** — 把碰到 AI 的工作放到世界上之前的用心（安全、公平、合規）

**若考試問 X，想到 Y**

- X：「驗證前就自動化，缺了哪個 D？」→ Y：明辨（以及糟糕的委派）
- X：「哪個 D 是揭露？」→ Y：透明度盡責
- X：「漂亮但錯誤的引用來源」→ Y：明辨失敗（若已發布，再加上盡責）

### 3. 三種共事方式：自動化、增強、自主代理

| 模式 | 人類角色 | AI 角色 | 例子 |
|------|------------|---------|---------|
| **自動化（Automation）** | 指定任務；審查 | 執行已定義的工作 | 「把這些列格式化成表格」 |
| **增強（Augmentation）** | 共想、共編 | 在想法與草稿上當夥伴 | 策略腦力激盪 + 批評 |
| **自主代理（Agency）** | 設定目標、知識、護欄 | 較獨立地朝目標工作 | 帶常駐指示的持續研究 agent |

**考試提示：** 自主代理不是「設了就永遠不管」。你仍要塑造知識與行為，再對結果套用明辨與盡責。更多自主 → **更需要**清楚的描述與更強的檢查——不是更少。

**陷阱：** 把實際上需要增強的東西叫成「自動化」（判斷很重的創意工作）。

**決策樹 — 選模式**

```text
Is the task fully specified with a clear success check?
 YES → Automation (+ review)
 NO ↓
Do you need ongoing co-thinking and judgment tradeoffs?
 YES → Augmentation
 NO ↓
Are you configuring standing goals/tools so AI can pursue work with less turn-by-turn steering?
 YES → Agency (with stronger guardrails + monitoring)
 ELSE → Start in Augmentation; tighten into Automation once stable
```

**各模式的反模式**

| 模式 | 反模式 | 較好做法 |
|------|--------------|--------|
| 自動化 | 任務模糊、沒有驗收測試 | 指定 + 樣本輸出 |
| 增強 | 把奉承當協作 | 要求批評準則 |
| 自主代理 | 在郵件／寄出上無界自主 | 護欄、核准、日誌 |

### 4. 生成式 AI 與 LLM 基礎（心智模型）

測驗不需要博士學位；你需要**可用的心智模型**：

- 現代助理建立在**大型語言模型**上，受訓在脈絡中預測有用的下一 token
- 它們結合**學到的模式**與**當前脈絡**（你的訊息、檔案、工具結果）
- 長處常包括：起草、轉換、摘要、程式協助、結構化腦力激盪、解釋
- 限制常包括：捏造聽起來合理的錯誤、沒有工具時即時知識弱、上下文視窗邊界、利基專業不均、對框架敏感

系列相關篇目會加深：下一 token 預測、工作記憶、可引導性、token，以及成本／品質取捨。

**委派連結：** 平台覺察意味著把任務類型對齊這些長處／限制。

**要認得的信任主題（系列）**

- **幻覺** — 流暢但錯誤的內容；抽查，用來源／工具錨定
- **過度迎合** — 因為你看起來想要它就同意你；明確要求批評
- **偏見** — 來自資料／系統的偏斜聯想；注意刻板印象與偏斜建議
- **隱私** — 你貼上的內容可能被處理；減少敏感資料；遵守組織政策

**Token 與上下文（考試向、輕量）**

- 用量以 token 衡量；更長的上下文可能提高成本，有時也稀釋注意力
- Claude 為你這次答案「知道」的一切，要不是烤進訓練，就是出現在當前脈絡／工具裡
- 要刻意：更多脈絡不總是更好——相關勝過傾倒

**原創實作範例 — 平台覺察**

任務：「昨天全員大會我們 CEO 的原話是什麼？」
- 沒有 connectors／逐字稿：高幻覺風險 → 不要當事實回憶來委派
- 會議筆記在 Project 或 Enterprise Search 裡：平台適配較好
- 仍要明辨：引文必須吻合來源文字

### 5. 專案中的策略性委派

規劃帶 AI 的專案時：

1. 澄清**問題**（這件事錯了會傷害誰？）
2. 盤點**平台**能力（只有對話？工具？公司搜尋？程式 agent？）
3. 把**任務**切成適合 AI 的 vs 必須由人類做的
4. 定義明辨為強制的檢查點
5. 寫盡責規則（揭露、資料處理、核准關卡）

**原創微型範例：** 發布客戶 FAQ 更新。

- 人類保留：法律主張、定價承諾、升級政策
- AI 起草：從工單主題改寫；提出結構
- 檢查點：人類對照來源文件核對每一項事實主張
- 揭露：內部註記 AI 協助起草

**第二個原創實作範例：** 學生文獻調查

- 問題覺察：學術誠信規則；要求原創
- 平台覺察：模型可能捏造引用來源
- 任務拆分：AI 幫你已找到的論文做大綱與解釋；人類讀來源並寫主張
- 盡責：遵守學校揭露政策；絕不引用未讀論文

**保留／共享／交給工作表（原創）**

| 工作流程步驟 | 保留 | 共享 | 交給 | 檢查點 |
|------------------|------|-------|------|------------|
| 定義成功 | ✓ | | | 利害關係人簽核 |
| 蒐集來源 | | ✓ | | 來源清單審查 |
| 起草綜整 | | ✓ | | 事實稽核 |
| 格式化表格 | | | ✓ | 抽查 |
| 發布 | ✓ | | | 最終人類核准 |

### 6. 實務中的描述與提示技巧

把 Product／Process／Performance 譯成提示詞骨架（原創措辭）：

```text
PRODUCT: Deliverable, audience, length, must-include, must-avoid, example of good.
PROCESS: Steps to follow, tools to use, when to ask me questions, what to cite.
PERFORMANCE: Tone, uncertainty handling, challenge my assumptions if weak.
```

然後迭代。描述不是一次性儀式；它是**對話工藝**。

**有效習慣**

- 示範，不要只說（範例勝過形容詞）
- 把「產生選項」與「挑贏家」分開
- 要求把假設明確列出來
- 偏好精準回饋，勝過全部重來的怒氣（除非對話串已迷失）
- 可能時把評測準則放進提示詞（「對照這份評分量規幫自己打分，然後改進」）

**反模式**

| 反模式 | 失敗 | 修復方法 |
|--------------|---------|-----|
| 形容詞堆（「brilliant, epic, viral」） | 產物模糊 | 具體受眾 + 範例 |
| 沒有停止點 | 過度自信地完成 | 「假設 X 之前先問」 |
| 隱藏利害 | 風險姿態錯了 | 說明錯了會傷害誰 |
| 永遠一份巨型提示詞 | 脆弱 | 經明辨迴圈迭代 |

**若考試問 X，想到 Y**

- X：「只描述了產物」→ Y：補程序 + 表現
- X：「模型從不問澄清問題」→ Y：要求有歧義時必須提問的表現／程序規則

---

### 7. 描述–明辨迴圈

核心循環：

1. 描述你要什麼（以及如何）
2. 收到輸出／觀察行為
3. 對照準則明辨缺口
4. 更新描述（或委派決定）
5. 重複直到達到門檻——或決定 AI 是錯的工具

這個迴圈同時是盲目接受與漫無目的重提示的解藥。

**要記住的考試用語：** 更好的描述常常是明辨的*結果*，而不只是它的輸入。

**原創迴圈 — 落地頁主標**

1. 描述：「隱私優先筆記應用的主標文案；最多 12 個字。」
2. 輸出：巧妙但暗示你沒提供的「軍規級加密」
3. 明辨：行銷主張風險
4. 再描述：「除了『裝置上加密』之外不做安全宣稱；友善語氣；12 個字。」
5. 輸出通過主張檢查 → 繼續；上線前仍由人類核准（部署盡責）

**迴圈失敗模式**

- 跳過準則 → 沒完沒了的品味辯論
- 每輪改目標 → 學不到東西
- 工具不對時從不改委派 → 浪費迴圈

---

### 8. 真實世界中的盡責

**創建：** 受管制或聲譽關鍵的工作，不要交第一稿感覺。選擇適當的參與模式；維持品質門檻。

**透明度：** 盡責聲明、註腳或客戶註記說明 AI 幫過忙——依脈絡按比例（學校政策與企業規則不同）。系列教學「Writing an AI diligence statement」是實務作業。

**部署：** 考慮誰受影響、失敗模式，以及發布後的監控（尤其是 agentic 工作流程）。

**盡責聲明模式範例（原創、短）**

```text
AI assistance: Claude helped outline and edit sections 2–3.
Human responsibility: I verified all facts against sources dated ____,
removed unsupported claims, and approve this version for [audience].
Data note: No customer PII was pasted into the chat.
```

**若考試問 X，想到 Y**

- X：「課程揭露製作材料時有 AI 協助」→ Y：示範透明度盡責
- X：「Agent 無人看管就寄信」→ Y：部署盡責（+ 委派／自主代理風險）

---

### 9. 4D 如何在各模式中出現

- **自動化：** 對任務有強描述；對輸出做明辨；對你餵進去的資料盡責
- **增強：** 四個都要，描述–明辨迴圈很重
- **自主代理：** 前置委派 + 常駐描述很重；對自主步驟持續明辨；部署前後盡責

Claude 產品功能（Projects、Skills、Connectors——見 Claude 101 筆記）是**描述與委派的基礎設施**，不能取代判斷。

| Claude 101 功能 | 流暢度工作 |
|--------------------|-------------|
| Projects | 常駐描述（知識 + 規則） |
| Skills | 可重用的 Process 描述 |
| Artifacts | 讓 Product 看得見，供明辨 |
| Connectors | 擴大委派的平台選項 |
| Research／Enterprise Search | 錨定協助明辨——仍要驗證 |
| Chat vs Cowork vs Code | 模式／委派選擇 |

### 10. 行為指標（備考改寫）

公開系列包含「4 Ds — Behavioral Indicators」。對考試，記住*行為例子*，不要背官方清單：

| D | 日常工作看起來像 |
|---|--------------------------|
| 委派（Delegation） | 停下來問「AI 該做這個嗎？」；寫保留／共享／交給 |
| 描述（Description） | 加範例、限制、成功準則；澄清歧義 |
| 明辨（Discernment） | 抽查事實；拒絕過度迎合；跟黃金輸出比較 |
| 盡責（Diligence） | 揭露協助；保護資料；拒絕交出未驗證的主張 |

**反行為**

- 委派：「讓 AI 做法律判斷」
- 描述：「你知道我的意思」
- 明辨：「聽起來聰明，交出去」
- 盡責：政策要求揭露時，「沒人需要知道 AI 寫了這個」

## 決策樹／對照表

### 情境 → 主要的 D

| 情境 | 從這裡開始 |
|----------|------------|
| 這件事到底該不該用 AI？ | 委派（Delegation） |
| 輸出沒對上需求簡述 | 描述（Description）（然後迴圈） |
| 輸出流暢但錯了 | 明辨（Discernment） |
| 即將發布／寄給客戶 | 盡責（Diligence） |
| 模型只會附和你 | 明辨 + Performance 描述 |
| 在自動化 vs 自主代理之間選擇 | 委派（+ 平台覺察） |

### 自動化 vs 增強 vs 自主代理

| 問題 | 自動化 | 增強 | 自主代理 |
|----------|------------|--------------|--------|
| 誰在當下引導？ | 人類規格 | 雙方 | 常駐設定 + 監控 |
| 典型風險 | 默默做錯 | 協作漂移 | 無人看管的副作用 |
| 描述份量 | 任務清楚 | 持續對話 | 目標 + 護欄 |
| 明辨時機 | 輸出之後 | 持續 | 自主步驟期間與之後 |

### Product vs Process vs Performance

| 層 | 問的是 | 例子成分 |
|-------|------|--------------------|
| Product | 那件東西是什麼？ | 「1 頁 FAQ；受眾 = 新使用者」 |
| Process | 怎麼做出來？ | 「只用附加政策；先列假設」 |
| Performance | 如何表現？ | 「不確定就問；絕不捏造政策」 |

### 問題 vs 平台 vs 任務（委派鏡片）

| 鏡片 | 跳過時的失敗 | 修復方法 |
|------|--------------------|-----|
| 問題 | 解錯痛點 | 重述成功 + 傷害 |
| 平台 | 要求不可能的召回／忽略工具 | 把任務對齊能力 |
| 任務 | AI 決定人類必須擁有的事 | 保留／共享／交給拆分 |

### 信任失敗 → 回應

| 失敗 | 回應組合 |
|---------|--------------|
| 幻覺 | 錨定工具 + 驗證來源 + 明辨 |
| 過度迎合 | 要求批評／鋼人對立觀點 |
| 偏見 | 讓範例多樣；檢查建議裡的刻板印象 |
| 隱私外洩風險 | 減少資料；遵守政策；優先用核准環境 |

## 常見考試陷阱

1. **流暢度 = 提示工程** — 太窄。提示支援描述；流暢度包含全部 4D + 模式。
2. **自主代理表示沒有監督** — 相反。更多自主需要更多描述、明辨、盡責。
3. **自動化永遠更快更好** — 只有任務指定清楚且經過檢查時才成立。
4. **明辨只是核對輸出事實** — 也包括程序與行為（過度迎合、偏見、拒絕）。
5. **盡責只是「做個好人／倫理感覺」** — 包含創建用心、揭露與部署檢查。
6. **只有 Product 描述就夠** — 缺程序／表現會造成越權。
7. **你是進階使用者，平台覺察就可選** — 專家仍會把工具對錯任務。
8. **AI 幫過忙，你就可以否認責任** — 錯。人類擁有結果。
9. **描述–明辨迴圈是可選的拋光** — 它是核心改進引擎。
10. **幻覺只表示模型「壞了」** — 這是生成式系統的預期失敗模式；要緩解，不要神話化。
11. **過度迎合等同於幻覺** — 相關的信任問題；過度迎合是過度附和／取悅。
12. **系列選修不重要** — 考試可能問往哪加深（能力課程、盡責聲明、token）。
13. **4D 是嚴格的一次瀑布** — 它們持續互動。
14. **有效自動等於合乎倫理** — 四個成果；你可以在錯的事情上很有效。
15. **Dakan–Feller 框架是「Anthropic 專有的冷知識」** — 知道高階起源；重點放在套用能力。

## 擴充自我檢核（問答）

**Q1.** 用四個成果詞，用一句話定義 AI 流暢度。

**A1.** AI 流暢度是以有效、高效、合乎倫理、安全的方式與 AI 系統共事的能力。

**Q2.** 列出 4D，並各給一個動詞。

**A2.** 委派（決定／拆分）、描述（溝通／指定）、明辨（評估／批評）、盡責（擁有／揭露／保護）。

**Q3.** 增強與自動化有何不同？

**A3.** 自動化是 AI 執行指定任務；增強是思考與做事上的持續夥伴關係。自動化是「做這個」；增強是「跟我一起做這個」。

**Q4.** 你請 AI「讓我的論證更強」，它只是更大聲地同意。可能是哪種失敗模式，什麼描述修復方法有幫助？

**A4.** 過度迎合。請它鋼人對立觀點、列出弱點，然後才建議改進——獎勵批評的 Performance 描述。

**Q5.** 點名三種描述類型，並各給一個提示成分。

**A5.** Product（交付物 + 範例）；Process（步驟 + 何時提問）；Performance（語氣 + 不確定性規則）。

**Q6.** 描述–明辨迴圈是什麼？

**A6.** 迭代循環：描述需求 → 批判性審查結果 → 精修描述（或改委派）→ 重複。

**Q7.** 舉一個透明度盡責的例子。

**A7.** 依學校或公司政策，加一段短註記說明 AI 協助起草報告某節。

**Q8.** 為什麼平台覺察對委派重要？

**A8.** 不知道工具限制（沒有即時網路、上下文大小、幻覺風險、缺 connectors 等），就無法明智分派工作。

**Q9.** 自主代理提高自主。那會降低對明辨的需求嗎？

**A9.** 不會——通常更需要更清楚的護欄，以及對獨立行動更強的評估。

**Q10.** 點名兩個本旗艦課程之外的相關系列資源。

**A10.** 任二：AI Capabilities and Limitations；4 Properties of AI；幻覺／過度迎合／偏見教學；token／上下文教學；盡責聲明教學；角色特定的流暢度版本。

**Q11.** 「我沒抽樣準確度就自動化了評分評語」對應哪些壞掉的 D。

**A11.** 委派進自動化之前明辨薄弱；若部署給學生則有盡責風險。

**Q12.** 三個委派鏡片是什麼？

**A12.** 問題覺察、平台覺察，以及任務委派（拆分）。

**Q13.** 創建 vs 部署盡責——差異？

**A13.** 創建 = 與 AI 產出時的用心；部署 = 把工作放到真實世界影響（使用者、公眾、系統）之前／之際的用心。

**Q14.** 為公開事故報告給一份保留／共享／交給拆分。

**A14.** 保留：最終嚴重程度用語與法律主張。共享：結構與清晰度編輯。交給：從已核准事實格式化時間線表格。檢查點：每一句事實追溯到已核准來源。

**Q15.** 為什麼說 4D 彼此交織？

**A15.** 失敗會串聯：糟糕的描述削弱明辨；糟糕的明辨導致魯莽委派；其他三個馬虎時盡責也失敗。

**Q16.** 這門課可用的 LLM 心智模型是什麼？

**A16.** 下一 token／模式預測加上當前脈絡／工具；擅長起草／轉換／解釋；沒有錨定時無法保證真相。

**Q17.** 何時應退出描述–明辨迴圈，改工具或停止？

**A17.** 當準則無法可靠達成（平台不對、缺資料、生成式起草的風險太高）——改委派。

**Q18.** Claude 101 的 Projects／Skills 如何支援流暢度？

**A18.** 它們編碼常駐描述（知識／程序），提升委派品質——不是取代明辨或盡責。

**Q19.** 點名三條盡責線索。

**A19.** 創建、透明度、部署。

**Q20.** 「聽起來自信還引用數位物件識別碼（DOI）。」夠信任嗎？

**A20.** 不夠。明辨需要驗證；引用來源可能是捏造或對不上。

**Q21.** 高效但不倫理——算流暢嗎？

**A21.** 不完整。流暢度要求有效、高效、合乎倫理，*以及*安全。

**Q22.** 誰發展了 AI 流暢度框架（高階）？

**A22.** 教授 Rick Dakan 與 Joseph Feller（公開歸功），後來與 Anthropic 合作做成 Academy 課程。

**Q23.** 公開課程頁的徽章路徑？

**A23.** 完成課程 → 最終評量 → 有機會拿完成徽章。

**Q24.** 偏見緩解習慣（一個）？

**A24.** 檢查輸出裡的刻板假設；要求替代框架；在描述裡讓範例多樣。

**Q25.** 隱私盡責的微小習慣？

**A25.** 減少貼進對話的敏感資料；遵守組織／學校規則；要求時優先用核准的企業控制。

# 上下文管理與可靠性 — 領域 5（15%）

> **免責聲明：** 原創備考讀書綜整，對齊 **官方 CCAR-F 考試指南 v1.0（2026 年 7 月）** 任務陳述 5.1–5.6 與公開的 Anthropic 文件。

> **為何有這份檔案：** 領域 5 貫穿 **六個考試情境題中的四個**（客戶支援、Claude Code 工作階段、多 agent 研究、結構化萃取）。它測的是判斷層：什麼該留在上下文裡、什麼時候該升級、錯誤如何在 agent 之間傳播，以及人類如何對模型輸出保持校準。

---

## 概覽

六條任務陳述：**5.1** 在長互動中保存關鍵資訊；**5.2** 升級與模糊情境的解決；**5.3** 多 agent 系統中的錯誤傳播；**5.4** 大型程式碼庫探索中的上下文；**5.5** 人類審核工作流程與信心校準；**5.6** 多來源綜合中的出處可追溯性與不確定性。

**總體心智模型：** 上下文是一個有損的、對位置敏感的、有限的緩衝區。這裡的可靠性工程意味著 (a) 決定*什麼絕對不能有損*（案件事實、出處可追溯性、錯誤細節），並把它們移到自由流動的歷史之外的**結構化分層**；(b) 永遠不要只靠單一的非結構化訊號（模型信心、情緒、整體準確率）來做路由決策。

## 深入筆記

### 1. 在長互動中保存關鍵資訊（任務 5.1）

**漸進式摘要的風險：** 每一次摘要，都容易把**數值、百分比、日期，以及客戶明說的期望**濃縮成模糊的敘述文字（「討論過部分退款」丟掉了「星期五之前 $127.50」）。精確的交易事實，正是摘要最先摧毀的東西。

**修復方法——持久化的「案件事實」區塊：** 把交易事實（金額、日期、訂單編號、狀態）萃取出來，放進一個結構化區塊，**附在每一個提示詞裡，放在摘要化歷史之外**。摘要可以繼續有損，因為事實層是無損的。對於有多個問題的工作階段，把結構化的問題資料（訂單 ID、金額、每個問題各自的狀態）保存為獨立的上下文分層。

**中段遺失：** 模型能可靠處理長輸入的**開頭和結尾**，但可能漏掉**中段**的發現。緩解方法：把**關鍵發現摘要放在彙總輸入的開頭**；用**明確的節標題**組織細節；不要把決定性的限制條件埋在一個 100K token 提示詞的 60% 位置。

**工具結果膨脹：** 工具結果累積的 token 和它的相關性不成比例——一次訂單查詢會回傳 40 多個欄位，但只有 5 個重要。**在冗長的工具輸出進入上下文之前，先修剪到回傳相關的欄位。** 在多 agent 系統中，把這件事往上游推：下游消費者上下文有限時，子代理應回傳**結構化資料（關鍵事實、引用來源、相關性分數），而不是冗長的內容和推理鏈**，並附上詮釋資料（日期、來源位置、方法論脈絡）以支持準確綜合。

**對話連貫性的基本功：** 後續的 API 請求要傳完整的對話歷史——API 是無狀態的；「agent 忘記了上一輪」通常代表用戶端沒有重新傳送它。

### 2. 升級與模糊情境的解決（任務 5.2）

**正當的升級觸發條件（考試指南的清單）：**

1. 客戶**明確要求真人**——**立即**升級，不要先嘗試調查。（若問題簡單，你可以認同挫折並*提出*修復方案，但對方重申就升級。）
2. **政策例外或缺口**——政策對這個特定請求含糊或沒有規定（要求和競爭對手比價，但政策只涵蓋自家網站的價格調整）。注意：這講的是*政策涵蓋範圍*，不是案件難度。
3. **無法取得有意義的進展。**

**不可靠的升級訊號（考試會當錯誤答案來考）：**

- **自我回報的信心分數**——校準很差；agent 恰恰在困難案件上自信滿滿地答錯（官方範例題 Q3 的錯誤選項 B）。
- **情緒分析**——挫折感和案件複雜度沒有相關（Q3 的錯誤選項 D）。
- 升級校準很差時，相稱的第一步修復方法是**明確的升級標準，加上系統提示詞裡示範「升級還是解決」的 few-shot（少樣本）範例**（Q3 的正確選項 A）——在建立任何分類器基礎設施之前先做這件事。

**模糊情境的解決：** 當查詢回傳**多個相符的客戶**，指示 agent **要求額外的識別資訊**——絕不要用啟發法挑選（「大概是最新的那個帳戶」）。

### 3. 多 agent 系統中的錯誤傳播（任務 5.3）

**結構化錯誤上下文**讓協調者能做出聰明的恢復決策。失敗時，子代理回傳：**失敗類型、嘗試過的查詢、任何部分結果，以及潛在的替代方案**（官方範例題 Q8 的正確選項 A）。

**兩個反模式（考試指南都點名了）：**

- **靜默壓制**——回傳標記為成功的空結果，隱藏了失敗，並有讓不完整的輸出被當成完整呈現的風險。
- **單一失敗就終止整個工作流程**——殺死了原本可能成功的恢復策略（用修改過的查詢重試、切換到替代來源、帶著部分結果繼續前進）。

**存取失敗對有效的空結果：** 逾時（「連不上來源」→ 需要重試決策）與查詢成功但沒有匹配（一個真正的答案）有根本的不同。錯誤回報必須區分兩者，否則協調者會對空結果重試，並且默默接受中斷。

**本地恢復優先：** 子代理自己處理 **transient**（暫時性）失敗（用退避重試）；它們只傳遞本地**無法解決**的錯誤，並附上嘗試過什麼以及部分結果。籠統的狀態（「搜尋不可用」）隱藏了恢復所需的脈絡。

**涵蓋範圍註記：** 當綜合在有缺口的情況下繼續進行，輸出必須**註記哪些發現有充分支持，以及哪些主題領域因為來源不可用而有缺口**——降級的覆蓋範圍必須可見，不能靜默。

### 4. 大型程式碼庫探索中的上下文（任務 5.4）

**劣化症狀：** 在拉長的工作階段中，模型開始給出**不一致的答案**，並引用「典型模式」，而不是它**先前發現的特定類別**——退回一般知識就是訊號，代表已發現的事實已被稀釋或逐出。

**對策（四個都是考試列出的技能）：**

1. **暫存檔**——agent 維護一個記錄關鍵發現的檔案，並**在後續問題中參考它**，讓知識跨越上下文邊界持續存在。檔案是無損的；上下文不是。
2. **子代理委派**——把冗長的調查交給子代理（「找出所有測試檔案」、「追蹤退款流程的依賴關係」）；探索輸出留在子代理的上下文裡，主 agent 保持高層協調乾淨。
3. **階段摘要**——在啟動下一階段的子代理之前，先摘要這一個探索階段的關鍵發現，並**把那份摘要注入它們的初始上下文**。
4. **`/compact`**——在拉長的工作階段中，當上下文被冗長的探索輸出填滿時，用來壓縮上下文（在 Claude Code 裡搭配定向壓縮——見檔案 `05`）。

**用 manifest 做當機復原：** 結構化狀態持久化 = 每個 agent **把自己的狀態匯出到一個已知位置**；恢復時，協調者**載入 manifest 並把它注入 agent 的提示詞**。一次當機付出的代價，只是一個階段的尾巴，不是整次執行。（同一個「檔案勝過上下文」原則，套用到全系統復原。）

### 5. 人類審核工作流程與信心校準（任務 5.5）

**整體指標會掩蓋分段失敗：** 「97% 整體準確率」可能藏著某一種文件類型或某一個欄位只有 60% 準確率。**在自動化高信心萃取之前，要按文件類型、按欄位分段驗證準確率。**

**分層隨機取樣：** 即使模型標記為高信心的萃取，每個分層也要**持續做隨機取樣**（文件類型 × 欄位），以量測真實的錯誤率，並捕捉**新出現的錯誤模式**。沒有這個取樣，漂移在事故發生前是看不見的。

**校準過的欄位層級信心：** 讓模型輸出**每個欄位的信心分數**，然後**用已標記驗證集校準審核門檻**——原始的自我回報信心不可信（與 5.2 同一課）；對照標籤校準，才讓信心可以用於路由。

**路由規則：** 低信心的萃取以及**模糊或互相矛盾的來源文件**交給人工審核，把有限的審核人力優先放在錯誤機率真正最高的地方。

### 6. 多來源綜合中的出處可追溯性與不確定性（任務 5.6）

**出處歸屬會死在摘要裡：** 當發現被壓縮而沒有保存**主張與來源對應**，最終報告就說不出哪個來源支持哪個主張。修復方法：子代理輸出**結構化的主張與來源對應（主張、來源 URL／文件名稱、相關摘錄）**，下游 agent **在綜合過程中保存並合併**——出處可追溯性是一份資料契約，不是一種寫作習慣。

**可信來源的統計數字互相衝突：** **用來源歸因註記這個衝突**——絕不要任意挑一個數字，也絕不要取平均。文件分析完成時，**要把衝突的數值都放進去，並明確註記**，讓協調者在綜合之前決定如何調和。

**時間詮釋資料：** 要求**結構化輸出帶上發布／蒐集日期**，這樣一個 2024 年的數字和一個 2026 年的數字讀起來是一條時間序列，而不是矛盾。

**報告結構：** 用明確的小節把**已確立的發現和有爭議的發現**分開，保留原始來源的表述方式以及方法論脈絡。依內容類型適當呈現——**財務資料用表格、新聞用敘述文字、技術發現用結構化清單**——不要把所有東西壓平成一致的敘述文字。

## 決策樹

**「這份資訊該住在哪裡？」**

```text
精確的交易事實（金額、日期、ID）？
 → 每一個提示詞的案件事實區塊，放在摘要化歷史之外
之後還需要的、已發現的程式碼庫／系統事實？
 → 暫存檔（按需重新讀取）
冗長的原始工具輸出？
 → 在進入上下文之前修剪到相關欄位
跨階段／跨當機的狀態？
 → 結構化狀態匯出 + 協調者載入的 manifest
跨來源的「誰說了什麼」？
 → 在每次交接中都保存下來的主張與來源對應
```

**「升級還是解決？」**

```text
客戶明確要求真人 → 現在就升級（不要先調查）
政策對這個請求沒有規定／含糊 → 升級（政策缺口）
無法取得有意義的進展 → 用結構化交接升級（檔案 08 第 4 節）
只是複雜，但在政策內而且有進展 → 繼續解決
多個身分匹配 → 要求更多識別資訊，絕不要猜
```

**「一個子代理失敗了——什麼該向上流動？」**

```text
暫時性？ → 先本地重試；恢復了就什麼都不上傳
不可恢復？ → 失敗類型 + 嘗試過的查詢 + 部分結果 + 替代方案
空結果集？ → 以零匹配的成功回報（不是錯誤）
綜合無論如何都要繼續？ → 輸出裡附上覆蓋缺口註記
```

## 自我檢查問答

**Q1.** 漸進式摘要最先摧毀哪類資訊？
**A.** 精確的數字、百分比、日期、訂單編號，以及客戶明說的期望——被濃縮成模糊的敘述文字。

**Q2.** 定義案件事實模式。
**A.** 把交易事實萃取出來，放進一個結構化區塊，附在每一個提示詞裡、放在摘要化歷史之外——有損摘要底下的無損層。

**Q3.** 什麼是中段遺失？有哪兩個緩解方法？
**A.** 模型能可靠處理長輸入的開頭和結尾，但會漏掉中段的內容；把關鍵發現摘要放最前面，並使用明確的節標題。

**Q4.** 一次訂單查詢回傳 40 多個欄位，只有 5 個相關。你要做什麼？什麼時候做？
**A.** 在結果進入上下文*之前*，修剪到回傳相關的欄位。

**Q5.** 下游上下文很緊時，上游子代理該回傳什麼？
**A.** 結構化資料——關鍵事實、引用來源、相關性分數，加上日期／來源詮釋資料——不是冗長的內容和推理鏈。

**Q6.** 三個正當的升級觸發條件？
**A.** 客戶明確要求真人；政策例外／缺口；無法取得有意義的進展。

**Q7.** 客戶為一個小事就能修好的問題要求真人。順序？
**A.** 立即照辦；最多認同一次、提出修復方案一次，對方重申就升級——絕不要違背他的請求先調查。

**Q8.** 為什麼情緒和自我回報信心是差的升級路由器？
**A.** 兩者都和案件複雜度沒有相關；信心未經校準——agent 在困難案件上自信滿滿地答錯（範例題 Q3）。

**Q9.** 工具為「John Smith」回傳三個客戶。正確行為？
**A.** 要求額外的識別資訊；絕不要用啟發法挑選。

**Q10.** 一個搜尋子代理逾時。協調者需要什麼才能聰明恢復？
**A.** 結構化錯誤上下文：失敗類型、嘗試過的查詢、部分結果、替代方案（範例題 Q8）。

**Q11.** 說出兩個錯誤處理反模式，以及各自的危害。
**A.** 靜默壓制（失敗被包裝成空的成功 → 不完整的輸出看起來像完整）以及單一失敗就終止整個工作流程（殺死可行的恢復）。

**Q12.** 存取失敗對有效的空結果——為什麼要區分？
**A.** 一個需要重試決策，另一個是真正的答案；混淆兩者會造成錯誤的重試，以及被默默接受的中斷。

**Q13.** 錯誤什麼時候離開子代理？
**A.** 只有在本地恢復（例如對暫時性失敗重試）失敗之後——上傳時附上嘗試過什麼以及部分結果。

**Q14.** 綜合在一個來源中斷的情況下完成。報告必須包含什麼？
**A.** 涵蓋範圍註記：哪些發現有充分支持，哪些主題領域因來源不可用而有缺口。

**Q15.** 長時間探索工作階段的上下文已經劣化，症狀是什麼？
**A.** 答案不一致，並且訴諸「典型模式」，而不是先前發現的特定類別。

**Q16.** 大型程式碼庫上下文管理的四個對策？
**A.** 暫存檔；把冗長調查交給子代理委派；注入下一階段上下文的階段摘要；/compact。

**Q17.** 為多 agent 執行設計當機復原。
**A.** 每個 agent 把結構化狀態匯出到已知位置；恢復時，協調者載入 manifest 並注入 agent 的提示詞。

**Q18.** 為什麼 97% 整體準確率不足以自動化？
**A.** 整體指標掩蓋分段失敗——在減少人工審核之前，準確率必須按文件類型、按欄位驗證。

**Q19.** 分層隨機取樣在審核工作流程中的角色？
**A.** 對高信心萃取按分層持續量測錯誤率，捕捉新出現的錯誤模式和漂移。

**Q20.** 模型信心如何變得可用於審核路由？
**A.** 模型輸出欄位層級分數；門檻對照已標記驗證集校準——原始的自我回報不被信任。

**Q21.** 兩個可信來源給出不同的市場規模。怎麼處理？
**A.** 兩個都放進去，附來源歸因註記；協調者決定如何調和——絕不任意挑選，也絕不取平均。

**Q22.** 為什麼結構化輸出要求發布日期？
**A.** 讓時間差異讀起來是隨時間的變化，而不是矛盾。

**Q23.** 什麼讓出處歸屬在多 agent 綜合中存活？
**A.** 結構化的主張與來源對應（主張、來源、摘錄），每個下游 agent 都保存並合併。

**Q24.** 綜合報告該如何對待有爭議的發現？
**A.** 已確立與有爭議的發現分開成明確的小節，保留原始來源的表述和方法論脈絡。

**Q25.** 一份報告包含財務資料、新聞和技術發現——格式？
**A.** 分別是表格、敘述文字和結構化清單——依內容類型呈現，不要壓平。
